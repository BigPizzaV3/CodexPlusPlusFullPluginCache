# Board Diagnosis

Use only tools exposed in this session; if a named tool is missing, say so and stop that step. Use visible plain-text `monday-crm-skill-id: <skill>` markers; monday Docs can strip HTML comments. Read back newly created artifacts to verify their marker. Before creating, search within the relevant workspace and read candidate content; match title, skill marker, board or item, and date or period. Treat surviving legacy `<!-- monday-crm-skill-id: … -->` and `<!-- claude-skill-id: … -->` markers as matches. If a candidate has the right title and generated-by footer but lacks a marker, or matching is ambiguous or incomplete, do not create or update automatically: show the candidate and ask the user. If search or read-back is unavailable, stop the write. For meeting recaps also include and verify a visible `meeting-id: <id>` marker; if either marker is missing, do not infer a match or create a duplicate automatically.

Structural audit of a CRM board — shaped as a CSM / admin deliverable. Surfaces missing-data patterns, stalled groups, column drift, automation gaps, and data-quality scores. Publishes a prioritized diagnosis doc in the user's workspace.

Flow: **Trigger → Gather → Synthesize → Show draft → offer publication (α, opt-in) → Share (β, opt-in) → Proactive extension (opt-in, fix tasks)**.

## Input
- Optional: board name / ID from the user's request.
- Optional: pre-declared mode (Default / Silent / Proactive).

## Output
- **α (default):** A `create_doc` diagnosis report in the user's workspace, title `Board Diagnosis — <board name> — <Mon DD>`. Body carries `Generated by monday CRM plugin · <ISO timestamp>` + `monday-crm-skill-id: board-diagnosis` for idempotency + auditability.
- **β (Share):** Share doc permission + `create_notification` to CSM.
- **Proactive extension:** `create_item` (fix-task) per issue, written into a `Fix Tasks` group with `Source = AI assistant` populated on a status column (auto-create the column with user confirm if missing); normalize trivial column data (phone, country code, email casing) via `change_item_column_values`; can also batch-edit owner / source / last-touch columns when the user confirms a plan. Never edits amount columns, never deletes.

A native monday dashboard or board cannot be created outside monday: present a concrete preview or blueprint, not a claim that it exists. State meaningful missing data or assumptions. Then ask once whether to publish the displayed draft to the specified monday destination; allow edits or decline. On decline, retain the draft and stop without monday writes. On approval, publish only the shown content and concrete actions the user approved. Separately describe and obtain approval for record edits, notifications, contacts, automations, or other actions not included in that publication. Do not ask to choose a mode before producing the draft; use read-only default behavior. Ask only for information essential to prepare a useful, accurate draft, and state reasonable defaults. This draft-first rule takes precedence over earlier or later mode and publish-first instructions.

## Step 1: Detect mode

Use read-only default behavior while preparing the diagnosis. Do not ask for a mode. Offer fix tasks or normalization only after the diagnosis and obtain approval for their concrete scope.

## Step 2: Resolve the board (Gather)

**Goal:** Same resolution path as morning-briefing Step 2. `get_user_context` → `list_workspaces` → `search("deal")`. Allow "all" for multi-board audits (produces one doc per board).

---

## Step 3: Read board schema (Gather)

**Goal:** Full column inventory + type classification for every column (not just CRM-critical ones — the audit looks at ALL columns to find drift).

1. `get_board_info(boardId)` → full column list.
2. `get_column_type_info` for any column where fill rate will be calculated.

---

## Step 4: Pull data (Gather)

**Goal:** Enough data to compute fill-rate, staleness, and activity patterns. Paginate up to 2K most-recent items. Also pull:
- `board_insights` for aggregate stats.
- `get_activity_logs` with this board's `board_ids` and a time window of at most 90 days. Follow its cursor with the same filters when further history is needed. Empty or partial visible logs do not prove inactivity; state coverage and missing evidence.
- `list_automations(boardId)` to read automation rules.

Same rate-limit + error-handling as morning-briefing Step 5. On partial failures, continue — note which strand failed in the diagnosis doc.

---

## Step 5: Synthesize — five diagnosis strands (Synthesize)

**Goal:** Produce a prioritized fix list across these strands:

1. **Missing data patterns** — required fields (stage, owner, value, close_date) blank on >25% of items. Compute fill-rate per column.
2. **Stalled groups** — assess visible item activity with `get_activity_logs` and the current group membership. Flag groups only when at least 30 days of sufficient history support the finding; for new boards or incomplete logs, report insufficient history rather than inactivity.
3. **Column drift** — report current fill rates below 5% as candidates for review. Suggest archiving only when usage history and the column's purpose support it; current emptiness alone does not prove abandonment.
4. **Automation gaps** — stage-based automations absent on deal boards (from `list_automations`).
5. **Data-quality score** — % of items with complete core fields.

Rank findings by impact × fix-effort. P0 = data blocking forecast / reporting; P1 = hygiene; P2 = structural.

Score = 100 × records with nonblank stage, owner, value and expected close date / records inspected. State the denominator, sampling and core-field definitions. Empty boards have no meaningful score. Report active and closed populations separately when that changes interpretation. This is a completeness score, not an invented weighted index. Rank actual forecast-blocking gaps P0, workflow/data-hygiene issues P1, and optional structural cleanup P2; describe a concrete action and supporting evidence for each.

---

## Step 6: Publish α — diagnosis doc (Publish)

**Goal:** Present the full diagnosis with evidence, score and prioritized actions, then ask whether to publish that report as a monday doc.

Show the concrete report and obtain approval before writing it. Core content sections:
- **Score:** overall data-quality score (0-100) + 5-strand breakdown.
- **P0 fixes** — concrete, actionable.
- **P1 / P2 fixes** — batched.
- **Automation recommendations** — per stage-based pattern missing.
- **Column cleanup** — archive list.

Idempotency: follow the platform notes and verify the matching board, date and marker before updating an existing doc; stop on ambiguity.

Non-admin fallback isn't applicable (docs don't require admin). But if Proactive mode is on AND user isn't admin, skip `create_item` fix-tasks with a note ("admin-only").

---

## Step 7: Share β — route to CSM (opt-in)

**Goal:** Notify the CSM with the doc link. Don't change doc permissions.

1. `list_users_and_teams` → user picks the CSM.
2. Confirm, then `create_notification` to the CSM with the doc link.
3. Tell the user: *"If <name> can't open the doc, share it from the doc's Share button in monday."* No dedicated tool exists for doc permissions, so the plugin leaves sharing to the user.

---

## Step 8: Proactive extension — create fix-tasks + normalize (opt-in)

**Goal:** Turn the diagnosis into action, but stay inside the safety rail.

For each P0 / P1 fix:
- `create_item` in a `Fix Tasks` group with title `Fix: <issue>`, assigned to board owner (or CSM if admin). Populate `Source = AI assistant` on the board's source/status column (auto-create the column with user confirm if missing).
- For **trivial** normalization (phone-number reformatting, country-code standardization, email lowercase): `change_item_column_values`. Never write to amount columns. Stage/owner/source/last-touch edits OK inside a batched-confirm plan, but call `bulk-data-hygiene` for board-wide passes — this skill stays focused on diagnosis-driven point fixes.
- If >20 fix-tasks: batch into one `Fix Tasks — <date>` doc list (with `monday-crm-skill-id: board-diagnosis` in body) rather than creating 20 items.
- Never deletes columns, never archives groups, never removes automations.

For a requested normalization, use the bulk-data-hygiene skill's conservative rules: retain known country context, propose E.164 phone and ISO country values only when unambiguous, and show the exact approved batch. Never infer a country or overwrite an ambiguous value.

---

## Step 9: Close the loop

**Goal:** Summary line + doc URL.

After publication succeeds, report the verified doc URL. If declined or failed, say the diagnosis remains a draft; report fix tasks only if actually created.

## Shared patterns

- **No title prefix.** Artifact discoverability is via the `Generated by monday CRM plugin · <ISO timestamp>` footer and the embedded `monday-crm-skill-id: board-diagnosis` visible plain-text marker in doc bodies. For items the plugin creates, use `Source = AI assistant` on a status column (auto-create the column with user confirm if missing).
- **Idempotency before create.** Always search for same-day artifact (by title + skill-id marker) first. Update, don't duplicate.
- **Safety rail.** No deletes, no amount-column writes, no cross-workspace moves. Stage/owner/last-touch/source edits OK in a batched-confirm plan.
- **Ask once per session**, not per item, when entering Proactive mode.
- **Type-based column resolution**, not name-based — global teams have non-English columns.

## Error handling reference

| Failure | Behavior |
|---|---|
| Connector not installed | Step 0 stops; print install link. |
| No CRM board | Step 2 stops; offer path to the `workspace-builder` skill. |
| Board >10K items | Cap at 2K most-recent, flag sampling. |
| MCP tool error (retryable) | Exponential backoff 3x; on third fail, skip that strand, surface partial report. |
| Same-day artifact exists | Update in place via doc ID. |
| 429 rate limit | Backoff 3x, then stop with retry note. |
| Non-admin publish perms | Degrade to print-only. |
| Non-English column names | Resolve by type via `get_column_type_info`. |

Additional:
- **`board_insights` 9% baseline error** → on retry failure, skip that strand; diagnosis still produced with hygiene-line noting the missing strand.
- **Automation probe fails** (`list_automations` permission error) → skip strand 4 with note "couldn't inspect automations — ask admin to re-run".
