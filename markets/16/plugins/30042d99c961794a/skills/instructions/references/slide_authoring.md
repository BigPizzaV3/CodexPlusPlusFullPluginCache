# Slide Authoring Standard

## Purpose

Use this reference whenever the user asks for slides, a presentation, a PowerPoint, a conference talk, a lecture deck, or a slide storyboard.

## 1. Start from the talk, not the slide count

Identify:

- audience and level;
- presentation duration;
- purpose: teach, persuade, update, case conference, journal club, workshop or assessment;
- 3–5 key messages;
- evidence/source constraints;
- requested language and visual style.

If duration is missing and materially affects structure, ask one concise question. Otherwise make a reasonable assumption and state it.

Do not use a rigid 1-minute-per-slide rule. A dense evidence slide may need several minutes; a visual transition may need seconds.

## 2. Story arc

Prefer a coherent sequence:

1. Why this matters / opening problem
2. Learning objectives or questions
3. Core concepts / framework
4. Evidence, mechanism or worked examples
5. Application / case / decision points
6. Summary / take-home messages
7. References when appropriate

Adapt the arc to the talk type. Do not mechanically include every section.

## 3. Slide-level rule

Each slide should have **one dominant message**. Use a message-oriented title when helpful rather than a vague label.

Avoid mandatory “three bullets per slide.” Choose the format that best communicates the message:

- short text;
- diagram;
- timeline;
- comparison table;
- algorithm / flow;
- clinical case reveal;
- chart;
- image with annotation;
- key quotation or statistic when sourced.

Keep on-slide text concise and readable. Put explanation in speaker notes when supported.

## 4. Visuals

Use visuals when they explain structure, comparison, trend, mechanism or sequence. Do not add decorative images that compete with content.

For medical education, prefer:

- anatomy/mechanism diagrams;
- process flows;
- diagnostic or management pathways for educational use;
- evidence-summary tables;
- timeline of disease/course/research;
- before–after or option comparison;
- case progression.

Do not fabricate images, charts or quantitative data. Label simulated data clearly.

## 5. PowerPoint output

When artifact-generation tools are available and the user asks for a `.pptx`, create the actual file. Use 16:9 unless the user requests another format. Use a clean professional theme, consistent typography, strong contrast, and restrained decoration.

Do not promise a downloadable `.pptx` if the environment cannot create one. In that case, provide a production-ready storyboard with:

- slide title;
- key message;
- on-slide content;
- suggested visual;
- speaker note / teaching point when useful;
- source cue when needed.

## 6. Long decks

Do not refuse or automatically convert to prose merely because the deck exceeds 20 slides. Instead:

- confirm the educational purpose and duration;
- group content into sections;
- remove redundancy;
- move detail to appendix/notes;
- split into modules only when pedagogically useful or required by tool limits.

## 7. Medical / evidence content

For current clinical or education guidance, verify sources when needed. Keep educational scope; do not turn a teaching deck into patient-specific advice.

For conference decks, prioritize novelty, decision relevance and take-home messages over textbook completeness.

## 8. Final slide check

Before finalizing:

- every slide advances the story;
- titles are specific;
- no slide is overloaded;
- tables are readable;
- visuals are informative;
- terminology is consistent;
- sources support the claims they follow;
- summary matches the learning objectives;
- appendix contains useful detail that would otherwise disrupt the main narrative.
