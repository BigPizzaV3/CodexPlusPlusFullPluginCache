# Pages and current capacity

Resolve the intended organization and use organization_capabilities before quota-sensitive operations. It reports effective current resource limits, usage, granted scopes and an approved billing destination. Enabled workflow count and enabled Line count differ from total resources; Line provider connection status is separate. Databases count all organization databases; optional databaseId/tableId reports their table, column and row usage. Pages count active published revisions, public or private, separately from total stored drafts. Draft editing does not consume publication capacity.

Treat unlimited and unavailable distinctly. These are snapshots; backend enforcement decides under concurrency. Do not label role denial, missing scope, validation failure, disconnected account or a resource dependency as a quota problem. Explain a quota failure using current resource usage and the applicable limit. Higher-plan capacity and offers are unavailable unless an authoritative response supplies them. Explain entitlement restrictions without promoting subscriptions or purchase flows; do not invent prices, benefits, plan limits or URLs. Never disable, delete, unpublish, purchase or change a subscription merely to free capacity.

## Discover and author

Use the separate pages_schema, pages_blocks, pages_templates, pages_feed_schema, pages_operations and pages_contracts tools. They return current native contracts, including extensions and visualization variants. pages_operations lists the exact individually discoverable tools and fields. Each action has its own typed schema; do not send an operation/section selector or an opaque configuration envelope. Do not assume the older widget baseline is complete. Guest FileUpload remains gated; a rendered widget is not proof of operational upload support.

Use pages_search, pages_draft, pages_export, pages_definition_part, pages_access, pages_usage, pages_readiness, pages_history, pages_draft_history, pages_checkpoint, pages_publication, pages_resource_usage and pages_feeds. Supply the discovered native field names as top-level arguments alongside organizationId. For a large tree, pages_definition_part accepts id and pointer; array windows use offset/pageSize (1–50). Retain the returned draft revision across windows and restart inspection if it changes. Narrow the pointer if a selected subtree is still too large. Omitted properties are not null values. Export is a definition, not a transferable identity or credential grant.

Use pages_create (blank or imported/template definition), pages_duplicate, pages_save, pages_mutate, pages_restore_draft or pages_update_access. Supply a UUID requestId and preview first; commit the identical reviewed arguments with commit=true. Retrying that exact tool/request returns the durable receipt. Switching tool or arguments needs a new requestId after reconciling any prior uncertain write. Native definitions are serialized versioned JSON. pages_mutate supports up to 100 related add/replace/remove edits with optimistic concurrency; whole-definition saves cover the same theme, tree, responsive properties, conditions, actions, bindings and URL inputs. Copies/imports create unpublished identities with fresh widget IDs. Never insert arbitrary scripts, HTML, unsafe CSS/URLs or credentials.

Use the already published pages_validate with its unchanged configuration input (title and serialized definition) for structure and owned bindings. Publication additionally checks workflow readiness, feed visibility, uploads and current quota. A preview is not proof of runtime success. pages_preview, pages_preview_rows, pages_preview_lookup and pages_preview_versions preserve native creator/revision authorization and do not run actions. Save, publish and execute are distinct.

## Publication, data and actions

Only use pages_publish, pages_unpublish, pages_visibility or pages_rollback when the user's request authorizes that exact action. pages_publish publishes only; it does not select another operation. Preview/commit uses actual expectedDraftRevision and required expectedPublishedRevision (explicit null for an unpublished Page). pages_visibility and pages_rollback accept the typed nested page revision object; visibility also requires expectedPrivate and makePrivate. Publication and visibility can change publicly visible internet content, links and visitor actions; their openWorldHint is true even though they do not execute those actions. Draft edits do not replace live revisions. Read publication and draft histories separately. Use pages_access for immutable addresses and native private views, and pages_update_access to review changes to allowed HTTPS embed origins. A private preview is not a public link or a quota bypass. Do not issue visitor tickets or subscribe ChatGPT to visitor streams.

Configure native Page Event -> Action mappings through the definition. Use existing authorized workflow bindings; never expose webhook credentials, invent a new trigger or treat URL parameters as identity. Navigation filters only narrow already publishable collections; use native Tracking for confidential reference lookups. Request forms must not promise confirmed appointments or authoritative order totals without the native server validation that establishes them.

Multiple ChatigramLine instances can share a Page. Resolve actual organization Lines and channel capabilities: Live Chat uses supported inline/popup launch. The current native launch contract does not supply Telegram/WhatsApp external destinations; report that channel as unavailable instead of claiming a working handoff. Never invent URLs or modify a connection to fit a Page. Native runtime authorization and publication gates remain authoritative.

## Live Feeds and bounded records

Use pages_feed_schema for current scalar fields, capacity, TTL and operation bounds. pages_create_feed requires an explicit publicSafe boolean: choose false unless visitor exposure was deliberately authorized. Never silently designate private data public-safe. Use pages_replace_feed for latest feeds, pages_append_feed for events feeds and pages_clear_feed to remove retained entries. Each takes feedId and eventId; replace/append additionally take declared scalar values. No operation selector is accepted. These writes may change data shown to public visitors, and append may evict old entries under retention. Reuse event IDs on retry; native deduplication is bounded by retained entries, while identical MCP request retries additionally use the durable receipt. pages_delete_feed requires explicit authorization and native draft/live dependency checks.

Configure the existing UPDATE_LIVE_FEED workflow node discovered through list_node_types. It writes an owned feed without running another workflow. Configure Static, Manual, Periodic, Change-based, Event-based or Live Push through the native binding schema and its restrictions. Push uses the native SSE runtime; normal stream renewal is not an outage. Stream tickets, heartbeat/recovery and private-view checks remain native behavior.

For a request like “Create a live page connected to my Chatigram data,” identify the organization, intended data source and audience. Inspect the available fields and refresh modes, select only fields appropriate for that audience, and create an unpublished draft. Use a creator preview to confirm the binding returns the expected data. Before public publication, review the fields, visitor actions and exact HTTPS origins allowed to embed the Page. Private publications require access to the owning organization. Verify the intended visitor route after publication.

Discover pages_render_preview before requesting a visual review. Supply id, source (draft or published) and the exact saved revision. viewport can be desktop or mobile, theme light or dark, and extent viewport or full. Inspect the returned native image and capture warnings. External assets are restricted. Use pages_preview to read the saved definition. Use theme.timeZone for dashboard date filtering, and Section presentation mesh with meshPalette, meshIntensity and meshSpeed for a layered form. Section children remain interactive. Use pages_component with component Section and example Layered task form to inspect its registered contract and editable example. For an installation icon use pages_list_icon_assets or use pages_upload_icon with a host-selected image and preview/commit. Set pwa.iconAssetId in the current draft with pages_save, then inspect the saved revision through pages_read_icon. Replace that ID to change the icon or remove the property for the fallback. Publishing requires separate authorization. Shorten the canonicalUrl from pages_access with create_short_link and a stable requestId. Native Page form WEBHOOK extractors read values under $.fields; review the actual saved workflow, enabled state and Page event binding.

For several inserts use create_records_batch with tableId, 1–32 scalar row maps in items and a stable requestId. Preview first, then commit identical input. Recover uncertain completion by replaying the same commit after the retry interval. Each successful row has an index and rowId; database atomicity applies only to the batch transaction.

Use read_records columns and pageSize to inspect metadata without image or payload bytes; an empty columns list selects system metadata. countOnly returns exact filtered matchedCount without row payloads. includeCount adds a count to a projected page. Omitted options preserve legacy responses. Use add_schema_columns for a previewable atomic additive batch when appropriate; do not commit multiple stale independent schema previews.
