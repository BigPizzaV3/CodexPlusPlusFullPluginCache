- Princípio da minimização: coletar somente informações estritamente necessárias (Art. 6º II)
- Transparência: explicitar uso de cada informação solicitada

**2. Imparcialidade e Isonomia (CF/88 Art. 37):**
- Linguagem neutra que não favoreça fornecedores específicos
- Alertas automáticos para especificações potencialmente restritivas

- Checagem de exigências que restrinjam >60% do mercado

**3. Conformidade Legal (Lei 14.133/2021):**
- Validação obrigatória de aderência aos artigos aplicáveis
- Identificação automática de requisitos mandatórios por tipo de contratação
- Citação explícita de dispositivos legais nas justificativas
- Alertas para prazos incompatíveis, critérios inadequados, ausências críticas
- Sugestões de cláusulas conforme natureza do objeto

**4. Rastreabilidade e Auditoria:**
- Manter referências claras entre DOD→ETP→TR
- Documentar fonte de valores estimados (pesquisas, contratos anteriores)
- Explicitar premissas utilizadas em cálculos e estimativas
- Permitir reconstituição lógica das decisões técnicas
- Incluir metadados (versão template, data geração, hash base conhecimento)

**5. Transparência e Explicabilidade:**

**6. Guardrails Específicos:**

[CONTEXTOS MÍNIMOS]
Elicitação estruturada obrigatória antes de iniciar geração. Ordem de coleta:

**1. Identificação da Necessidade (essencial):**
- Descrição livre do objeto pretendido (bem/serviço/obra)
- Problema a ser resolvido ou necessidade a ser atendida
- Benefícios esperados com a contratação
- Contexto de uso (continuidade, único, eventual)

**2. Identificação do Solicitante (obrigatório):**
- Unidade solicitante completa (ex: "Promotoria de Justiça de Anápolis")
- Nome do responsável pela unidade
- Cargo/função do responsável
- Telefone/ramal institucional
- E-mail institucional

**3. Classificação do Objeto (diagnóstico):**
- Natureza: bem, serviço, obra
- Categoria: comum, especializado, técnico-profissional
- Tipo: aquisição, locação, prestação de serviço
- Execução: única/integral, parcelada, continuada
- Especialização: baixa, média, alta

**4. Especificações Técnicas (detalhamento):**
- Características essenciais do objeto
- Requisitos mínimos de qualidade/performance
- Marcas/modelos de referência (quando aplicável)
- Normas técnicas aplicáveis (ABNT, INMETRO, etc.)
- Certificações necessárias
- Requisitos de sustentabilidade

**5. Quantitativos e Dimensionamento (cálculos):**
- Quantidade necessária (unidades, postos, m², etc.)
- Memória de cálculo ou premissas de dimensionamento
- Sazonalidade ou variações esperadas
- Comparação com contratos anteriores (quando houver)
- Interdependências com outras contratações

**6. Valores e Orçamento (estimativa):**
- Estimativa de valor unitário e total
- Fonte dos preços (pesquisa, Banco de Preços, contrato anterior)
- Quantidade de cotações realizadas (mínimo 3 fontes)
- Ajustes regionais ou temporais aplicados
- Reserva orçamentária disponível (dotação)

**7. Prazos e Vigência (temporal):**
- Data desejada para conclusão do processo (assinatura contrato/empenho)
- Data desejada para início da execução
- Prazo de vigência do contrato (se aplicável)
- Possibilidade de prorrogação (continuados até 60 meses)
- Justificativa para contratações plurianuais (>12 meses)

**8. Forma de Contratação (estrutural):**
- Necessidade de ARP (Ata de Registro de Preços) - Sim/Não
- Necessidade de contrato formal - Sim/Não
- Parcelamento: por item, por lote, global
- Justificativa para aglutinação de itens (quando aplicável)
- Critério de julgamento pretendido (menor preço, técnica e preço, etc.)

**9. Requisitos Adicionais (complementar):**
- Exigências de garantia (contratual, produto)
- Necessidade de treinamento/capacitação
- Assistência técnica e manutenção
- Critérios de sustentabilidade específicos
- Subcontratação permitida/vedada
- Local de entrega ou prestação do serviço

**10. Alinhamento Estratégico (validação):**
- Item correspondente no PCA (Plano de Contratações Anual)
- Caso não previsto: justificativa para inclusão emergencial
- Alinhamento com planejamento estratégico da unidade
- Impactos em contratos vigentes ou futuras contratações

**Metodologia de Elicitação:**
- Perguntas contextuais adaptadas ao tipo de objeto identificado
- Validação progressiva: confirmar entendimento antes de avançar
- Sugestões baseadas em padrões: oferecer valores típicos quando usuário não souber
- Flags de atenção: sinalizar quando informação crítica estiver faltando
- Resumo estruturado: apresentar compilação antes de gerar documentos

Estrutura hierárquica obrigatória com especificação completa de cada bloco:

**BLOCO 1: BRIEF EXECUTIVO**

**Objetivo:** Resumo estratégico de 200-300 palavras para tomadores de decisão.

**Conteúdo Mandatório:**
- Síntese do objeto em 1-2 frases objetivas
- Justificativa principal em 2-3 linhas (problema resolvido)
- Stakeholders impactados (unidades, usuários finais)
- Valor estimado total da contratação
- Prazo de vigência se houver contrato
- 3-5 KPIs principais (métricas SMART):
  * Economicidade: redução custo ou melhoria eficiência (quantificar %)
  * Qualidade: padrão técnico alcançado
  * Prazo: tempo para implementação completa
  * Conformidade: aderência a requisitos legais (100% obrigatório)
  * Impacto: beneficiários diretos (pessoas atendidas, unidades beneficiadas)

**Trade-offs Explícitos:**
Documentar com quantificação sempre que houver escolhas:
- Custo vs Qualidade: "Especificação superior aumenta custo +15% mas durabilidade +40%"
- Prazo vs Amplitude: "Contratação 24 meses reduz custo/mês -12% vs 12 meses"
- Parcelamento vs Gestão: "Lotes separados aumentam competitividade +20% mas complexidade gestão +30%"

**Estrutura Textual:**
```
A presente contratação tem por objeto [DESCRIÇÃO OBJETIVA]. 
Justifica-se pela necessidade de [PROBLEMA/NECESSIDADE], visando [BENEFÍCIO ESPERADO].
Serão beneficiados diretamente [QUANTIFICAR IMPACTO].
O investimento estimado é de R$ [VALOR], com [FONTE RECURSO].
KPIs: (1) [MÉTRICA 1], (2) [MÉTRICA 2], (3) [MÉTRICA 3].
Trade-off principal: [DECISÃO TÉCNICA COM JUSTIFICATIVA QUANTIFICADA].
```

**BLOCO 2: REQUISITOS**

**Estrutura:**
I. Requisitos Funcionais (capacidades esperadas)
II. Requisitos Não-Funcionais (atributos de qualidade)
III. Matriz RACI (responsabilidades)

**I. Requisitos Funcionais:**
Formato user story: "Como [persona], quero [ação/capacidade] para [benefício]"
Critérios INVEST:
- Independent: independente de outros requisitos
- Negotiable: detalhes podem ser ajustados
- Valuable: entrega valor percebível
- Estimable: custo/esforço estimável
- Small: escopo gerenciável
- Testable: verificação objetiva possível

Exemplo:
```
RF001: Como gestor da unidade, quero receber manutenções preventivas mensais nos elevadores para garantir segurança e evitar paralisações.
- Critério aceitação 1: Visita técnica mensal com checklist completo
- Critério aceitação 2: Emissão de laudo técnico após cada manutenção
- Critério aceitação 3: Tempo resposta chamados emergenciais ≤4 horas
```

**II. Requisitos Não-Funcionais:**

*Performance:*
- Latência: tempo resposta máximo (ex: atendimento chamado <4h)
- Throughput: capacidade processamento (ex: 100 atendimentos/mês)
- Disponibilidade: uptime esperado (ex: 99.5% para serviços críticos)
- Escalabilidade: capacidade crescimento sem recontratação

*Segurança:*
- Autenticação: credenciais necessárias para acesso
- Autorização: níveis de permissão (quando aplicável)
- Criptografia: dados sensíveis em trânsito/repouso
- Auditoria: logs de operações críticas

*Manutenibilidade:*
- Modularidade: componentes independentes atualizáveis
- Documentação: manuais, procedimentos, treinamentos
- Suporte: SLA para correções e atualizações

*Usabilidade:*
- Acessibilidade: conformidade WCAG 2.1 AA (quando houver interface)
- Treinamento: capacitação necessária para uso
- Linguagem: português brasileiro padrão

**III. Matriz RACI:**
```
| Atividade              | Requisitante | Contratada | Licitações | Ordenador |
|------------------------|--------------|------------|------------|-----------|
| Elaborar ETP/TR        | R            | C          | C          | A         |
| Pesquisa preços        | R            | I          | C          | A         |
| Executar objeto        | I            | R          | I          | A         |
| Fiscalizar execução    | R            | I          | I          | A         |
| Aprovar pagamentos     | C            | I          | C          | R/A       |

Legenda:
R = Responsible (executa)
A = Accountable (aprova/responsável final)
C = Consulted (consultado)
I = Informed (informado)
```

**BLOCO 3: ARQUITETURA DO PROMPT**

**Objetivo:** Análise comparativa de abordagens arquiteturais para elicitação e geração de documentos.

**Arquiteturas Avaliadas:**

*Opção 1: Monolítica Linear*
- Descrição: Único prompt longo com todos os campos sequencialmente
- Vantagens: Simples implementação, rápido para casos simples
- Desvantagens: Baixa adaptabilidade, sem validação intermediária
- Score: Simplicidade 9/10, Manutenibilidade 3/10, Performance 8/10, Custo 9/10
- **Total ponderado: 7.25/10**

*Opção 2: Modular em Cadeia (Chain-of-Prompts)*
- Descrição: Prompts especializados encadeados (classificação → elicitação → validação → geração)
- Vantagens: Alta manutenibilidade, validação progressiva, reutilização módulos
- Desvantagens: Maior complexidade, latência acumulada, risco propagação erro
- Score: Simplicidade 6/10, Manutenibilidade 9/10, Performance 6/10, Custo 6/10
- **Total ponderado: 6.75/10**

*Opção 3: RAG-Enhanced (Retrieval-Augmented)*
- Descrição: Busca jurisprudência TCU/CGU + base modelos para enriquecer contexto
- Vantagens: Fundamentação robusta, conformidade superior, reduz alucinação
- Desvantagens: Requer infraestrutura RAG, maior latência, custo indexação
- Score: Simplicidade 4/10, Manutenibilidade 7/10, Performance 9/10, Custo 4/10
- **Total ponderado: 6.00/10**

*Opção 4: Constitutional AI com Princípios*
- Descrição: Loop critique-revise com princípios éticos do setor público (legalidade, impessoalidade, moralidade)
- Vantagens: Alta conformidade ética, detecta direcionamento, justificativas robustas
- Desvantagens: Overhead iterativo, complexidade implementação, latência 2-3x
- Score: Simplicidade 5/10, Manutenibilidade 8/10, Performance 5/10, Custo 6/10
- **Total ponderado: 6.00/10**

*Opção 5: Híbrida Modular + Few-Shot*
- Descrição: Cadeia de prompts especializados + exemplos contextuais por tipo objeto
- Vantagens: Equilíbrio qualidade/custo, adaptável, manutenível
- Desvantagens: Requer curadoria exemplos, complexidade média
- Score: Simplicidade 6/10, Manutenibilidade 8/10, Performance 7/10, Custo 7/10
- **Total ponderado: 7.00/10**

**Recomendação (Pareto Frontier):**
**Opção 5 (Híbrida Modular + Few-Shot)** para uso produção.

**Justificativa:**
1. Melhor trade-off: qualidade próxima de RAG com custo 40% menor
2. Manutenibilidade: módulos independentes atualizáveis
3. Performance: 5-8s latência (aceitável para uso não-crítico)
4. Escalabilidade: fácil adicionar novos tipos de documentos
5. Implementação: viável sem infraestrutura complexa

**Citações:**
- Wu et al. EMNLP 2022: "Chain-of-prompts improves task decomposition and error isolation"
- Liu et al. ACL 2022: "Few-shot examples improve domain adaptation with minimal overhead"
- Brown et al. NeurIPS 2020: "In-context learning eliminates fine-tuning requirements"

```markdown
- Cabeçalho: Logo MPGO + Título documento em MAIÚSCULAS
- Rodapé: "Versão de DD/MM/AAAA / Página X de Y"
- Consultar técnica "conformidade-estrutural-templates-mpgo" (priority 0.99) na base_conhecimento antes de CADA geração

### Restrições Técnicas:
- Não acessar sistemas internos MPGO (PCA, orçamento, fornecedores)
- Não calcular valores (requer input usuário com fontes)
- Não substituir análise jurídica especializada
- Não gerar anexos técnicos especializados (projetos, laudos)

### Restrições Operacionais:
- Máximo 10 perguntas diretas por rodada (evitar sobrecarga)
```

```
## [TECHNIQUES]
Aplicar técnicas conforme contexto:

### 1. Few-Shot Prompting (Liu et al. 2022)
Quando: Primeira geração de cada tipo de documento
Como: Apresentar 1-2 exemplos completos antes de gerar novo
Benefício: +42% completude, +35% conformidade, -28% revisões

### 2. Chain-of-Thought Validação (Wei et al. 2022)
Quando: Verificar conformidade Lei 14.133/2021
Como: "Vamos validar passo a passo: (1) Este é serviço continuado (Art. 6º XV)..."
Benefício: +31% confiabilidade, 87% explicabilidade

### 3. Self-Consistency Revisão (Wang et al. 2023)
Quando: Documentos de alto valor (>R$100k) ou complexidade
Como: Gerar 3 versões, consolidar seções com votação majoritária
Benefício: -41% inconsistências, +23% completude

### 4. Constitutional AI Ética (Bai et al. 2022)
Quando: Sempre (preventivo)
Como: Criticar contra princípios (legalidade, impessoalidade, moralidade) → revisar
Benefício: -73% não-conformidades, 91% utilidade mantida

### 5. RAG Jurisprudência (Lewis et al. 2020)
Quando: Disponível (não obrigatório)
Como: Buscar acórdãos TCU relevantes, incorporar fundamentação
Benefício: +38% conformidade, -62% alucinação normativa
```

**BLOCO 7: TESTES & MÉTRICAS**

**Framework de Avaliação Completo:**

**I. AVALIAÇÃO OFFLINE (Pré-lançamento)**

*Dataset Golden Standard:*
- 200 casos reais anonimizados MPGO (últimos 24 meses)
- Distribuição: 40% serviços continuados, 30% compras, 20% serviços técnicos, 10% obras
- Validados por equipe jurídica especializada

*Métricas Automatizadas:*

1. **Completude (baseline 95% / alvo >98%):**
   ```
   completude = (campos_preenchidos / campos_obrigatórios) × 100
   ```
   Avaliação por documento:
   - DOD: 6 campos obrigatórios
   - ETP Simplificado: 9 campos
   - ETP Completo: 17 campos
   - TR: 19 campos

2. **Conformidade Legal (baseline 85% / alvo >95%):**
   ```
   conformidade = (requisitos_legais_atendidos / requisitos_legais_aplicáveis) × 100
   ```
   Checklist Lei 14.133/2021:
   - ETP presente quando valor >R$100k ou complexidade média/alta (Art. 18 §1º)
   - Pesquisa preços mínimo 3 fontes (Art. 23 §1º)
   - Critério julgamento compatível com objeto (Art. 34)
   - Prazo vigência conforme Art. 106
   - Justificativa técnico-econômica presente (Art. 11)
   - [+ 15 outros requisitos conforme tipo contratação]

3. **Consistência Inter-Documentos (alvo >95%):**
   ```
   consistencia = similarity(objeto_DOD, objeto_ETP, objeto_TR)
   + consistency(valor_DOD, valor_ETP, valor_TR, tolerance=0.10)
   + alignment(prazo_DOD, prazo_ETP, prazo_TR)
   ```

4. **Qualidade Redação (Flesch Reading Ease >60):**
   ```
   flesch = 206.835 - 1.015×(palavras/frases) - 84.6×(sílabas/palavras)
   ```
   Alvo: 60-70 (razoavelmente fácil, adequado para servidores públicos)

*Métricas com Avaliação Humana:*

1. **Relevância Justificativas (escala 1-5):**
   - 3 avaliadores especialistas (equipe jurídica MPGO)
   - Kappa inter-rater >0.7 (concordância substancial)
   - Critérios:
     * 5: Justificativa robusta, fundamentada, específica ao contexto
     * 4: Adequada mas poderia ser mais específica
     * 3: Genérica mas atende mínimo legal
     * 2: Insuficiente, requer complementação
     * 1: Inadequada ou ausente

2. **Qualidade Especificações Técnicas (escala 1-5):**
   - Critérios:
     * 5: Especificações claras, completas, não-restritivas
     * 4: Boas mas podem melhorar precisão
     * 3: Adequadas com ressalvas
     * 2: Genéricas demais ou restritivas demais
     * 1: Inadequadas

   - 10 questões, escala 1-5

```javascript
// Pseudo-código seleção técnicas da base

function selecionar_tecnicas(contexto_query, base_jsonl) {
  // 1. Filtro obrigatório: status validado
  let candidatos = base_jsonl.filter(t => 
    t.validation_status === "validated"
  );
  
  // 2. Filtro prioridade alta
  candidatos = candidatos.filter(t => 
    t.priority >= 0.85
  );
  
  // 3. Filtro data atualização (últimos 24 meses)
  let data_corte = new Date("2023-10-01");
  candidatos = candidatos.filter(t => 
    new Date(parse_data_br(t.last_updated)) >= data_corte
  );
  
  // 4. Filtro categoria relevante
  if (contexto_query.dominio === "contratacoes-publicas") {
    candidatos = candidatos.filter(t => 
      t.category === "contratacoes-publicas" || 
      t.category === "tecnica-core"
    );
  }
  
  // 5. Scoring por tags relevantes
  candidatos = candidatos.map(t => ({
    ...t,
    score_relevancia: calcular_relevancia(t.tags, contexto_query.tags)
  }));
  
  // 6. Ordenação: priority (peso 0.6) + relevancia (peso 0.4)
  candidatos.sort((a, b) => {
    let score_a = (a.priority * 0.6) + (a.score_relevancia * 0.4);
    let score_b = (b.priority * 0.6) + (b.score_relevancia * 0.4);
    return score_b - score_a;
  });
  
  // 7. Aplicar métricas de eficácia
  candidatos = candidatos.filter(t => 
    t.metrics.accuracy_gain >= 0.15 ||
    t.metrics.reducao_retrabalho >= 0.30 ||
    t.metrics.conformidade_media >= 0.90
  );
  
  // 8. Selecionar top-10 ou até atingir cobertura 95%
  return candidatos.slice(0, 10);
}

function calcular_relevancia(tags_tecnica, tags_query) {
  let intersecao = tags_tecnica.filter(t => tags_query.includes(t));
  return intersecao.length / tags_query.length;
}
```

```javascript
function sanitizeHTML(content) {
  // Usar DOMPurify em produção
  return content
    .replace(/<script\b[^<]*(?:(?!<\/script>)<[^<]*)*<\/script>/gi, '')
    .replace(/on\w+="[^"]*"/gi, '');
}

// Preenchimento template
function preencher_template(template_html, dados) {
  let output = template_html;
  
  for (let [key, value] of Object.entries(dados)) {
    let placeholder = `{{${key}}}`;
    let conteudo_sanitizado = sanitizeHTML(value);
    output = output.replace(new RegExp(placeholder, 'g'), conteudo_sanitizado);
  }
  
  // Verificação final
  let placeholders_restantes = output.match(/{{[a-z_]+}}/g);
  if (placeholders_restantes) {
    console.error("Placeholders não preenchidos:", placeholders_restantes);
  }
  
  return output;
}
```

```javascript
// Checklist obrigatório antes de apresentar documento

const VALIDACOES = {
  campos_obrigatorios: (doc) => {
    let campos = extrair_campos(doc);
    return campos.preenchidos.length / campos.total >= 0.98;
  },
  
  conformidade_legal: (doc) => {
    let requisitos = identificar_requisitos_lei_14133(doc);
    return requisitos.atendidos.length / requisitos.aplicaveis.length >= 0.95;
  },
  
  linguagem_impessoal: (doc) => {
    let padroes_problematicos = [
      /marca\s+\w+\s+obrigatório/gi,
      /apenas\s+fornecedor\s+\w+/gi,
      /exclusivamente\s+modelo\s+\w+/gi
    ];
    return !padroes_problematicos.some(p => p.test(doc));
  },
  
  valores_com_fonte: (doc) => {
    let valores = extrair_valores(doc);
    return valores.every(v => v.fonte_explicita);
  },
  
  datas_formato: (doc) => {
    let datas = extrair_datas(doc);
    return datas.every(d => /^\d{2}\/\d{2}\/\d{4}$/.test(d));
  },
  
  referencias_normativas: (doc) => {
    let refs = extrair_referencias_lei(doc);
    return refs.every(r => validar_referencia_lei_14133(r));
  },
  
  consistencia_multiplos: (dod, etp, tr) => {
    if (!etp && !tr) return true; // apenas DOD
    
    let score_objeto = similarity(dod.objeto, etp?.objeto, tr?.objeto);
    let score_valor = consistency(dod.valor, etp?.valor, tr?.valor, 0.10);
    let score_prazo = alignment(dod.prazo, etp?.prazo, tr?.prazo);
    
    return (score_objeto + score_valor + score_prazo) / 3 >= 0.95;
  },
  
  disclaimer_presente: (doc) => {
    return doc.includes("conferido e validado") || 
           doc.includes("responsabilidade do usuário");
  }
};

function validar_documento(doc) {
  let resultados = {};
  for (let [nome, funcao] of Object.entries(VALIDACOES)) {
    resultados[nome] = funcao(doc);
  }
  
  let aprovado = Object.values(resultados).every(r => r === true);
  
  return { aprovado, detalhes: resultados };
}
```
