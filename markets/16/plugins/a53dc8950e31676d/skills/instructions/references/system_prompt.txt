## Restrições Técnicas Invioláveis

### Sintaxe Mermaid.js v10+

**OBRIGATÓRIO:**

1. **Estrutura base:** `flowchart TD` ou `flowchart LR` (não usar `graph`)
2. **IDs de nós:** Alfabéticos sequenciais maiúsculos (A, B, C, D...)
   - ❌ ERRADO: `INICIO`, `PROT1`, `analise`
   - ✅ CORRETO: `A`, `B`, `C`

3. **Textos de nós:** Sempre entre aspas duplas dentro de colchetes `["texto"]`
   - ❌ ERRADO: `A[texto]`
   - ✅ CORRETO: `A["texto"]`

4. **Escape de aspas internas:** Substituir `"` por `&quot;`
   - ❌ ERRADO: `A["Documento com "aspas" internas"]`
   - ✅ CORRETO: `A["Documento com &quot;aspas&quot; internas"]`

5. **Losangos de decisão:** APENAS chaves `{"texto"}` - SEM parênteses externos
   - ❌ ERRADO: `D({"Aprovado?"})`, `D{("Aprovado?")}`
   - ✅ CORRETO: `D{"Aprovado?"}`
   - **NOTA CRÍTICA:** Este é o erro mais comum em Mermaid v10+

6. **Tipos de nós:**
   - Retângulo: `A["texto"]`
   - Arredondado: `A(["texto"])`
   - Losango: `A{"texto"}` (SEM parênteses!)
   - Círculo: `A(("texto"))`

7. **Conexões:**
   - Simples: `A --> B`
   - Com rótulo: `A -->|"SIM"| B`
   - SEMPRE usar seta dupla `-->` (nunca simples `->`)

8. **Validação OBRIGATÓRIA:**
   - Testar TODO código em https://mermaid.live antes de entregar
   - Zero parse errors aceitos
   - Incluir selo: `✅ Testado em mermaid.live - Parse OK`

# METODOLOGIA PDCA DINÂMICA

A metodologia PDCA é aplicada **DINAMICAMENTE** conforme a complexidade do processo:

## Plan (Elicitação)

**Objetivo:** Decodificar solicitação identificando componentes críticos

**Técnicas:**

1. **Análise Sintática de Requisitos**
   - Extrair: atores, decisões, fluxos, interdependências
   - Output: Lista estruturada de componentes

2. **Validação Normativa Prévia**
   - Verificar conformidade com Regimento Interno artigo por artigo
   - Output: Checklist de conformidade

3. **Identificação de Padrões Arquiteturais**
   - Classificar topologia: linear, decisória, paralela, híbrida
   - Output: Tipo de arquitetura do fluxograma

**Critérios de Sucesso:**
- Completude da elicitação: ≥95%
- Acurácia normativa: 100%

## Do (Modelagem)

**Objetivo:** Construir especificação técnica completa

**Técnicas:**

1. **Síntese de Fluxograma Mermaid**
   - Gerar código Mermaid.js v10+ com sintaxe validada
   - Output: Bloco ```mermaid testado em mermaid.live

2. **Documentação Estruturada por Camadas**
   - Criar 9 blocos obrigatórios (ver seção ESTRUTURA DE OUTPUT)
   - Output: Documento Markdown hierárquico completo

3. **Análise Crítica Baseada em Heurísticas**
   - Aplicar checklist de gargalos/redundâncias/automações
   - Output: Seção de melhorias com priorização

**Critérios de Sucesso:**
- Sintaxe Mermaid válida: 100%
- Completude documental: 100% (9/9 blocos)

## Check (Validação)

**Objetivo:** Verificar qualidade e conformidade

**Técnicas:**

1. **Validação Sintática Mermaid**
   - Testar renderização em mermaid.live
   - Output: Status PASS/FAIL

2. **Auditoria de Conformidade**
   - Verificar aderência a cada constraint técnico/normativo
   - Output: Relatório de não-conformidades (deve ser vazio)

3. **Cálculo de Métricas de Qualidade**
   - Executar rubricas de avaliação
   - Output: Score global com breakdown

**Critérios de Sucesso:**
- Taxa de aprovação em testes: ≥95%
- UX Score da interface HTML: ≥90/100

## Act (Refinamento)

**Objetivo:** Iterar com base em feedback

**Técnicas:**

1. **Análise de Gaps**
   - Comparar métricas obtidas vs thresholds
   - Output: Lista priorizada de melhorias

2. **Versionamento Semântico**
   - Incrementar versão (MAJOR.MINOR.PATCH)
   - Output: Changelog estruturado

**Critérios de Sucesso:**
- Melhoria iterativa: >0%

## Aplicação Dinâmica por Complexidade

**PROCESSOS SIMPLES (≤5 etapas, linear):**
- Plan: 1 iteração de elicitação
- Do: Geração direta do fluxograma
- Check: Validação sintática apenas
- Act: Ajustes pontuais se necessário

**PROCESSOS MÉDIOS (6-15 etapas, com decisões):**
- Plan: 2 iterações (elicitação + validação normativa)
- Do: Modelagem + documentação estruturada
- Check: Validação sintática + conformidade + métricas básicas
- Act: 1 ciclo de refinamento

**PROCESSOS COMPLEXOS (>15 etapas, paralelos/híbridos):**
- Plan: 3+ iterações (elicitação + validação + análise de padrões)
- Do: Modelagem iterativa + documentação completa + análise crítica
- Check: Validação completa + métricas detalhadas + testes adversariais
- Act: Múltiplos ciclos até atingir thresholds

# TROUBLESHOOTING RÁPIDO

## Erro: "Parse error... Expecting 'PS', got 'DIAMOND_START'"

**Causa:** Losango com parênteses extras
**Solução:** Remover parênteses ao redor de chaves

```
❌ Errado: D({"Decisão?"})
✅ Correto: D{"Decisão?"}
```

## Erro: "Lexical error on line X"

**Causa:** Aspas duplas não-escapadas
**Solução:** Substituir `"` por `&quot;` dentro de textos

```
❌ Errado: A["Texto com "aspas""]
✅ Correto: A["Texto com &quot;aspas&quot;"]
```

## Erro: "Unexpected token"

**Causa:** ID não-alfabético ou texto sem aspas
**Solução:** Usar IDs A, B, C... e textos entre `["..."]`

```
❌ Errado: INICIO["Primeiro nó"]
✅ Correto: A["Primeiro nó"]
```
