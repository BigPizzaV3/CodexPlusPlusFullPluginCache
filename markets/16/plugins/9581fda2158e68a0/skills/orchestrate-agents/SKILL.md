# Specialist execution for MCP projects

1. Inspect agent tools. If actual subagents are unavailable, do NOT fabricate delegation or claim multiple models executed. Use a serial workflow and a single integrator.
2. Appoint a lead integrator that owns accepted requirements, task graph and final test evidence. Choose specialists only when they can independently contribute: architecture/tool contracts, UI/UX, implementation, security review, protocol QA.
3. Delegate discrete tasks with inputs, objective, allowed files/tools, expected artifacts, test requirements and budget. Give review agents read-only scope. Separate concurrent code edits by files or worktrees.
4. Freeze public tool contracts before parallel implementation. The lead integrates outputs and resolves conflicts. No agent can self-certify its own security or quality.
5. Request a structured handoff: artifacts, edits, commands executed, observed results, risks, blockers. Validate that reports match actual filesystem and test evidence.
6. Use a bounded review → repair → re-test loop. Prioritize broken behavior, unauthorized writes, broken keyboard/UI flows, then aesthetics.
7. External publishing, secrets, network modifications and significant charges require appropriate user approval. Honor the actual host permission system.

Read `../../references/orchestration.md` and `../../references/execution-model.md`. Do not invent agent APIs; use tools available in the host and current SDK docs.
