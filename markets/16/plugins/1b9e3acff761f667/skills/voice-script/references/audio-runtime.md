# 添付音声の自動読み取り：準備から取得まで一度に実行する

音声ファイル、または修正を話した画面録画があり、発話全文をまだ取得できていない場合の共通入口。初回・2回目・修正音声・単独の文字起こしで同じ処理を使う。**「文字起こしが必要です」「全文を貼ってください」で利用者に作業を返す前に、以下を実行する。** 標準のテキスト閲覧ツールで開けないこと、音声認識ライブラリやモデルが未導入であることだけでは、読み取り不可と判断しない。

## 1. 今回の実ファイルと実行機能を確認する

- 添付メタデータやファイル一覧で、今回の録音の実パスを特定する。ファイル名から `/mnt/data` 等のパスを作らず、別端末の絶対パスをクラウドへ流用しない。別の録音を探して代用しない。
- 標準機能から本人発話の全文が既に取得できていれば再処理不要。添付されたという表示や題名しか読めていない場合は未取得。
- 利用可能なシェル／Python実行を確認する。汎用のコード実行でパッケージを導入できるなら、専用音声ツールが見当たらなくても次へ進む。シェルがなくPython実行だけなら `subprocess` 等で同梱スクリプトを呼べるか実際に確認する。
- ファイルが見えない時は再添付による参照回復を案内する。コード実行そのものが利用不可の場合だけ、実行できるWorkのチャットで同じ音声を続ける方法を短く案内する。プラグイン選択だけで権限が増えるとは言わない。

## 2. 自動処理を実行する（通常はこの1回）

**`scripts/ingest_audio.py` を実行する。** ライブラリ・モデルが不足していれば、この入口が作業領域内に専用環境を作り、公開配布元から取得し、同じ録音の文字起こしまで続ける。利用者にインストールの手順、コマンド、Codexの導入、APIキーの取得を求めない。通常のタスク内準備は今回の音声処理に含めて進め、実行環境が承認を要求する場合だけその仕組みに従う。

初回の案内は「音声を読み取るための準備をして、そのまま文字起こしします。初回は少し時間がかかります」程度。工程の選択を利用者に委ねない。

```text
<利用可能なPython> <このSkillのscripts/ingest_audio.pyの実パス> --input <添付録音の実パス> --out-dir <新規の出力先> --runtime-dir <作業領域内の専用runtime> --language ja
```

山括弧部分は実際に確認した値で置き換え、空白・日本語を含むパスは引数として正しく渡す。作業用カレントディレクトリをその案件の書込み可能な領域へ設定し、runtimeはその下に置く。**スキルのインストール先や配布Pluginを作業領域にしない。** 第1・第2・第3音声ごとに新しい出力先を使い、同じタスクのruntimeは再利用する。録音を共有Pluginへ格納しない。

- Python・音声認識ライブラリ・多言語モデルは専用環境を使い、システム全体へ変更しない。モデル等はダウンロードするが、録音を外部文字起こしAPIへ送信しない。無料のローカル推論で追加API契約を前提にしない。
- パッケージ／モデル取得は既知の配布元から行う。一時的な取得失敗や、この処理が作った環境の不整合は、同梱処理の範囲で修復・再試行する。実際のネットワーク禁止、権限拒否、容量不足等を、別経路や権限変更で回避しない。
- 進行中の処理は終了結果まで追う。ツールの待機時間が過ぎて実行IDが返ってきた場合は、その処理を待ち合わせる。まだ実行中なのに「読み取れませんでした」と返さない。
- `--offline` は依存・モデルが揃いネット接続を使わない場合の指定で、初回に常用しない。標準の長さ上限は実行時の `--help` を確認し、超過時は同じ音声を順番に分割するか、許容できる計算量で上限を明示して再実行する。利用者に分割や撮り直しを委ねず、未処理部分を黙って切り捨てない。

既存の検証済み環境を個別に確認する必要がある時だけ `prepare_transcriber.py`／`transcribe_audio.py` を使う。通常の入口は `ingest_audio.py` に統一する。

## 3. 結果を読み、元の依頼を続ける

標準出力のJSON、`transcript.raw.txt`、`transcript.json`を実際に読む。ファイルの存在や準備完了だけを読取成功としない。音声全長、処理範囲、区間、警告と末尾を確認する。

| 状態 | 次に行うこと |
| --- | --- |
| `transcribed_unverified` | 原文を受領し、依頼の段階へ進む。認識の正確さを保証する名称ではない。 |
| `needs_review` | 終了コードだけで失敗と判断しない。原文と時刻・警告を読み、疑わしい区間を照合する。取得できた明確な部分は活用する。 |
| `no_transcript` | 無音・音量不足・発話なし等を実データで確認する。存在しない発話を補わない。 |
| `failed` | どの段階の何が失敗したかを記録し、下記の回復判断へ進む。 |

認識範囲の空白は無音か欠落か未確定。医学用語、数値、単位、否定、人名のうち意味を変える疑いがある部分だけ、該当時刻と短い確認で補う。本人に全文を清書・再承認してもらう手順を定例化しない。原文と整理版を分け、推測で内容を創作しない。

- 第1音声なら経験・考え・調査したい主張を整理し、依頼済みの調査へ進む。
- 第2音声なら本人が選んだ方向性を引き継ぐ。第1段階へ戻さない。
- 修正音声なら最新稿へ反映する。画面録画は音声と映像の取得を分け、音声しか読めていないのに選択文を見たとしない。
- 文字起こしだけの依頼なら原文を渡して完了する。「3回喋る」や論文調査を強制しない。

## 4. 本当に止まった時の案内

停止前に、実ファイルへの到達、利用可能な実行機能、自動準備と読み取りの結果、実施した回復処理を確認する。専用処理が利用できなければ、同じ作業環境で実行可能な標準の読み取り機能も確認する。利用不可の機能を使ったとは言わない。

- ファイル未到達：同じ録音の再添付を依頼する。
- コード実行不可：実行機能を使えるWorkのチャットへ案内する。
- 許可された取得先へ接続できない／実行資源が足りない：具体的な失敗段階を一文で示す。保留中の実行を失敗扱いしない。
- 音声の一部だけ不明：読めた内容を保持し、該当部分だけ確認する。

**全文の文字起こしを利用者へ依頼するのは、これらを確認しても自動取得できない時の最後の代替。** その場合も、既存の録音アプリ等で取得済みの文字起こしを渡す選択肢を提示し、最初から録り直しや外部契約を必須にしない。「このチャットでは音声非対応です」と一般化せず、今回止まった具体的な理由を述べる。

## 動作確認の範囲

タスク内のライブラリ・モデル取得と推論は実行環境の権限・ネットワーク・資源に依存する。ローカル試験成功を全受講生のWeb版Workで検証済みと表現しない。公開版の受入試験は、更新版を選んだWeb版Workで実際のM4Aを添付し、利用者による再指示なしで読み取りから本来の依頼へ進むこと。

実装方式： [faster-whisper](https://github.com/SYSTRAN/faster-whisper) のCPU推論とPyAVによる音声読み込み。配布元とモデルの版は同梱コードに固定して記録する。
