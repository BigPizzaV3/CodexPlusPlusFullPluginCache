# 音声・文字起こしの受け取り

第1・第2段階の語りと、第3段階の修正音声で同じ入口を使う。利用者にツールの仕組みやファイル形式を選ばせる前に、今回すでに受け取れている内容を確認する。Liveの質問役を求められた時は [Liveインタビュー](live-interview.md) を使い、録音の再提出を必須にしない。

## 入力ごとの扱い

| 渡されたもの | 実行すること |
| --- | --- |
| 音声入力で送信された文章、貼り付けた文字起こし | その文章を原文として進む。音声ファイルの追加提出を求めない。 |
| 文字起こし全文のTXT・Markdown・Googleドキュメント等 | 実際に本文を読む。要約だけなら原発話を読めた扱いにしない。 |
| ボイスメモ等の音声ファイル | 標準機能で全文を取得できるか確認し、取得できなければ [同梱の文字起こし処理](audio-runtime.md) を実行する。ツール・実行処理、対象ファイル、音声全長と取得範囲を記録する。添付成功・拡張子・ファイル名だけでは読取成功にしない。 |
| 接続済みの文字起こしツール | 実行可能で依頼の範囲に合う場合に使用し、全文と取得範囲を確認する。未接続のサービスやAPIキーを前提にしない。 |
| 未取得の音声・リンク | [自動読み取り](audio-runtime.md)で実ファイル参照・準備・実行・回復を先に行う。実際に取得不能と確認できた場合だけ、その原因に合う代替を短く案内する。 |

最初から外部サービスの契約やCodexの導入を必須にしない。実行できなかった処理を成功したと言わず、連携方法を提案しただけで文字起こし機能を実装済みとも説明しない。現時点で音声が読めないことを、全受講生・全環境で非対応という意味に広げない。

音声会話を使った場合も、台本の元にする本人発話の全文がこの作業で参照可能か確認する。AI側の相づちや提案を本人の発話へ混ぜない。別チャットの音声会話が自動的にこのチャットやProjectへ共有されるとは説明しない。

会話まとめだけが読める場合は「会話の整理」として取得範囲を残し、全文文字起こしを確認済みとは扱わない。具体例・理由・本人の言い直しを含む詳細なまとめを使い、欠落が結果を左右する箇所だけ補う。第3段階の画面録画は [修正入力の読み取り](../../script-improvement/references/revision-input.md) に従い、音声と映像の取得状況を分ける。

## 原文を保ち、必要な誤認識だけ確認する

- 原文は第1回／第2回とファイル・メッセージ・段落位置で区別する。録音日時やタイムスタンプは実際に取得できた場合だけ記録する。長い音声を分割処理した場合は順番、重複、抜けを確認する。
- 「と思う」「たぶん」「自分の経験では」、否定語、条件、感情、具体例、本人独特の表現を残す。言いよどみを整えた整理版と、元の文字起こしを区別する。根拠を調べる前に発話を医学的に正しい文章へ書き換えない。
- 聞き取れない箇所は不明と記す。人名・薬剤名・数値・単位・否定など、解釈や調査を左右する箇所だけ短く確認し、その他の読めた範囲は進める。全文の再承認や清書を毎回要求しない。
- 「まだ続きがある」「数回に分けて送る」場合は同じ段階に追記し、終了の発言を受けるまで調査結果や最終稿を出さない。普通の完結した入力には機械的な「以上です」の再送を求めない。
- 要約しか得られない場合は取得範囲を明示し、元の語りが必要な箇所を絞って補う。確認できない本人の体験や口調を創作して埋めない。
- 原音声・本人の原発話は案件内に保持する。患者を特定できる情報は台本・共有資料へ持ち込まない。本人の音声や設定を、全受講生向けの共通プラグインへ混入させない。

## 利用者への短い案内

自由なボイスメモ方式の初回は「まずは資料を見ず、経験や考え、感じていることを自由に話してください。順番や文章を整える必要はありません。録音したボイスメモをそのまま添付できます。音声入力の文章や、既にある文字起こしでも進められます」と伝える。まだ本人が話していない内容や参考動画の結論を例に出して誘導しない。

音声ファイルを受け取った時は「添付の音声を読み取り、内容を整理します」と伝え、自動処理を進める。必要な準備もこちらで行う。途中の依存不足やテキスト閲覧の失敗で全文提出を求めず、[自動読み取り](audio-runtime.md)の停止条件を満たした時だけ具体的な原因と最小限の代替を伝える。二度目の語りはリサーチ資料を提示した後に受け取る。

## 現行仕様を説明するときの確認記録

2026-10-16の公式資料確認では、デスクトップのDictateは話した内容を送信前に編集できる入力文へ変換する。リアルタイムのVoiceは別機能で、利用可否はプラン・展開状況等による。

- [公式：音声入力（Dictate）](https://learn.chatgpt.com/docs/prompting#use-voice-dictation)
- [公式：Voice](https://learn.chatgpt.com/docs/features/voice)

この確認から、ChatGPT Web Workへ任意の.m4a／.mp3を添付すれば必ず読めるとは判断できない。2026-10-17の本人によるWeb版Work試験では、M4A添付とvoice-script起動に成功した一方、発話内容の取得には失敗した。その後0.4.1で文字起こしスクリプトを追加し、本人から「うまくいった」「ボイスメモの読み取りの結果、台本制作はとてもうまくいきました」と成功報告を受けている。これはその試験環境での利用者報告であり、全アカウント・すべての音声形式・ChatGPT標準機能だけでの成功を保証するものではない。現在の入力ごとに実際の取得結果を確認する。

音声録音用のChatGPT Recordの現在の利用条件も、この資料では確認できていない。利用者へ製品の現行対応を説明する必要が生じた時は、公式資料とその環境の実機能を確認し直す。「Record & Replay」は操作を記録する別機能なので混同しない。
