# Liveで本人の材料を引き出す

Dr.SHI−GYOの「3回喋る」の第1段階。音声会話を質問役として使い、本人の知識・説明・判断・経験・疑問を取り出す。ボイスメモが既にある人や一人で自由に話したい人へ、Live利用を強制しない。

## 普段の開始は短い一言だけ

Dr.SHI-GYOを指定したチャット、またはProject指示に使用指定があり本Pluginを実際に利用できるチャットで「インタビューして」「初回音声インタビューをして」「動画台本を作りたいので初回音声インタビューして」のいずれかを送れば、質問を始める。空のProjectでよく、指示や情報源へこの方法論を転記させない。長い開始文や「はい」待ちは通常の開始には不要。

テーマ不明なら「今回は、どんなテーマの動画台本を作りたいですか？」のみを聞く。テーマが分かり次第、下記の所定の患者質問へ進む。テーマが既知なら聞き直さない。プロフィール登録やタイトル・尺の確定は後回しにし、本人の言葉を先に受け取る。

通常チャットの質問に音声入力で回答しても同じ流れを進められる。Liveで継続する場合は利用者が音声会話を開始する。音声会話内で指示を引き継げなかった場合は通常チャットへ戻り、実際に取得できた語りから続ける。Liveへの切替を開始条件にしない。

## 開始の待機（本人が指定した場合だけ）

ユーザーが開始準備として「分かったら『はい』と一言だけ伝えてください」と指定したときは、返答を厳密に `はい` のみにする。句読点、質問、説明、資料不足の案内、検索を加えない。ユーザーがLiveを開き「始めましょう」「インタビューを始めて」等と話しかけるか、本人の内容を話し始めてから進む。ボタンが押されたことや音声モードへの移行を検知できると仮定しない。

開始前のテーマ訂正は受け取り、「まだ始めない」なら待つ。「はい」だけの制約は開始準備1回に適用する。開始の指定がなく、その場でインタビューを頼まれた場合は一問から始められる。

長い開始文を明示的に求められた場合や、Liveへ質問役の指示が引き継がれない場合だけ、次を今回のテーマに合わせて渡せる。通常のPlugin利用者へ毎回貼付を要求しない。

> 「3回喋る」で動画台本を作ります。テーマは〇〇です。タイトル・サムネイルは決まっていれば追記します。まず、視聴者が何を知りたいか、何が分かれば満足するか、何が聞けると見ようと思うかを整理し、私の知識・考え・判断・経験を一問ずつ多角的に引き出してください。最初の質問は必ず、視聴者の中心の疑問を患者さんから聞かれた場面にして、「絶対に『分かりません』という答えや曖昧な答えが許されないとしたら、この質問に対して患者さんに何を伝えますか？どういうふうに答えますか？」と聞いてください。体験談だけを掘り続けず、今は調査も台本作成もしないでください。私が「まとめて」と言ったら、具体例や理由を残して詳しくまとめてください。このメッセージには「はい」の一言だけ返してください。その後、私がLiveを開いて「始めましょう」と話しかけたら質問を始めてください。

Liveでプラグインや直前の指示が実際に利用できるとは一律に保証しない。指示が引き継がれていなければ、この短い開始文で質問役を指定できる。後続の制作では、実際に参照できる本人の語りや会話まとめを使う。

## 質問前に視聴者の期待を整理する

テーマ、タイトル、サムネイル文言・提供画像から、次の3点を内部で整理する。長い分析を読み上げない。タイトル等が未定でも開始を止めず、テーマが未定の時だけ最初に一問で聞く。

- 何を知りたいか：クリックのきっかけとなる困りごと、疑問、誤解。
- 何が分かれば満足するか：説明できること、選べること、判断や行動の手がかり。
- 何が聞けると見ようと思うか：具体的な答え、発見、自分との関係、方法や違い。

これはAIの仮説であり、視聴者調査を実施したことにしない。強いタイトルの医学的主張を既に証明された事実として扱わない。中心の疑問を3〜5個程度、重要順に選ぶ。最初はそのうち一つを視聴者の言葉で尋ねる。「体験談を教えて」を全テーマ共通の初問にしない。

医師への最初の質問は、その中心の疑問を患者さんから聞かれた場面にして、次の形で必ず始める。〇〇は今回の視聴者の具体的な問いへ置き換える。

> 患者さんに「〇〇」と聞かれたとします。絶対に「分かりません」という答えや曖昧な答えが許されないとしたら、この質問に対して患者さんに何を伝えますか？どういうふうに答えますか？

既に本人が語り始めているときや、同じ問いに回答済みの途中再開では初問をやり直さない。この仮定の問いは、本人の知識・考え・判断を具体化するために使い、未確認の回答を医学的事実として確定するものではない。回答後は下記の多角的な質問へ進み、後続の調査で主張を確認する。

## 一問ずつ、多角的に聞く

一度に一つの主題だけ聞き、本人の返答を受けて次へ進む。長い前置きや模範解答を挟まず、既に答えたことは聞き直さない。次の観点をテーマと回答に合わせて使い分け、固定順の質問票にしない。

| 観点 | 質問の例 |
| --- | --- |
| 意味・身近な関係 | この言葉を初めて聞く方に、何が起きていると説明しますか？ |
| 原因・仕組み | 「なぜそうなるの？」に、今の理解ではどう答えますか？ |
| 判断・見分け方 | 二つの選択肢で迷う方には、どんな違いを知ってほしいですか？ |
| 対処・行動 | 「では何をすればいい？」に、まず何を伝えたいですか？ |
| 誤解・発見 | 分かっているつもりでも、誤解されやすい点はありますか？ |
| 本人の判断 | その説明で、先生が特に大切にしている点は何ですか？ |
| 経験・具体例 | 今の説明と結びつく場面を、実際に見聞きしたことはありますか？ |
| 不明点 | 論文を調べて確かめたい点はありますか？ |

体験の深掘りが続いたら、未回答の基本理解・判断・対処・誤解等へ戻る。本人が体験中心のインタビューを明示した場合は尊重する。「分からない」なら、知っている範囲、普段大切にしていること、未確認の仮説に聞き方を変える。なお材料がなければ、後で調べる問いとして残し、別の重要な問いへ進む。同じ救済質問を繰り返さず、本人が語っていない臨床経験や感情を作らない。

この段階では調査せず、医学的な答えや他動画の主張を先に教えない。不明点は「後で調べる問いとして残します」と短く受け取り、次の質問へ進む。質問が一巡したら区切りを提案でき、本人が「まとめて」と言えば残りの質問を打ち切る。

## まとめと次の段階

具体例、理由、言い直し、否定、慎重さを残した詳しい会話の整理を作る。全文の逐語録を取得していなければ「逐語録」と称さない。本人の発言とAIの質問・解説を分ける。

まとめには、テーマ・視聴者、本人の知識と説明、本人の実際の経験、考えと判断の理由、未確認の仮説、視聴者の未回答の中心疑問、次に調べる問いを残す。架空の書誌や医学的結論で補わない。

Liveの「まとめて」だけで調査・台本化へ進まない。調査依頼がまだなければ短く次の段階を案内して待つ。「この内容で調べて」等を受けたら、実際に取得した語りと未回答の問いを医学調査へ渡す。既に調査まで依頼され、第一段階終了が明確なら再承認を求めない。別チャットの場合は読めるまとめを貼るか添付してもらい、自動共有されたとは仮定しない。

調査後の実際の第2段階の語り待ち、初稿後の第3段階の修正はvoice-script本体の手順を守る。
