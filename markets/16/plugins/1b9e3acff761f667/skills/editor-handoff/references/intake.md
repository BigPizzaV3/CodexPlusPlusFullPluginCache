# 入力と実行条件

最小入力は完成台本。本人の登録済み素材・デザインが読めれば一式制作へ進む。自己紹介や終了画面が不要な台本なら、登録必須のためだけに止めない。

## 入力の優先順位

1. 今回の明示指定と添付。
2. 現在の案件の採用済み計画・本人素材の指定。
3. 本人専用Project等から実際に読める最新版。
4. 未登録部分だけ、仮の中立的デザイン。別人の設定を流用しない。

Markdownは原文を保持。Google Docsは正規の接続から本文・見出し・文献を取得する。取得できない場合はその事実を伝え、共有権限の確認かMarkdown等の入力で回復する。別ファイルを同名だけで代用しない。Docsに提案・コメントがあるときは採用本文と指示を区別する。

実行前に、台本読取、画像生成、ファイル出力、必要時の動画生成、Sitesによる限定確認ページの配信可否を確認。同案件の既存SiteとURLがあれば引き継ぐ。会話内表示は明示依頼時だけ確認する。機能の列挙と実行成功は区別し、採用計画に必要な種類の最初の生成・取得で動作を確かめる。利用枠、接続や実行エラーで制約が判明した場合は、該当素材をpendingとして、実際の理由と必要な対応を記録する。未実行はnot_testedとし、使えないと決めつけない。ChatGPTのモデル名や、過去にCodexで使えた事実だけで画像・動画・ファイル機能が揃うと決めない。

必要な動画機能が利用できるなら現在の接続を使う。利用できない場合も、全員に新規サービス契約を先に要求しない。実際に不足する接続・権限・ファイルだけを案内し、そのほかの制作を進める。必要な動画を提案だけに移して全部完成としない。

## 初回登録

「自己紹介画像、終了画面、プレゼント画像（複数可）、雰囲気を参考にしたい自分の動画や画像」を一度まとめて受け取る。既知分を再度要求しない。受領素材を本人に紐付け、参照先・版・使用条件を本人素材設定へ記録。画像を開いて内容・比率を確認し、別チャットからも実ファイルを読み戻せた範囲を登録状態とする。登録名だけ、外付けドライブのパスだけ、以前のチャットの生成完了文だけでは再利用可能としない。共有Pluginにはひな形と手順だけを入れる。

本人素材の自己紹介・終了画面・プレゼントの3役について、取得済み、不足、今回の台本には不要、本人が省略を指定、を必ず区別して記録する。不要・省略の理由を発明せず、原稿や本人の発言に根拠を置く。本人指定の画像が欠ける場合、文字テロップや話者映像への代替を勝手に確定しない。

既に作った素材を後で個人設定へ反映する場合、今回だけの配色や任意の提案を恒常ルールにしない。本人が「次もこの形」と承認したところを更新する。

## 完成の種類

- 撮影前：素材入り編集用台本＋実素材のZIP。撮影動画未提供と表示するが、素材制作の完了とは分ける。
- 撮影後：上記＋提供された撮影動画。音声・向き・尺とファイル一致を確認。
- 採用素材の不足：部分完成。欠けた場所を見える形にして引き継ぐ。
- HTML作成だけ：画像や動画まで作成したとは言わない。

## 納品後の追加素材

本人が後から画像・動画を持ち込めるよう、初回・修正版を渡したら[持ち込み素材の案内と反映](provided-materials.md)を必ず適用する。今回任意の追加と、完成に必要な登録原本の不足を混同しない。添付と挿入位置の指定を受けたら、同じ案件へ実ファイルを統合する。
