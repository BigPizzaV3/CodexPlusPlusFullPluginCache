# 制作メモと変更の引き継ぎ

受講生に管理表を入力させず、作業側で案件ごとに記録する。識別子は裏側の照合用であり、読み上げ台本や画像に印字しない。

## 最小記録

- case_id、対象医師、本人設定の参照先・版、対象視聴者。
- 企画と必要成果物、今回の依頼範囲、採用された条件。
- 主張：claim_id、主張、出典と確認状態、対象・限界・許容表現。
- 成果物：artifact_id、版、実在する保存先/本文、参照した主張と原稿の版。
- 状態：未着手／作業中／完了／要更新／確認待ち。保存待ちと保存確認済みを区別。
- 変更点、未解決事項、次の作業。
- 限定確認ページのproject_id、実URL、保存版ID、配信ID・結果、閲覧対象の確認結果、配信した原稿SHA。同案件の修正では既存Siteを再利用する。認証情報は保存しない。

各Skillは既存IDと版を保持する。IDがなければC001等を採番する。同じ案件で独自の別一覧を作らない。元の資料は保ち、原稿の意味と根拠を変えた箇所を記録する。

## 変更規則

成果物は参照した版を持つ。主張が変われば、それを使う台本と、その台本を使う素材等を要更新にする。台本の語尾のみなら該当台本とその引用だけ、画像の色のみなら画像だけを直す。完了した過去案件を本人プロフィールの更新だけで一括変更しない。

並行作業の返却時は使用した版を照合する。上流が更新済みなら、その成果物を最新版とせず再照合・修正する。新しい主張を入れる場合は根拠確認に戻り、「関連」が「必ず改善」に変わる等の意味の拡大を最終点検する。

原稿の一部だけ修正した場合は、変化した主張/節を明記すれば影響範囲を絞れる。節の依存関係を記録していなければ、下流を一旦要更新にして該当しないと確認したものを戻す。推測で影響なしにしない。

## 再開と保存

同じ案件は同じチャットでの継続を基本にする。別チャットで再開するときは制作メモと最新成果物をProject資料等で読めるように案内する。チャットの添付が自動でProject原本へ登録されるとは説明しない。新しいチャットでは保存済みメモと実際の成果物を照合してから、未完了・要更新の工程から続ける。

文章版メモでもよい。実行環境が使える場合、STARTに同梱する `scripts/case_state.py` はJSONの版・依存関係を検証し、変更の影響を機械的に記録できる。利用可能なSTARTの場所を解決できる時だけ使う。各Skillがこのスクリプトの存在を前提に停止してはいけない。スクリプトは医学的意味・ファイル内容・保存先のクラウド反映を検証しないので、成果物と主張の意味は別に点検する。
