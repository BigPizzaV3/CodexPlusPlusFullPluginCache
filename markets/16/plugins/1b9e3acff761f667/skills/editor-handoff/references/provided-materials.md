# 完成後の持ち込み画像・動画を組み込む

## 納品したら必ず案内する

初回の素材一式と修正版を渡した返答には、次の案内を短く添える。完成物とリンクを先に渡し、任意の追加素材を待つために納品を止めない。

> もしご自身で作成した、もしくはお持ちの素材を組み込みたいときは貼り付けてください。どこに入れるかも指示してください。「このセリフのところ」「素材03と差し替え」などで大丈夫です。

既に持ち込み素材を反映した返答では「ほかにも、ご自身で作成した…」と案内してよい。追加不要と明示されている今回の作業では再募集しない。案内は「見本登録・独自スキル化」の二つの質問とは別で、第三の必須確認にはしない。

## 後から素材が届いた時

1. 現在の案件・台本の版・採用素材・既存の確認URLを読み戻す。添付を実際に開き、画像か動画か、内容、元の比率・透過、動画の尺と音声の有無を確認する。ファイル名やユーザーの説明だけで確認済みにしない。音声で場所を指示された場合は [音声の自動読み取り](../../voice-script/references/audio-runtime.md) を使い、全文の文字起こしを先に要求しない。
2. ユーザーの指示を、本文の一意な引用／素材番号／節と前後の発話へ対応させる。「追加」か「差し替え」か、開始・終了の合図、表示形式、動画の音声を使うかを既存の指定から判断する。全部を質問票にしない。同じセリフが複数ある、追加か差し替えかで結果が違うなど、特定できない点だけ短く確認する。位置が未指定なら自然な挿入先を一つ提案し、勝手に別の場面へ差し替えない。
3. 受領原本を変更せず、案件の素材フォルダへ衝突しない名前でコピーする。原本とコピーのハッシュを確認する。元の比率・透過を保持し、ユーザーが望まない再生成・切り抜き・再圧縮をしない。動画内の実時刻が未確認なら、台本上の発話位置で指定する。長い動画の使用範囲が不明なら、その点だけ確認する。
4. 同じ場面の採用案・`files`・制作メモを更新する。複数素材は実際に使う順で残し、表示開始・終了、切替、画面配置を編集者向けメモへ記す。本人提供とAI生成を区別する。差し替え前の素材を無断で削除せず、必要なら未採用案として残し、HTMLでは採用案を明確にする。本文・他の場面・ダイジェストは、今回指示された変更に必要な範囲だけ更新する。
5. [納品確認](acceptance.md) を通して、台本HTML・Markdown・配置一覧・manifest・ZIPを同じ案件から再生成する。本人向け確認ページは同じSiteとURLを更新する。画像・動画が本当に開くか、変更箇所の引用とファイルが合うか、ZIP内に実ファイルがあるかを確認する。コピーや記述を更新しただけで納品物へ反映済みとしない。

## 修正結果を次回へ残す

修正版を渡した後は、[見本と独自スキルの登録](../../doctor-profile/references/personal-growth.md)に従い、今回の完成例を残すか、繰り返し使える作り方を残すかを別々に確認する。「この画像をこの箇所に入れた」は今回の制作記録であり、それだけで全動画へ同じ画像を強制するルールにはしない。「運動は実演写真を優先する」等、本人が今後も望む判断を独自スキルにする。

登録を希望された画像・動画の見本は、完成HTML・ZIP等の実在ファイルと選定理由を見本Markdownへ記録する。短命のダウンロードURLやローカルパスだけを残して、将来も参照可能と報告しない。Projectが動画やZIPを保存できない場合は対応する見本Markdown・画像等を渡し、保存可能な範囲と実素材の保管先を区別する。保存の成功と読み戻しを確認できたものだけ「登録済み」と伝える。
