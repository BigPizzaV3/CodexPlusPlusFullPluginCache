# はじめてのDr.SHI-GYO

具体的な依頼がある人は、その作業から始める。この案内全体を毎回読ませず、初回設定を済ませないと使えないと説明しない。

## 初回導入で、今後もプラグインを使う指示を登録する

「初めて使います」「設定から案内して」には、[Projectの設定手順](../../doctor-profile/references/project-setup.md)のコピー用指示をその場で提示する。冒頭に「このProject内の情報発信に関する作業では、必ずDr.SHI-GYOプラグインの該当スキルを使ってください」と明記し、各チャットでの名前指定なしでも依頼から選ぶ方針を伝える。本人設定の完成を待たずに提案し、既存の本人指示を消さず統合する。

導入済みのDr.SHI-GYOを最初に選ぶ→Projectの「…」→「プロジェクト設定」→「指示」へコピーして保存→同じProjectの新しいチャットで、手動選択せず「インタビューして」等の依頼を試す、という順に案内する。画面表記は実際の画面に合わせる。提示しただけで保存済みとは言わない。利用可能ならスキルの指示を実際に読み、そのまま作業する。使えない場合だけそのチャットでのプラグイン選択を案内する。指示で未導入のプラグインが追加されたり、すべての環境で必ず自動起動したりするとは説明しない。

これは繰り返し使うための初回設定のおすすめ。設定せずにすぐ始めたい場合も、次の最短ルートで制作を止めない。

## 台本は、空のProjectからも始められる

設定せずにすぐ試したい人への最短案内は次の3手順。

1. ご自身のChatGPTで、他の人と共有しない「動画台本生成プロジェクト」を作る。**指示欄も情報源も空のままでよい。**
2. そのProjectのチャットで、導入済みの **Dr.SHI-GYO** を指定する。Projectを作っただけでPluginが組み込まれるわけではない。画面で選択されたことを確かめる。
3. **「インタビューして」** と送る。「初回音声インタビューをして」「動画台本を作りたいので初回音声インタビューして」でもよい。テーマが決まっていれば同じ文に添えられる。

この方法論はPluginに入っている。別配布の台本制作ガイドや長い開始プロンプトを、Projectの指示・情報源へ登録する必要はない。上記の短いプラグイン利用方針は、方法論の複製ではなく日常の指定を省くために使う。テーマが未定ならテーマだけ一問を聞き、分かっていれば患者さんの疑問を使う質問から始める。氏名・診療科・本人設定・見本台本・タイトル・尺の一括入力を先に要求しない。

「インタビューして」は動画台本の初回を既定にする。「公開プロフィールを作るためにインタビューして」等、別の用途が明示されていればその用途を優先する。読める会話や資料があれば再利用するが、Project名を取得できないだけで止まらない。

## 3回喋る、の進め方

**1回目：知っていること・経験・考えを出す。** 質問に一つずつ答える。文章を整えず、順番が前後しても大丈夫。質問中は調査を挟まず、本人の言葉を取り出す。「まとめて」で詳しく整理し、「この内容で調べて」で医学論文・参考動画の調査へ進む。既に調査まで依頼されている場合は重ねて承認を求めない。

**2回目：調査を読んで、伝える方向性を話す。** 残す話、考えが変わった点、自分ならどう伝えるかを自由に喋る。「2回目も質問して」でもよい。実際の本人の語りを受けて台本にする。「台本にしてと言うまで待って」の指定は守り、単なる「OK」を第二の語りへ置き換えない。

**3回目：初稿を見て修正を話す。** 違和感のある言葉や足したい経験を喋る。初稿HTMLの直したい文を選択しながら画面録画する方法も使える。最新版の全文を返し、直すたびに第一インタビューへ戻らない。3段階は、録音3本や修正3回という制限ではない。

一問ずつの質問は通常チャットでも動く。受講生は文字やマイクの音声入力で回答できる。Liveを使いたければ、利用者自身が音声会話を開始する。Live内でPluginや直前の指示が利用できるかは環境によるため、引き継がれなければ通常チャットの質問へ音声入力で答えて続ける。長い開始文や「はいだけ」の待機は、利用者がそれを指定した場合だけ使う。ボタン操作をAIが検知したとは言わない。

録音済みのボイスメモがあれば、撮り直しやインタビューへのやり直しを要求しない。音声ファイルは[自動読み取り](../../voice-script/references/audio-runtime.md)へ渡し、必要な環境の準備から読み取りまで実行する。利用者に文字起こしを求めるのは、実行・回復を試しても取得できない時だけにする。詳しくは[音声の受け取り方](../../voice-script/references/voice-input.md)を読む。

## 作りながら、自分専用に育てる

最初から本人設定や見本を準備しなくてもよい。本人の材料が出た後や完成時に、必要な分だけ次を案内する。

「仕上げた台本を次の見本としてProjectの情報源に残せます。まず1本、代表的なものを最大5本ほど。『この修正を今後も使う自分専用ルールにまとめて』と頼めば、次に参照する個人用ファイルを作れます。」

見本は本人が確認・採用した完成HTMLのままでよく、Markdownへの変換は不要。他の著者の経験・肩書・告知を利用者本人の事実にしない。見本を登録しただけで自動的に学習し続けるわけではなく、各作業で参照できる資料を使う。[本人の完成稿を使う案内](script-examples.md)に従い、初回インタビューの最初の一問には登録案内を挟まない。

本人設定を明示的に作りたい場合はdoctor-profileを使う。改訂ファイルと保存先を示し、実際に保存・読み戻しできた場合だけ登録済みとする。登録済みでも読めない場合は必要な資料の参照を回復し、全文の再入力は求めない。まだ一度も登録していないことを参照障害と扱わない。

## ほかにできることとモデル案内

「YouTube分析、企画、資料からの台本、サムネイル、イラスト・図解・動画素材、記事化、出版企画、公開プロフィール、発信の軸、配色、公開用概要欄も依頼できます。『これがしたい』と普通の言葉で伝えてください。」

モデル選びを求められた時や必要機能が不足した時に[モデル案内](model-guide.md)を使う。台本・医学リサーチは推論できるモデルと必要な検索機能、画像には画像生成機能など、用途と画面で選べるものを合わせる。モデルを自動変更したとは言わず、初回インタビューに長い設定講座を挟まない。

続きは同じ案件のチャットで進める。新しい案件は同じProject内の新しいチャットにし、本人の過去情報は実際に参照できた範囲だけ使う。別チャットの音声や設定がすべて自動で共有されるとは説明しない。

## 素材入り台本を使う場合の初回登録

自己紹介カードまたは画像、終了画面、使用するプレゼント画像を受け取り、参考にしたい本人の過去動画や見本画像から配色・雰囲気・文字量を登録する。全部揃うまで全作業を止めず、不足する役割を明示する。動画URLは映像を実際に確認できた範囲だけをデザインの根拠にする。

「本人素材・デザイン設定_最新版.md」と実素材は本人専用Projectへ保存する。スキルへの同梱と混同せず、新しいチャットから設定だけでなく実画像も読み戻せたことを確認する。登録後は「この台本を、素材込みで編集者に渡せる形にして」と伝える。

標準では、生活場面のイラスト、比較の図解、動きを伝える動画などを内容に合わせて選び、おすすめ案の実素材を台本に組み込む。クリックして開く本人向け限定確認ページで全文を確認し、気になる箇所だけ別案へ変更できる。同じ案件の修正は同じURLへ反映する。会話内の小さな分割表示やアプリの切り替えを標準手順にしない。動画生成の接続や本人画像が必要な場合は不足する部分だけ案内し、勝手な代替で完成にしない。HTML上の選択変更は生成やZIP更新を実行しないため、書き出した依頼文や選択結果を元のチャットへ戻す。各自にコマンドやJSONの手書きを求めない。
