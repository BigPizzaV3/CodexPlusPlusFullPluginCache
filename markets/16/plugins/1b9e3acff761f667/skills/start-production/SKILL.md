# START・制作進行

Liveの開始準備として「分かったら『はい』と一言だけ」と指定された依頼は、初回設定や見本案内より先に [voice-script](../voice-script/SKILL.md) の開始待機を適用し、返答は `はい` のみにする。ユーザーの次の開始発話を待ち、ボタン押下を検知したと仮定しない。

[共通運用](references/common.md) を最初に読む。初回設定か、具体的な制作か、途中再開かを依頼から判断し、使い方説明を毎回挟まない。

## 録音を受け取った時

添付音声の発話が未取得なら[自動読み取り](../voice-script/references/audio-runtime.md)を適用する。必要な環境の準備と文字起こしを `ingest_audio.py` で実行し、利用者にアプリ導入や全文提出を任せない。文字起こしだけの依頼も同じ入口で完了できる。本人設定や見本の登録を待たずに進め、既に取得済みの文章は再処理しない。

## インタビュー開始を初回設定より優先する

Dr.SHI-GYOをそのチャットで指定している場合、またはProject指示に使用指定があり実際に本Pluginを利用できる場合に、「インタビューして」「初回音声インタビューをして」「動画台本を作りたいので初回音声インタビューして」と頼まれたら、[voice-script](../voice-script/SKILL.md)を読み、その入口からすぐ一問を出す。明示的な「はいだけ」の開始待機は最優先。テーマが分からなければテーマだけを聞き、分かれば所定の患者質問へ進む。用途を特定しない「インタビューして」は動画台本の初回を既定にするが、プロフィール・発信軸・出版等の明示された別用途は担当を尊重する。

**空の「動画台本生成プロジェクト」で使える。** プロジェクト名を取得できなくても、指示欄・情報源・本人設定・見本が未登録でも進める。プロフィール作成、Sourcesへの登録、長い開始文の貼付、モデル講座、別スキルの手動選択を最初の返答に挟まない。インタビューが済んだことや、Projectへ登録したことを先取りして報告しない。

## 初回の案内

「初めて使います」「本人設定と使い方を案内して」「プロジェクト指示を作って」等には、[Projectの設定手順](../doctor-profile/references/project-setup.md)を読む。**このProjectの情報発信では必ずDr.SHI-GYOの該当スキルを使い、毎回の名前指定なしでも依頼から選ぶ**と明記したコピー用指示を必ず提案する。本人資料が完成するまで提示を先送りしない。既存指示は保持・統合し、保存と新しいチャットでの利用確認まで案内する。自動インストールや全環境での自動起動を保証しない。具体的な制作依頼と「はいだけ」の待機には割り込ませない。

[初回レクチャー](references/first-use.md) を、使い方の案内を求められた時に必要な部分だけ伝える。具体的な制作・インタビューの依頼は、そのまま担当工程へ進める。本人設定の登録を依頼された時だけdoctor-profileで作る。担当機能が使えなければ、本人資料から設定ファイルを作り、Project登録まで案内する。設定を一度も登録していない人へ、参照回復やプロフィール全文の入力を要求しない。既存設定が読めるならやり直さない。

用途に応じ [モデル案内](references/model-guide.md) を提示する。モデルを自動変更したと報告しない。必要な検索・画像生成・表計算・ファイル生成機能の有無は別に確認する。

本人らしさを先に整えたい人には、公開用プロフィール、3＋3の発信キーワード、撮影セットと配色相談を目的に応じて案内する。すべてを初回の必須課題にしない。使い方のマニュアルを求められたら [全機能の使い方](references/manual-index.md) から該当ガイドを読み、普通の言葉で始められる例文と手順を渡す。マニュアル閲覧だけの依頼で制作工程を開始しない。

## 制作を始める

台本を扱う時は [本人の完成稿を使う案内](references/script-examples.md) を読み、初回作成時と台本の内容・語り口への不満時に適用する。本人が仕上げた見本をProjectへ1本から最大5本程度登録する推奨と、AIに任せきりにしない仕上げの案内を短く伝える。既存の見本と案内状況を担当Skillへ引き継ぎ、重複案内・再登録要求・登録待ちによる停止を避ける。担当Skillが利用不可の場合もこの手順を使う。

初回インタビュー・ボイスメモ方式の最初の語りを受け取る前は、見本台本の登録や本人設定・タイトル等の質問を挟まず、先に語ってもらう。見本の案内や不足する執筆条件は、その語りを受け取った後の必要な段階で扱う。

[依頼と担当の対応](references/routing.md)、[制作メモ](references/production.md) を読む。既にある成果物から開始し、今回依頼されたものだけ作る。「動画一本」は既定では撮影・編集に渡す企画、読み上げ台本、サムネイル、必要素材。動画ファイルの撮影・編集が依頼されているなら利用可能な機能と入力を確認し、台本を納めて動画完成とは言わない。

入力から医師・視聴者・テーマ・必要成果物を整理する。元GPT名を指定された場合は [依頼と担当の対応](references/routing.md) で該当モードを選び、その原文・Knowledgeにある件数、入力条件、確認段階を守る。一括制作では既に確定した条件や承認を引き継ぎ、同じ質問は繰り返さない。未回答の方向性確認やマニュアル更新前の合意を勝手に通過させず、利用者が確認省略を明示した範囲でまとめて実行する。

「インタビューして」「初回音声インタビューをして」「動画台本を作りたいので初回音声インタビューして」「3回喋る」「Liveで考えを引き出して」「ボイスメモから台本」「まず経験を話し、調べてもらってからもう一度話したい」には [3回喋る動画台本](../voice-script/SKILL.md) を入口にする。Liveは視聴者の期待を軸に一問ずつ、多角的に聞き、最初の語りの前に論文・参考動画・完成構成を提示しない。調査後は本人の第二の語りを待ち、既存の一括制作ループで台本まで自動的に進めない。初稿HTMLを渡した後の第三段階は修正音声・画面録画・文章をscript-improvementへ渡す。音声入力の文章や文字起こしも受け付け、単なる録音の文字起こし、完成音声の忠実な台本化へ3段階を強制しない。voice-scriptから最終執筆用の資料が引き継がれた場合は、その段階と確定条件を保持してsource-scriptで執筆し、第一段階へ戻さない。

担当Skillが利用可能ならその指示を読んで進める。単に担当名を並べて終了しない。利用可能でない場合は必要な資料を参照して自分で作業する。医学的な判断を含む工程では [根拠規則](references/evidence.md) に従う。

1. 企画を絞り、視聴者の問いと動画の約束を決める。月次分析は与えられている時だけ使う。
2. 提供資料が主な根拠なら資料ベース台本、テーマから調査が必要なら医学リサーチ型台本へ進む。両者が混在する場合は提供資料を基準に不足だけ調べる。
3. 主張と出典、本人経験を保持して台本を作る。作成・実質的改稿時は [初心者視聴者レビュー](references/viewer-review.md) を読み、医学知識のない初心者・本人文体・簡易事実照合の3役を実サブエージェントで実行し、指摘を検討・修正してから次へ進む。意図的省略は利用者の明示指定時のみ。担当Skillの同一原稿版で実施・修正済みなら二重起動しない。担当Skillが使えず自分で執筆する場合もこの工程を適用し、委任機能そのものが使えない場合は未実施を明示する。
4. 最新台本を使ってタイトル・サムネイル・素材を作り、数字や断言の強さを照合する。完成台本への「素材を作って」や素材入りの編集用一式はeditor-handoffへ進み、その[完成条件](../editor-handoff/references/completion-contract.md)を読む。用途に合うイラスト・図解・実動画と取得できた本人素材を台本に配置し、同じ原稿の全文プレビュー・HTML・ZIPへまとめる。必要な動画や本人素材を未制作案や無断の代替へ落として完成にしない。先に候補だけ選びたい依頼はasset-planningで提案する。元GPTの挿入画像10点等を明示された時はvisual-materialsの該当モードを使う。
5. 記事化等は依頼されている場合だけ追加する。

完成した動画の公開準備を依頼された場合はyoutube-metadataへ、公開用の実動画・文字起こし・確定タイトル等を渡す。台本の読上げ見積もりを動画の実時刻へ変換しない。出版企画が確定し提出文面を求められた場合はpublishing-planの提出用モードへ渡す。採用済みの企画や本人の回答を聞き直さない。

## 変更・再開

「この修正をスキル化して」「独自スキルに追記して」「今回の完成形を見本登録して」は、[doctor-profileの個人成長フロー](../doctor-profile/references/personal-growth.md)へつなぐ。新しい台本の執筆や旧マニュアルの長文作成を始めない。担当Skillが修正版を納品したら二つの登録提案の実施状態を引き継ぎ、未実施ならその場で行い、回答済みなら繰り返さない。

一つの制作メモを更新し、影響を受ける成果物だけを要更新にする。実行環境があれば [状態管理の使い方](references/state-tool.md) に従って `scripts/case_state.py` を利用できる。スクリプトが使えない環境でも文章版メモで同じ規則を守る。

途中再開では、保存された制作メモと成果物を読み、本人設定・主張・台本の版を合わせる。見つからないものを完了済みとしない。

## 納品

台本の初稿・改稿・完成稿は [共通のHTML納品仕様](../source-script/references/script-output.md) を適用する。音声方式の調査まとめは [調査レポートの構造](../voice-script/references/research-brief.md) に従った別のHTMLとし、台本用ビルダーや読み上げ本文の要件を使わない。利用者の別形式指定は優先する。台本だけの依頼と素材入りのeditor-handoffを区別し、素材未依頼なら画像・動画制作を追加しない。

最初に完成した成果物と使い方を簡潔に示す。実在するファイルへのリンク、未完了部分、次に必要な資料を必要な範囲で添える。台本・画像等の読者向け成果物と、内部の根拠・制作メモは分ける。最後に保存確認済みか、Projectへの登録待ちかを明記する。
