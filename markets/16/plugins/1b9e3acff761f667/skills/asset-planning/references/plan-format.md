# 素材計画データと任意の選択画面

ChatGPTが台本を読んで判断し、下記データを作る。付属スクリプトは推薦を自動推論するエンジンではなく、計画の整合性を検査して選択画面へ整形する補助機能。

## 計画

- `plan_id`：案件ごとに安定した識別子。
- `source`：`title`、`version`、原稿ファイルの生バイトの `sha256`。版名をファイルが実際に持たなければ「受領原稿 2026-10-09」等の管理用名を付ける。
- `scenes`：台本順の一覧。各項目に `id`、`label`、原文の一意な `quote`、`message`、推奨option IDの `recommended`、`options`。
- 各option：`id`、表現種類の `type`（イラスト・漫画・図解など）、`title`、具体的な `concept`、推薦/代替の `reason`、表示形式・比率・配置を記す文字列の `format`、必要入力の文字列配列 `requirements`、`delivery_status: "proposal"`。
- 必要な時だけ `preview: {kind: "image" または "video", path: 計画JSONからの相対ファイルパス}`。実在する見本のみに使う。初版の画面では見本は完成素材として扱わない。

自然文の提示のみならJSONは不要。原文に同じ短文が複数回あれば引用を前後へ広げて一意にする。原文の句読点や全半角を変えた引用は使わない。

`format` は①正方形（1:1）のインサート、②16:9の全画面静止画、③16:9の全画面動画を基準に書く。例えば `type: "イラスト"` と `format: "① 正方形（1:1）のインサート。話者・字幕と重ならない空白へ配置。撮影動画未提供のため位置は仮案"` のように、表現種類と表示形式を分ける。①の縮小時の読みやすさ、②③の情報量・表示順は `concept` に含め、配置確認や動画出力に必要な入力は `requirements` に記録する。別比率の明示依頼がある場合は指定値を使う。

推奨は用途に合う1件を選び、別案は意味のあるものだけを添える。3つの表示形式をすべて `options` に入れる必要はない。今回の採用形式と本人の画風の好みはそれぞれ案件・個人設定に保存し、共通の既定値へ置き換えない。

## 出力

実行できる環境では次の形で利用する。パスはその環境で解決し、受講生に実行を求めない。

```bash
python3 scripts/render_choices.py plan.json --script script.md --output choices.html
```

原稿のSHAと引用を検査してからHTMLを作る。HTMLは外部通信を行わず、推奨案を初期選択する。ユーザーは別案、素材なし、修正メモを指定し、依頼文をチャットへ戻すか選択結果JSONを添付する。

返却形式は `plan_id`、`source`、`choices`。各choiceは `scene_id`、`quote`、`option_id`（素材なしはnull）、`note`。戻ったIDが現行計画にあり、台本の版が合っているか照合する。元の計画が読めなければ参照を回復する。

## 状態を混同しない

計画と選択結果は「何を作るか」の記録。制作メモには別途、採用／制作待ち／本人素材待ち／生成済み／確認済み／要更新を記録する。計画画面のサンプル、ブラウザ内のアニメーション、実際にダウンロードできる完成MP4を同じ完了状態にしない。

## 医学説明の3〜5案

[医学説明の3〜5案](medical-variants.md)に従い、対象場面の制作メモへ候補数、各案のstyle・説明目的・省略範囲を記す。提案画面は従来どおり未制作の計画を表示するものであり、render_choices.pyのproposalをreadyへ書き換えて完成画像の比較に使わない。

実画像での比較まで依頼されたらeditor-handoffへ渡し、[案件データ](../../editor-handoff/references/bundle-format.md)のmedical_variantsとmedical_visualへ変換する。全候補を実制作したscript.htmlと本人向け確認ページを使用する。
