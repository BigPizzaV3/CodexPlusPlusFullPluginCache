# 発信の軸を決める3＋3キーワード

音声・動画ファイルの発話が未取得なら、[添付音声の自動読み取り](../voice-script/references/audio-runtime.md)で `ingest_audio.py` を実行する。必要な処理環境の準備も行い、文字起こしの提出を最初から求めない。取得後はこのSkillの依頼を続け、動画台本の3段階フローへ自動的に切り替えない。

[共通運用](references/common.md) と [判断の基準](references/keyword-framework.md) を読む。発信活動全体の方向性を、本人の言葉を使って決める。通常は、専門性や届ける価値を示すメインキーワード3つと、姿勢・人柄を伝えるドライブキーワード3つを作る。

元GEMの6段階を使う。質問を一度に全部出さず、各段階の回答を待って進む。本人が既に書いた資料・音声の内容・採用済みの回答は再質問しない。現在の依頼が開始の合図であり、名前の入力や特定の開始語を重ねて要求しない。率直に改善点を伝えるが、実在の著者の人格を名乗ったり、利用者を罵る口調にはしない。

## 1. 棚卸し

経歴、得意分野、スキル、趣味、失敗、こだわり、違和感、今後やりたいことを、まず**20項目以上**目標に出してもらう。最初は短い項目や音声でよく、良し悪しを選別しない。既存資料から本人が語った項目を先に並べ、不足分だけ聞く。

20個を一度に出しにくい場合は、本人の回答に基づいて一問ずつ掘り出し、今ある項目数を伝える。同じ内容の水増しや、架空の失敗・実績で20個を埋めない。「今ある分で進めて」と明示されたら、その範囲で仮案を作り、材料不足で判断が弱いところを残す。非公開の事情やコンプレックスを話すことは必須にしない。

## 2. メインキーワード3つ

本人が届けたい相手を具体化し、「何について、誰に、どんな価値を届ける人か」を示す候補を出す。過去の肩書きだけで決めず、今の活動・実態と今後の方針を分ける。

各候補に、本人のどの材料から出したかと選ぶ理由を添える。3つを組み合わせたときの分かりやすさと特徴を比較し、本人の選択・修正を待つ。一般の人に意味が通じるか、狭すぎないか、組合せが散漫にならないかを点検する。「日本唯一」「需要がある」と実測済みのように保証しない。

## 3. ドライブキーワード3つ

本人が語ったストーリー、譲れないこと、回復・挑戦の姿勢などから、人柄が伝わる3語の候補を選ぶ。肩書きの言い換えではなく、メインの3語にどんな温度や考え方を加えるかを示す。

「大切にしていること」「違和感を覚えること」「発信ではあえて言わないこと」「失敗から変わった考え」などを一問ずつ必要な範囲で尋ねる。怒り・逆張り・強い言葉を全員に求めない。本人の自然な言葉を優先し、候補の採用を待つ。

## 4. 言葉を磨く

抽象的すぎる言葉を、本人が実際に使える表現へ整える。強い表現と穏やかな表現を比べる場合も、本人の事実・姿勢が変わらない範囲にする。数字は裏づけのある実績や本人が指定した目標にだけ使い、目標を達成済みの実績にしない。

候補6語を本人が採用したら確定する。すでに確定・反映が明示されている内容を再確認待ちに戻さない。選択が未了なら仮案であることを保ち、最終本人設定へ混ぜない。

## 5. 方向性を文章にする

[成果物ひな形](assets/brand-keywords-template.md) を使い、次を出す。

- メイン3語とドライブ3語。それぞれの意味、本人の材料、発信での使い所。
- 過去・現在・未来をそれぞれ1行にした3枚看板。転機が本人から語られていれば加えてよいが、ない転機は創作しない。
- 「誰が、どうなれるように、何を届けるか」が分かる1文。
- それらを自然につないだ短い発信方針文。6語すべてを無理に毎文へ詰め込まない。

## 6. SNSで使える案へ展開する

通常は下記を**各5案**、合計20案提示する。本人が媒体や件数を指定した場合はそれを優先する。

1. YouTubeチャンネル名
2. 動画の冒頭で使う短い挨拶・キャッチフレーズ
3. Xの表示名（アカウントIDの空き確認とは区別）
4. Xのプロフィール欄テキスト

メインキーワードを中心に、ドライブキーワードを必要な範囲で使う。専門資格や成果を盛らず、5案は単なる語順違いにならないよう、伝える価値や口調を変える。指定された文字数がある場合は数える。現行の媒体上限・名前の利用可能性・検索需要を未確認のまま確認済みにしない。外部アカウントの変更・公開はこの作成依頼に含めない。

## 保存・更新・他の制作への引き継ぎ

納品は「発信の軸_最新版.md」。採用済み／仮案を分け、対象者、版、更新日、6語、方向性、各5案、採用された案、非公開事項、変更理由を残す。本人から更新を頼まれたら前版を読み、変更対象とその理由を記録して全文を更新する。単発動画のテーマ変更を本人の恒常的な軸へ自動で昇格させない。

「今後も使う設定にして」と頼まれたら **doctor-profile** へ、採用された6語・対象者・方向性・参照先・版を引き継ぐ。同Skillが読めない場合も本人用ファイルを渡せる形にする。直接書き込み可能な本人専用の保存先へ保存し、読み戻して確認したときだけ登録済みとする。ファイルを生成しただけの場合は、Projectの情報源へ登録または旧版と差し替えるよう案内する。共有Pluginには利用者の確定キーワードや私生活を保存しない。

3種類の公開プロフィールが必要ならpublic-profile、動画の企画ならvideo-planning、本人が喋って台本にしたいならvoice-scriptへ、今回確定した材料を引き継ぐ。作成後の投稿文・台本・出版企画では、語句の強制挿入よりも、その人の対象者と価値観を判断に使う。
