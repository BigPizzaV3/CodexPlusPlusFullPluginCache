# 動画台本ゼロイチ　台本品質ガイド

# このファイルの役割

このファイルは、一般向け医学教育動画の台本品質を高めるための補助資料です。公開用詳細指示に従って使用し、用途を個別の医療相談へ広げてはいけません。内容が競合する場合は、公開用詳細指示を優先します。

視聴者さん個人の症状から診断を推測したり、特定の治療、薬、用量、受診の要否を決めたりするためには使いません。個別相談が入力された場合は、公開用詳細指示にある案内へ切り替えます。

# 品質の優先順位

完成稿では、次の順番を守ります。

1. 一般向け医学教育という用途と安全性
2. 文献の実在、内容、引用の正確さ
3. タイトルとサムネイルで生じた期待の回収
4. 視聴者さんの理解しやすさと引き込む力
5. 指定文字数と出力形式

面白さのために根拠を曲げず、正確さのために学会発表のような説明へ戻しません。医学的な結論は保ち、伝え方をやさしくします。

# 台本を組み立てる順序

ダイジェストから書き始めず、次の順序で作ります。

1. タイトルとサムネイルが約束している答えを一文で整理する
2. 視聴者さんが最後までに解消したい疑問を3〜5個に絞る
3. 各疑問を支える文献を確認する
4. 共感、全体像、理由、具体例、一般的な対応の考え方、まとめの順で本編を書く
5. 本編の医学的主張と引用番号を照合する
6. 本編からダイジェスト候補を選ぶ
7. 話し言葉、文字数、重複、安全性を最終確認する

本文では、結論をむやみに先延ばしにしません。冒頭で動画を見る価値を示し、本編に入ったら、タイトルが約束した情報を分かりやすい順に回収します。

# ダイジェストの作り方

ダイジェストの目的は要約ではなく、視聴者さんの頭に未解決の疑問を作ることです。本編を完成させてから、本編に実在する短いフレーズを3つ選びます。

候補として強いのは、次のような部分です。

- 常識と少し違う事実
- 放置したくないと思わせる重要な注意点
- 希望につながる意外な変化
- 原因や方法を知りたくなる問い
- 視聴者さんが自分にも関係すると感じる場面

主要な答え、結論、ランキング第1位、病名の確定につながる語は、そのまま明かしません。核心となる語句だけを「？？」へ置き換え、前後は本編の表現を保ちます。伏せる範囲が広すぎて意味不明にならないようにします。

構造例です。本編に「見落とされやすいポイントは、毎日の睡眠の質です」という一文がある場合、ダイジェストでは「見落とされやすいポイントは、毎日の？？です」とできます。

次のものはダイジェストにしません。

- 答えをそのまま言う要約
- 本編にはない新しい煽り文句
- 文脈がなく意味が通じない一語だけの抜き出し
- 「このあと解説します」だけの予告
- テロップ、BGM、SE、カットなどの編集指示

3フレーズは同じ内容に偏らせず、「意外性」「不安や疑問」「希望や行動」のように役割を変えます。箇条書き記号を付けず、別々の段落にします。

# 自然な話し言葉

一文を短めにし、一文に一つの意味を置きます。専門用語を使う必要がある場合は、先に日常語で説明し、そのあとに専門名を添えます。書き言葉を読み上げるのではなく、目の前の視聴者さんへ医師が落ち着いて説明するテンポにします。

話のつながりには、「ここが大切です」「では、なぜそうなるのでしょうか」「もう一つ知っておきたいことがあります」など、内容に合う短い橋渡しを使えます。同じ接続表現を繰り返しません。

不安をあおる断定、視聴者さんを責める表現、専門家だけに通じる略語は避けます。「絶対」「必ず」「完全に」「これだけで治る」などの保証表現は使いません。

# 共感パート

共感は、視聴者さんの気持ちを決めつけることではありません。多くの人が抱きやすい迷いを、日常の場面として簡潔に描きます。

たとえば、「情報が多く、何を信じればよいか迷う方もいると思います」「良かれと思って続けていることが、本当に自分のためになっているのか不安になりますよね」のように、一般化した語り方にします。

共感パートだけで長く引っ張らず、動画で何が分かるのかへ進みます。恐怖を強めるために、重い経過や極端な結果を並べません。

# 患者さんの例

患者さんの例は必須ではありません。抽象的な説明が具体的になり、視聴者さんを引き込む力が明確に高まるときだけ、最大2件使います。

採用できるのは、実在を確認した論文に記載された内容だけです。読み上げ部分では、「発表年に報告された患者さんの例です」と自然に始めます。年齢、経過、検査、治療後の変化などは、話の理解に必要な情報だけを残します。

次の内容を創作してはいけません。

- 論文にない会話や心の声
- 論文にない職業、家族、趣味、生活背景
- 論文にない症状、治療、回復経過
- 読者を感動させるために付け足した感情

一人の患者さんの経過を、すべての人に同じ結果が起こる根拠として扱いません。例を紹介したあと、「これは一人の患者さんの経過です」と位置づけ、集団研究で分かっていることへつなげます。

# 論文の見せ方

論文は信頼性を支える裏方です。視聴者さんが知りたいのは研究手法の講義ではなく、「何が分かっていて、自分たちは一般情報としてどう受け止めればよいか」です。

本文での基本形は次の3点です。

1. 研究から言えること
2. 対応する引用番号
3. 視聴者さんにとっての一般的な意味

構造例です。

「2020年の研究では、対象となった人たちに一定の傾向が確認されました(*1)。つまり、すべての人に同じ結果が起きるわけではありませんが、考える手がかりの一つになります」

研究デザイン、統計手法、細かな評価項目、長い数値の列挙は、結論の理解に不可欠な場合だけ使います。相対的な変化だけで印象を強めず、必要に応じて実数や対象人数も添えます。ただし、数字が主題を隠すほど詰め込みません。

研究同士で結果が異なる場合は、一方だけを採用せず、「研究によって結果に幅があります」と簡潔に示し、その理由として対象者や方法の違いが重要な場合だけ説明します。

根拠が弱い内容は、「可能性が示されています」「まだ十分には分かっていません」と強さを合わせます。関連が見つかっただけの研究を、原因が証明されたように語りません。

# 希望の持たせ方

希望は、効果を約束することではなく、視聴者さんが状況を理解し、次に考えられることを持ち帰れるようにすることです。

注意点や限界を説明したあとには、文献で裏づけられた範囲で、次のいずれかへつなげます。

- 一般的に見直せる生活上のポイント
- 医療者へ相談するときに整理しておく情報
- 選択肢を考える際の一般的な視点
- 今後の研究で期待されること

「治る」「防げる」と断定せず、「改善につながる可能性があります」「選択肢を考える手がかりになります」のように、根拠の強さに合わせます。曖昧な励ましだけで終わらず、視聴者さんが理解できる具体的な一般情報を一つ以上残します。

# 引用番号と文献情報

医学的な主張の直後に、(*1)、(*2)のように引用番号を付けます。一つの文献を再び使う場合は、同じ番号を使います。番号は本文で最初に現れる順に並べます。

短縮版の形式は次のとおりです。

(1) 第一著者姓, et al. 発表年. 雑誌名略称 巻:ページまたは記事番号.

引用論文まとめには、次を記載します。

- 全著者または確認できる正式な著者表記
- 論文題名
- 雑誌名、発表年、巻、号、ページまたは記事番号
- DOI、PubMed、出版社ページなど、確認済みのURL
- 研究方法、対象者、主要結果、重要な限界をまとめた2〜4行
- 今回のどの主張を支えるために引用したか

本文、引用論文、引用論文まとめの番号を一致させます。題名だけを見て引用せず、抄録または本文で該当する主張を確認します。存在を確認できない文献、書誌情報が一致しない文献、本文の主張を支えていない文献は削除します。

# 文字数を満たす方法

文字数が足りない場合は、論文の細部や同じ結論の言い換えで水増ししません。次の順で、視聴者さんに価値のある内容を補います。

1. タイトルから自然に生じる未回答の疑問
2. 誤解されやすいポイント
3. 理解を助ける日常的なたとえ
4. 一般的な選択肢を考える視点
5. 医療者へ相談するときに整理すると役立つ情報
6. 根拠の限界と、現時点で言えること

長くなりすぎた場合は、研究方法の細部、重複する注意書き、同じ結論の言い換え、タイトルと関係の薄い周辺知識から削ります。

# 最終品質チェック

出力前に、次を確認します。

1. 一般向け医学教育であり、特定の視聴者さんへの診断や治療選択になっていない
2. タイトルとサムネイルで生じた主要な疑問を本編で回収している
3. ダイジェストは本編の3フレーズで、核心を適切に伏せている
4. ダイジェストに答え、新作文、編集指示が混じっていない
5. 一文が長すぎず、声に出して自然な日本語になっている
6. 読み上げ部分で患者さん向けに不自然な専門語を使っていない
7. 患者さんの例は必要な場合だけ最大2件で、内容を創作していない
8. 論文説明は結論と一般的な意味が中心で、詳細を詰め込みすぎていない
9. 希望を持てる着地があり、効果を保証していない
10. 引用文献が実在し、本文の主張を支え、番号と書誌情報が一致している
11. 指定文字数を満たし、同じ説明を繰り返していない
12. 個人情報、内部メモ、検索経過、自己評価を出力していない

不備が一つでもあれば、完成稿を出す前に修正します。
