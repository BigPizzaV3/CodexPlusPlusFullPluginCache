# 改善結果と引き継ぎ

## 元GPTの通常出力

「台本魅力アップ」「属人性を高める」等の通常依頼では original-11.txt のA〜Fを全て出す。診断・採点だけ、あるいは修正版だけに短縮しない。

| 部分 | 主要成果物 |
| --- | --- |
| A | 6軸0〜5点、AIらしく埋もれる文3〜6引用、画像があれば期待との一致 |
| B | 独立した5〜10の原文引用候補・訴求と各A/B改稿案、ベスト3、20〜35秒目安の冒頭台本。最終ナレーションは完成本文の連続原文と一致（意味を保つ語尾カット可）。位置特定用引用・実際の抜き出し範囲・表示文を区別 |
| C | 35文字以内のタイトル10案、上位3比較、最有力1案 |
| D | キーワード上位10、複合2語、450〜550文字の紹介文と文字数 |
| E | 3カテゴリ各3以上、合計15〜20の引用つき質問 |
| F | 質問ベスト5、回答順、挿入位置。画像ありは質問ベスト3と期待回収の一文 |

明示された限定依頼ではその範囲を優先する。入力の長さ等により原本の数量を満たせない場合は不足を説明し、存在しない引用・頻出語・本人経験を作らない。サムネイルなしの場合は画像との一致を評価したふりをしない。

Bの候補数と執筆順は2026-10-12のユーザー承認による [共通基準](script-quality.md) を優先する。全文改稿では5〜10か所を設計して本文へ組み込み、最終本文から抽出する。評価のみでは実在候補だけを出す。A/Bは同じ箇所の別表現として1候補に数え、本文未反映の案を原文引用や撮影済み音声からの抜き出しにしない。

## 全文改稿・限定修正

改稿も依頼された場合は、確認済み材料で修正版を作る。主要変更と未確認事項を本文外へ付ける。全文依頼なら全文、差分のみの依頼なら変更箇所を返す。本人への質問の未回答を、本人の回答として生成しない。修正音声・画面録画を反映する依頼は [修正入力](revision-input.md) に従い、未依頼のA〜F全件を追加せずに改稿する。台本の既定納品は [全文HTML](../../source-script/references/script-output.md) とし、今回の別形式指定を優先する。

| 節ID・元の引用 | 問題と影響 | 修正内容 | 関連する主張ID・根拠 | 後続成果物への影響 |
| --- | --- | --- | --- | --- |

## 保存・引き継ぎ

共通 production.md の様式に合わせ、案件ID、元原稿の版、新版、本人設定の版、変更した節IDと主張ID、確認状態を残す。比較できる元原稿がない場合に、以前との変更点を推測で書かない。

本文の実質的改稿では [初心者視聴者レビュー](viewer-review.md) の3役の実行・結果受領・統合修正・再確認を記録する。原稿版を揃え、明示省略と機能利用不可を区別する。

構文・説明順の反復で修正した箇所と意図的に残した箇所、ダイジェスト候補の原文・位置・訴求・根拠・採否を本文外へ記録する。候補不足の場合は理由を添える。素材・編集納品へは最新版本文と採用候補をセットで引き継ぐ。

- **医学的意味が変わる修正**：数値、比較、対象、結論、断言の強さ。根拠との対応と、その主張を使う画像・記事の更新要否を確認する。
- **医学的意味が変わらない修正**：語尾、誤字、同じ意味の言い換え。通常は根拠を再調査しない。画像内に元の文が掲載されている場合はその表示のみ照合する。
- **継続方針の候補**：原稿での修正と別に扱う。「今後も使う」と明示された内容があれば、doctor-profileへ変更内容を引き継ぐ。マニュアル更新の依頼は本Skill内で勝手に確定しない。

保存先へ書き込めるときは読み戻して版と内容を確認する。ファイルを生成して渡すだけの場合は、生成済みと本人設定・制作記録への登録済みを区別する。
