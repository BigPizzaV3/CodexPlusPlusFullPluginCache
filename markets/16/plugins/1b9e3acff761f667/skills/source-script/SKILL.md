# 資料ベース台本

「ボイスメモから台本」や二段階の語りで作りたい依頼は [voice-script](../voice-script/SKILL.md) を入口にする。ただしvoice-scriptから第二の語り・採用根拠・執筆条件を受け取った最終執筆は、本Skillが担当し、第一段階へ戻さない。その場合は第二の語りの話したい内容・順序・語り口を主軸に、第一の語りの本人経験と確認済み根拠を対応させる。調査メモの見出し順で本人の構成を上書きしない。未確認の医学的断言はそのまま強めず、該当箇所だけ調査・限定・省略の判断を進行側へ返す。確定済みのテーマや尺を質問し直さない。音声の文字起こしだけ、完成した口述原稿を整えるだけの指定はその範囲で行う。未取得の録音は[自動読み取り](../voice-script/references/audio-runtime.md)の `ingest_audio.py` で準備・文字起こしまで進める。3段階フローへ戻さず、取得後は今回の変換依頼を続ける。

これは統合設計で追加した資料変換の手順で、独立した元GPTの設定を再現したものではない。「動画台本ゼロイチ」を指定された場合はresearch-scriptの原指示・Knowledgeに従い、その入力・方向性確認・固定出力を省略しない。資料が添付されただけで別手順へ自動的に切り替えない。

開始時に [共通手順](references/common.md) を読む。医学的主張を扱う場合は [医学情報の共通基準](references/evidence.md)、コメント・修正音声の反映、元資料・台本などの複数成果物や途中再開は [制作管理](references/production.md) も読む。本人設定と元資料を読み、読み取れる内容を質問し直さない。

完成稿を返す直前に [日本語の仕上げ](../japanese-finish/SKILL.md) を当てる。語り口は本人設定と独自スキルを優先する。

このSkillでは提供資料を内容の主軸にする。素材の内容を別の話題へ置き換えたり、勝手に広範な調査へ拡大したりしない。資料の誤りや不足は引き継がず、確認状態を明示して補足する。

執筆前に [読み上げ・ダイジェストの共通基準](references/script-quality.md) を必ず読む。2026-10-12・13のユーザー承認、2026-10-14の完成稿差分と2026-10-17承認の汎用化案を反映し、構文と話の運びの反復、無駄バランス発言、解釈と提案、ダイジェスト、CTA、レビューの合格条件を適用する。元資料に根拠のある5〜10か所の候補を本文へ自然に配置する。元資料の意味と範囲を保ち、候補数のために医学的事実・本人経験を追加しない。

本文作成・実質的改稿の前に [初心者視聴者レビュー](references/viewer-review.md) を必ず読む。医学知識が全くない初心者に伝わるかを、実サブエージェント3役で点検し、妥当な指摘を修正してから納品する。起動を意図的に省くのは利用者の明示指定時のみ。機能利用不可は未実施として扱い、自己点検と区別する。

[本人の完成稿を使う案内](references/script-examples.md) を読み、初回の台本作成時と、内容・構成・語り口への不満が出た時に適用する。本人が仕上げた見本台本を専用Projectへ1本から最大5本程度登録するよう短く勧め、本人による推敲・判断の大切さも伝える。既存の見本は再利用し、登録待ちで制作・修正を止めず、同じ案内を重ねない。

## 元資料を特定する

1. 資料の名称、著者、版、対象範囲と読み取れた範囲を把握する。複数資料なら重複と矛盾を先に整理し、用途が明確なら一つの動画へ統合する。
2. PDFの図表や画像に重要な情報があれば、利用できる閲覧機能で該当ページを確認する。文字抽出だけで読めない図の内容、見切れた表、未取得ページを推測しない。
3. URLしか渡されていない資料は取得して内容を確認する。到達できなければ既に読める資料で作業し、必須部分だけ本文やファイルの提供を依頼する。題名から中身を創作しない。
4. 発信者と資料の作者を区別する。元資料の「私」「当院」「担当患者」は、発信者本人の記述と確認できなければ一人称へ転用しない。

## 台本への対応を設計する

- [資料対応表と変換の判断](references/source-map.md) に沿って、主要な主張に既存の主張IDまたは新しいIDを付け、資料のページ・節・表と対応づける。
- 対象視聴者、動画の目的、本人の文体、尺・文字数が分かればそれを使う。用途が曖昧でも内容を要約して構成案までは進め、中心テーマや対象が複数候補で結果を左右するときだけ確認する。
- 順序、言い換え、例は動画向けに調整してよい。主張の方向、研究対象、条件、数値の意味は保持する。内容を省いた場合も、主要な結論が変わらないか確認する。
- 論文を解説する動画と、論文を根拠の一つとして使う動画を区別する。前者は研究方法と限界を軸に、後者は視聴者の疑問を軸に構成する。
- 楽々ポジティブ・高頻度のリスク・重症度の高いリスクから適した訴求を選び、独立した5〜10か所の配置と、本文で説明・回収する内容を決める。短い資料や根拠不足では成立する数に留め、不足理由を本文外へ記す。単語の言い換えで候補を増やさない。
- 節ごとの入口と説明順を見て、同じ対比・同じ進め方が続けば具体例、結果、問い、行動等から内容に合う構成へ組み直す。資料の事実上の区別を削るための規則にはしない。

## 必要箇所だけ補足する

- 資料内の医学的主張について、引用元と支える箇所が確認できるかを確認する。書籍に論文名があるだけで、その一次論文を検証済みにしない。
- 根拠が不明な数字、資料間の矛盾、更新が疑われる重要情報は、その箇所だけ追加確認する。使えるなら medical-evidence を利用し、なければ自分で一次情報URLを開き、内容と書誌情報・対象・限界を確認する。
- 補足資料は元資料と別の出典として残す。確認できなければ未確認部分を省く・限定する・注記する。中心結論が未確認の場合は草稿扱いとし、元資料の断言をそのまま完成原稿へ流し込まない。
- 引用は短い必要箇所に限定し、基本は出典付きの再構成とする。外部資料の文章を長く転載して、本人のオリジナル原稿として扱わない。

## 台本と対応表を仕上げる

本文中の文献表示は **「（引用文献挿入：1）」** の形式に統一する。数字は巻末の対応番号へ置き換え、同じ出典は同じ番号を再利用する。複数の出典は `（引用文献挿入：1）（引用文献挿入：2）` と別々に記す。これは編集者向けの目印で、発話本文の文字数・プロンプター稿には含めない。詳しくは [本文引用の統一書式](../source-script/references/script-output.md#本文引用の統一書式) に従う。

[対象・形式・長さの変換](references/adaptation-modes.md) から必要な調整を選ぶ。本人が述べていない体験や感情を創作せず、資料の説明と本人の解釈を分ける。資料の結論を保ちながら、各話題で分かることや対処の判断を具体的にする。必要な病名は短い説明と組にし、全文台本ではテーマに合うCTA案も書く。未確認の本人経歴・商品・特典・リンクは追加せず、CTA不要等の明示指定は優先する。

成果物は台本本文、元資料対応表、実際に確認した出典、必要な未確認事項。[台本全文のHTML納品](references/script-output.md) を読み、初稿・改訂稿・完成稿は標準で、台本全文と出典を含む単独で開ける実HTMLファイルにする。ダイジェストから本文へ移動でき、該当原文は太赤字で示す。Markdown等の明示指定は優先する。文字数を測った場合は本文の集計範囲を示し、未計測なら概算とする。元資料の読めた範囲、原稿の版、本人設定の版、採用主張IDは読み上げ本文外の制作メモへ残す。

初稿を3役へ委任して全結果を待ち、妥当な専門用語の説明不足・反復・事実不一致を直す。変更箇所と同型問題を再確認してから、統合後の全文を通読し、各話題の答え・判断や行動・期待回収、無駄バランス発言、構文・説明順・同義の主張の反復を点検して直す。レビュー実施だけで合格にしない。コメント改稿は全件の対応と同型問題の確認を記録する。そのうえで、候補の引用・位置・訴求・出典を元資料対応表または制作メモへ記録する。通常は完成本文の候補から最適な3か所を冒頭ダイジェストとして抽出する。冒頭不要・既定書式等の明示指定があれば従う。伏せ字は核心のみとし、対象・条件・否定語を隠さない。候補一覧や点検内容を読み上げ本文へ混ぜない。

引き継ぎ先のSkillが利用できなくても本Skillで資料との整合性と読み上げやすさを確認して進める。これは実サブエージェントの省略理由にはせず、委任機能が利用不可なら初心者視聴者レビューの未実施時の手順と表示に従う。改稿の依頼では元資料の変更箇所や対象視聴者の変更から影響範囲を特定し、関係のない論文調査や完成済み工程をやり直さない。

## 修正を本人の作り方へ育てる

本人の音声・文章・コメントによる修正を反映した完成稿を渡した後は、[見本登録と独自スキル更新](../doctor-profile/references/personal-growth.md)を必ず実行する。今回の変更を短く具体化し、「見本としてProjectのソースへ登録するか」「次回のために独自スキルへ反映するか」を独立した二問で提案する。対応する個人ルールは「独自スキル_動画台本生成」。同じ修正版で二重に質問せず、既に回答済みなら選択どおりに進める。初稿だけ、修正継続中、初回インタビューの途中には挟まない。

見本のみ／スキルのみ／両方／どちらも不要を区別する。登録を選んだら、その場で実Markdownを作成・更新し、保存先を読み戻せたものだけ登録済みと伝える。生成だけで保存済み・ネイティブSkill追加済みとしない。既存の独自スキルがあれば採用済みルールを保持して全文更新し、次回は今回の用途の最新版を再利用する。

ダイジェストの自動選定には[見続ける理由の選定基準](../source-script/references/digest-selection.md)を適用する。章紹介や留保だけの候補を落とし、視聴者の具体的な利益・避けたい結果・続きへの疑問が伝わる候補を比較して通常3本を選ぶ。執筆・実質改稿の範囲なら弱い本文を先に改善し、その完成版から抜き出す。撮影済み・抽出のみの依頼では新作文を録音済みとして扱わない。
