# 台本全文のHTML納品

台本の内容・執筆手順・必要な確認・レビューは担当Skillに従い、ここでは納品方法をそろえる。初稿・改訂稿・完成稿とも、指定がなければ**読み上げる全文と出典が入った、単独で開ける実HTMLファイル**を返す。修正時も差分だけで終えない。明示されたMarkdown、文章のみ、プロンプター専用などの指定は優先する。構成相談や評価だけの依頼に完成台本を追加しない。

## 内容と読みやすさ

- タイトル、原稿の版、作成日、確認済みの著者情報を表示する。本人の名前・経歴・特典・登録済み素材・公開URLを補完しない。
- 章と段落を持つ台本全文をHTML内に保持し、要約・「以下略」・画像・canvasだけで代用しない。章見出しや文字を選択してコピーできる形にする。
- 白い本文面、濃い文字、本文18〜20px、行間1.8〜2.0、最大幅900〜1,100px程度を基本にする。スマホで横にはみ出さず、印刷でも読めるようにする。
- 読み上げ文は `spoken`、タイトル等は `metadata`、ダイジェストは `digest`、文献は `references`、制作記録は `notes` として区別する。編集指示・修正報告・レビュー記録を読み上げ段落へ混ぜない。
- ダイジェストは最新版本文に実在する**連続した原文**から抽出する。各抜粋から本文へ移動でき、本文の該当原文を太赤字にする。離れた文をつなぐ、新しい煽り文句を引用扱いにする、否定・対象・条件を切り落とすことはしない。
- 通常の3抜粋・5〜10候補という編集判断は既存の品質基準に従う。レンダラーのために数を水増ししない。伏せ字を使う場合も原文を保持して核心の範囲だけを指定し、本文の原文は隠さない。不要指定時はダイジェスト欄を省いてよい。
- 候補は [ダイジェスト選定基準](digest-selection.md) で比較し、本人が指定した箇所以外は短文だけで具体的な利益／不利益と続きへの疑問が伝わるものを使う。本文を改善した場合は完成版から再抽出して太赤字・リンクを更新する。撮影済み・素材のみの未反映案は制作メモに「追撮が必要」と分け、実在する本文のダイジェスト欄へ入れない。
- 本文の `（引用文献挿入：1）` 等から同じ番号の文献へリンクする。同一文献は同一番号を再利用する。実際に確認した著者・題名・年・URL・資料の種類・確認範囲を残し、必要な研究条件・要約・支える主張も本文外へ置く。

**research-scriptの固定10見出しを保持する。** HTML化を理由に標準の見出し順・タイトル・サムネイル文言・文字数条件を変更しない。引用論文の短縮一覧と引用論文まとめは同じ文献番号を使う。自己紹介が未提供なら、その見出しを残して本文を空にする。CTAは現行の共通品質基準と本人指定を優先する。追加の制作メモだけを10見出しの後ろへ置ける。

source-scriptやvoice-script経由では、本人が決めた章立てを使い、ゼロイチの10見出しを強制しない。読み上げ本文の文字数を表示するときは集計範囲を明記する。HTMLの文字量、文献、編集用の重複ダイジェストを読み上げ本文の実測値に含めない。research-script固有の集計条件は別途維持する。

## 本文引用の統一書式

1.1.2以降、初稿・改訂稿・完成稿の動画台本は、引用する主張の文末に **`（引用文献挿入：1）`** のように記す。「番号」という文字は実際の巻末文献番号へ置き換える。全角の括弧・コロンと半角の数字を使う。HTML、Markdown、チャット本文、素材入り編集用台本で共通とする。

- 例：`研究で確認された内容を、条件を保って説明します。（引用文献挿入：1）`
- 同一文献は同一番号。複数文献は `（引用文献挿入：1）（引用文献挿入：2）` と記す。巻末の文献番号・順序・書誌情報・URLは対応を保持し、ラベル変更だけで採番し直さない。
- 標準台本ビルダーで作るHTMLでは、このラベル全体を同じ番号の巻末文献へのリンクにする。素材入り編集用HTMLでは、元の文献リンクや書誌情報を保って表示を揃える。標準台本ビルダーは従来の `(*1)` も受け取り、表示時に新形式へ揃える。裸の `(1)`・`（1）`・`[1]` は数量や列挙との誤認を避けるため、文献との対応を確認して引用箇所だけ新形式へ直す。未対応の番号を作らない。
- 編集者が挿入場所を判断するための目印なので、本文内に表示しても読み上げない。発話文字数から除外し、プロンプター専用原稿には目印を入れない。医学的な説明や数字を削る操作には使わない。
- 改稿・編集者用書き出しでもこの書式を維持する。元原稿や元GPTのKnowledgeは改変せず、出力する台本のコピーを整える。旧指示・原本にある `(*1)` や `(1)` 等の本文表記より、この書式を優先する。
- ダイジェストは実在する本文から照合する。引用ラベルを途中で切ったり伏せ字にしたりしない。入力表記を直すときは抜粋・位置指定も照合し直し、HTML上の表示だけを変更する場合も本文の文言と対応番号を失わない。
- 文献一覧自体、独立した医学調査レポート、記事・出版物・YouTube分析レポートには、この編集用ラベルを強制しない。

## 実ファイルを作る

Pythonを実行できる環境では、同Skill内の `scripts/build_script_html.py` を使える。標準ライブラリのみで、ネットワークや外部フォント・画像・JavaScriptを使わずにHTMLを生成する。相対パスはこの参照ファイルではなくSkillルートを基準に解決する。

```bash
python3 /実際のSkillルート/scripts/build_script_html.py /作業先/script-v1.json /出力先/台本_v1.html
```

上のパスは説明用。実行時は利用環境で確認した実在パスへ置き換える。利用者の端末へPythonをインストールする手順を基本にしない。別の実ファイル作成機能を使える場合は、以下と同じ内容・検証条件を満たして生成してよい。

入力JSONの構造（説明用の短い例。これを完成台本として納品しない）：

```json
{
  "title": "実際の動画タイトル",
  "version": "初稿 v1",
  "date": "2026-10-26",
  "layout": "standard",
  "sections": [
    {"id": "digest", "heading": "ダイジェスト", "role": "digest",
     "items": [{"source": "p-intro", "quote": "私が話したいことから始めます。"}]},
    {"id": "main", "heading": "台本全文", "role": "spoken", "blocks": [
      {"id": "chapter-intro", "heading": "最初の章"},
      {"id": "p-intro", "text": "今日は、私が話したいことから始めます。"}
    ]},
    {"id": "sources", "heading": "文献・出典", "role": "references", "style": "full"},
    {"id": "notes", "heading": "制作メモ", "role": "notes", "blocks": [
      {"id": "note-1", "text": "実際に行ったレビュー方式と修正内容だけを記す。"}
    ]}
  ],
  "references": []
}
```

- `author` は確認済みの場合だけ追加する。`date` は実際の作成日とする。
- `sections` の並びが出力順になる。`blocks` は `id` と `text`、または `id` と `heading` のどちらか。すべてのIDは英字で始まる英数字・`-`・`_`で、全体で一意にする。`ref-`・`digest-item-`で始まるID、`script-document`・`page-title`・`toc`は使用しない。
- 文献は `{"id":1,"authors":"確認済み著者","title":"確認済み題名","year":"確認済み年","url":"実際に確認したHTTP(S) URL","kind":"原著等","scope":"全文／抄録等"}`。`bibliography`（雑誌・巻・ページ等を含む確認済みの完全な書誌）、`short`（短縮書誌）、`summary`（方法・対象・結果・重要な限界の要約）、`supports`（支える主張）を追加できる。ゼロイチでは元の文献まとめ仕様を保つため、この4項目も必須にする。分からない項目はその状態を明記し、架空の値で穴埋めしない。書誌確認ができない中心主張を完成扱いにしない。
- 本文中で使う文献だけを入れる。確認したが不採用の資料は本文外の別調査記録へ置く。文献がある場合、`style:"full"` の文献欄が一つ必要。短縮欄を加える場合は `style:"short"` を使い、同じ `references` を参照する。
- `layout:"zeroichi"` はresearch-script用。固定10見出しを原Knowledgeと同じ文字列・順番で用意する。役割は順に `metadata, metadata, digest, spoken, spoken, spoken, spoken, spoken, references, references`、末尾2欄のstyleは `short, full`。本文中の章は7番目の `blocks` 内の `heading` にする。任意の制作メモは10欄の後に `notes` として足す。
- ダイジェストの `quote` は本文段落にある原文そのもの。段落内に同じ原文が複数ある場合だけ、1始まりの `occurrence` で対象を選ぶ。引用番号の途中を切らない。
- 伏せ字は任意の `masks:[{"start":0,"end":2}]` のように、`quote` の文字位置を0始まり・終点を含まない範囲で指定する。指定範囲だけを「？？」へ置換する。重複・逆順・範囲外・全文の伏せ字・引用番号を隠す指定はエラーになる。伏せ字によって対象・条件・否定が変わらないかは編集者役が確認する。元の `quote` 自体を伏せ字へ書き換えない。

## 納品前に確認する

1. 生成前に、全文が最新稿であること、本人の修正・章順・ダイジェスト・引用が対応していることを確認する。レンダラーは文章を執筆せず、医学的妥当性やリンク先の実在・書誌内容も検証しない。
2. ビルダーが出典欠落・重複・不正URL形式・原文にない抜粋等を報告したら、元データを直して再生成する。検証を外したり、不一致の引用を黙って削除したりしない。
3. 保存した実ファイルを読み戻す。本文末尾まであること、段落を選択できること、章・文献・ダイジェストの内部リンクが存在することを確認する。閲覧機能があればスマホ幅と通常幅でも確認する。実際に行っていないブラウザ確認を実施済みとしない。
4. **生成できたファイルの実リンク**を返し、「初稿」「改訂稿」「完成稿」を実際の段階に合わせて説明する。ローカルファイルを公開URLと呼ばない。本人用Projectへの自動登録・他者への送信は実行した証拠がない限り完了扱いにしない。
5. ファイル作成機能が使えない場合だけ、その制約を短く伝え、全文HTMLコードとUTF-8での保存方法を代替として返す。コードブロックだけを完成ファイル納品と呼ばず、次の実行環境で実ファイル化が必要なことを残す。

台本HTMLは台本の読み込み・修正・撮影準備用。イラスト・動画素材入りの編集用 `script.html` とZIPまで頼まれた場合は、全文と出典を保って [editor-handoff](../../editor-handoff/SKILL.md) へ渡す。台本HTMLだけで素材制作済みとは報告しない。
