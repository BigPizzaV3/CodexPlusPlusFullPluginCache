# 本人設定・台本マニュアル

音声・動画ファイルの発話が未取得なら、[添付音声の自動読み取り](../voice-script/references/audio-runtime.md)で `ingest_audio.py` を実行する。必要な処理環境の準備も行い、文字起こしの提出を最初から求めない。取得後はこのSkillの依頼を続け、動画台本の3段階フローへ自動的に切り替えない。

台本の初回作成、見本の登録、台本への不満の相談では [本人の完成稿を使う案内](references/script-examples.md) を読む。自分で書いた、またはAIの案を本人が直して完成させた見本を、専用Projectへ1本から最大5本程度登録するよう勧める。既存の見本を読み、本人による仕上げの必要性を短く伝え、見本がなくても進める。素材だけの登録にはこの台本案内を挟まない。

[共通運用](references/common.md) を読む。医師本人の資料を繰り返し使える形にし、その人の台本作成方法を作る。本人と版を確認し、Project等で読める登録済み情報は聞き直さない。他人の台本は構成・文体の参考であり、その人の経歴・経験・感情を利用医師へ移さない。

## 修正後の見本・独自スキル登録（標準モード）

動画台本・動画編集素材・サムネイルの修正を終えた時、および「見本にして」「この修正を独自スキル化して」「独自スキルをアップデートして」には、[見本と独自スキルを育てる手順](references/personal-growth.md)を全文読む。完成した修正版を先に渡し、実際の変更点を短く示してから、見本登録と独自スキル登録・更新の2問を独立して尋ねる。両方／見本だけ／独自スキルだけ／不要を別々に扱い、採用された側は再承認を挟まず実行する。同じ完成版には繰り返し尋ねない。

既存の本人設定・マニュアルがなくても、今回の指示と完成版から始める。台本生成、動画素材作成、サムネイル生成の分野ごとに、同じ本人の最新版へルールを統合し、実行条件・例外・変更根拠・版を含むMarkdown実ファイルにする。Projectソースへの書き込みと読み戻しができた場合だけ登録済みとし、できなければ実ファイルと最小の追加手順を渡す。個人の更新を共有プラグインへ反映しない。詳しい旧GPT差分分析を指定されていなければ、以下の旧モードの3点提出・5000文字・5つの質問を持ち込まない。

## Projectの利用方針を初回から提案する

初回導入・本人設定登録・Project指示の作成や見直しでは、[Projectの設定手順](references/project-setup.md)を読み、**情報発信の作業では必ずDr.SHI-GYOの該当スキルを使う**と明記したコピー用指示を、その場で提案する。利用者が各チャットでプラグイン名を言い直さなくても依頼から担当を選ぶ方針を入れる。既存の本人指示は保持し、同じ指定を重複追加しない。指示の提示・実際の保存・次のチャットでの使用確認を区別する。利用できない場合だけ選択を案内し、使ったと偽らない。設定は制作の開始条件にしない。

## 依頼に合うモードを選ぶ

| 依頼・入力 | モードと開始前に全文を読む原本 |
| --- | --- |
| 初回のProject指示を作りたい／毎回のプラグイン指定を省きたい | [Projectの設定手順](references/project-setup.md)。必要な指示を提示し、保存と次のチャットでの利用確認を案内 |
| 台本・素材・サムネイルの修正後の登録提案に回答／今回の修正を独自スキル化・更新／完成見本を保存 | [見本と独自スキルを育てる手順](references/personal-growth.md)。選択した側だけを本人用Markdownへ。既存マニュアルや旧GPTの質問を開始条件にしない |
| プロフィールを登録・訂正したい | 本人設定登録。下記「保存と再利用」へ |
| 自分の考えや経験から公開用プロフィールを作りたい | public-profileで表現を作り、本人採用済みの文章と確認済み事実を分けて受け取る。登録のみなら対話を始めない |
| 発信の軸・3＋3のキーワードを掘り下げたい／撮影セットの色を相談したい | brand-keywords／brand-colorへ。確定した結果の登録だけなら本Skillで進める |
| 自己紹介・終了画面・プレゼント画像を登録したい／参考動画の色や雰囲気を今後の素材へ使いたい | 本人素材・デザイン登録。下記の独立モードへ。旧GPTの台本マニュアル作成は開始しない |
| プロフィール・チャンネル情報・モデリング台本から、台本を作りながらマニュアルを作りたい | マニュアル新規作成：[旧GPT 13全文](references/original-13.txt) |
| 自分の完成台本とプロフィールを渡し、最初から「マニュアル化して」と依頼 | 直接マニュアル化：[旧GPT 13全文](references/original-13.txt) |
| 現行マニュアルとモデリングしたい成功台本から更新したい | モデリング更新：[旧GPT 12全文](references/original-12.txt) |
| 【Before】・【After】台本と現行マニュアルから更新したい | 差分更新：[旧GPT 10全文](references/original-10.txt) |

旧GPTを使うモードでは、選択した原本の固有の手順・数量・出力様式を使う。原本は旧GPTの挙動を保存した移行資料であり、そこにあるプロンプト開示拒否等を、このPluginの所有者による確認・編集の拒否理由にはしない。現在のユーザーの明示指示、共通の本人識別・根拠規則、および本Skillで記した運用上の調整を優先する。原本の一人称は利用医師の経験の証拠ではない。

台本マニュアルの新規作成・直接マニュアル化・モデリング更新・差分更新の全モードで、[本文引用の統一書式](../source-script/references/script-output.md#本文引用の統一書式) の `（引用文献挿入：1）` を既定にする。過去の見本に番号だけの表記があっても、そのまま現行の推奨書式として再学習しない。利用者が別書式を明示した場合は、その指定範囲に従う。

旧モードでも完成した修正稿を渡した時には標準モードの2問を使う。ただし見本・マニュアルの登録更新をすでに明示された側は再質問せず、未指定の側だけを提案する。マニュアルの更新や保存自体を新しい作品修正とみなして同じ登録質問を循環させない。

## 本人素材・デザイン登録（独立モード）

初回または変更があるときに [本人素材・デザインの登録手順](references/media-profile.md) を読み、[専用ひな形](assets/media-profile-template.md) を使う。自己紹介カード、終了画面、プレゼント画像、参考動画・画像を、読める本人設定と今回の添付から登録する。既にこの本人が採用・提供した素材を再確認させず、今回の完成形を再利用してほしい依頼なら、確認済みの素材とデザインを引き継ぐ。他の医師や別用途への転用は自動で決めない。

本人の識別と版、素材の実ファイル参照、今回の環境から原本を開いた結果、終了画面が完成版か配置用テンプレートか、プレゼントごとの適用主題・CTA・提供済みの案内先を記録する。元比率と透過を保ち、名前が設定にあるだけで取得済みとしない。未登録・参照不能・本人が省略指定・今回の台本に不要は別状態で扱う。デザインは観察した参考フレーム・時刻と、配色、文字、余白、イラスト、配置、動画利用条件を分ける。動画URLや文字起こしだけから画面の外観を確認済みにしない。

素材だけの登録では、5000文字の見本台本、旧GPTの5つの質問、台本マニュアルの採用確認を発動しない。登録済み情報と与えられたファイルを使って進め、受講生にJSONやコマンドの入力を求めない。本人専用の保存先で実ファイルと設定を読み戻せた場合だけ登録済みとし、それ以外は設定ファイルを渡して登録待ちと説明する。

「本人素材・デザイン設定_最新版.md」を「本人設定_最新版」から参照できるようにする。台本から素材付きの編集納品一式を求められたらeditor-handoffへ、構成案だけならasset-planningへ、この本人の設定・素材参照・版を引き継ぐ。共有Pluginには登録の手順と空のひな形だけを置き、個人の画像・氏名・配布先URL・確定した作風を追加しない。

## マニュアル新規作成・直接マニュアル化（旧GPT 13）

1. 本人のプロフィール、チャンネル情報、モデリング台本を既存資料から受け取り、足りないものだけ確認する。台本テーマ・方向性を既知情報から特定する。既に本人の完成台本があり、最初からマニュアル化を依頼された場合は、下記5へ直接進む。
2. 台本を新規作成・実質的改稿する場合は [初心者視聴者レビュー](references/viewer-review.md) を必ず読み、3役の実サブエージェントによるレビューと修正を適用する。今回の明示省略以外は起動する。素材登録・直接マニュアル化・マニュアルだけの更新は対象外。通常ルートでは短い見本で代用せず、**5000文字以上**の台本を作る。本文の文字数を確認する。医学的主張は [根拠規則](references/evidence.md) に従い、確認できない引用・本人経験を創作しない。
3. 原本の構成を維持する。3〜10程度のH2見出しと本文、タイムスタンプ・[導入]等のラベルなし、段落ごとの改行、本文の箇条書き0〜3箇所。導入は短い挨拶→共感→ベネフィット、本論は根拠を演者の言葉へ、約20秒のCTA直前に次の行動を予告し、最後は一つの実行案へつなぐ。医学知識が全くない初心者を標準とし、必要な専門用語だけを選び、日常語で意味を伝えてから名称を添えるか、初出で平易に説明する。用語の羅列や専門語による専門語の説明を避け、再出で必要なら短く補足する。これは2026-10-12のユーザー指定で、旧原本の専門用語の積極使用より優先する。定型句の反復を避ける。
4. 本文中は `（引用文献挿入：1）`、`（引用文献挿入：2）` を使う。本文表記は原本より [本文引用の統一書式](../source-script/references/script-output.md#本文引用の統一書式) を優先し、本人用台本マニュアルにもこの既定書式を記す。末尾に「引用論文（簡易リスト）」と「引用論文まとめ（詳細解説）」を原本形式で両方出す。初稿を3役へ委任して全結果を待ち、妥当な指摘を修正・再確認した台本を返してから、原本Step 3の**5つの質問をそのまま提示して回答を待つ**。雰囲気、キャッチフレーズ、口調・語尾、エビデンス、CTAの回答を反映し、実質的な改稿箇所にもレビューと修正を行い、本人の満足まで反復する。好みを確定する対話と、レビューだけの無制限な反復を混同しない。回答や承認を代筆しない。
5. 「満足」「マニュアル化して」等の合図が出てから、確定した文体・専門用語説明・文献形式・構成ルールを再利用可能なProject用カスタム指示として全文出力する。成功台本をさらに書くだけで終えない。最初からの直接マニュアル化では提出した本人台本を見本にする。Projectへ「見本の台本例」と「演者のプロフィール」を登録し、毎回「テーマ（タイトル）」と「方向性」で依頼できる運用を含める。

本人の確認を挟むのは、好みを確定してからマニュアルへ反映する元の設計を守るため。既に採用・満足が明示されている内容を再確認させない。見本台本とマニュアルは別成果物として保存する。

## モデリング台本から更新（旧GPT 12）

現行マニュアルと成功台本の両方を読む。構成、リズム、フック、CTA、視聴維持の構造を抽出し、表面的な語句の置換に終わらせない。現行マニュアルとの差、追加・修正・削除案、その理由を提示する。

**どの提案を採用するかのフィードバックを待ち、合意されたものだけ**を完成版へ反映する。採用済みの明示指示があればそれを使い、未採用案を紛れ込ませない。最後はCustom Instructions／Project Instructionsへコピーできる**Markdownコードブロックの全文マニュアル**を返す。抜粋や変更箇所だけにしない。

## Before/After差分から更新（旧GPT 10）

現行マニュアルと、更新前の【Before】台本・更新後の【After】台本を読み、どちらが前後か確認する。元GPT同様にこの3点を必要入力とする。ただしProject上にある現行マニュアルは再貼付させず、利用者が前後を明示済みならファイル名を直すためだけの再添付は求めない。方向が不明なら分析前に確認する。

最初に [更新判断](references/update-rules.md) を読む。全文と付随メモを照合し、変更なしの範囲、削除、挿入、語尾・句読点を含む全差分を記録する。観察した変更と目的の仮説を分け、本人専用／汎用／案件限定／医学精査・誤字等の非採用に分類してから反映先を選ぶ。

**A. 差分分析**：原本の4項目（変更サマリー3〜7行、変更一覧、意図マップ、再現ルール化）を出す。変更一覧は「変更箇所／Before／After／目的の仮説／視聴体験への効果の仮説／次回の再現ルール」に、分類・採否・保存先を添える。末尾に太字の **台本マニュアルの追記・修正案** を記載する。分析のみの依頼、または採否が未指定で確認が必要な提案では、最終行を次の固定文とし、この時点で改訂マニュアルを確定・保存しない。

この分析結果で間違っている点があれば指摘してください

**B. 指摘修正**：ユーザーの指摘を受けたら、どの項目をどう修正したかと修正後の結論を示す。採用確認をまだ受けておらず、下記の明示反映依頼にも該当しない場合は、最終行を次の固定文にする。

この分析結果でよろしいですか？

**C. 承認・明示反映依頼後の全文更新**：「OK」「はい」「それで合ってる」等で差分分析が承認されたら、確定ルールだけを現行マニュアルへ統合する。「差分を読み、本人用と汎用スキルへ反映して」等、更新まで明示されている場合は、観察が確実な変更と依頼範囲内の再現ルールを記録して反映する。固定文による確認待ちのためだけに停止しない。これは推測した動機・恒常的な好み・全提案への承認ではなく、不明な意図は仮説のまま分離する。

既存の文体と粒度を維持し、**更新版マニュアル全文／追加・修正・削除の一覧／次回運用5〜8ステップ**を出力する。Aへの直接の肯定でもCへ進める。本人用と汎用は別々に保存し、元台本は依頼なく改稿しない。今回固有の変更を恒常的な好みへ自動変換せず、利用者が確定した意図を優先する。

## 保存と再利用

本人専用の独自スキルは、次回の制作開始時に同じ本人・同じ分野の採用済み最新版を実際に読み、適用条件に従って使う。既存マニュアルと重複・矛盾する最新版を増やさない。未登録なら制作を進め、登録済みだが読めない場合だけ参照先を確認する。独自スキルをネイティブSkillとしてインストールした、モデルが永続学習したとは説明しない。

[本人設定ひな形](assets/profile-template.md) を使い、確認済みプロフィールと経験の出典・使用範囲、完成した台本マニュアル、見本台本への参照を分けて保持する。長いマニュアルを短いプロフィール欄へ要約して失わない。不明な経歴・人数・患者の会話は未登録のままにする。

public-profile、brand-keywords、brand-colorからの引き継ぎは、同じ医師か、本人採用済みか、適用する媒体と版を確認して本人設定へまとめる。実績等の事実、公開用の文章、今後の発信方針、観察した撮影環境、採用したデザイン提案を混ぜない。本人がすでに採用を明示した内容を重ねて承認待ちにしない。保存先を更新して読み戻せなければ、更新版ファイルと登録手順を渡し、保存済みとは報告しない。

[Projectの設定手順](references/project-setup.md)に沿って必須使用の段落を含め、本人専用の非共有Projectに「本人設定_最新版」、見本台本、プロフィール原本を登録する手順と、[Project用指示](assets/project-instructions.md) を渡す。マニュアルを独立ファイルにした場合は本人設定から最新版を参照できるようにする。版と更新日、前版、変更理由を保持する。

生成したファイルとProject登録済み原本を区別する。直接保存できる接続先が明示され、書込機能がある場合だけ、依頼の範囲で更新して読み戻す。それ以外は改訂ファイルの差し替えを案内する。Project原本の自動上書きや記憶を約束しない。新しいチャットで本人・版・マニュアルを読めたことを確かめ、初回登録・更新確認を完了にする。

納品は「本人設定_最新版.md」、必要なマニュアル全文・見本台本、変更点（初回は未確認事項）。本人設定を変えただけで過去案件を自動改稿しない。現在の案件へ影響するなら [制作メモ](references/production.md) に新版と影響範囲を記録する。保存先を読めない場合は再参照を案内し、プロフィールを最初から入力させない。
