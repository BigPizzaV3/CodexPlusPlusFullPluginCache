# 本人が仕上げた見本台本の案内と再利用

## いつ案内するか

台本の初回作成時、および「自分らしくない」「しっくりこない」「AIっぽい」「この台本ではうまく話せない」等、内容・構成・語り口への不満が出た時に適用する。見本台本を参照して本人らしさを高め、本人の推敲と判断が必要なことを短く伝える。ファイルが開けない等の操作不具合、誤字だけの修正、素材登録だけの依頼へ一律にこの案内を出さない。

1. 先に、読める本人設定・マニュアル・Projectの情報源と、この会話での案内済み状況を確認する。登録済みの見本は読み、同じ資料の再登録を求めない。読めない資料を読んだことにしない。
2. 初回で見本がなければ、入力確認や制作開始の返答に下記の短い推奨を添える。ただし、初回インタビューやボイスメモで「3回喋る」を始める返答には挟まない。第一の語りが出た後の必要な段階、または完成時へ回し、本人の言葉を引き出すことを優先する。登録を制作開始の条件にせず、分かっている入力で作業を進める。既に見本があれば、その語り口・構成を参照して進め、必要なら本人による仕上げの一言だけ添える。
3. 不満には、まず指摘された箇所と直し方を具体的に示し、今回の修正を進める。読める見本と比較して、語彙・一文の長さ・構文・説明順・具体例・距離感のどこが違うかを特定する。見本がない、または今回の好みを判断する材料が不足する場合にだけ登録を勧める。数字の誤り、根拠不足、反復等のAI側の不備を、利用者の入力や推敲不足のせいにしない。
4. 同じ会話・制作メモで案内済みなら繰り返さない。STARTから担当Skillへ案内状況を引き継ぎ、一つの返答に重複させない。保存先を実際に読める場合だけ過去の案内状況を使い、別チャットの記憶を装わない。利用者が「案内不要」「本文だけ」等を指定した場合はその形式を優先する。

## 推奨する資料と伝え方

本人が自分で書いた、またはAIの案に手を入れ、「自分の言葉で話せる完成形」と判断した動画台本を使う。**まず1本でよく、代表的なものを最大5本程度**。AIを使わず書いた台本に限定せず、未確認のAI初稿を本人の完成稿扱いにしない。これは参考にする代表例の目安であり、Projectのファイル数制限ではない。既に十分な見本があれば追加を要求せず、5本超ある場合も削除させずに今回に合う代表例を選ぶ。

登録先は**本人専用の非共有Projectの情報源（Sources）**。ファイル名にテーマ・版があると選びやすい。本人が好きな箇所や直した理由が分かれば添えてもらうが、全項目の記入を必須にしない。完成稿がない場合は、今回の一段落を本人の言葉に直した例や短いコメントでも作業を進め、仕上がった台本を今後の見本にできると案内する。

### 完成HTMLをそのまま見本にする

本人が採用した初稿・改訂稿・完成稿のうち、今後の見本にしたい完成版HTMLを、そのままProjectの情報源へ追加できる形で渡す。Markdownへの変換を必須にしない。本文がHTMLの見出し・段落として保存されていることを確認し、見た目だけの画像や実行時にしか現れない本文を見本にしない。今回参照する著者・版を明記し、他の著者の見本から本人の見本へ更新するときも事実の出所を混ぜない。

完成時に本人が継続利用を希望した判断基準・好む説明・修正理由を3〜5点程度の次回用メモへまとめ、完成HTMLの本文外または本人設定に残す。一度の指定を自動で恒常ルールにしない。保存・読み戻しできた場合だけ登録済みとし、そうでなければ完成HTMLとメモを渡し、Sourcesへの追加・差し替えを短く案内する。

### 初回の短い案内例

> ご自身で書いたり、AIの案に手を入れたりして完成させた動画台本を、このProjectの情報源に入れておくのがおすすめです。まず1本、最大5本ほどを目安に、その語り口や構成を参考にできます。AIに任せきりにせず、最後はご自身で読んで直し、内容と話し方に納得できる台本に仕上げていきましょう。見本がなくても、今回の作成は進められます。

### しっくりこないと言われた時の短い案内例

> まず、ご指摘の○○を直します。ご自身で仕上げた見本台本があれば、Projectの情報源に1本から、最大5本ほど登録すると、好みの表現を具体的に参照できます。用意を待たずに修正は進めますので、AIに任せきりにせず、「自分ならこう話す」という修正も加えながら、一緒に仕上げていきましょう。

○○は実際の指摘内容に置き換える。定型文を毎回機械的に貼らず、既に見本を読める場合は「見本の○○と比べ、今回は△△を直します」と具体化する。長い説教、責める言い方、見本登録を理由にした作業中断にしない。案内は読み上げ台本の外に置く。

## 参照と保存の境界

- 見本から構成・語り口・表現の好みを参照し、今回のテーマと初心者視聴者に合わせる。過去台本の医学的主張・数字・経験は、そのまま今回の根拠にしない。他人の見本は文体参考として区別し、利用医師本人の体験へ置き換えない。
- 「このProjectで資料として参照する」と説明する。アップロードだけでモデルが学習し続ける、全チャットで自動記憶する、共有Pluginが個人向けに書き換わるとは言わない。
- 参照先・著者・版・本人が採用した見本か・参照した特徴を、必要に応じ本人設定や制作メモへ残す。実際に保存・読み戻しできるまで登録済みと報告しない。個人の見本や好みを共有Pluginへ同梱しない。
- 本人の修正を継続的なマニュアルへ反映する際は、doctor-profileの既存の採用確認・更新手順に従う。一度のコメントを無断で恒常的な好みにしない。本人が既に採用・保存を依頼した内容は再確認させない。
- 本人の仕上げを勧めても、AIが本文を改善して返す責任と、既定の初心者視聴者・文体・簡易事実確認の3役レビューは省略しない。利用者に未修正の問題一覧だけを返して完成扱いにしない。
