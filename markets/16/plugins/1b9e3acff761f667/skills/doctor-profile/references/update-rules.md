# 修正から本人マニュアルへ

修正後の2つの質問に答えて見本・独自スキルを登録する標準フローでは、[見本と独自スキルを育てる手順](personal-growth.md)を使う。以下の詳細分析は旧GPTの差分・モデリング更新を指定された場合に使う。標準フローでは既存マニュアルがなくても始め、本人が提示済みの修正ルールの登録を選んだ後に同じ採否を再確認しない。

原本10・12の「提案→本人の採用確認→マニュアル全文更新」を基本にする。既に採用内容が明示されている場合は再確認しない。「差分を分析してスキルへ反映して」等、反映まで明示依頼された場合は、観察が確実な範囲の分類・更新・保存を進め、固定の確認文だけを理由に停止しない。更新依頼を、推測した変更意図や全提案への承認と扱わない。迷う意図は仮説として分離し、確実な作業を先に完了する。

## 全文差分を分類する

1. Before・After・現行マニュアル・付随メモを読み、版と前後を特定する。変更なしの範囲も照合し、追加・削除・置換を段落単位、その中の語句・語尾・句読点まで記録する。目立つ追加だけで済ませない。
2. 各変更へID、両版の位置と原文、観察事実、目的・視聴効果の仮説を付ける。削除された文の内容が別の位置に残っていないか全文を確認する。変更なしは積極的な採用確認とはみなさない。
3. 下表で分類し、採用・限定採用・保留・非採用と理由、反映先を記す。一つの変更に個人の実話と汎用の編集原則が含まれる場合は分割する。

| 分類・変化 | 判断と保存先 |
| --- | --- |
| 本人専用 | 本人の実体験・具体的な感情の発言・固有の口癖・オファー・プロフィールは本人専用に保存する。「今後必ず」等の明示は指定範囲で継続方針へ。単発の表現変更は適用条件を付け、恒常的な好みは仮説と区別する |
| 汎用化できる手順 | 別テーマでも成立する書き方・編集手順は判断条件と例外つきで再現ルールにする。受講生の通常の独自スキル更新では、一般化できるルールもその本人のProjectだけへ保存する。共有プラグインの所有者が共有側の更新を明示した場合だけ共通スキルへ反映する。氏名、逐語の個人台本、体験、特典名、配布先は移さない |
| 案件限定 | 今回の構成、削除、順番、オファー選択等は案件メモへ。今回の自己訂正ブロック削除から「今後は過去発言を訂正しない」としない。救急案内の一部削除から「緊急行動を省く」としない |
| 医学精査・誤字等の非採用 | 主張の強さ、因果、対象条件、禁忌・緊急度が変わる箇所は文体と切り離して根拠確認へ。括弧の不整合や誤字は作風へ学習させない。修正権限がなければ指摘に留める |

一つの原稿の語尾・表現から意図を断定しない。複数の成功原稿で同じ特徴があれば、根拠例を添えて更新候補にする。誤った経歴や経験は本人事実として訂正し、原稿への反映は依頼範囲で行う。本人が書いた具体的な感情は保護するが、経験を他の医師へ移したり、医学的主張の正しさの証拠にしたりしない。

共有プラグインの所有者が「完全に個人に属する部分以外は汎用へ」と指定した場合は、その共有範囲を優先する。個人固有の内容を切り離した再現ルールを共通基準へ反映し、本人専用スキルはその共通基準を参照する。一方に汎用ルールを残して本人の暫定的な好みと呼び、もう一方で共通の採用ルールと呼ぶ不整合を作らない。受講生の「独自スキルに登録して」「両方はい」は共有側の更新許可ではない。今回以前の個人設定まで自動で共有しない。

動画台本の引用書式をマニュアルへ取り込むときは、[本文引用の統一書式](../../source-script/references/script-output.md#本文引用の統一書式) の `（引用文献挿入：1）` を既定にする。過去の見本・原本の番号だけの表記を、新たな好みの指定がないまま現行書式として再学習しない。

## 更新・保存・読み戻し

差分更新は原本10の分析4部を使い、確認が必要な場合だけSKILL.mdの固定文言で採否を尋ねる。モデリング更新では原本12の構成・リズム・フック・CTA等のギャップ分析を行う。元台本は依頼なく改稿しない。

本人用、汎用、案件限定の成果物と差分記録を別々に保存する。本人用と汎用の両方を依頼された場合は、一方だけ更新して完了としない。共有側には匿名化した判断手順を置き、個人の原文差分は本人専用に保持する。前版、版・日付・理由・根拠資料、採否と未確認事項を残し、採用後は変更部分だけでなく更新版全文を返す。

完成本文と学びメモ・候補一覧・訂正位置・文字数が食い違う場合は、現在の本文に照らして再確認する。未更新の記録は「旧版・要更新」と明示し、AI生成の「一致」「対応済み」を検証の代わりにしない。依頼範囲内で同期し、範囲外の資料まで勝手に改稿しない。

保存先から本人・版・変更内容を読み戻す。ファイル生成と、本人専用Project等への登録・共有スキルへの反映完了を区別する。不採用・保留を完成版へ紛れ込ませない。
