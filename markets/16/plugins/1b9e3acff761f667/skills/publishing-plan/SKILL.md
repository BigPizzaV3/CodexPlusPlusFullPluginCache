# 出版リサーチ・企画書

音声・動画ファイルの発話が未取得なら、[添付音声の自動読み取り](../voice-script/references/audio-runtime.md)で `ingest_audio.py` を実行する。必要な処理環境の準備も行い、文字起こしの提出を最初から求めない。取得後はこのSkillの依頼を続け、動画台本の3段階フローへ自動的に切り替えない。

## 今回進める作業

- テーマ選び・市場調査・類書比較の依頼は、以下の「入力と分析順序」から進める。
- 「提出用の企画書へ仕上げて」「出版社に見せる企画書を作って」は、[提出用企画書の作り方](references/proposal-workflow.md) を読む。市場調査後の企画を、企画書2ページと送付状1ページにまとめる。
- 同じ案件の棚比較・採用案・著者情報が読める場合は引き継ぎ、最初から聞き直さない。企画書の一部修正だけならその部分と関連箇所を直し、市場調査全体をやり直さない。
- 企画未定の新規依頼では市場棚の比較を先に行い、採用する方向を決めてから企画書に進む。提供された企画をそのまま整える依頼では、調査済み範囲を確認し、未調査の市場性は仮説として残す。決まった方向を無断で別企画へ変更しない。

## 原本と参照

【SG】出版リサーチGPTの提供済み指示全文と登録Knowledge4件を移行したSkill。開始時に必ず [原本09](references/original-09.txt) と [共通ルール](references/common.md) を読む。原本09の分析順序、棚の評価、競合調査と最終出力を既定動作とし、利用者の明示した変更を優先する。

提出用企画書モードは、追加選択されたGem「ベストセラー出版企画書クリエイター」の手順を統合したもの。原本09の市場調査を置き換えず、企画を編集者へ伝える工程として使う。追加Gemの教材全文・見本企画書・個人連絡先・外部テンプレートは同梱せず、同梱の [空欄テンプレート](assets/proposal-template.md) を使う。

作業に合わせて以下を読む。4件とも受領原文を変更せず保持している。

- 棚・企画を評価する前に [出版企画評価ルール](references/publishing-evaluation-framework.md) を読む。読者の悩み→解決→変化、7要素、3つの差別化、3企画類型を使用する。
- 競合本を調査・比較するときは [売れ筋本データベース設計](references/publishing-book-database.md) と [出版リサーチ分析例](references/publishing-analysis-examples.md) を読む。前者は1冊1レコードの項目、後者は分析の書き方の例。
- 企画とタイトルを出す前に [売れるタイトル構造パターン](references/publishing-title-patterns.md) を読む。数字・習慣・専門家・最短・不安解消・人生改善を候補として比較する。根拠なしの効果や危険で魅力を作らない。
- 最終整理は [出力・照合票](references/templates.md) に従う。医学的主張を扱うときは [根拠の扱い](references/evidence.md)、他工程からの引継ぎ・再開時は [制作メモ](references/production.md) も読む。

Knowledge内の『運動脳』『7つの習慣』の例、テーマの強弱、タイトル例は方法論の参考であり、**今回の時点で実際に調査済みの市場データや確認済みの医学的効果ではない**。事実として使う場合は現在の根拠を調べる。

## 入力と分析順序

本人設定・提供資料から著者名、職業、専門性、実績、発信、書きたいテーマ、読者の変化、一次情報、似た著者を拾う。読める経歴を繰り返し聞かない。資料例や歌島氏の実績を別の著者へ移さない。

**著者の強み分析や企画提案より先に市場棚を比較する。** 詳細な著者情報が不足しても、入力から可能な最低限の棚比較は先に行う。テーマも専門も特定できないときは不足を確認し、無関係な棚で埋めない。

原本のStep0〜4を守る。

1. 市場棚3〜6個を一次比較する。読者母数、悩みの深さ・継続期間、一過性か継続需要か、定番優位、新規参入、単著かムック・シリーズか、市場の拡大、社会的追い風を確認する。有望、避けたい、相性はよいが弱い棚を区別する。
2. 著者の専門性、肩書、発信力、読者との距離、一次情報、信頼性、語れるテーマ、人物像を、その強みが生きる棚との関係で分析する。
3. 強い棚を優先し、出版ジャンル3〜5個を出す。市場が弱い棚を相性だけで上位にしない。
4. 各候補を「市場棚の強さ／著者との相性／新規企画の入りやすさ／差別化／継続販売」の5軸で点数またはA〜C評価し、第一・第二・却下候補を示す。支持根拠と反証を両方探し、仮説が崩れれば候補を変える。
5. 優先棚から各ジャンル最低3冊の売れ筋候補を調査する。1冊のヒットと棚全体の強さを区別し、有名著者・定番・シリーズ優位なのか新規単著が入りやすいのかを検討する。必要数が確認できない場合は不足を明記し、架空書誌で埋めない。

女性医療の著者では、原本の指定する妊娠・出産、産後ケア、更年期、プレ更年期、女性ホルモン不調、美容と健康の接点、家族向け支援本を比較に入れる。原本の棚への仮説を結論として固定せず、対象人口・需要期間・定番優位などを実際に確かめる。

## 調査と事実の扱い

- 書名・著者・出版社・発売日・Amazon URL等は実際の書誌・出版社ページ・販売ページで確認する。市場統計・対象人口・増刷は公式情報を優先する。URLやレビュー数を作らない。
- ランキング・レビュー数・SNS話題等は確認した時点と出典を残す。数値が取れなければ「未確認」。書誌だけの確認を読了とせず、目次や試し読みなど確認範囲を示す。
- 原本の「事実として扱うもの」は**実際に確認したときのみ**事実欄へ置く。売れ筋度、棚の勢い、新規参入余地、編集者に通りやすいかは推定として根拠とともに書く。不明の販売部数をランキングから確定しない。
- 検索できないときは提供資料の事実と仮説を区別し、市場判定を暫定と明示する。未調査の競合比較を済ませたように企画を確定しない。調査可能な環境へ渡すため、調べる棚・項目と暫定案まで作る。
- 各本に対象読者、読む前A→読後B、売れていると考える理由、著者が勝てる点・弱い点・差別化点、そもそもその棚を選ぶべきかを付ける。根拠と編集者としての解釈を混ぜない。

## 最終出力と連携

市場調査の成果物では、原本の最終9項目を順に返す。冒頭に市場棚の結論（有望、避けたい、相性はよいが弱い、市場は強いが相性が弱い）、判定理由、第一・第二・却下候補を置く。

企画はど真ん中、差別化、ブルーオーシャン、却下の4類型を示す。追加質問は必要な場合だけ最後に3つ以内。単なる本の紹介や著者の称賛で終えない。企画書・章立てまで依頼された場合は、棚比較と企画選定を踏まえて [提出用企画書モード](references/proposal-workflow.md) につなぐ。市場調査だけの依頼に目次作成を必須にしない。企画書の最終稿には9項目の長い調査報告を貼り込まず、調査記録と未確認事項を別紙に分ける。

制作メモには、本人設定の版、調査日、棚評価と反証、実在を確認した競合、採用・却下案、仮説と未確認事項を残す。出版社への送信、応募、公開は別途の明示依頼に基づく。
