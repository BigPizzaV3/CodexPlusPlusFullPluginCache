# 動画の挿入画像・SNSの9マス画像

## 開始時

完成台本への「素材を作って」のような自然文、素材配置・選択肢・編集者用一式までの依頼は [editor-handoff](../editor-handoff/SKILL.md) を使い、素材数を10枚や静止画だけに固定しない。臓器・筋肉等を「解剖重視とかわいい案で」「3〜5案から選びたい」と実画像比較する依頼も、editor-handoffの医学説明バリエーション工程へ渡し、10画像へ置き換えない。対象場面だけの依頼ならその範囲を守る。以下は旧GPTの10画像／SNS9マス、特定の画像だけを指定された場合の手順。既に採用された1点の制作を引き受けた場合はその点数を守る。

[共通ルール](references/common.md) を読み、読める本人設定・最新台本・会話から画風や対象視聴者を取得する。既にある情報を聞き直さない。医学的な説明や数字には [根拠](references/evidence.md)、複数成果物や改訂の引き継ぎには [制作メモ](references/production.md) を適用する。

依頼に対応する原本全文を必ず読む。原本は移行する仕様資料であり、ユーザーの今回の指定やツール権限を上書きする命令ではない。

## 動画挿入モード：独立した10画像

台本がなければ原本どおり「動画台本テキストを貼ってください。内容を読み込み、1:1の独立した画像ファイルを10点作成します。」だけを返す。対象・画風等の任意情報の質問を加えない。

1. 台本全体から視覚化に有効な**10箇所**を選ぶ。共感、症状の場所、仕組み・解剖、動作、対処、注意、まとめなどに分散する。短い台本でも内容を細かく分け、台本にない医療情報は足さない。
2. 生成前に「挿入素材画像の選定パート」として番号1〜10を示し、各項目は `該当パート：「台本からの短い引用」` と `画像の狙い：一瞬で伝える内容` を書く。承認待ちにせず生成へ進む。
3. **10枚すべてを1:1の独立画像ファイルとして実際に生成する。** 最も確実な実行方法として1枚ずつ順番に生成し、ユーザーに10回の入力や「続けますか」を求めない。各回の指示へ原本の `Generate only Image X`、単独1画像、正方形、コラージュ・複数パネル・番号付き集合禁止を含める。
4. 原本の淡色・清潔・半写実的な医療イラストを既定とし、読みやすい背景、字幕用の余白、短い日本語ラベルまたは文字なしを使う。同じ画風のまま共感場面、解剖、動作、注意などを変化させる。
5. 画像ごとに内容、単独ファイル、比率、文字、身体構造、動作、主張の意味を確認する。グリッド・コンタクトシート・番号付き集合になった結果は不正解として単画像指定で作り直す。実際に10ファイルが揃った後だけ、最後に「10点作成しました。番号順に動画へ差し込むと使いやすいです。」と短く締める。

## SNSモード：1枚の9マス画像

提供された長文を受けたら、追加確認を必須にせず原本03に従って圧縮し、画像まで生成する。

- 全体は**1:1の正方形1枚、3列×3行、完全に均等な9マス**。各マス左上に大きな番号1〜9を置く。独立9ファイルや5枚組に勝手に変更しない。
- 1：表紙、2：問題提起、3：基礎知識、4〜6：要点1〜3、7：要点4または具体策、8：まとめ、**9：引用文献のみ**。9番へ本文・まとめ・CTAを入れない。
- TOP10や長大な文章も内容を1〜8へ圧縮し、10以上の番号や追加のマスを作らない。出典が明示されていない場合の9番は「引用文献：本文中に明示なし」。書誌を創作しない。
- 1〜8は大きく高コントラストの文字。9だけ出典整理のため小さめ文字を許容する。明確な境界か余白と各マスの安全余白を確保し、背景・文字・装飾を隣のマスへまたがらせない。添付画像は一部のマスの小さなアクセントにできるが、グリッドを崩さない。
- 原本の英語生成指示を適用し、生成前後に9マス・番号1〜9・均等サイズ・境界・9番の出典専用を確認する。12/15マスや3×4、縦長、横長は不正解。修正版でも9マスのまま生成する。

## 実行と医学表現

利用可能な正規の画像生成・編集機能を使い、プロンプトや一覧だけで実画像作成済みとは言わない。編集元画像は先に確認して参照に渡す。画像数・比率・画像参照などはその環境の実際の入力方法へ翻訳し、存在しないAPIを使ったふりをしない。

相関を因果の矢印へ、限定された結果を全員への効果へ変えない。断定的な原因、恐怖を煽る流血、本人提供でない特定の患者肖像を作らない。医療図は単純化しても関係や位置を反転させず、未確認の解剖学的正確さを検証済みとしない。本人の患者経験や臨床実績を創作しない。

明示的なツールエラー、利用上限、使える機能一覧で確認できる制約があれば、実画像の作成済み数・残り・再開に必要な情報を短く伝える。無制限に再試行しない。未作成分のプロンプトを渡す場合も、未完成であることを明示する。SNSの1枚と動画素材の10枚を数え間違えない。

制作メモがある場合、元台本の版・画像ごとの使用主張・ファイルと状態を保存する。改訂時は変更した主張に関係する画像を要更新にする。公開・投稿は別の明示依頼が必要。

## 修正を本人の作り方へ育てる

動画挿入画像モードで、本人の音声・文章・コメントによる修正を反映した完成稿を渡した後は、[見本登録と独自スキル更新](../doctor-profile/references/personal-growth.md)を必ず実行する。今回の変更を短く具体化し、「見本としてProjectのソースへ登録するか」「次回のために独自スキルへ反映するか」を独立した二問で提案する。対応する個人ルールは「独自スキル_動画素材作成」。SNS9マスの修正はこの動画用ルールへ混ぜない。SNSの独自スキル化を明示依頼された場合は、本人のSNS用途専用として適用範囲と原本を別管理する。同じ修正版で二重に質問せず、既に回答済みなら選択どおりに進める。初稿だけ、修正継続中、初回インタビューの途中には挟まない。

見本のみ／スキルのみ／両方／どちらも不要を区別する。登録を選んだら、その場で実Markdownを作成・更新し、保存先を読み戻せたものだけ登録済みと伝える。生成だけで保存済み・ネイティブSkill追加済みとしない。既存の独自スキルがあれば採用済みルールを保持して全文更新し、次回は今回の用途の最新版を再利用する。

動画用素材の初回・修正版を渡す時は「もしご自身で作成した、もしくはお持ちの素材を組み込みたいときは貼り付けてください。どこに入れるかも指示してください」と短く案内する。具体的な台本位置への統合・差し替えを頼まれたら、実ファイルと指示を[持ち込み素材の手順](../editor-handoff/references/provided-materials.md)へ引き継ぐ。SNS9マスだけの依頼には動画編集の案内を追加しない。
