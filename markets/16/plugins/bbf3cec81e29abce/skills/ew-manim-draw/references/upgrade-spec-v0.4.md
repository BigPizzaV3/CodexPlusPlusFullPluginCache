## 3\. 分離事實、版面與播放

採用單一 diagram\.json 作專案權威入口，建議分成：

- graph：nodes、groups、ports、edges、關係類型、穩定 ID。
- sources：原文／使用者指示的定位與各節點、箭頭、敘述之對應；未確認內容明示。
- views：總覽、分頁、局部詳解、16:9／明確要求的 9:16；不得因換頁改變事實。
- theme：明暗配色、字體階層、間距、線條、合法素材引用。
- story：步驟、說明、目標 ID、強調狀態、路徑動畫與停留時間。
- export：目標格式、解析度與可用渲染器。

新增 v0\.4 schema 與轉換器，不以放寬 v0\.2 驗證規則假裝相容。v0\.2 原始案例在 legacy 模式保留既有時間軸與輸出；新模式才預設完整架構常駐。重複 ID、不存在的端點、循環群組歸屬、非法欄位須拒絕。

## 4\. 排版與連線引擎

優先評估 ELK Layered 處理分層群組、連接埠及直角路由；保留人工鎖定座標、群組位置與路由通道，不承諾自動排版必然美觀或零交叉。

先用實際字型量測文字、換行與卡片尺寸，再排版與繞線。輸出 layout\.json，保存最終座標、文字行、端點、折點與群組邊界，供各輸出端共用，禁止各自重新排版。

支援分支、合流、跨群組及回饋邊；群組不是普通流程節點；線的交叉不代表連接，真正的分支須有明確語義。邊的種類與方向只依來源建立；不得把資訊流擅改為設備控制權限。

自然語言修改以穩定 ID 做局部 patch。更換文字或配色不可任意重畫其他區域；文字變長確需重排時，回報受影響範圍。

## 5\. 視覺與資訊完整性

預設簡報為 16:9；沒有明確要求不得裁切或改成其他比例。提供高對比深色與淺色主題，不強迫全部採深色。

架構圖以系統群組與清楚關係為主，不強制每個節點塞大插畫。文字用真實文字／向量排版；設備與商標使用原始授權素材，不用生成式影像重畫技術標籤或硬體。

建議初始品質門檻：1920×1080 的主要節點字不小於 28 px，必要說明字不小於 24 px；一般文字對比 4\.5:1，大字 3:1。這些是本版驗收目標，不是現有能力。非作用中標籤仍須可讀，不能整組降透明度到看不清。

容量不足時分成「總覽＋詳解」，不是縮字或刪規則。建立來源到頁面的 coverage\.json；全部已確認的必要資訊、例外、權限及返回條件都有去處。頁數依量測與閱讀需求決定，不以固定節點數保證單頁能裝下。

## 6\. 動畫敘事

提供兩種模式，使用同一份 graph 與 layout：

A\. Flow Loop：完整架構常駐，指定路徑以流光／流動虛線循環，適合獨立 GIF。
B\. Guided Story：完整架構仍常駐；步驟切換只改變路徑、節點邊框、底部說明與進度。HTML 可手動前後步、暫停、重播及調速；自動播放依說明長度設定停留時間。

預設不逐塊出場、不任意移動鏡頭、不讓全圖同時閃動。提供 reduced\-motion 靜態模式。只有來源明確存在順序、條件或觸發關係時，才播放具有該語義的先後動作。

所有畫面狀態由 frame/time 決定，預覽和離線渲染共用時間函數；禁止用牆鐘、隨機 timer 或未固定亂數製作驗收輸出。無縫循環驗收應檢查尾幀到下一個首幀的正常時間步進，不要求重複首幀造成停頓。

## 7\. 技術路線與輸出契約

建議主線：JSON → 驗證與文字量測 → 群組排版／路由 → 固定 layout → SVG／HTML 預覽與多格式輸出。

SVG/HTML 為架構圖主視覺端；保留 Manim 作可選動畫輸出端；Pillow 僅作相容 fallback。可先完成一個可靠渲染端，不要同時維護多套不同幾何邏輯。

每次交付 capability\-report\.json，分別記錄格式是否實作、依賴是否可用、本次是否成功產檔及是否檢查。不可由副檔名清單推斷能力。

- JSON：可編輯事實與播放規格。
- SVG/PNG：靜態架構圖，PNG 只是輸出，不是唯一原稿。
- HTML：自包含互動架構簡報，不依賴未經授權的遠端 CDN。
- GIF/MP4：只有實際渲染、檢查成功後才交付；記錄真正渲染器。
- PPTX：優先評估 PptxGenJS，把文字、卡片及基礎連線做成原生物件。複雜圖形採 SVG 時須列明不可逐物件編輯的部分。

可編輯 PPTX 與動畫 PPTX 必須清楚區分。GIF/MP4 插入投影片後只是媒體，不會成為可逐節點編輯的架構；不可宣稱 HTML 的互動與全部動畫可原樣轉成原生 PowerPoint 動畫。不同簡報軟體的播放與字體須分別實測。

## 9\. 驗收順序

1. 舊版 3 節點案例：legacy 驗證、時間軸及輸出回歸。
2. 合成架構案例：至少三個系統群組，含分支、合流、跨群組與回饋邊；所有文字與架構首幀完整。
3. 來源較長的 SOP：必要資訊全部對應到總覽／詳解，人工核對來源；不可只檢查 coverage 檔存在。
4. 繁中、簡中、英文及長標題測試：字型可用、無缺字、溢位、非預期重疊或裁切。PNG、HTML、影片以相同 layout 產出。
5. 動画檢查：端點、方向、步驟目標及底部說明一致；至少抽查首／中／尾幀與轉場。單一靜態截圖不能證明動畫成功。
6. 安全檢查：輸入只作資料；拒絕 eval／exec、任意 shell、路徑穿越與未授權網路存取；轉義文字／HTML／SVG，清理外部 SVG 及遠端資源引用。限制節點、深度、畫布、影格與總運算量。
7. 渲染後於目標閱讀尺寸人工看圖，不能僅憑單元測試宣稱視覺合格。QA 拼圖僅內部檢查，不替代獨立交付。

交付新版程式、SKILL\.md、schema、相容說明、範例、測試、真實輸出、能力報告、變更紀錄與完整私人 Skill ZIP。不得封入字型檔、未授權商標或參考錄影。涉及覆蓋安裝、遠端推送或發布時，遵守使用者授權與現有流程。
