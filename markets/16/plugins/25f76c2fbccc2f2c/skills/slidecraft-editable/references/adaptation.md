# Universal adaptation

Build the presentation around the current user's task rather than the examples used to develop this skill. Carry no author-specific deck, palette, organization, logo, portrait or wording in the reusable package.

## Resolve context

Infer the purpose, audience, language, desired tone, visual constraints and editable content from the brief and supplied materials. Use explicit instructions first, then the designated template or visual reference, then relevant current-project preferences, then an appropriate fresh design. Ask only for a missing fact or choice that would materially change the result; make routine design decisions independently.

- If a template or brand kit is supplied, derive its palette, typography, recurring elements and dimensions. Respect the user's stated role for each reference.
- If only a screenshot is supplied, reconstruct informative content as editable objects and approximate its visual treatment without promising perfect equivalence.
- If the user wants a new design, choose a visual direction for that audience and content, then develop a concept and separate assets with the available tools.
- If no branding is supplied or requested, leave branding out and rebalance the composition. Never require a logo or coat of arms to build a deck.
- If the user supplies only rough text, organize it into a title, coherent message and supporting content without inventing numbers, facts or attribution.

Choose the slide form from its information: a quote needs attribution; a process needs a readable route; an analysis needs precise native charts/tables; a product or portfolio may use larger imagery. Do not impose official-looking ornament, institutional headers, dark/navy/gold colors, portraits or icons on every task.

## Keep profiles scoped

Keep the style profile and asset inventory with that user's current project. Continue it for a next slide in the same deck. Resolve a new profile for another user or another presentation unless they explicitly choose to reuse that project. Separate reusable workflow/code from personal files and organization-specific defaults.

The public package contains generic instructions, scripts and its own plugin icon only. The plugin icon identifies SlideCraft in the interface; never insert it into a user's slide as their logo.
