# Site Recon and Brief

Use before designing a 3D redesign or building from an existing site. Also use when a prompt needs to preserve a current brand, information architecture, content, indexed paths, or project claims.

## Inputs

A reference URL, repository or files, approved brand assets, page list, and known facts. Work only with sources the user supplied or tools the user authorized.

## Process

1. Inspect the home page and representative pages, navigation, routes, mobile states, content, metadata, contact paths, forms, and legal pages. Use browser or repository tools if available. Record which pages and states were actually inspected.
2. Build a fact inventory with source and confidence for names, services, products, client relationships, prices, dates, statistics, testimonials, and claims. Separate verified facts, user-provided facts, placeholders, and questions.
3. Preserve useful page intent, working links, brand identity, and indexable routes where possible. If routes change, identify redirect needs instead of silently dropping them.
4. Find external project URLs in actual links, supplied records, or public application data. Never infer a domain from an organization name. Respect access controls and upstream terms; do not bypass logins or scrape protected content.
5. Note assets and rights: supplied/approved marks and photography may be reused as authorized; third-party material needs permission or a suitable license. Do not invent approval.
6. Produce a route inventory and concise brief: audience, purpose, required pages, verified content, brand constraints, project facts, available assets, unknowns, and technical constraints.

## Output

For each route, state the page purpose, source facts to preserve, proposed scene opportunity, essential semantic content, and any missing material. Clearly mark inaccessible pages and unverified claims. Do not treat an assistant-generated prompt from the source conversation as verified business data for a different project.
