# Objections and concessions

## Objection process

1. Acknowledge the concern without conceding.
2. If unclear, ask a short neutral question.
3. Classify it as price/budget, value, scope, timing, risk, authority/approval, competition, priority, or another stated concern.
4. Respond only with relevant facts the user supplied or that have been verified from current sources where needed.
5. If useful, offer a conditional trade and confirm whether the concern is resolved.

Possible prompts include: “Which part is the main concern?”, “What would need to change for this to work?”, “Who else needs to approve this?”, and “Is the issue mainly price, scope, timing, or risk?” Tailor, don't interrogate.

## Concession tracking

Record term, current position, possible change, requested return (if any), priority as stated by the user or `UNKNOWN`, and status (`NOT_OFFERED`, `OFFERED`, `ACCEPTED`, `REJECTED`, `WITHDRAWN`). Do not assume a concession was accepted. Warn if a suggested trade gives up a user-identified must-have for a lower-priority return; let the user decide.

Avoid unnecessary concessions before the objection is understood. A possible trade is not a recommendation or commitment. Do not teach ways to bypass another person's informed choice.
