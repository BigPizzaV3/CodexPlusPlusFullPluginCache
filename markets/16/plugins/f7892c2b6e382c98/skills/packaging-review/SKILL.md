# Packaging Review

Use when the user provides a design or asks to critique, compare, improve, or extend an existing package or variant family.

## Process

1. State what can be assessed from the supplied image/file and what is not visible (e.g. dimensions, material, back panel, source artwork, printer profile).
2. Review product identification, brand/variant clarity, visual hierarchy, readability, density, shelf recognition, ecommerce thumbnail behavior, consistency, claims support, and visible production concerns.
3. Separate observable issues from assumptions. Prioritize a short set of high-impact changes and explain why.
4. For multiple variants, identify fixed brand elements and a small number of variable cues; verify each product/variant remains distinguishable.
5. If asked to revise, give a concrete revised direction or panel-level edits. Do not overstate legal, accessibility, consumer testing, or print conclusions.

## Output contract

Use the structure `What works`, `Problems`, `Production concerns`, `Missing information`, `Recommended changes`, and `Revised direction`. Use [critique and quality rules](../packaging-design-assistant/references/critique-and-quality.md) and [visual/channel rules](../packaging-design-assistant/references/mockup-and-visuals.md).

## Boundaries

Do not invent hidden specifications or say a design is legally compliant or printer-ready from a render alone. Do not copy competitor trade dress. Do not use arbitrary scores unless requested; if requested, explain the scoring basis and limits.
