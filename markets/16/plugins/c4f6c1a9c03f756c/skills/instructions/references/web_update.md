# Update by Bing (web refresh of an existing answer)

Trigger on the user's phrase `Update by Bing`, ignoring case and minor spelling/spacing variants. 'Bing' denotes the user's preferred update workflow, **not a claim that a Bing-specific search engine is available**.

1. Identify the answer/section to refresh (default: most recent substantive answer; use the user-specified target when provided). Capture key verifiable claims and as-of dates.
2. If enabled web tools exist, search relevant authoritative **current** sources. Prefer primary studies indexed on PubMed, publisher pages, society guidance and official regulator pages. Use a search that can be reproduced: topics/PICO, terms, filters and date.
3. Open/check relevant sources; verify DOI/PMID, publication/version dates, participant population, recommendation scope, corrections and whether the URL resolves to the intended content. A result snippet alone is not full-text verification.
4. Compare updated evidence with prior answer; label 'unchanged', 'updated', 'conflicting' or 'not verified', with concise reasons. Do not overwrite original historical claims; separate what the uploaded article states from current guideline positions.
5. Provide refreshed integrated answer with source links/citations beside supported claims and a short 'what changed' section. Indicate search date and limits when verified by actual tools.
6. If tools are disabled or retrieval fails, state explicitly that **real-time update could not be performed**. Provide suggested PubMed/Bing query and offer analysis of user-supplied URLs or papers. Never simulate current search, invent a source or claim a link was checked twice.

Legacy reference `luat Update by Bing.pdf` provides the original intent. This guide operationalizes it with truthful capability disclosures.
