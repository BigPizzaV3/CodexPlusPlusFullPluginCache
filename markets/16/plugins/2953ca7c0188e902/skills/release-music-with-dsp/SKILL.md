# Release Engine

> A release plan that works backward from drop day.
> *Release desk · Release & DSP · about 25 minutes*

## When to use

- A release date exists or needs to be chosen.
- The artist wants a checklist instead of guessing.
- A date feels too close and needs a reality check.

## Ask first

Read the artist profile first (`artist-profile.md`, or the profile pasted in chat) and only ask for what is missing. Ask in one short batch.

- Release date (or target window) and today's date.
- Release type and number of tracks.
- Which assets exist: master, artwork, metadata, video, lyrics.
- Budget and hours per week available.
- Distributor and whether editorial pitching is planned.

## Workflow

1. Count back from release day using the offsets below, adjusting for assets already finished.
2. Flag timeline risks: distributor upload later than about two weeks before release, or an editorial pitch inside seven days, is at risk. Four weeks for upload and three weeks for pitching is the comfortable target.
3. Attach each milestone to the skill that does it.
4. Add a weekly rhythm for the final three weeks (teasers, outreach, community).
5. Write the day-of checklist and the first-30-days plan (follow-ups, playlist pitching, analytics review, thank-yous).
6. State clearly that nothing is scheduled or submitted by this plan.

## Deliverables

- Dated milestone list.
- Risk flags.
- Release-day and first-30-days checklists.

Save each deliverable as a Markdown file if file tools are available; otherwise present it in the conversation.

## Output template

Offsets from release day (T):
- T minus 8 weeks: asset lock (final master, artwork, video plan)
- T minus 6 weeks: metadata, credits, splits signed
- T minus 4 weeks: deliver to distributor (no later than T minus 2 weeks)
- T minus 3 weeks: submit editorial pitch in the DSP's artist tools (no later than T minus 7 days); pre-save link live; teasers begin
- T minus 3 to 1 weeks: outreach to press, curators, and community
- T minus 1 week: confirm registrations are in place (PRO, MLC, SoundExchange)
- T: release day
- T plus 1 to 30 days: follow-ups, playlist pitching, analytics review, content from the release

## Quality checks (run before handing over)

- [ ] Every milestone has a date.
- [ ] Risk flags are shown wherever the date is inside the minimum window.
- [ ] The plan never claims anything is scheduled.
- [ ] Milestones match the assets that actually exist.

## Guardrails

- Do not promise editorial placement or playlist adds.
- Do not schedule spend the artist did not approve.
- Never invent facts, numbers, credits, quotes, placements, or contacts. If the artist has not supplied something, ask or mark it `[CONFIRM]`.
- Label every estimate as an ESTIMATE and show the formula or assumption behind it.
- Never collect, solicit, or process Restricted Data: payment card data (PCI DSS), protected health information (PHI), government identifiers (Social Security numbers, ITINs, EIN digits, passport or driver's license numbers), or access credentials and authentication secrets (passwords, API keys, MFA/OTP codes, bank logins). The artist enters sensitive information directly on official sites.
- Gather only the minimum task-specific input required; never request full conversation history, raw chat transcripts, or precise user location data (street addresses or GPS coordinates).
- Do not display subscription plans, promote paid upgrades, sell digital goods/credits, or embed checkout flows.
- Draft first. Never claim anything was filed, registered, sent, posted, uploaded, or paid. The artist takes every outside action.

## Hand-offs

- `distribution-readiness`: verify the delivery
- `create-content-calendar`: plan the teasers
- `pr-campaign`: press outreach
- `playlist-outreach`: curator pitches
- `register-tracks-with-pro`: registrations

## Start with

> My single comes out on this date. Build the plan counting back from it.
