# 無料検索Skillから書類作成へ

本人が書類作成を希望した時だけ使う。同じ会話の内容を次の担当Skill・プラグインへ渡し、会社条件を聞き直さない。第1回専用版は `shinmono-application`、他制度は利用可能で対象範囲の合う申請書作成機能へ。未導入の機能を使えたと説明しない。

同じ会話では、既知の最小プロフィール、目的・概算予算・時期、選んだ正式名称と年度／枠／回、公式の根拠URLと確認日時、確定／概算／不明、未解決の質問を引き継ぐ。資料全文・不要な連絡先は入れない。公式情報の調査で解けることと、本人の回答が必要なことを分ける。

受け手がJSONを必要とする場合はAIが [共通形式](application-handoff.schema.json) に従って作る。利用者にJSONの編集・貼付けを求めない。識別子は `schema: subsidy-application-handoff`、`schema_version: 1`、`origin: subsidy-search`。`created_at` は引継ぎ作成日時であり、公式資料の確認日時を上書きしない。`requires_current_official_recheck` は必ず true。

- `profile` と `project` は分かっている項目だけ。不明は省略する。
- `selected_candidate` は確認した正式な制度・年度・枠・回と受付状態・根拠・抽出条件を保持する。未選択なら null。別回の根拠を混ぜない。検索で除外した終了回を復活させない。
- `sources` は確認済みの公開資料だけ。URLを推測せず、確認日時・公募の識別を保持する。資料名や箇所が不明なら unknown。
- `known_facts` は confirmed（確定）／estimate（概算）／unknown（不明）を区別し、unknown の value は null。未回答を0やfalseに置き換えない。
- `open_questions` は未確認点だけ。回答済みの質問を入れない。

専用版が受け付ける提出準備と、現在申請を送信できることを混同しない。開始前の準備は本人の依頼に従って進められるが、受付中の検索候補として表示しない。

別会話での再開・持ち帰りを本人が希望した時は、本人のプロジェクト規則に従い、本人用 outputs 内などの許可された場所へ新規保存する。共有領域、Skill本体、公開物に保存しない。保存できない環境では会話内の引継ぎメモで渡す。受け手は本人が指定・提供した情報だけを読み、別会話・別利用者の資料を自動探索しない。
