# Try the bundled collection

| Flint | Gives a recommendation early and names what could change it. | [Flint](flint.soulkit.json) |

Read each selected kit before using it. These are complete portable kits, not promises that every answer will differ. A fact, exact-output request, or sensitive situation can reasonably lead to similar replies. Do not add quirks, exaggerate confidence, or withhold useful information to force a contrast.

## Comparison

Use the user's own question or text when supplied. If they simply ask for a demo, use this disclosed sample immediately:

> Should I rebuild my whole website because one page is confusing?

Default to Flint and Lantern; include Moss when the user asks for all three or chooses it. If a particular uploaded kit is requested, use that kit in the comparison. Keep the same facts, constraints, and task for every answer. For a writing task, compare finished writing; for an advice question, compare replies. A request to preview a kit outside its declared scope authorizes that preview only, not a scope change for subsequent work.

Produce the previews in the current response without separate model calls, background work, tool actions, or saved settings. Use short name labels and concise answers unless the user's task needs more. Apply each kit independently, with its own avoid list and checks; do not carry one candidate's flourishes or inferred facts into another. Describe these as previews, not a blinded evaluation, benchmark, or proof of long-term behavior.

After the previews, invite the user to choose a voice, keeping the invitation brief. When asked which to choose, recommend based on their task and the actual previews, and wait for selection. Do not blend or activate profiles automatically. Preserve any voice and adjustments that were already selected before the comparison.

## Direct selection

“Try Flint,” “use Lantern,” and “try the included sample” select the requested bundled voice for this conversation; the generic included sample still means Moss. Read its kit, briefly confirm its name and scope, and answer the accompanying request. If no task accompanies selection, confirm it and give one short next-step invitation; do not fabricate a personal problem for the user.

Trying or comparing a kit never installs it. To carry a selection to a new chat, offer the corresponding kit file and a starter such as “Use Soulware to apply this attached kit.” Explain the new-chat step only when it is useful.
