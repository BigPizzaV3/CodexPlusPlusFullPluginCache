# 月次レポートの構成・計測票・読みやすさの基準

数字を見せるだけで終わらせず、初めて読む人が「今月どうだったか」「なぜそう考えるか」「次に何をするか」を理解し、次に撮る動画、直す箇所、翌月に確認する数字を決められるレポートにする。本文で伝える結論と、確かめたい人のための詳しい根拠を分ける。

目次：構成と分量／初めて読む人への説明／外部の参考チャンネルと具体的動画／入力要約と全体像／動画とエンゲージメント／次の企画と自他の参考動画／検索ワード／外に開く・内につなぐ／再生リストとトップ／毎月の計測票／次月へ渡すメモ／図表・リンク・引用／サムネイルと動画の埋め込み／形式・文字・画面確認。

## 構成と分量

情報の充実度は、説明の量ではなく判断に必要な根拠と具体案がそろっているかで評価する。初めに「今月の結論と次にすること」、前半の主要章に「どの外部チャンネルのどの動画を参考にするか」、その後に詳しい分析と次企画、最後に計測票・資料一覧を置く。ページ数や企画数を埋めるために同じ説明を繰り返さない。詳細PDFが15〜25ページ程度になることはあっても、その分量を本文の目標にしない。Webも長文をそのまま流し込まず、全内容を表示したまま、見出しと余白、比較表、個別カードで読む順番を分かりやすくする。

| 読む順序 | 含めるもの | 配置 |
| --- | --- | --- |
| 今月どうだったか | チャンネル、期間、目標進捗、大きな発見、優先行動を最大3つ | 冒頭 |
| 誰のどの動画を参考にするか | 外部候補の比較と優先順位、チャンネルと具体動画、根拠の数字、直接リンク、自分の次企画への応用 | 前半の主要章。結論と基本数値の直後 |
| なぜそう考えるか | 前期間比較、主力動画、新作と既存、視聴者の反応、入口と次の視聴 | 本文。数値ごとに意味を説明 |
| 次に何をするか | 次企画、自他の参考動画、検索語、内部誘導、再生リスト・トップの具体案 | 本文。根拠と行動を対にする |
| 来月どう確かめるか | 変更対象、見る数字、比較条件、確認時期 | 本文の終わり |
| 詳しく確かめたいとき | 主要指標の比較表、必要な入力範囲・計算条件、資料一覧 | Web末尾の常時表示の章、またはPDFの付録。読者の確認に必要なものを選ぶ |

## 初めて読む人への説明

本文は「分かったこと → どういう意味か → 次に何をするか」の順に書く。分析時の確認手順・内部の判断チェックリストを、そのまま読者向けの段落にしない。確認日や入力の内訳・定義は、読者の確認に必要な範囲を選び、末尾の「計算と出典」に一度だけ置く。日付の異なる値を比較するなど結論を変える場合だけ、該当箇所で短く補う。

末尾へ移すだけで読みやすくなったと判断しない。付録も必要な根拠と出典に絞り、不要な注意書きは削る。比較に用いた全動画ID・全行番号の羅列など内部の照合記録は作業記録に保持し、読者が根拠を確認するために必要な代表動画・比較条件・出典をレポートに載せる。詳しい全件情報を利用者が求めた場合は、その指定に従う。

「今回の重要な限界」「順位は成長順位ではない」「本編を通覧していない」「流入0とは断定しない」等を、各章・動画カードに繰り返さない。「参考にする順番」「タイトルの切り口を参考にする」「今回確認した7本からの流入」など、確認した事実の範囲に合う短い表現に置き換える。未確認を事実へ書き換えるのではなく、初めから言える範囲で表現する。それでも読者の判断が変わる条件は一文残す。

各章の冒頭に、何を決めるための章かを1〜2文で説明する。提案は「対象の動画・ページ／変更する場所／実際に変える内容」を具体化する。「回遊を強化」「つなぎ方を試す」「最初の3本へ」のような抽象的な見出しだけで説明したことにしない。

複数の案で共通する手順や確認時期は章の導入で一度説明し、カードには対象・案内先・理由・添える言葉など、案ごとの違いを残す。終了画面の3案すべてに同じ固定コメントの置き方や28日後の確認手順を繰り返す必要はない。個別の場所が異なる場合は、そのカードに明記する。

専門語は初出のすぐ近くで短い日本語に言い換える。例えば「クリック率（サムネイルが表示されたうち、視聴につながった割合）」「回遊（1本を見た後、同じチャンネルの別の動画も見ること）」。エンゲージビュー等は実行時の公式定義を確認し、何を数えるかに加えて、今回その数字を使う理由を説明する。用語集だけに説明を置かない。

EV・CTR・KPI等の略語を本文・カード・図の単独ラベルにしない。「クリック率」のような日本語を優先する。資料にある略語との対応が必要なら括弧に添える。％と％ポイント、視聴回数と視聴した人数など、読み違いやすい区別は該当箇所で補う。

重要な数値には「数字がどう変わったか／チャンネルにとって何を意味するか／だから何を試すか」を添える。例えば登録につながる割合が下がったなら、視聴が増えても登録は同じ割合では増えていないことを説明し、次に見る動画の案内を試す等の行動へつなぐ。データだけで理由を断定できない場合は、考えられる理由と試す変更を分ける。

本文は1つの図やカードで1つの問いに答える。数字を並べた直後に、読者が受け取るべき意味を1〜2文で書く。詳細な数式、長い一覧、判断に直結しない注意点を本文へ繰り返さない。ただし計測定義の変更や期間の不一致など、結論を変える制約は該当数値の近くに短く残し、説明の続きから詳細へ進めるようにする。

例えば「視聴の約69％を過去動画が支えている」のように数字を解釈する。良し悪しを判断する場合は、比較値と比較した動画数を同じカードに置く。今回の行動判断に使わない補助指標は冒頭へ詰めず末尾へ回す。具体的な外部参考動画、企画を選ぶ根拠、サムネイルや埋め込みまで削って内容を薄くしない。

長い分析原稿をそのままPDF化したり、同じ原稿をWebの箱に分割したりして済ませない。見出しを読者の疑問に変え、説明順序と文章を書き直す。表は比較する列が必要な場面に限り、企画の理由や行動案は短い文章やカードを使って読みやすくする。

## 外部の参考チャンネルと具体的動画

[関連動画と参考先](recommendations.md) の規則に従い、この章を前半の中心に置く。最初に短い候補比較を示し、次に候補ごとの詳しい推薦を書く。チャンネル名だけの一覧や、企画末尾の参考リンクだけで済ませない。

各候補で「チャンネルとして参考になる理由」と「今回この動画を選ぶ理由」を分け、チャンネルと動画それぞれへ直接リンクする。推薦のすぐ近くに、関連流入数・自チャンネル側の流入後の視聴時間、外部動画の公開再生数・公開日・尺、確認できた登録者数等を種類が分かるラベルで示す。未確認の数字を埋めない。

優先する順番と候補間の違いを説明し、「取り入れる具体的な箇所」「自分ならどう変えるか」「対応する次の動画企画」まで結び付ける。同じチャンネルで複数動画を確認できたら比較対象と確認範囲を示し、1本しか確認できなければその動画に限った推薦と書く。公開期間等が異なる動画を再生数だけで成長順位にしない。

## 入力要約と全体像

冒頭には対象チャンネル・28日間の期間と主な成果を示す。入力ファイル・シートに短い資料IDを付け、行数、取得範囲、欠損、計測定義、処理手順は末尾の資料一覧へまとめる。全体・長尺・Shorts・ライブは判別できる範囲で分ける。全行を集計して注目例を選び、巨大な全件表は本文に貼らない。

視聴、再生時間、登録増減、露出、CTR、平均視聴時間、主要流入を対応させる。前期間と日数が違う場合は元値と日数を示し、日平均で補える加算指標だけ補足する。前期間なしで成長や悪化を断定しない。

期間内公開の新作と既存動画、主力1本とそれ以外を分けて見る。新作の観測日数が違えば公平な初動比較ではない。生涯再生数は期間内の成果に混ぜない。

目標欄は、今回の目標、現在総数と確認日、期間純増、差分を出せるか、次月に見る数字を示す。現在総数が分からなければその項目は未確認とし、個別の目標値をスキルの共通値にしない。

## 動画とエンゲージメント

好成績、改善する価値がある動画、判断保留の新作を理由付きで示す。動画リンク、公開日、観測日数、主要指標、比較群の本数、読み取り、資料IDを対応させる。

エンゲージメントは高評価・コメント・共有・登録増加の件数と率を示す。母数の小さい高率動画に順位を引っ張られないよう、比較群と分母を見せる。反応と維持率の両方を見て、「どこで何を問いかけるか」「どの質問を次回に持ち越すか」「次を見る理由をどう伝えるか」を具体化する。曲線・コメント・動画を見ていなければ、その内容に関する説明は仮説にとどめる。

## 次の企画と自他の参考動画

本人の制作可能本数に合わせ、指定がなければ優先3本と予備2本を目安にする。根拠の弱い企画で数を埋めない。優先企画には次のカードを付ける。単に人気タイトルを並べず、自分の既存動画の成果、検索語、関連流入とつなぐ。

| 項目 | 書く内容 |
| --- | --- |
| 視聴者と問い | 誰が、どんな疑問を解決するために見るか |
| 仮タイトル・扱う語句 | 検索語を自然に含め、まだ確かめていない結論を約束しない |
| 今作る理由 | 元動画、語句、流入、登録・反応等の実測値と、解釈を分けて示す |
| 自チャンネルの参考動画 | 正確な動画名・クリックできるURL・期間指標・取り入れる箇所 |
| 他チャンネルの参考動画 | 正確な動画名・チャンネル名・URL・参考にする箇所。確認日と確認範囲は出典一覧へ |
| 内容と違い | 冒頭で答える問い、3〜5個の主題、既存動画との差、専門性による補足 |
| 入り口と次の1本 | 接点を作りたいテーマ、視聴後に勧める自動画とつなぐ理由 |
| 検証 | 公開後7日・28日等で見る指標、比較する動画群、続けるか見直すかの判断 |

自他の参考先を探しても適切なものを確認できなければ、その欄を未確認とし、代わりに何を調べれば候補が確定するかを短く書く。架空のチャンネル・タイトル・数値で埋めない。外部動画をタイトルしか確認していなければ、構成や話し方まで参考になると断定しない。実際の関連流入元であることと、参考にする価値があることは別に説明する。

撮影する1本の判断材料が別章に散らばらないよう、企画カードの中で理由・自分の参考動画・外部の参考動画・取り入れる点・次に案内する動画まで読める形にする。同じ動画の詳しい根拠は元のカードにまとめ、サムネイル付きの小カードとページ内リンクで結ぶ。

## 検索ワードの提案

語句を視聴者の問いごとにまとめ、元の検索語、期間流入、取得範囲、動画との接点を示す。上位語だけでなく、少量でも複数語に共通する具体的な悩みを拾う。検索語と流入先動画の組がなければ対応は企画上の提案とする。

提案には「核になる語／関連する問い・組み合わせ／根拠の種類／仮タイトル／つなぐ自動画／優先理由」を対応させる。すべてを横長の表へ詰めず、語句を選ぶ理由が読めるカードや短い表に分ける。根拠の種類は、実測検索流入、実測関連流入からの推定、公開調査、試す仮説など。市場全体の検索回数は確認できる専用データがある場合だけ載せ、地域・期間・取得元を示す。

## 外に開く・内につなぐ

関連流入を、自動画確認済み・他者動画確認済み・所有者未確認・明細未取得に分けて示す。取得範囲はグラフのラベルと末尾の集計条件で分かるようにし、同じ限界説明を繰り返さない。他チャンネルからの関連流入と、サイト等からの「外部」流入を混同しない。

内部への誘導は「起点の自動画／次の自動画／次を見る理由／案内する言葉／終了画面・固定コメント・概要欄等の配置案／確認する数字」を対応させる。1つの組合せごとのカード等を使い、長い文章を6列の表へ押し込まない。動画間の矢印を描くときは、観測された遷移か提案する接続かを図内で明示する。流入元だけ分かるデータを、特定の流入先と実線で結ばない。

見出しは「既存動画の最後に、次に見る1本を表示する」のように変える場所が分かるものにする。冒頭で「以下は、どの動画の終了画面に、どの動画へのリンクを置くかの提案です」と説明する。終了画面は「動画の最後に表示する、次の動画を開く枠」と初出で説明する。各カードは「変更する動画：正確な動画名とURL → 表示場所：終了画面 → 次に見てもらう動画：正確な動画名とURL」の順にする。固定コメント・概要欄の案は別の置き場所として示す。声かけ例は新しく撮る動画向けと明記し、公開済み動画へ設定だけでナレーションを追加できるように書かない。

直接の回遊率が測れない場合は、終了画面の要素クリック、自己動画からの関連流入、再生リスト内視聴等を代理指標として並べる。これらを足して単一の回遊率にしない。後日の再訪と同じセッション内の連続視聴も分ける。

## 再生リストとチャンネルトップ

可能なら現在の公開ページ・再生リストを確認してから変更案を出す。未確認なら現在の構成に問題があるとは断定せず、新しい配置の候補として提示する。

再生リストは「対象視聴者の問い／リスト名／最初の1本／次の順番／各動画の役割」を具体化する。入り口になる動画と、理解を深める動画を既存成果に照らして選ぶ。リストを作るだけで連続視聴が増えるとは約束しない。

最初に「同じ悩みの人に、順番に見てもらう動画のまとまり」と意味を説明する。「3本の新しい再生リストを作る」「既存リストの先頭を並べ替える」など、何を変える提案かを明記する。1本目から動画名・URL・役割・その順番にする理由を示す。既存の長いリストを残すのか、変更するのかも具体化する。チャンネルトップへの配置は、どのリストをどの欄で何番目に見せるかまで書く。

トップページは新規視聴者が見る順番を考え、最初に見せる動画、セクション名、配置順、根拠となるテーマ需要を提案する。公開画面の確認日は末尾の出典一覧へ記録する。トップページ経由の成果を直接測れる表がなければ、全体増加をトップ修正の効果と決めない。

## 毎月の計測票

各項目に「今回／前回／差／直接観測・代理・欠測／資料ID／次月の確認」を付ける。利用できない項目は0とせず欠測とし、取得できる表や画面を短く記す。名称・単位・分母・期間を次月も揃える。

初回など全項目に前回値がない場合は、表の前に一度説明し、前回・差の列を省いてよい。「未取得／算出しない」を全行に繰り返さない。入力一覧も同じファイルのシート情報を1行へまとめるなど、必要な情報を保って読みやすくする。

| 領域 | 基本項目 | 補助項目と注意 |
| --- | --- | --- |
| 目標 | 登録者総数・確認日、増加、減少、純増 | 現在総数がなければ目標差や期限を計算しない |
| 全体 | 視聴、エンゲージビュー、再生時間、露出、CTR | 計測定義・期間の相違を記録 |
| 新作と既存 | 投稿本数、群別の期間寄与、主力1本の比率 | 同じ公開後7日・28日があれば初動を比較 |
| 外からの関連流入 | 関連流入全体、他者動画確認済みの数と比率 | 所有者未確認・未取得、明細カバー率も記録 |
| 内部への誘導 | 自動画確認済み関連流入、終了画面の要素別表示・クリック・CTR | 代理指標。クリック先不明なら自動画行きとみなさない |
| 反応と登録 | 高評価、コメント、共有、登録増加と各1,000視聴あたり | 分母と計数対象を固定し、人数とは呼ばない |
| 再生リスト・再訪 | 取得可能な再生リスト指標、リピーター等 | 公式定義を確認し、セッション内回遊と分ける |
| 検索 | 検索流入、主要な語句群、群別寄与、明細カバー率 | 市場全体の検索量ではない |

翌月の作業表は「優先順／対象動画・ページ／変更内容／比較対象／確認指標／確認時期／続ける・見直す判断」にする。最優先は最大3つに絞り、提案と実際に変更したものを区別できる記録欄を付ける。過去のレポートがあるなら、前回提案が行われたかと結果を確認し、未実施を失敗と扱わない。

## 次月へ渡すメモ

レポートと一緒に `次月引継ぎ_期間終了日.md` を作る。期間終了日は入力の実際の終了日とする。月次比較を継続するための資料であり、AIが過去の会話や元ファイルをいつでも参照できると約束する代わりにしない。利用者には、次月も使うプロジェクトにレポートとメモを残すよう短く案内する。元データの削除は求めない。

メモには次の内容を含める。

| 項目 | 残す内容 |
| --- | --- |
| チャンネルの条件 | URL、対象視聴者、本人の目標、制作可能本数、現在の登録者総数と確認日。不明な値は作らない |
| 観測期間と資料 | 今回と前回の開始日・終了日、入力ファイル・シート・資料ID、フィルタ、取得範囲 |
| 主要指標の履歴 | 指標名・値・単位・分母・直接観測か代理か・期間・出典。実際に読めた過去の履歴に今回の行を追加する |
| 注目動画と参考先 | 自動画のID・タイトル・URL・主な成果、今回選んだ外部動画のURL・推薦理由・確認日 |
| 次に行うこと | 優先提案を最大3つ、変える動画・場所、変更内容、次回見る数字と確認時期 |
| 実際に行ったこと | 本人が報告した変更と結果を提案から区別する。記入欄は「実行日／変えた動画・箇所／実際にしたこと／気づいたこと」 |
| 未確認事項 | 比較や提案を変える不足資料、未確認の条件、次回取得する項目 |

前回メモを読めなければ履歴を復元したふりをせず、今回分から記録する。詳細比較には元データを優先する。次月にメモだけが読める場合は出典付き転記値として比較し、未読の元ファイルを再集計済みとしない。読めない過去資料の再提出を理由に今回のレポートを止めず、比較なしで進める。

未実施の提案を失敗として扱わない。前後の数字が変わっただけで変更の効果とは断定せず、公開本数・観測期間・流入構成等の違いも見る。ファイル生成が使えない場合はメモの内容をチャット末尾に示し、保存できた場合だけ保存済みと伝える。

## 図表・リンク・引用

図は判断に役立つものを選ぶ。全体の時系列、動画・テーマ別寄与、流入構成、登録への寄与などを必要に応じて使い、装飾のために増やさない。図中に期間、単位、分母、取得範囲、資料IDを表示する。既知の対応関係は表、正確な数値は通常の作図ツールで作成する。

動画名・参考文献・入力資料へのリンクは、Web・PDFのどちらでもクリック可能にする。長いURLを本文の狭い列に露出させず、動画名や資料IDをリンクにする。非公開資料のURLや業績値を外部検索に送らない。

主な発見に資料ID・シート・動画ID・行範囲等を対応させ、巻末に資料一覧を置く。Web根拠は対応する主張の近くにもリンクを置く。医学の主張を含む場合は査読済み一次論文を確認し、本文に対応番号、巻末に番号／Science短縮版の書誌情報／URL／研究要約／引用理由を載せる。YouTubeの指標定義や操作には公式資料を使い、無関係な医学論文を添えない。

## サムネイルと動画の埋め込み

自チャンネル・他チャンネルとも、モデリングとして紹介する各動画を、実際のサムネイル・動画名・チャンネル名・根拠の数字・参考箇所が対応するカードで見せる。Webではその場で見られるYouTube埋め込みを用意する。埋め込みの初期表示で実サムネイルが見えれば別画像を重複表示する必要はない。同じ動画が別の章にも出る場合は、サムネイル付きの小さなカードと元の動画カードへのページ内リンクでもよい。

確認済みの動画IDと対応するYouTubeの実サムネイルを使い、別動画の画像や生成画像で置き換えない。取得できない場合は画像の欠測を示し、正確な動画名と直接リンクを保つ。サムネイルの文字・色・構図を評価する前に実画像を確認する。画像を見ただけで動画の内容や視聴者の反応を断定しない。

通常動画の表示は16:9の可変幅とし、小さな画面では縦に並べる。埋め込みには動画名の識別できるタイトル、サムネイルには意味のある代替テキストを付け、キーボードでも再生操作とリンクを利用できるようにする。自動再生はしない。多数の動画による読み込み負荷は遅延読み込みや、実サムネイルを押すと同じ場所でプレーヤーになる表示で抑えてよい。その場合もサムネイル、数値、推薦理由は最初から見え、説明の展開操作を必要としない。

各動画には常時見える「YouTubeで見る」等の直接リンクを添え、埋め込みが制限される場合にも使えるようにする。プレーヤーを表示しただけで再生確認済みとは扱わない。実際に確認できた範囲を正確に伝える。参考時刻を示すなら確認済みの時刻だけを使い、見てほしい点と自分の動画への応用を近くに書く。

PDFや印刷表示では、再生枠を実サムネイルとクリックできる動画名に置き換える。Webの広い画面・狭い画面で、画像と動画名の一致、縦横比、読み込み、再生操作、代替リンクを確認し、サムネイルの重要部分や本文が切れないようにする。

## 形式・文字・画面確認

標準はダウンロードしてブラウザで開ける1つのHTMLファイル。指定があれば優先し、PDFも作成する。公開サイトの作成は標準作業に含めない。ファイル生成が使えない場合は全文をチャットに示し「暫定の文章版」と明記する。完成したHTMLや保存済みファイルと偽らず、コードだけを初心者へ渡して終了しない。

HTML作成時は [レポートひな形](../assets/report-template.html) と [ひな形の使い方](template-usage.md) を使う。仮文言や仮数値を残さず、確認した動画・根拠・入力範囲に合わせて埋める。個人情報や過去チャンネルの数値を共通ひな形へ書き戻さない。

Webも許容されており、PDFでは文字が小さくなる、横長の表が多い、詳細を読み分けにくい場合はWebへ切り替えてよい。PDFを依頼されたのに無断で納品形式を変更しない。変更可能な場合は、変えた理由を読みやすさの面から短く伝える。

Webは本文を18px程度、行間を1.7前後から調整し、スマートフォンでも日本語を無理なく読める幅と余白を取る。重要な本文を小さな補足文字へ逃がさない。詳しい数値・計算・制約も見出しを付け、全内容を常時表示する。折り畳み・タブ切替・「もっと見る」等で内容を隠す表示は、ユーザーが明示的に求めた場合だけ使う。目次のページ内リンクで目的の章へ移動できるようにし、横幅の狭い画面では表の列を減らす、カードへ組み替える等で詰込みを避ける。

PDFはPDFスキルに従い、埋め込み可能な読みやすい日本語フォントを用いる。本文11ポイント以上、表10ポイント以上を目安にし、行間と余白を確保する。日本語フォントが実際に適用・埋め込みされているかも確かめる。文字を縮小して表を収めず、表を分けるか詳細を付録へ移す。ページ番号と章が分かるヘッダー・フッター、必要に応じPDFのしおりを付ける。

どちらの形式でも、見出し、表、図、注記の位置と色を揃え、色だけに意味を持たせない。本文と背景の読みやすさ、改行、余白を先に整え、装飾は理解を助ける範囲にする。

重要な結論と優先行動には濃い赤や太字を控えめに使ってよい。段落全体や注意書きばかりを目立たせず、言葉でも何が重要か伝える。初心者が章の冒頭から目的を理解し、提案から対象・場所・変更内容を答えられるかを確認する。分かりにくさを注意書きの追加で解決しない。

Webは実際のブラウザで広い画面とスマートフォン相当の狭い画面を開き、冒頭から末尾まで文字、改行、表、リンクを確認する。操作せずに全内容が表示され、外部候補のチャンネル名・動画名・根拠の数字を前半で読めることも確かめる。PDFは全ページを画像へレンダリングし、文字化け、切れ、重なり、表の途中の不自然な改ページ、見出しだけのページ、過大な空白を目視確認する。縮小一覧だけで済ませず、文字や表を実際に読む大きさでも確認する。問題があれば直して該当箇所を再確認する。

初心者の読者として通読し、冒頭だけで「今月の変化」「理由」「次の行動」を自分の言葉で答えられるか、略語を調べるために読むのが止まらないか、各主要数値が行動につながるかを評価する。独立した読者評価が可能なら活用する。書き手の知識がないと読めない箇所は説明を直し、この確認を外見の確認で代用しない。

HTMLは `python3 scripts/validate_report.py report.html` で検査し、指摘を確認して修正する。スキルのディレクトリを基準にし、作成したHTMLのパスを引数にする。この検査は形式上の確認を補助するもので、数値の正しさ、外部候補の妥当性、画面の読みやすさ、埋め込み再生の成功を保証しない。実行できなかった確認を完了済みとしない。

主要な数値・単位・動画タイトルを計算結果と照合し、動画と資料へのリンクが機能するかを確認する。見た目だけ、テキスト抽出だけの片方で完了扱いにしない。完了時は保存済みレポートと次月引継ぎメモへのリンク、最優先の行動、メモを次月も残す案内を短く伝える。判断を制限する欠測だけを添え、同じ注意書きを繰り返さない。

修正後は、確認状況の説明も最新の結果に合わせる。確認を終えた後に古い「表示未確認」を残さず、確認していない再生成功も主張しない。動画の表示に関する共通案内は末尾に一度だけ置く。旧版との取り違えが起きた場合は、ファイル名と冒頭に修正版番号を付け、変更箇所を具体的に示す。
