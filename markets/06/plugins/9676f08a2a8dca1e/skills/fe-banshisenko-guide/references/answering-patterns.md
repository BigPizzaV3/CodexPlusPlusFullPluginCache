# 代表性问题的回答思路

用途：当问题需要组合多个页面或澄清条件时按需参考。以下由实际攻略问答抽象而来，不是本作事实库，也不限制其他提问。简单事实查询直接查对应条目即可。

| 问题类型 | 查证思路 | 适合的回答 |
| --- | --- | --- |
| 推进到下一阶段会不会漏内容 | 路线章节页定位时间范围；必要时联查任务/事件详情与补救机制。核对期限、昼夜、前置条件，区分未出现、已过期与已完成 | 事项、处理窗口、触发方式、错过影响；说明已核实范围，不保证穷尽 |
| 一个任务/人物在哪里，为什么没有看到 | 先辨认对象，再核对适用路线、阶段、位置与出现条件。通用地图操作不等于已查到具体站位 | 先给已核实位置；条件不足时给最小检查步骤，不因看不到就认定漏接 |
| 便宜、当前可以买到且适合某角色的礼物 | 组合角色喜好、礼物获得方式、商店/地点开放条件。类别喜好不能冒充具体物品已验证效果 | 候选、已知价格、取得方式、适用条件；缺一项就标明，不补造 |
| 该培养谁、转什么职业 | 角色成长/技能页与职业要求/效果页组合；根据目标及现有资源比较，不只照抄排名 | 推荐及理由、实现条件、取舍；当前可行方案与后期目标分开 |
| 战斗为什么失败、机制如何工作 | 区分机制提问与具体战局；前者查机制专题，后者联查章节战斗与相关角色/技能，需要时补充决定性战况 | 已验证机制与可执行调整；不从不完整战况声称逐回合最优 |
| 攻略与实际游戏或另一来源矛盾 | 比较路线、版本、章节、模式及原文是否真的作出排他性结论；用户观察是调查线索 | 说明哪里冲突、哪部分已证实、仍缺什么证据；更正时撤回旧结论 |

不要为所有问题同时套用这些检查。不要保存历史会话中的特定角色数值、日期、价格或任务归属作为答案。

## 社区样本补充的提问角度

小范围贴吧检索发现属性作用、开局选择与跨作品背景关联等问题线索，样本不足以称为高频问题。详细出处与采样限制见开发记录；这些模式不预设游戏答案。

- 属性/技能作用：查本作机制与角色/职业页，区分数值作用与培养建议；不要直接搬用旧作同名属性。
- 开局/路线选择：先区分玩家喜好、流程体验和已验证收益；发售前猜测需要重新求证。
- 跨作品关联：分开说明两作各自的事实及玩家解释，先按用户允许的剧透范围决定展开程度。
