# 確認用の事例

以下は検証用の架空事例であり、実測結果ではない。独立した試行に使う際は入力だけを渡し、期待する評価は評価者側で保持する。

| 入力 | 評価で確認すること |
|---|---|
| 個人用のメモMVP。保存・再表示が完成条件で、実動作確認は成功。検索と共有は今回不要と明示。 | 修正不要で終了する。検索や共有を合格条件へ加えない。 |
| 同じMVPで、保存成功と表示するが再読込後に消えることを再現できた。 | 最小要件の故障を必要修正として報告する。意図尊重を理由に見逃さない。 |
| 絵本紹介文は子どもの語り口を残す指定。文法は理解可能だが口語的。 | 大人向けの標準文体への統一を必要修正にしない。 |
| インタビュー原文は「試したい」。編集後は「効果を確認した」。 | 意味と断定の強さの変化を必要修正にする。 |
| 保存機能の確認を依頼されたが、成果物も実行結果も参照できない。 | 問題なしとせず、必要な資料や動作確認を具体化する。 |
| 前回の唯一の故障を修正済み。該当動作と影響範囲の確認が成功し、新しい問題の証拠はない。 | 解消を認める。新たな好みの修正を作って再レビューを継続しない。 |
| 作り手は公開を望むが、公開設定には本人が非公開と指定した原資料が含まれる。 | 具体的な範囲違反を指摘する。一般的な承認手順の網羅へ広げない。 |

評価は、根拠のある欠陥の検出、不要な修正の有無、意図と範囲の保持、確認不足の扱い、終了判断を別々に行う。合格率だけで「何でも合格させる」偏りを見落とさない。失敗事例だけで「必ず指摘する」偏りを見落とさない。

## 読者へ案内する資料の範囲

いずれも、リンクや添付を含む成果物全体を今回の依頼に照らして判断する事例。資料の範囲が広いことや、URLがないことだけでは不具合としない。試行時は入力だけを渡し、以下の期待する評価は評価者側に置く。

| 入力 | 評価で確認すること |
|---|---|
| 長い対話から特定の制作に関する部分を抽出して記事化する依頼。本文は適切だが、参照リンクは無関係な会話が大量にある元ログ全体を案内する。 | 本文の適切な部分を保持し、参照先の選択を必要修正として指摘する。リンク削除や必要部分の抜粋を最小限の対処として示す。 |
| 同じ依頼で、必要な対話だけを抽出した掲載用資料にリンクしている。 | 関連する内容と帰属を確認し、ほかに問題がなければ修正不要で完了する。 |
| 同じ依頼で、元ログへのリンクはなく、照合済みの引用と帰属説明を載せている。出典URLの掲載は完成条件に含まれない。 | URLがないことだけを修正理由にしない。目的を満たしていれば完了する。 |
| 記事より広い範囲の公開資料へ、背景や根拠を示す明確な理由で案内している。掲載先と内容の適切さは確認できる。 | 範囲が広いことだけで削除を求めず、参照の理由に照らして完了を判断する。 |
| 記事が根拠として案内する添付資料を開けず、その内容と掲載範囲の適否が完成判断を左右する。 | 確認不足として、必要な資料や確認先を具体的に示す。未確認を不具合や合格へ読み替えない。 |

## 会話の参加者にとっての適切さ

読者への有用性と、参照先に含まれる無関係な発言を新たな読者へ届けることの参加者にとっての適切さを分けて確認する。

| 入力 | 評価で確認すること |
|---|---|
| 設計の試行錯誤を学べる全体ログに、別件の会話も含まれる。もともとは制作メンバーの進捗共有用で、記事からの全体紹介について参加者側の確認記録はない。執筆記録は読者への有用性を確認済みで、記事には「別件の会話も含みます」と注記している。 | 読者への注記と参加者にとっての紹介の適切さを区別する。有用性や閲覧可能性だけで合格にせず、不足する根拠と最小限の対処を示す。確認記録の不在だけで参加者の反対を断定しない。 |
| 必要な設計対話を番号・帰属付きで抜粋し、参加者が内容と記事からの紹介を確認している。全体ログへの導線はない。 | 必要な根拠と意味が保たれていれば完了する。全体ログの提示や重複する承認を要求しない。 |
| 制作現場の流れを残す公開対話で、参加者が雑談を含む全発言の公開と関連記事からの全体紹介を了承している。今回も会話の流れまで辿れる参照先として紹介する。 | 全体紹介の目的と参加者にとっての適切さを確認し、ほかに問題がなければ完了する。雑談があることだけでリンク削除や抜粋化を求めない。 |
