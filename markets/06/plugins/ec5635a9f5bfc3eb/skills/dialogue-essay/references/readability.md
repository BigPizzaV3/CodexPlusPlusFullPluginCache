# 情報の充実と読みやすさを両立する配置例

固定テンプレートではなく編集判断の見本。題材によって節をまとめ、不要な補足は作らない。

## レース論考を使った構成の見本

以下は既存の対話を題材にした構成案。新しい完成論考や逐語録ではない。

| 本文の流れ | 読者へ伝える内容 | 帰属・情報の置き方 |
| --- | --- | --- |
| 一台が止まったら、世界も止まるのか | 個々の失敗と全体の継続を区別する問い | 出自と人間・AIの役割を冒頭の短い説明に置く |
| 人間の着想：失敗しても続けられる | 人間とAIが互いに補い、他の主体が活動を引き継ぐという筋道 | 本人の仮説としてまとまって展開。AIが足した根拠は混ぜない |
| AIの検討：何を「失敗」と数えるのか | 一台の走行終了と、全体の回復不能では測る対象が違う | 実測の対象・期間・分母と、比喩で対応させる範囲を本文で説明 |
| AIの検討：継続を支える設計 | 各社の内部と、共有基盤・社会全体の修正能力を分ける | 対話の中で誰が提案・修正したかに従って記述 |
| 対話を経て見えてきたこと | 失敗率だけでなく、失敗後に残る回復能力を調べるという到達点 | AIの総括と、人間が明示的に採用した考えを区別 |

この例では「リタイアと競技そのものの終了を区別する問い返し」を、理解が動いた転機として短く紹介できる。正確な元発言を参照できなければ引用符で会話を再現せず、対話の要約として記す。

## 本文に残すか、補足へ移すか

- 結論に使う数値の分母や対象：本文。ここが変わると結論も変わる。
- 比喩の統計がAIの破滅確率を直接測るものではないこと：AIの検討部分にまとめて説明。人間の仮説の各文へ反復しない。
- 細かな集計手順、全データ、再現方法：必要なら別資料。本文から参照できるようにする。
- 着想の意味を変えた問い返し：本文に短く置く価値がある。
- 誤字修正の履歴や投稿操作：論考本文ではなく作業記録へ。

## 短い作品感想なら

人間の印象、AIの読み解き、対話後に広がった見方を数段落でまとめてもよい。研究用の検証節や方法付録を足す必要はない。感情を証明対象にせず、AIの解釈を本人の経験として書かない。

## 編集の確認

本文だけを読んで、何が問いで、誰がどう考え、何が新しく見えたかが分かるか。詳しく確かめたい箇所には根拠への道があるか。重要な条件を補足へ隠していないか。説明やラベルの反復が思考の流れを遮っていないかを点検する。
