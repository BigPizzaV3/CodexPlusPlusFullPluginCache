# 読者へ案内する資料の範囲：2026-09-16の改訂

## 人間の指摘と維持する意図

長い対話から特定の制作に関する部分を抽出して記事化した際、Essayが無関係な会話を大量に含む元チャット全体へのリンクを載せた。Checkerも本文の意味・帰属・経緯を確認して完成と判断し、利用者が参照先の不適切さを指摘してからリンクを削除した。

今回の目的は、制作・照合に使う資料と、完成稿を通じて読者へ案内する資料を区別すること。人間の意図の保持と、必要な修正がなければ完成と認める方針を維持する。原稿は未公開であり、この事例から実際の情報漏洩が発生したとは扱わない。元の共有チャットや内部の編集資料は、この改訂記録には含めない。

## 採用した変更

- Essayの「読みやすさを設計する」1段落を改訂。参照先・添付も読者に届ける内容として選び、範囲と案内する理由を確かめる。必要な引用や抜粋で根拠と帰属を伝える方法も選べる。
- Checkerの「確認と判定」第1項を改訂。リンク・添付から受け手に渡る情報を検査対象に含め、制作側の確認記録が必要な範囲をカバーしているかも照合する。
- [確認事例](../../skills/dialogue-checker/references/scenarios.md)に5件を追加。リンクの存在、資料の広さ、URLの不在だけを修正理由にしない。

Codexの暫定案を、利用者の依頼でAntigravity CLIにもレビューしてもらった。Antigravityは、完成条件を新しく作り直すより既存の手順の確認対象を明確にする最小限の改善を提案した。Codexはこれを取り入れ、公開可否だけでなく今回の読者へ案内する適切さを判断する文言に整えた。利用者が最終案を了承した後に実装した。

## 実行確認

架空の読書メモ道具の制作対話を使った。買い物・旅行など9節の日常会話と、制作に関する5発言を含む資料から、一般読者向けの短い記事を作る設定である。URLは架空の識別子とし、参照先の表示内容はローカル資料で提供した。

これまでの対話、原因分析、期待する判定を渡さない3つのCodexサブエージェント実行で確認した。1つがEssayの原稿作成、1つがCheckerの事例A、1つが互いの資料を流用しない条件でCheckerの事例B〜Eを担当した。各実行には改訂後のSKILL.mdと対象の入力資料だけを渡し、期待する判定を記したscenarios.mdは渡していない。入力・出力の全文はローカルの作業記録に保存し、以下は実際の結果をCodexが要約したもの。
