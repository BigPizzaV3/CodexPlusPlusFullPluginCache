# SQL Copilot — Public Listing

## Display name
SQL Copilot

## Category
Productivity

## Short description
Safer, dialect-aware SQL

## Description
SQL Copilot helps analysts, engineers, BI teams, data-platform users, and application developers write, debug, review, and improve SQL across major database dialects. It focuses on correctness first: output grain, keys, join cardinality, duplicates, NULL semantics, date and timestamp boundaries, deterministic deduplication, and validation. It can also make UPDATE, DELETE, MERGE, DDL, and permission changes safer with read-only previews and impact checks, and it gives evidence-based performance guidance from execution plans and platform metrics instead of generic tuning advice. It supports PostgreSQL, MySQL, SQL Server, Oracle, Snowflake, BigQuery, Redshift, Azure Synapse, and Databricks SQL while avoiding mixed-dialect syntax and never claiming a query was executed unless a connected tool actually ran it.

## Capabilities
- Write dialect-aware SQL from plain-language requirements
- Debug joins, aggregations, windows, NULLs, and date logic
- Review SQL for output grain, keys, duplicates, and correctness
- Add safer previews and validation to UPDATE, DELETE, MERGE, and DDL
- Tune queries using execution plans and platform-specific evidence
- Support major transactional, warehouse, and lakehouse SQL dialects
- Design BI-friendly SQL for marts, semantic models, and incremental loads
- Explain SQL without falsely claiming database execution or verification

## Starter prompts
1. Write the correct SQL for this requirement using my database dialect and schema.
2. Review this SQL for correctness, duplicates, NULL/date issues, and performance risks.
3. Make this UPDATE, DELETE, or MERGE safer with a preview and validation checks.
