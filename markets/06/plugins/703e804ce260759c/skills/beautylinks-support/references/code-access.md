# コード照合：表示・権限・契約

確認版：`source-index.md` の F・B（2026-09-20）。原本p.80〜87、`navigation.md` と併用する。コード断片は X1〜X3。

## ボタンがないとき

最初に対象画面と状態を見る。新規予約の担当欄はスタッフ人数、空き時間候補はカレンダーからの入口、店販発送は注文状態などでも変わる。すべてを権限不足や未契約のせいにしない。

| 条件 | 確認した挙動 |
| --- | --- |
| 閲覧者 | 予約の追加・変更などは画面だけでなくサーバー側でも拒否する。URLを直接開いて回避できるとは言わない。 |
| 営業・メニュー・スタッフ・店舗情報の設定 | 店舗内の通常権限ではオーナー／管理者が対象。表示可能と書き込み可能を分ける。 |
| 売上向上のサイドバー入口 | スタッフ／閲覧者には表示しない。店舗オーナー／管理者でもプラン選択・有効な利用権により表示やロックが変わる。 |
| 売上向上の画面定義に閲覧者が含まれる | 汎用のページ権限表だけではサイドバー表示を説明できない。サイドバーの追加条件とAPI権限まで確認する。 |
| 支払い済みのつもりだがロックされる | 選択プランと有効になった利用権を分ける。状態名だけで利用可能とは断定せず、契約画面の状態・対象機能・反映結果を確認する。 |

## 月額契約の状態

入口：「アカウント設定 → ご契約・お支払い」。店販の口座や決済は「営業設定 → 決済設定」であり別。

確認したサーバーの利用権判定は、有効フラグと確定したプラン情報を前提に、`active`／`trialing` を許可し、`past_due`／`unpaid` は有効な猶予期限内に限る。その他はこの判定では許可しない。

これはコードの判定条件であり、契約料金・猶予日数・ユーザーの現在の契約状態を示すものではない。「past_dueなら即使えなくなる」「activeなら必ず全機能が使える」のどちらにも一般化しない。操作には別途画面・機能・権限の条件がある。

契約状態を手動で偽装したり、スタッフに開発者向け権限の利用を勧めたりしない。必要な場合は店舗オーナーに契約・アカウント設定の確認を依頼する。
