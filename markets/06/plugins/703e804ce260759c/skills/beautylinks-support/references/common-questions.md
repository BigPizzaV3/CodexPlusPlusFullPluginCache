## よくある質問と、間違えやすい条件
### Q01 スタッフを追加したのに予約枠が出ない
プロフィールだけでなく、対応メニューと通常勤務の設定・保存が必要。公開状態、例外勤務、店舗の営業日と営業時間も確認する。指名なしで出ない場合は担当候補の設定を確認する。
参照：原本p.39〜42、88

### Q02 休業日に特別営業時間を登録したのに予約できない
休業日の設定が特別営業時間より優先する。該当日の休業登録を確認し、営業するならその設定を見直す。
参照：原本p.32〜33、44

### Q03 予約したお客様だけ時間を長くしたい
顧客詳細 → 顧客別時間 → 単品時間を追加／セット時間を追加。1〜720分の整数と必要なメモを入れて保存。既存予約の終了時刻は自動変更されないため、既存予約は別途編集する。
参照：原本p.19

### Q04 画像を変えたのにLINEに反映されない
店舗情報・メニュー・クーポン・紹介は画像選択後に各保存が必要。店販画像は商品を登録／商品を更新。既存スタッフ写真はアップロード操作で反映。どの画像かを確認して手順を分ける。
参照：原本p.30、35、40、48、54、60、65

### Q05 並び替えにも保存が必要か
説明書で対応が確認できるメニュー・FAQ・管理者一覧などのドラッグは離した時点で自動保存。テキストや価格の入力変更は該当する保存が必要。全画面に一般化しない。
参照：原本p.36〜38、45、47〜48、86

### Q06 予約を変更したい
予約一覧 → 対象予約 → 予約内容を変更。日時・担当・メニューを調整し、プレビュー → 予約変更を保存 → 確認。備考は備考を保存という別操作。状態によって変更欄が出ない。
参照：原本p.14

### Q07 来ていないのに来店済みになっている
施術終了後に自動で来店済みに変わる仕組みがある。実際に来店がなかったことを確認して無断キャンセルの操作を確認する。未来予約に無断キャンセルを使わない。
参照：原本p.15

### Q08 通知を消せば予約もキャンセルされるか
通知削除は通知の整理。予約の取消は予約詳細の予約をキャンセルから別途行う。
参照：原本p.15、26〜27

### Q09 LINEを1人に送りたい
顧客管理・カルテ → 該当顧客の詳細 → LINE送信。連携・同意・宛先を確認し、5,000文字以内の本文 → LINEを送信 → 確認画面のLINE送信。確定で実送信になる。
参照：原本p.18

### Q10 店舗で同意済みに変更できるか
同意欄は確認用。顧客基本情報で店舗側が代わりに同意へ変更する項目ではない。お客様のLINE上の手続きを確認する。
参照：原本p.17

### Q11 カルテ写真を消したら元に戻せるか
保存済みカルテの画像削除は確認後すぐ反映し、入力を元に戻すでは戻らない。新規の未保存写真を外す操作とは異なる。
参照：原本p.24〜25

### Q12 カルテをExcelで出したい
顧客詳細上部のカルテをダウンロード。画像付きExcelを出力する。予約・顧客・売上の出力はCSV。
参照：原本p.24〜25、29

### Q13 売上向上や管理者権限が見つからない
売上向上は対応プランとオーナー・管理者権限を確認。スタッフ・閲覧者には通常のサイドバーに表示されない。管理者権限は店舗オーナーの操作。
参照：原本p.49、84

### Q14 クーポンを作ったが届かない
クーポンの作成保存と、顧客への配布・LINE送信は別。配布先のLINE連携と同意、配布結果の新規発行・送信成功・失敗を確認する。
参照：原本p.54〜56

### Q15 獲得期限と利用期限は何が違うか
獲得期間は受け取れる期間、利用期間は使える期間。開始・終了の両方の日付と時刻を確認する。
参照：原本p.54

### Q16 配布履歴を消したらクーポンを使えなくなるか
履歴削除では保有クーポンや利用可否は変わらない。使用を止める場合は対象の失効を確認する。クーポン設定自体の削除は別で、獲得・利用の有無により影響が異なる。
参照：原本p.56〜57

### Q17 誕生日クーポンの手動テストを何回か押していいか
手動配信は実際のLINE送信とクーポンの再発行を伴い、同じ人・同じ年でも新しいクーポンを発行できる。先に設定を保存し、対象と結果を確認する。連打しない。自動配信は同じ年に1人1回。
参照：原本p.58〜59

### Q18 友達が予約したが紹介者のクーポンが出ない
紹介された方の同意・情報登録後の特典と、紹介した方への特典を分ける。紹介者特典は紹介された方の初回来店が来店済みになった後。予約だけでは条件を満たさない。紹介履歴の理由・発行・送信も確認する。
参照：原本p.60〜61

### Q19 追加メニューを送ったら予約も変更されるか
送信時点では予約は変更されない。顧客の希望後に、送信履歴の顧客回答と予約反映結果を確認する。自動反映失敗は理由と予約詳細を確認する。
参照：原本p.62

### Q20 店販候補を採用したのにLINEが届かない
採用だけでは送信されない。必要に応じて提案価格を保存し、送信 → 確認 → 送信するを行う。送信履歴で結果確認。一括送信は確認待ちも採用してから送るため、対象を確認する。
参照：原本p.63〜64

### Q21 店販で売り切れにしたい
売上向上 → 店販提案 → 設定 → 登録商品の編集。販売中をOFFまたは在庫を適切に更新し、商品を更新。配送・自動送信の設定を保存とは別。
参照：原本p.64〜66

### Q22 発送の追跡番号はどこに入力するか
対象版では発送メモを入力し、追跡番号の入力欄はない。過去に登録された追跡番号が表示される場合はある。現行画面が異なるならその表示を確認する。
参照：原本p.67〜68

### Q23 一括で発送準備を押したら発送完了か
発送準備の一括処理であり発送完了ではない。実際の発送後に対象注文から発送完了を記録し、LINE送信結果を確認する。
参照：原本p.67、69

### Q24 注文を削除すれば返金されるか
注文履歴の整理と返金は別。対象注文の返金 → 注文・商品・残り返金対象額を確認 → 返金する。対象版の画面では残額の全額返金を行う。
参照：原本p.70〜71

### Q25 利益が未算出、入金日が分からない
原価・実送料を登録し、保存する。不明は空欄、費用0円は0。入金情報を更新し、目安・予定・入金済みなどを区別する。このGPTは実際の入金情報を照会できない。
参照：原本p.70〜71

### Q26 空席販売を止めたら通常予約も取れなくなるか
販売停止は送信済み案内URLからの受付を停止する操作。通常の予約枠そのものを削除しない。未送信の却下や履歴削除とも区別する。
参照：原本p.73〜76

### Q27 口コミを書きましたの申告だけで特典が出るか
申告だけでは完了しない。スタッフが投稿を確認し、送信履歴で確認してクーポン送信。リンクを開いただけとも区別する。
参照：原本p.77〜79

### Q28 月額料金の支払いと店販の入金口座は同じ設定か
月額契約はアカウント設定 → ご契約・お支払い。店販オンライン決済は営業設定 → 決済設定。店販がテスト環境でもBeautyLinks月額契約の扱いは別。
参照：原本p.80〜83

### Q29 支払い後も鍵が付いている
アカウント設定 → ご契約・お支払い → 契約情報を更新。利用中・選択中プランと支払い状態、売上向上なら対応プランを確認する。実状態を見ずに未払いと断定しない。
参照：原本p.82〜84

### Q30 スタッフを追加したがログインできない
スタッフプロフィールと管理画面のログインアカウントは別。オーナーが管理者権限でアカウントを追加・有効化し、必要ならスタッフを紐づける。
参照：原本p.43、84〜86

### Q31 スタッフの紐づけを外せばログインも止まるか
紐づけ解除ではアカウント自体は削除されない。利用を止めるには管理者権限でアカウントの有効状態を別途確認する。
参照：原本p.43、86

### Q32 最後のオーナーを削除したい
有効なオーナーは最低1人必要。最後の有効オーナーの削除・無効化・権限引き下げ、自分自身の削除はできない。必要なら先に別のオーナーを追加する。
参照：原本p.84〜86
