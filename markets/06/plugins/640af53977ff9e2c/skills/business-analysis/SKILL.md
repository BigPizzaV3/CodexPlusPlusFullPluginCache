# Business Engineer analysis

Build a defensible explanation that changes a decision. Infer the audience, decision owner, unit of analysis, and time horizon from the request. Respect requested brevity; use depth when the decision or evidence calls for it.

## Retrieve before applying

The plugin root is two directories above this skill directory. Use its `scripts/library.py` with Python 3; see [Library commands](../../references/library-commands.md). Search for the mechanism, then retrieve the full definitions of the selected entries. Usually a few complementary models and a credible counter-model are enough. Load neither `data/library.json` nor the complete source Markdown wholesale.

The current catalog contains 1,052 entries, including 261 core models, plus fifteen separate practice instruments. The earlier 258-concept ontology overlaps and uses different IDs. Read [Identity and evidence](../../references/identity-and-evidence.md) when working across editions, following redirects, or using numerical formulas. Never transfer an earlier concept number onto a core model with the same number.

## Apply the method

Use [The analytical engine](references/analysis-method.md) for substantial work. Retrieve a suitable instrument or guided path when it changes how the analysis is performed:

- `routes` lists twelve authored decision paths; `routes <id>` returns one with its counter-lens.
- `practice routing` maps decisions to source entries.
- `get instrument:J` retrieves an instrument by letter; read its full body before applying it.
- `practice engine` and `practice quality` return the source engine and checklist.

For each model, connect the mechanism to case evidence, identify the boundary or failure condition, and state its decision implication. Explain why differing lenses agree or conflict. Shared assumptions do not provide independent confirmation.

Separate observed facts, user context, inference, and hypotheses. Verify changing company, market, technical, legal, or financial facts using available primary sources. The bundled library supplies frameworks, not live business data. If access is missing, delimit the structural analysis and identify the missing evidence.

## Deliver the result

Lead with the conclusion, then explain its mechanism and evidence. Include the constraint, economic consequences, rival explanation, and what would change the decision when relevant. Use qualitative judgments unless numerical scales or calculations have a stated basis. Do not invent application steps for compressed source entries or promote proposed syntheses to established laws.

For a substantial strategic analysis, provide the written reasoning first and a faithful HTML visual after it, unless the user requests text only or another format. Read [Visual output](references/visual-output.md) only for that deliverable. Follow the environment's file-saving workflow for generated artifacts.

Use plain, precise language. Keep the user's requested tone and length. Attribute framework material to The Business Engineer and Gennaro Cuofano, and distinguish borrowed named frameworks from original syntheses.
