# Content Gaps and Programmatic SEO

## Content-gap evidence

Use:
- Search Console queries/pages;
- SERP research;
- site inventory;
- competitor pages;
- customer/support questions;
- internal-site search;
- product workflows;
- actual keyword datasets when supplied.

Do not invent volume, CPC, difficulty, or trend numbers.

## Opportunity classes

### Existing demand / weak page
The site gets impressions, but the landing page is incomplete, mismatched, or outdated.

### Missing intent
A real user problem is not covered.

### Cannibalization / overlap
Multiple pages satisfy nearly the same intent without clear differentiation.

### Product-led SEO
The product/tool itself solves the query and should be the primary landing surface.

### Editorial authority
Original research, examples, data, or expert explanation can create differentiated value.

## Prioritization

Use:
- user value;
- business relevance;
- observed search demand;
- current ranking/visibility;
- competitive gap;
- ability to create meaningfully better content;
- maintenance cost.

Avoid fake numeric precision if estimates are subjective.

# Programmatic SEO

## Suitable pSEO

A template family is suitable when each page has genuinely distinct useful data or functionality.

Examples:
- location pages with real location-specific data;
- integration pages with actual integration behavior;
- calculators with distinct inputs/outcomes;
- structured reference pages backed by authoritative datasets.

## Unsuitable pSEO

Avoid:
- changing one keyword while content remains identical;
- mass AI pages with no additional value;
- scraped/recombined content;
- fake location/service pages;
- pages created primarily for ranking coverage.

Google's scaled-content-abuse policy focuses on large volumes of unoriginal low-value pages created primarily to manipulate Search, regardless of the production method.

## Indexability gate

A programmatic URL should become indexable only if:
- page is complete;
- page serves a distinct intent;
- unique data/value is present;
- duplicate similarity is acceptable;
- canonical is correct;
- required data is not placeholder;
- content quality checks pass;
- user/product policy allows indexing.

Otherwise use:
- noindex;
- consolidation;
- canonicalization;
- no public URL;
depending on the product.

## Template QA

Before rollout test:
- representative best-case page;
- sparse-data page;
- missing-data page;
- edge-case values;
- duplicate variant;
- canonical;
- metadata;
- schema;
- internal links;
- sitemap inclusion;
- mobile rendering;
- page speed.

## Stop criteria

Pause/index-gate a template family when:
- Google indexes very few despite good discovery;
- quality/duplication issues dominate;
- impressions show no relevant demand;
- maintenance cost exceeds value;
- template errors affect large URL cohorts.
