# Component workflow

1. Define component type, function, audience, message, context, format and acceptance criterion.
2. Present the consolidated requirements with explicit/inferred states and always offer `FILES_AND_CONTEXT_ONLY` versus `WEB_COMPLEMENTARY`; wait for confirmation or adjustment.
3. After confirmation, apply M0–M2 analysis unless the content is materially consequential or contradictory; escalate only when needed. Browse only with confirmed `WEB_COMPLEMENTARY`.
4. Select representation by question and evidence.
5. Specify a native/editable object model when updates or auditability matter.
6. Build exclusively with Presentations and `@oai/artifact-tool`, with clear hierarchy, correct units and source treatment.
7. Render/inspect the component at intended scale.
8. Deliver the component plus only the context needed to insert or use it.
