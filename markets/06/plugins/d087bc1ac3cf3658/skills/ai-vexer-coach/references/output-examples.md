# 관계 표현 예제

아래는 제공된 관계를 보존하는 예제다. 문장 일치·날짜·단계명·행 수는 다른 요청의 규칙이 아니다. 필요한 본문 설명이나 후속 AI 행동은 해당 계약으로 추가하되 같은 관계를 반복하지 않는다.

## 무분기 순서

운영팀: 자료 취합 → 검토 → 승인 요청 → 승인 후 게시

## 검수 분기

```text
검수
├─ 통과 → 게시
└─ 실패 → 수정 → 다시 검수
```

## 날짜와 행동

9월 15일 초안 → 9월 18일 검토 완료 → 9월 20일 게시

## 후속 AI 작업

확정 제목의 공백을 정리해 재사용할 목록을 만드세요 — 권장 모델: Luna / medium.
호스트가 GPT-6 Sol / medium을 해당 작업에서 지원한다고 명시한 경우: 필터 구현 계획을 작성해 화면 동작과 확인 기준을 정하세요 — 권장 모델: GPT-6 Sol / medium. 목록이 없으면 모델명을 만들지 않고 일반 / medium 수준·설정 미확인으로 표시한다.

## 민감한 HTML

실명·개인 평가 점수·외부 추적 스크립트·제출 폼을 제외한 비식별 정적 대안을 제공한다. 어떤 위험을 제거했는지 설명하고 실제 파일 또는 코드로 전달하며, 미제공 숫자·평가 목적·보관 정책을 덧붙이지 않는다.

## 매출 분석

현재 자료의 총매출 변화와 채널 구성 변화가 서로 다른 판단 근거라면 각각의 관찰과 근거를 인접하게 배치한다. 자료가 단순 동반 변화만 보여주면 원인을 확정하지 않는다. 사용자가 투자 판단까지 요청했다면 원인 확인을 조건으로 설명한다. 이 예제는 특정 날짜·매출값·투자 결론을 제공하지 않는다.

## 조건부 배포·인증 예시

배포·인증 업무의 관계 표현이 어려울 때만 이 절을 읽는다. 입력 조건이 같은 경우에만 참고하고 이름·수치·날짜·문구·질문 개수를 복제하지 않는다.

- 배포 입력에 승인 절차·책임, 시작 시각, 완료 후 관찰 기준이 모두 없고 각각 독립적이면 한 질문 묶음에 함께 확인한다. 절차의 내용과 담당자가 모두 미정인 경우 “어떤 절차이며 누가 확인하나요?”처럼 두 빈칸을 모두 묻는다. 일부가 이미 답해졌으면 나머지만 묻는다.
- “시작 14시, 완료 후 30분 관찰”만으로 14시 30분에 관찰이 끝난다고 쓰지 않는다. 완료 시각은 미정이며 상대 조건을 유지한다.
- 회귀 검사 통과와 사전 승인이 서로 독립인 입력이면 둘 다 충족해야 배포한다고 표현한다. 반려 후 “수정 → 재검사 → 재승인”이 따로 주어졌을 때만 그 분기에 순서를 둔다.
- 인증 요청의 식별자는 요청에 속한다. 이를 성공 응답에도 포함시키려면 그 응답에 대한 근거가 있어야 한다. 화면 구현팀과 수용 검사팀이 다르면 각각의 행동과 책임을 구분한다.
