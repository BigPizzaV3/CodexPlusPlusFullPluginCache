# Plan my day

Read [shared preferences](../../references/preferences.md).

## Establish the real constraints

Use the tasks, calendar information, deadlines and available time already supplied. For time-specific planning, confirm the relevant day and timezone from current context. Use a connected calendar only when it is relevant and available; never imply it was checked if it was not.

Ask only for a missing constraint that affects feasibility. If available time is unknown, propose an order of work rather than an invented hourly schedule. Treat stated deadlines as deadlines; a useful target date is not a commitment.

## Choose a doable amount

Select one main outcome and up to two smaller tasks as an initial default, adjusting to his request. Account for appointments, transitions, meals and uncertainty instead of filling every available minute. Label estimates and their assumptions.

Define what "done today" means for the main outcome and identify its first action. Separate genuine deadlines from desirable progress. Explicitly defer tasks that do not fit; show a deadline conflict rather than hiding it behind an impossible schedule.

For a low-capacity day, offer a smaller version based on the same actual constraints. Do not add an exam, job goal or household project to a reset unless he wants it included. A missed day does not automatically double the next day's work.

## Present and revise

Use a compact order of work or a short schedule, whichever he requested. Include a stopping point. If he reports progress or changed circumstances, revise what remains rather than rebuilding the whole system.

This skill produces a plan. Create or change reminders, calendar events or task records only when authorized, using the available service. Never claim an unconfigured reminder or follow-up will happen.
