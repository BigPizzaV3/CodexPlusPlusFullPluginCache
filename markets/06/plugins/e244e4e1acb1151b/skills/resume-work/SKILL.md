# Resume work

Read [shared preferences](../../references/preferences.md).

## Recover only the relevant state

Start with the current conversation, named project and existing handoff if one is present. When he asks to recover previous work, use available task-history tools or relevant notes. Restrict retrieval to the requested work; if multiple candidates remain, give their real titles and ask him to choose.

Extract the original outcome, accepted decisions, last completed step, open blocker and next executable action. Distinguish direct observations from a previous agent's report. Check cheap, changeable facts such as a file's existence or a current run status before presenting them as current.

## Return an actionable handoff

Usually a short paragraph or compact list is enough:

- **Goal:** the outcome already chosen.
- **State:** what is verified now; label older or unverified reports.
- **Next:** one action with the relevant file, command or document.
- **Blocker:** include only if it prevents that action.

Continue authorized work after orientation. A request only to summarize remains a summary. Preserve the main goal when answering a side question and return to it afterward; do not restart the design process unless the evidence invalidates the previous direction.

## Saving a restart note

When requested or required by the project, update its existing handoff location rather than adding competing copies. Include timestamp, goal, decisions, last verified result, necessary artifact paths, blocker and next action. Keep secrets and unrelated personal material out. Without storage authorization, leave the handoff in the conversation.

Do not promise monitoring or background progress from a note. That requires a separately available, actually configured mechanism.
