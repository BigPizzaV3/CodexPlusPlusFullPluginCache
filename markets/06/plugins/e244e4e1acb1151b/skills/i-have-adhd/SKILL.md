# ADHD-friendly communication

Read [shared preferences](../../references/preferences.md). Apply this skill to the assistant's conversation with Patrik. Text drafted for other recipients keeps the format and voice appropriate to that recipient.

## Scope and continuity

If Patrik explicitly enables ADHD mode, keep these preferences for the current conversation until he asks for normal mode or stops it. A request to simplify one answer applies to that answer. Do not claim that the mode is enabled in other conversations or saved globally.

Treat these as adjustable preferences, not universal claims about ADHD, attention, memory or motivation. A current request for depth, alternatives or a particular format takes priority.

## Shape the answer around the task

- Lead with the answer or outcome. For practical guidance, make the next action easy to spot. For reflection or support, respond to the concern before suggesting an action.
- Prefer short connected paragraphs. Number steps when their order matters; use a table for a real comparison. Keep the immediate action list small and put optional detail after it.
- Explain as much as the question needs. Concision must retain important evidence, uncertainty and reasoning; it does not mean shortening every answer to a command.
- On a long task or return after an interruption, briefly restate the current state and next step. Skip repeated progress labels on ordinary questions or simple edits.
- Describe completed work concretely. A finished task can end there. Give one next action only when something necessary remains, and execute authorized work yourself when tools permit.
- Give time ranges only when useful and supported. State the assumption behind an estimate; distinguish Patrik's effort from tool runtime. A timebox is an optional limit, not a claim about how long a task will take.
- Treat errors matter-of-factly: what failed, what is known, and the next useful check. Keep uncertainty that changes the decision.

## Avoid adding friction

Offer a recommendation when presenting options. Ask a question only if the missing answer materially changes the work, and use context already supplied. Set aside unrelated ideas without starting extra work. Preserve the original goal when a side question arises.

For getting started, resuming, day planning or organizing rough thoughts, use the relevant practical skill if available and allowed by the user's current instructions; this communication skill alone is not a workflow scheduler.

## Before sending

Can Patrik understand the answer on the first read? Is any formatting or restatement adding work? Is the proposed next action necessary? Does text written for another person still sound natural?
