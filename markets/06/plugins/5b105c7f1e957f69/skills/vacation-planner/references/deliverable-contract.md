# Full-plan deliverable contract

A complete plan passes only when it is useful without reading the research process.

In collaborative mode, the complete plan is produced only after the traveler approves the route-and-budget skeleton or explicitly delegates the remaining choices. The final plan must reflect confirmed, preferred, delegated, open, and rejected items from the decision ledger.

## First screen

Show the recommended route, trip character, all-in estimate, amount above or below target when one exists, confidence, and the next booking decision. If no target exists, say so and show a useful estimate or range without invented variance.

Briefly state which material choices came from the traveler and which were delegated to the planner. Do not bury a still-open, trip-changing decision inside the detailed itinerary.

## Required detail

- Dates and hotel nights reconcile.
- Arrival and departure logistics fit the first and last day.
- Each day has at most one demanding anchor by default, realistic transit, meal space, and a lighter alternative.
- Each base has one recommendation, one value alternative, and one deliberate upgrade.
- Activities show location, duration, likely cost, booking pressure, source status, and weather sensitivity.
- Budget categories sum exactly to the stated total and disclose exclusions.
- Material time-sensitive claims link to the source observed.
- Accessibility, allergy, medical-equipment, and medication constraints have a pass/fail/unknown table. Unknown or failed critical links are excluded from the recommended configuration and force a **not ready** provisional plan with a verification checklist.
- When the user caps daily activities, the plan defines what counts and shows the scheduled-commitment count for every day.

## Interactive output

Every full plan includes an image-rich interactive decision workspace unless the user explicitly requests text only or HTML creation is unavailable. Use `$trip-dashboard` and its bundled template. Include editable budget assumptions; visual, decision-ready comparisons for hotels, activities, restaurants, and transport; exact total and per-person recalculation; target variance; category breakdown; complete day-by-day itinerary; source links; confidence/freshness labels; and clear observed/estimated status. Every option carries truthful attributable images, useful details, traveler-fit reasoning, and explicit pros and cautions so external links remain secondary. The recommended audited configuration is selected by default. The written plan and canonical budget remain the source of truth.

Before delivery, compare the dashboard's initial total, per-person amount, selected hotels, selected activities, selected transport, dining shortlist, trip dates, traveler count, and target against the audited plan. Browser-check the primary image for every decision item. Any mismatch or broken primary image is a release blocker.
