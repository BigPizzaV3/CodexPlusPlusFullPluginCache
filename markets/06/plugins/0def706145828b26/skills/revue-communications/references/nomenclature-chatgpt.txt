## 1. Objectif

Ce guide définit les règles de nommage des éléments utilisés dans l’environnement ChatGPT d’Antoine.

Le but est que le nom permette de comprendre immédiatement :

* de quel type d’objet il s’agit ;
* à quoi il sert ;
* s’il est permanent ou ponctuel ;
* à quel domaine il appartient ;
* et, lorsque pertinent, à quel client, dossier ou période il se rattache.

La nomenclature doit rester courte, cohérente et lisible.

Le système doit éviter les noms vagues comme :

`Test`
`Projet`
`Analyse`
`Client`
`Nouveau GPT`
`Divers`
`À voir`

---

# 2. Principe général

Avant de proposer un nom, déterminer d’abord **la nature de l’objet**.

Il existe cinq catégories principales :

| Objet      | Rôle                                |
| ---------- | ----------------------------------- |
| GPT        | outil spécialisé réutilisable       |
| Project    | environnement de travail persistant |
| Chat       | dossier, cas ou travail concret     |
| Site       | interface ou application            |
| Programmée | tâche automatique ou récurrente     |

Ne pas utiliser la nomenclature d’une catégorie pour une autre.

---

# 3. GPT — OUTILS

## Règle

Un GPT représente généralement une **fonction réutilisable**, et non un projet ou un client.

Format principal :

`TYPE — Fonction`

Deux préfixes sont utilisés.

### WF — Workflow

Utiliser `WF —` lorsque le GPT applique un processus métier structuré pour produire un résultat.

Exemples :

`WF — Préavis AMF`
`WF — Lettre justificative`
`WF — Compte-rendu client`
`WF — Analyse illustration`
`WF — Présentation prêteur`
`WF — Note CRM`

Un workflow doit normalement :

1. recevoir des informations ;
2. suivre un protocole ;
3. effectuer des contrôles ;
4. produire un livrable standardisé.

### UTIL — Utilitaire

Utiliser `UTIL —` lorsqu’il s’agit d’un petit outil spécialisé ne représentant pas réellement un workflow métier.

Exemples :

`UTIL — Filename Generator`
`UTIL — Calculateur rendement`
`UTIL — Normaliseur téléphone`
`UTIL — Extracteur données`

Le GPT actuellement appelé `Liga Filename Generator` devrait donc idéalement devenir :

`UTIL — LIGA Filename Generator`

ou, si sa fonction devient plus générale :

`UTIL — Naming Generator`

---

# 4. Ne pas créer un GPT pour tout

Un GPT doit correspondre à une compétence suffisamment répétitive pour justifier un outil permanent.

Créer un GPT lorsque la phrase suivante est vraie :

> « Je vais refaire cette opération régulièrement et je veux que ChatGPT applique toujours le même protocole. »

Ne pas créer un GPT pour :

* un client ;
* une transaction ;
* une recherche unique ;
* un projet entrepreneurial ;
* une tâche temporaire ;
* une seule lettre.

Ces éléments doivent généralement être des chats ou des Projects.

---

# 5. PROJECTS — DOMAINES DE TRAVAIL

## Format

Pour les principaux Projects permanents :

`NN — Domaine`

Le numéro sert à créer une hiérarchie visuelle stable.

Architecture de référence :

`00 — Cockpit`
`10 — Conseil financier`
`11 — Planiprêt`
`20 — Business / LLGP`
`30 — DocFinance`
`40 — Mexique`
`50 — Immobilier`
`60 — Famille / Admin`
`70 — Systèmes`
`99 — Archives`

Les numéros ne représentent pas une priorité.

Ils représentent une **position logique permanente dans l'architecture**.

---

# 6. Project ou GPT ?

Toujours appliquer cette règle :

> Activité persistante = Project
> Procédure répétitive = GPT

Exemples :

`DocFinance` → Project

car il contient des recherches, articles, décisions, stratégie, fichiers et discussions dans le temps.

`Préavis AMF` → GPT

car il s’agit d’un protocole réutilisable appliqué à différents dossiers.

`Planiprêt` → Project

car il représente une activité professionnelle permanente.

`Compte-rendu client` → GPT

car le même traitement est répété après chaque rencontre.

---

# 7. CHATS — DOSSIERS ET EXÉCUTIONS

Un chat correspond généralement à une **unité de travail concrète**.

Pour un dossier client :

`AAAA-MM-JJ — Client — Sujet`

Exemple :

`2026-09-03 — Tremblay — Assurance vie`

Autres exemples :

`2026-09-03 — Mario Saint-Amand — Refinancement`

`2026-09-04 — Gagnon — Analyse Equimax`

La date à utiliser est normalement la date de création ou de début significatif du dossier dans ChatGPT.

---

# 8. Chats issus d’un workflow

Lorsque le chat est créé avec un GPT métier, ne répéter le nom du workflow que si cela apporte réellement de l’information.

Dans :

`WF — Préavis AMF`

préférer :

`2026-09-03 — Tremblay — Vie permanente`

plutôt que :

`2026-09-03 — Tremblay — Préavis AMF vie permanente`

Le contexte du GPT indique déjà qu’il s’agit d’un préavis.

Même principe dans :

`WF — Compte-rendu client`

Utiliser :

`2026-09-03 — Tremblay — Rencontre initiale`

ou :

`2026-09-03 — Tremblay — Suivi assurance`

---

# 9. Chats permanents

Certains chats ne correspondent pas à une transaction unique.

Ils doivent recevoir un préfixe fonctionnel.

### MASTER —

Source principale ou conversation centrale.

Exemples :

`MASTER — Priorités`

`MASTER — Architecture DocFinance`

`MASTER — Stratégie acquisition`

### STRAT —

Réflexion ou travail stratégique.

Exemples :

`STRAT — Modèle de rémunération`

`STRAT — Distribution assurance`

### RECH —

Recherche structurée destinée à être conservée.

Exemples :

`RECH — Commissions courtiers dommages QC`

`RECH — Marché Airbnb Puebla`

### MODÈLE —

Contenu de référence destiné à être réutilisé.

Exemples :

`MODÈLE — Courriel de suivi`

`MODÈLE — Lettre explicative`

---

# 10. Conversations ponctuelles

Une conversation qui répond à une petite question ne nécessite généralement aucune nomenclature sophistiquée.

Exemples :

`Numéro Passeport Canada`

`Calcul conversion CAD MXN`

`Cinéma enfants Puebla`

Ces conversations peuvent rester hors Projects et disparaître progressivement de l’espace de travail actif.

Ne pas surclasser l’information.

---

# 11. ARCHIVES

Une archive est un élément qui :

* est terminé ;
* n’est plus opérationnel ;
* doit être conservé uniquement pour référence.

Projet principal :

`99 — Archives`

Lorsqu’un préfixe est nécessaire :

`ARCHIVE — Nom`

ou utiliser l’année :

`2025 — Impôts`

`2024 — Ancien projet immobilier`

Éviter de multiplier les Projects :

`Archives 2024`
`Archives Business`
`Archives personnelles`
`Archives fiscalité`

sauf volume exceptionnel.

Par défaut, conserver un seul environnement :

`99 — Archives`

---

# 12. SITES

Un Site représente une interface ou une application.

Format :

`APP — Fonction`

Exemples :

`APP — Dashboard LLGP`

`APP — Calculateur retraite`

`APP — Analyse hypothécaire`

`APP — Outil Préavis AMF`

Utiliser `APP` plutôt que `WF`, car l’objet est une interface et non seulement un processus conversationnel.

---

# 13. PROGRAMMÉES

Une tâche programmée doit être nommée d’après **l’action future effectuée**, et non le projet auquel elle appartient.

Format :

`Action + objet`

Exemples :

`Revue quotidienne`

`Revue hebdomadaire LLGP`

`Suivi accréditation BNC`

`Renouvellement E&O`

`Surveillance taux hypothécaires`

Éviter :

`Rappel`

`Tâche`

`Test`

`À faire`

Le nom doit permettre de comprendre la tâche sans l’ouvrir.

---

# 14. Hiérarchie décisionnelle

Lorsque le GPT Filename Generator reçoit une demande, il doit déterminer successivement :

### Étape 1 — Quel objet ?

GPT ?
Project ?
Chat ?
Site ?
Programmée ?
Fichier LIGA ?

### Étape 2 — Permanent ou ponctuel ?

Permanent → Project / GPT / Site.

Ponctuel → Chat / fichier / tâche.

### Étape 3 — Fonction ou domaine ?

Fonction répétitive → `WF —`

Utilitaire → `UTIL —`

Application → `APP —`

Domaine permanent → `NN —`

### Étape 4 — Client ou dossier ?

Si oui :

`AAAA-MM-JJ — Client — Sujet`

### Étape 5 — Nature spéciale ?

Référence principale → `MASTER —`

Stratégie → `STRAT —`

Recherche → `RECH —`

Modèle → `MODÈLE —`

Archive → `ARCHIVE —` ou `99 — Archives`

---

# 15. Règles stylistiques

Les noms doivent être :

* courts ;
* descriptifs ;
* stables ;
* compréhensibles hors contexte.

Utiliser préférentiellement entre **2 et 6 mots significatifs**.

Éviter les phrases.

Éviter les articles inutiles.

Préférer :

`WF — Analyse illustration`

à :

`WF — Outil pour analyser les illustrations d’assurance`

Préférer :

`RECH — Commissions courtiers dommages`

à :

`Recherche concernant comment fonctionnent les commissions des courtiers en assurance de dommages`

---

# 16. Majuscules

Les préfixes structurants sont en majuscules :

`WF`

`UTIL`

`APP`

`MASTER`

`STRAT`

`RECH`

`MODÈLE`

`ARCHIVE`

Le titre utilise une casse normale :

`WF — Préavis AMF`

et non :

`WF — PRÉAVIS AMF`

sauf lorsqu’un acronyme impose naturellement les majuscules.

---

# 17. Séparateur

Utiliser systématiquement le tiret cadratin :

`—`

avec une espace avant et après.

Exemple :

`WF — Compte-rendu client`

Ne pas mélanger :

`WF-Compte rendu`

`WF | Compte rendu`

`WF : Compte rendu`

`WF_Compte_rendu`

---

# 18. Réponse attendue du GPT Filename Generator

Lorsque l’utilisateur demande simplement comment nommer quelque chose, répondre prioritairement par **le nom recommandé**, sans explication inutile.

Exemple :

Utilisateur :

> Comment nommer mon GPT qui produit les préavis AMF ?

Réponse :

> `WF — Préavis AMF`

Lorsque plusieurs interprétations sont possibles, proposer au maximum 2 ou 3 options en indiquant clairement la recommandation principale.

Exemple :

> Recommandé : `UTIL — LIGA Filename Generator`
> Si l’outil devient général : `UTIL — Naming Generator`

---

# 19. Principe directeur

Toujours privilégier la cohérence du système existant plutôt qu’un nom individuellement créatif.

Le nom doit aider Antoine à répondre immédiatement à la question :

> « Qu’est-ce que c’est et où cela appartient ? »

La nomenclature est un système de navigation, pas un exercice de branding.

---

Je ferais d’ailleurs évoluer le rôle du GPT actuel de **simple générateur de filename LIGA** vers un véritable **`UTIL — Naming Generator`**, qui connaîtrait deux référentiels :

1. `LIGA — Guide de nomenclature documentaire`
2. `ChatGPT — Guide de nomenclature`

Tu pourrais alors lui envoyer indifféremment :

> « Nom pour le rapport annuel Manuvie d’Ephraïm »

→ `202410 EPH AS Rapport Manuvie`

ou :

> « Je crée un GPT qui fait mes comptes-rendus après rendez-vous »

→ `WF — Compte-rendu client`

Ça en ferait un petit **gardien de nomenclature transversal**, ce qui est probablement plus utile à long terme que de le limiter aux fichiers.
