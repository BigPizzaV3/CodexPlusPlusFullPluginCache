# Programmation

Utiliser les outils d’automatisation réellement disponibles lorsque l’utilisateur demande une exécution future ou récurrente. Vérifier horaires, fuseau et capacités d’accès du contexte planifié; ne pas supposer qu’une tâche peut invoquer un skill ou toutes les connexions accessibles en conversation.

Préférer des revues transversales : « Revue communications matin », « Revue communications hebdomadaire », « Alerte communications prioritaires »; fin de journée facultative. Ne pas créer une tâche par compte. Une alerte conditionnelle nécessite une fréquence de vérification; ce n’est pas une surveillance en temps réel.

Construire le prompt de tâche avec mode, période, sources effectivement accessibles, déduplication, couverture, comparaison persistante seulement si disponible et sortie par dossier. Si le contexte planifié ne charge pas le skill, inclure les règles indispensables dans le prompt. Ne pas programmer une tâche connue comme incapable d’accéder aux sources attendues sans expliquer cette limite.

Respecter les horaires demandés; ne pas inventer le fuseau à partir du pays mémorisé. Confirmer uniquement les tâches effectivement créées. Une alerte sans changement significatif reste silencieuse seulement si la fonction de notification le permet; une panne de couverture n’est pas une preuve d’absence de nouveautés.
