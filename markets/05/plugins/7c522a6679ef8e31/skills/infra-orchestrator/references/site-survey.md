# As-Is / Site Survey Module

Create an evidence-backed current-state document. Never blend future recommendations into current-state facts.

When these categories are present, keep them distinct:
- Verified Current State
- Findings / Observations
- Risks / Gaps
- Recommendations
- TBD / Missing Evidence

Do not force Findings, Risks, or Recommendations when the user requests a pure As-Is inventory.

## Typical sections
Executive overview, scope, source/evidence register, architecture, inventory, compute/virtualization, network, SAN, storage, backup/DR, schedules, plans/storage policies, copies, retention, replication, monitoring, dependencies, findings, risks, recommendations, TBDs.

Use exact object names from evidence when available. Avoid generic renaming that breaks traceability.
