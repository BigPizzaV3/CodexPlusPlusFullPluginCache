# 联调协助快速路径

> 功能：依据一个正在发生的联调现象或证据快速定位责任阶段并更新对应场景。与联调准备和 CR 前复检不同，本模式不重新建立完整变更范围。

## 执行边界

- 只使用当前证据和本任务最近的相关结论，默认处理一个场景。
- 不读取完整检查清单、完整项目知识或完整 Git Diff，不运行 lint、测试或构建。
- 证据不足时，只定向读取回答当前问题所需的代码或文档。
- 用户要求全量重查、CR 复检，或代码/分支/环境/需求变化导致多个结论失效时，说明原因并切换到对应完整模式。

## 定位方法

先将现象放入真实链路，例如：输入校验 → 参数转换 → 资源上传 → 业务保存 → 后端处理 → 查询 → 页面回显，并根据证据判断当前已证明的阶段。

证据优先级按问题类型选择：

- 请求响应：接口、参数、状态码和响应内容。
- 日志或任务记录：后端处理、异步任务和落库结果。
- 截图：页面现象、提示和展示状态。
- 前端代码：触发条件、转换逻辑、状态管理和错误展示。
- 接口文档：契约；文档未定义的语义不得臆造。

## 单轮输出

每轮只输出：当前判断、证据及边界、责任层或待确认人、一个最小下一步、场景状态变化。证据足够时直接更新结论，不重复要求验证；只有用户要求总览或联调闭环时才汇总完整台账。

| 场景 | 预期依据 | 当前证据 | 状态 | 责任方 | 下一步 |
|---|---|---|---|---|---|
| 具体场景 | PRD/接口/用户确认 | 请求响应、日志、截图或人工结果 | 允许的场景状态 | 前端/后端/产品/共同 | 一个最小动作 |
