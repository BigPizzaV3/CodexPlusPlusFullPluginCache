# 联调准备

> 功能：在编码完成后建立需求变更范围，判断是否需要联调并生成可执行清单。与 CR 前复检不同，本模式只判断“可开始/暂不可开始联调”，不输出 CR 准备度。

## 执行流程

1. 按 SKILL.md 的仓库知识规则，只加载与本次变更相关的业务及工程规则。
2. 查看 Git 状态、分支、上游关系和提交统计，再按“变更范围确定”选择 base、head 和工作区范围。
3. 排除用户已有的无关改动。范围混入多个需求时，按提交、文件和对话证据收窄；仍无法判断时停止完整检查，只索取一项最小范围信息。
4. 按业务场景归纳页面、组件、接口、类型、转换和配置变化，并引用文件路径或符号。
5. 依据 [checklist.md](checklist.md) 选择相关条目，判断需要联调的链路、前置条件、异常与责任方。
6. 生成场景清单。上传、保存、异步处理、查询和回显等多阶段链路必须拆开验证。

## 变更范围确定

按以下顺序选择范围，命中可证明的来源后停止：

1. 用户明确指定的 base、head、commit、文件或变更范围。
2. 当前 PR/CR 元数据中明确的目标分支及其 merge-base。
3. 能由当前分支上游关系明确证明的目标分支及其 merge-base。
4. 能通过提交记录、文件和对话证据明确收窄的本需求 commit 集合。

禁止默认猜测 `main`、`master` 或远端默认分支，也不得仅用相对 `HEAD` 的工作区 diff 代表整个需求。目标分支无法确定、多需求无法分离、前序依赖归属不明或工作区变更无法归属时，请用户提供目标分支或本需求 commit 范围。

## 输出

- 变更范围：base、head、纳入的 commit/文件、工作区变更和排除项。
- 按业务场景组织的代码变更摘要。
- 适用的仓库知识与证据缺口。
- 是否需要联调及依据。
- 联调场景清单。
- 结论：`可开始联调` 或 `暂不可开始联调`。

没有可检查的代码变更且用户也未指定范围时停止，并请用户提供范围。
