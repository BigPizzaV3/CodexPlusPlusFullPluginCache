# 納品形式

文章一式は、貼り付け先ごとのコードブロックへ分ける。コードブロックはコピー用の枠としてだけ使い、中身はプレーンテキストにする。

## 順序

1. `タイトル案1`
2. `タイトル案2`
3. `タイトル案3`
4. `本文`
5. `X投稿文`
6. タイトル選択の案内

タイトル三本は別々のコードブロックにする。本文とX投稿文も各一つの専用ブロックにする。noteタグ専用のコードブロックは作らない。

## 本文

- 各節を`[大見出し] 見出し名`で始め、前後を空行にする。
- 利用者が希望した場合だけ`[小見出し] 見出し名`を使う。
- Markdown見出しの`#`、太字、斜体、箇条書き、引用記号、表、水平線を入れない。ただし末尾のnoteタグ行では`#`を使う。
- 絵文字、顔文字、装飾記号、作業用の注記を入れない。
- 明示した引用やURLはプレーンテキストで置く。
- 外部事実の出典は必要な出典名を文章へ自然に含める。利用者が明示的に求めない限り、資料名だけの行、URLだけの行、参考文献一覧を本文へ入れない。

## 本文末尾のnoteタグ

本文の最終段落から一行空け、タグごとに`#`を付け、半角空白で区切った一行を同じ本文コードブロックの末尾へ置く。基本は5個とし、記事へ別の有効な入口を一つ足せる場合だけ6個にする。タグ内に空白を入れず、commaや箇条書きで分けない。

## X投稿文

一投稿分だけを入れる。実際に使うハッシュタグ0〜2個は`#`を付けてよい。正規URLが提供済みの場合だけ、同じブロックの末尾へ直接置く。

## 追加しないもの

本文の最終段落とタグ行の間や、一式の末尾へ、次を勝手に足さない。

- 調査報告、出典一覧、内部点検。
- 制作工程、文字数計測の説明。
- URLを返信欄へ付ける案内。
- 見出し画像の制作指示。
- 宣伝や相談案内。

## 途中の応答

利用者の判断に必要な質問、回答状況、構成案、成果だけを表示する。Plugin名、Skill名、添付ZIP、参照file、同梱script、内部の工程番号、画像のprompt、検査や寸法調整の実況は表示しない。

選択タイトルまたは差し絵の生成依頼を受けたら、制作開始の前置きを返さず、そのまま画像生成へ進む。

## 画像応答

見出し画像の応答では、完成画像と、必要な場合だけ差し絵の一案を返す。差し絵の完成応答では、完成画像と挿入位置だけを返す。

次のような制作事情を表示しない。

- 内蔵画像生成を使用したこと。
- prompt、model、生成回数。
- 切り抜き、resize、寸法調整の手順。
- 構図や表現を選んだ内部理由。
