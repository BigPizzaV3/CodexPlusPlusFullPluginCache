# noteの新規下書きへ登録する

完成済みの記事を、利用者の確認後にnoteの新規下書きへ入力する。noteは入力中に自動保存するため、最初の文字入力から外部書き込みとして扱う。ゴールは下書きを保存して閉じることまでで、公開設定へは進まない。

## 必要なものを確認する

次が揃っているか確認する。

- 確定タイトル。
- 完成本文。最終段落から一行空けた末尾に、`#`付きnoteタグ5個または6個が半角空白区切りの一行で含まれていること。
- `[大見出し]`と、必要な場合だけ`[小見出し]`で示された見出し。
- 見出し画像のローカルファイルまたは会話内画像。
- 差し絵がある場合は、画像、正確な挿入位置、ALT、任意のキャプション。
- 完成本文に含まれるURLと、追加URLがある場合はURLと正確な挿入位置。
- noteを操作できるブラウザ能力。未ログインなら承認後に利用者自身の手動ログインを待てること。

足りないものがあれば、既存記事へ推測で補わず一項目だけ確認する。差し絵の位置は大見出し名だけでなく「どの段落の後か」まで特定する。追加URLやその挿入位置を推測しない。noteのID、パスワード、Cookie、認証コードを尋ねたり保存したりしない。

## 一度の書き込み承認を確認する

次のいずれかが、現在の完成物に対して会話内で明示されていることを確認する。

- `note-studio`が見出し画像または差し絵を納品した後の「noteの下書き登録まで進めますか？ 公開はしません。」へ、利用者が明示的に「はい」と回答した。
- 利用者が現在表示されている完成物を指して、noteの新規下書きへ登録・入力・保存するよう明示的に依頼した。

この承認は、新規下書き一件、確定タイトル、本文末尾のタグ行を含む完成本文、承認時点の見出し画像と指定済み差し絵、本文内URLと指定済み追加URL、保存後に閉じて公開しないことへ結び付ける。本文文字数、見出し数、タグ数、画像、URLは内側で照合し、同じ一覧を利用者へ再表示して承認を取り直さない。

承認が確認できない場合だけ「noteの下書き登録まで進めますか？ 公開はしません。」と尋ねて待つ。Skillの引き継ぎ、ブラウザを開くこと、ログイン状態の確認、手動ログインの完了だけを理由に再承認を求めない。承認後にtitle、本文、タグ、画像、URL、対象下書きのいずれかが変わった場合、または別会話で承認を確認できない場合は、同じ確認文で改めて承認を得る。

## 操作するブラウザを選ぶ

書き込み承認後に、次の順序で今回使える操作面を確認する。利用者が今回使うブラウザまたは操作面を明示した場合は、その指定が利用可能で安全なら優先する。

1. すでにnoteを開いてログイン済みで、現在の会話から安全に操作できるブラウザ面。ローカルかクラウドかを問わず、そのまま続けられる状態を優先する。
2. CodexまたはChatGPTデスクトップアプリのローカル内蔵ブラウザ。
3. Chrome連携。
4. ChatGPT WorkのWeb、iOS、Android等で現在の会話に提供されているクラウドブラウザ。
5. コンピューター操作。

同じ条件で複数を選べる場合は、ログイン状態と生成済み画像へのアクセスを保ちやすいローカルブラウザをクラウドブラウザより優先する。ローカルブラウザが使えない、noteの操作に必要な機能を満たさない、またはクラウドブラウザの方がすでにログイン済みでそのまま続けられる場合は、クラウドブラウザを使う。コンピューター操作は他の操作面でnoteを操作できない場合だけ使う。

Chrome連携またはコンピューター操作へ移る前には、利用者の画面へ別のウインドウやタブが開く可能性があるため、「Chromeでnoteの新規下書き画面を開きます」など、使う操作面を一文だけ知らせる。切り替え理由や内部の能力一覧は説明しない。同じ下書きの途中で操作面を混在させず、現在の手段が失敗して切り替える場合も一文知らせてから続ける。

クラウドブラウザはローカルブラウザとは別セッションとして扱う。noteへのログインが必要な場合は、platformのログイン画面で利用者自身に入力してもらい、会話へID、パスワード、認証コードを送らせない。ログイン完了後、登録内容が変わっていなければ再承認なしで続ける。

すべて使えない場合は書き込みを始めず、現在の環境でブラウザ操作を有効にするか、ブラウザ操作が使えるChatGPT WorkまたはCodexで再開するよう一度だけ案内する。記事と画像は完成済みのまま維持する。

## ブラウザで新規下書きを作る

承認後、[noteエディター操作](references/note-editor-workflow.md)を読む。

1. noteを開き、主要な画面要素の描画を待ってからログイン状態を確認する。ページを開いた直後に認証済み要素が見えないことだけでは、未ログインと判定しない。
2. 初回の読み取りで判断できなければ短く待ち、画面状態を最低一度は再取得する。プロフィールメニュー、通知、メッセージ、`新規投稿`への導線等、現在のUIで認証済みと判断できる要素を確認する。
3. 再確認後もログイン画面、`ログイン`や`会員登録`等の明示的な未ログイン状態が表示され、認証済み要素がない場合だけ、利用者へ手動ログインを依頼して停止する。単に認証済み要素を取得できなかった場合は「未ログイン」と報告しない。利用者がログイン完了を知らせた後は、承認済みの登録内容が変わっていなければ同じ確認を挟まず手順4から続ける。
4. 新規のテキスト記事を作る。既存下書きは開かない。
5. タイトルを入力する。
6. 本文から`[大見出し]`と`[小見出し]`の識別子だけを除き、見出し名を独立段落として、末尾のnoteタグ行を含む本文全体を入力する。
7. 識別子が付いていた段落へ、noteの大見出しまたは小見出し書式を適用する。
8. 完成本文に独立したURL行がある場合は、URL末尾で改行してOGP表示を試す。追加URLは、指定位置の追加メニューから埋め込みとして登録する。
9. 見出し画像を設定する。
10. 差し絵がある場合は、指定段落の直後へ一枚だけ挿入し、ALTと任意のキャプションを設定する。
11. 下書き保存の完了表示または同等の保存状態を確認し、エディターを閉じる。
12. 公開前の下書き表示または下書き一覧で、非公開の下書きとして残っていることを確認する。

必須の本文書式は大見出しと小見出しだけとする。目次、区切り線、中央寄せ、引用、太字は、利用者が今回の登録内容として明示していない限り自動で追加しない。

納品済み本文のタグ行は追加生成、分離、並べ替え、言い換えをせず、本文末尾へ置いたまま保存する。タグ登録を確認するために公開設定画面へ進まず、本文末尾からタグを削除しない。このSkillではnote側の公開用タグ設定まで確定しない。

OGPが表示されなくても、正しいURLが残り、リンクとして機能していれば登録を続ける。OGP未表示を失敗条件にしない。URLが消えた、別URLになった、リンクとして機能しない場合だけ停止する。

## 検証する

次を確認する。

- 表示タイトルが確定タイトルと一致する。
- 本文の冒頭と、タグ行を含む元本文の末尾が一致する。
- 大見出しと小見出しの数が元原稿と一致する。
- `[大見出し]`や`[小見出し]`の文字が本文に残っていない。
- 納品済みnoteタグ5個または6個が本文末尾の一行に`#`付き、半角空白区切りで一致し、公開設定画面を操作していない。
- 各URLが正しいリンクとして残り、OGPが表示されたかどうかを区別できる。
- 見出し画像が設定されている。
- 差し絵がある場合、指定段落の直後に一枚だけあり、ALTと指定済みキャプションが一致する。
- 保存完了後にエディターを閉じている。
- 公開前の下書きまたは下書き一覧として確認でき、公開状態になっていない。

確認できない項目を成功扱いにしない。UI変更、選択範囲のずれ、URL消失、画像の誤選択、画像アップロード失敗が起きたら、その時点で止める。別の既存記事へ移動して埋め合わせない。

## 完了報告

保存して閉じたことを確認したら、下書きURLと次だけを短く返す。

- 新規下書きを保存して閉じたこと。
- 登録できたタイトル、本文、本文末尾タグ、見出し画像、差し絵。
- URLごとのOGP表示または通常リンクでの登録結果。
- 登録できなかった項目があれば、その一項目。
- 公開はしていないこと。

公開、予約投稿、SNS投稿を続けて実行しない。利用者が後から公開を頼んでも、このSkillの範囲外として別の明示確認を必要とする。

## 禁止

- 既存下書きの上書き、削除、差し替え。
- 公開、予約投稿、公開設定への遷移または確定。
- 複数記事の一括登録。
- ログイン情報の受領、保存、再利用。
- 目次、区切り線、中央寄せ、引用、太字の推測追加。
- URL、差し絵、挿入位置、ALT、キャプションの推測。
- UIを確認せず、座標や古い手順だけでクリックを続けること。
- 保存して閉じた状態を確認せず「登録済み」と報告すること。
