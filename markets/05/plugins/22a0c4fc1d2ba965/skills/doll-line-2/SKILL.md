# ドールラインβ

既存の `doll-line` を変更しない独立した実験ライン。人物写真から直接線画を作り、その線画を固定して彩色する。完成カラー画像を崩して人間味を作らない。

実行前に [references/style-spec.md](references/style-spec.md) と [references/anti-ai-workflow.md](references/anti-ai-workflow.md) を全文読む。

## 実行モード

実行環境に応じて次のどちらかを使う。どちらのモードでもSubject台帳、線画Gate、固定彩色、完成Gate、即時Fail条件を維持し、一発生成へ縮退しない。

### Workモード

主担当はデザインオーナーとして全工程を管理し、利用可能なサブエージェント／サブルーチン機能を使って次の3役を**逐次実行**する。同一担当による通し生成・自己採点へ置き換えない。

1. **設計・線画担当** — Subject台帳と新規構図を決め、Subject＋主Styleから線画だけを生成する。
2. **独立検査担当** — 生成には参加せず、Subject、主Style、実際の線画を原寸で比較してPass／Failを返す。Fail時は具体的な修正点を設計・線画担当へ戻す。
3. **彩色・最終調整担当** — Pass済み線画だけを固定彩色し、完成検査を行う。線画構造を変更しない。

主担当は各Gateで実画像を直接確認し、担当の自己申告だけで次へ進めない。各役への受け渡しにはSubject、主Style、直前成果物の実ファイル、Subject台帳、禁止事項、Pass条件を含める。詳細は [references/anti-ai-workflow.md](references/anti-ai-workflow.md) の「サブルーチン運用」を使う。

### Chat互換モード

サブエージェント／サブルーチン機能がない通常のChatでは、同一担当内で生成Passと検査Passを明確に分離して最後まで実行する。サブエージェントがないことだけを理由に停止したり、Workへの移動を要求したりしない。

1. Subject台帳と新規構図を確定し、Subject＋主Styleから線画だけを生成する。
2. 生成指示から独立した検査Passへ切り替え、Subject、主Style、実際の線画を原寸比較する。Failなら彩色せず線画生成へ戻る。
3. Pass済み線画だけを固定彩色し、線画構造を変更しない。
4. 彩色指示から独立した完成検査Passへ切り替え、Subject、主Style、Pass線画、完成候補を原寸比較する。
5. Fail時は原因の工程へ戻す。彩色だけの問題はPass線画から、線画由来の問題は線画生成からやり直す。

同一担当で実行しても、生成中の自己評価を検査の代用にしない。検査Passでは実画像を改めて開き、項目別にPass／Failを判定する。詳細は [references/anti-ai-workflow.md](references/anti-ai-workflow.md) の「Chat互換運用」を使う。

## 適用範囲

- 一人の人物写真だけを扱う。複数人は既存 `doll-line` を案内する。
- Subject写真は本人情報の唯一の取得元。
- 主Styleは `assets/style_refs/style_06_flat_line_primary.jpeg` の一枚だけを通常生成へ使う。
- `style_01`〜`style_05` は過去比較用で、通常生成へ渡さない。
- 主Styleの人物、顔、髪、衣装、小物、ポーズ、背景、文字、固有配色を転写しない。
- 文字はユーザー指定時だけ正確に一度入れる。未指定なら文字なし。

## Subject台帳

生成前に原寸で目視し、確認できる事実だけを記録する。

- 本人識別アンカー（ほくろ、ピアス、タトゥー等）の位置と数
- 髪型、前髪、髪色、年齢感、体形、肌色
- 衣装の形、重なり、柄、配色
- アクセサリー、ネイル、小物
- 保持すべき手の動作や所有物
- 指定文字または「文字なし」

写真のUI、撮影背景、レンズ歪み、画面枠は作品要素にしない。判別不能な細部を推測しない。

## 固定工程

1. **直接線画** — Workでは設計・線画担当、Chatでは線画生成Passが、Subject＋主Styleだけから新規構図のモノクロ線画を作る。完成済みAI絵を線画元にしない。
2. **線画検査** — Workでは独立検査担当、Chatでは独立した線画検査Passが、本人情報、衣装構造、手指、小物、文字、構図を原寸で確認する。破綻があれば彩色せず線画生成へ戻す。
3. **固定彩色** — Workでは彩色・最終調整担当、Chatでは彩色Passが、合格線画＋Subject＋主Styleを使い、線、顔配置、手、衣装、装飾、文字を変更禁止にして淡い平面彩色だけを行う。
4. **完成検査** — Workでは彩色担当と主担当、Chatでは独立した完成検査Passが、Subject保持、線画保持、彩色文法、解剖、文字を確認する。実画像による確認を最終Gateとする。
5. **顔候補は例外** — 完成作の目だけが過剰に光沢化した場合のみ顔案を一度作れる。生命感または本人らしさが低下した案は不採用。顔以外まで変わった案はそのまま使わず、必要な場合だけ顔内部を元画像へ局所合成する。

具体的な参照順、prompt要件、停止条件は [references/anti-ai-workflow.md](references/anti-ai-workflow.md) に従う。

## 合格基準

- 細い線の精密さと、少数の淡い色面による単純さが同居する。
- AI特有の全面的な艶、立体陰影、均一なデジタル塗りが目立たない。
- 人物の髪、衣装、装飾、識別アンカー、手や小物がSubjectと一致する。
- 目は簡略化されても視線と生命感を失わない。
- 人間味は形の選択、わずかな左右差、情報の省略から生じる。汚し加工では作らない。
- 構図はSubject写真にも主Styleにも依存したトレースでない。

「下手くそ」は合格条件にしない。本βが再現するのは、精密線と単純な彩色、わずかな非均整である。技術的な未熟さを確実に再現できたとは扱わない。

## 即時Fail

- generic photo-to-anime、商業アニメ風の完全な均整、写実的な美容絵
- 完成後の点線化、線切れ、scribble、grunge、全面grain、色版ずれ、ぼかし
- 平坦化しすぎて目の焦点、表情、本人らしさが消える
- 線画彩色時に顔、髪、手、衣装、文字を描き直す
- 主Styleの人物、服、ケーキ、フォーク、ポーズ、構図、背景記号、文字の転写
- 手指、関節、衣装構造、小物、文字の破綻

Fail画像を完成扱いしない。線画Failは線画から、彩色Failは合格線画からやり直す。

通常の「ドールライン」指定には本スキルを使わず、既存 `doll-line` を使用する。
