# Diagnostic checklist

- [ ] The use case is legitimate and authorized.
- [ ] The exact symptom and redacted error are known.
- [ ] Host and port match the current documentation.
- [ ] HTTP(S) versus SOCKS5 is selected correctly in the client.
- [ ] Credentials remain private and have not been pasted into chat.
- [ ] Proxy authentication is supported by the application.
- [ ] A single low-concurrency request has been tested.
- [ ] Another client or destination has been tested to isolate the failing layer.
- [ ] Rotation or sticky-session parameters are intentional and consistent.
- [ ] Visible IP, country, DNS, and WebRTC are checked by the user.
- [ ] Local VPN, firewall, split tunnel, and bypass rules are considered.
- [ ] Current inventory, plan limits, and account state are confirmed through official pages or support.
