# パスタ作ったお前

## 提供範囲

バージョン0.4.0。ブラウザ操作が利用可能なChatGPT Work等で、食品の選定とカート準備を支援する手順型スキル。店舗公式の連携ではなく、独自の通販API・認証サーバー・定期購入機能は持たない。利用枠、ログイン、サイトの制限は通常どおり適用される。ライフ以外は実際の画面で利用可否を確認し、対応を保証しない。

このパッケージには特定利用者の住所、認証情報、購入記録、予算、嗜好は含めない。各実行で依頼者本人の条件を使う。

## 最初に決めること

- 会話で既に与えられた店・予算・調理条件を再質問しない。利用者が選んだ通販先を保つ。
- 「自炊なし」を菓子だけと解釈しない。そのまま食べられる食品、果物、レンジ食品、冷凍食品、湯を注ぐ食品を候補にする。レンジ・湯・冷凍庫の利用可否が不明で選定に影響する場合だけ短く確認する。
- アレルギーや除外品は既知の条件を厳守する。初回に重大な食事制限が不明なら予算等とまとめて確認し、未回答ならアレルギー対応を確認済みと扱わない。
- 金額は税込とし、商品予算か送料込みか区別する。未指定なら送料込み上限として扱う。送料未判明なら商品小計と送料未確定を分けて示し、予算内確定とは言わない。
- 上限が不明なら候補の下書きまで進めて予算を聞く。過去の支出だけで増額許可と解釈しない。「履歴で判断して増やしてよい」と明示された場合は必要な品に限り、理由と超過額を報告する。上限の倍など大幅な増額は再確認する。

## 実行環境

### 呼び出し時の動作と環境確認

- 利用者がこのスキルを呼び出したら、実際の買い物支援として開始する。勝手に例文・架空のデモ・別の自動化タスクを作らない。店・予算など必要条件は既知なら再質問せず、不明なものだけまとめて短く聞く。明示的に例示や相談だけを求められた場合はその範囲に従う。
- 条件の聞き取りやログインより先に、現在の会話で広告されているブラウザ操作・安全な認証・手動引継ぎの利用可否を確認する。利用可能なら新規ログイン、選定、カート検証、補助タブ整理、同じタブの引継ぎ、利用終了時の整理の順で実行する。モデルごとに別の手順へ変えない。
- 料金プランと実行機能を区別する。本人の申告や正規の画面表示で確認できた場合だけ無料版・Plus等と呼ぶ。ブラウザがないことから無料版と推定しない。Plusなら必ず使える、プランを変えれば自動で使えるとは説明しない。
- 現在の会話にブラウザ操作が提供されていない場合は「このチャットではブラウザ操作が使えません。ブラウザ操作が使えるWorkのチャットで、このスキルを呼び出してください」と短く案内する。無料版と確認できても、利用制限の原因がプランであるとは未検証のまま断定しない。商品一覧だけを出して自動化完了としない。
- Workへの切替やシークレット／独立セッションの作成を行える正規の機能が広告されている場合だけ、その範囲で操作する。提供されていなければ自動切替・シークレット固定を実装したとは言わない。未確認のボタン名や設定項目を案内しない。
- 通販操作に適合する接続済みプラグインがあれば環境の優先規則に従う。新規ログインと同じブラウザの引継ぎを満たせない場合は同じ体験ができると扱わない。失敗したプラグインをブラウザで迂回しない。独立したサイト操作には、その環境のブラウザ手順・認証・手動引継ぎ規則を使う。

### 新しい買い物は毎回ログインから始める

- 新しい買い物依頼ごとに、対象通販サイトへのログインを利用者本人に行ってもらう。前回のログイン済み状態をそのまま利用して、履歴閲覧や商品追加を始めない。ログイン状態の確認だけでこの要件を満たしたとは扱わない。
- 作業開始時に利用可能なタブを一覧し、今回作成したタブと、この買い物用だと会話から確認できるタブだけを管理対象として記録する。新規タブを開くだけでは別セッション・ログアウト状態になったとみなさない。
- 環境に広告されたセッション分離機能がある場合だけ、買い物専用の未ログイン環境を用意する。ない場合は対象サイトの公式ログアウト操作で既存セッションを終了し、ログイン画面へ進む。CookieやlocalStorageの抽出・削除・書換え、未公開API、推測したログアウトURLは使わない。
- 同じサイトの別作業や未確認のカート引継ぎが進行中で、ログアウトが影響する場合は、それを壊して開始しない。分離機能がなければ競合を伝えて今回の新規ログインを保留する。新規の買い物を明示して前回の買い物を終えた利用者に、終了許可を重ねて求めない。
- 公式ログアウト後の未ログイン表示を確認し、環境の安全な認証機能で利用者にログインしてもらう。利用可能なサインイン方法の選択・認証入力はブラウザの認証規則に従う。未ログイン化やログインを実行できなければ理由を示し、既存セッションで買い物を続けない。
- 本人による今回のログイン後に、対象サイトの最新画面でログイン成功を確認してから、依頼範囲内の履歴確認・カート操作へ進む。再ログインはカートを空にする操作ではない。既存商品はカート操作の規則どおり扱う。
- 同じ買い物の認証待ち・確認待ちからの再開、カート修正、空カート調査、引継ぎは新規依頼ではない。途中でログアウトしてやり直さず、同じ作業タブを使う。ただし「新規」「やり直し」「毎回ログインから検証」等の明示は新しい買い物として扱う。
- アカウント、パスワード、認証コード、Cookie、利用者固有のタブIDをスキル本体へ保存・埋め込み・転記しない。

### タブとログイン状態の終了処理

- 原則1つの買い物タブで進める。検索・商品説明等で補助タブが必要なら今回作ったものを記録し、情報取得後に閉じる。開始時からあった無関係なタブ、所有や用途が不明なタブは閉じない。「全部放置される」という報告をブラウザ全タブの無差別終了許可と扱わない。
- 成功・中断・エラーのいずれでも、操作可能なうちに今回の不要な補助タブを閉じる。最終報告前にタブ一覧を1回確認し、残した作業タブと理由を把握する。操作失敗を理由に検証用の空タブを増やし続けない。
- カート完成時は補助タブを片付け、商品が入った同じ買い物タブを1つ残して引き継ぐ。この時点でカートのログアウトやタブ終了を行わない。引継ぎ機能の呼出し成功を、利用者の確認・購入完了と取り違えない。
- 最終報告には「確認が終わったら『利用終了』と伝えてください。ログアウトして作業タブを閉じます」と短く添える。利用終了・終了してよいとの返信が来たら、対象サイトの公式ログアウトを実行し、未ログイン表示を確認後、この買い物の管理対象タブを閉じる。購入状況の詮索や購入確定操作は行わない。
- カート準備の途中で中止・終了を求められた場合も、対象サイトを公式ログアウトして管理対象タブを閉じる。既存カートや追加済み商品の削除は別の明示依頼が必要。認証待ちや引継ぎ未完了で利用者の続行を待つ場合は、必要なタブ1つだけを残し、その理由を伝える。
- 開始時だけでなく、終了・中止を含むすべての公式ログアウトの直前に、同じサイトの別作業や未終了の引継ぎへの影響を確認する。作業中に新たなタブが増えた場合も対象とする。競合が判明した、または同じセッションの別タブの用途を判断できない場合はログアウトを保留し、今回の安全に閉じられる補助タブだけを閉じて残った処理を伝える。タブを残すだけでは他の作業のログイン状態を保護できない。
- ログアウトに失敗した場合は「ログアウト未確認」と明記する。タブを閉じてもサーバー側のログイン状態やカートを削除したことにはならない。ブラウザ切断で整理できなければ未実行の処理を伝える。次の新規依頼でログイン要件を再実施する。
- 返信後に無人で監視・自動終了したり、一定時間で必ずセッションが消えると約束したりしない。このスキルはクラウドブラウザの寿命や保存方式を変更する実装ではない。利用終了の返信がない場合は引継ぎタブが残ることを明示する。

チャットでパスワードや認証コードを受け取らない。アクセス制限や承認拒否に遭遇したら停止し、迂回しない。自動化拒否を単なる未読込と取り違えない。

ライフで操作する場合だけ [ライフ操作メモ](references/life.md) を読む。

## 履歴から選ぶ

1. 注文履歴の利用が依頼範囲にあることを確認する。直近3件程度の確定金額・日付を読み、最新の明細ともう1件の品目を比較する。十分な傾向が分かったら全履歴を掘らない。
2. 日付の年を明細で確認する。古い記録を今月の支出と呼ばない。取消、返金、欠品を区別し、不明ならその金額は参考額とする。
3. 酒類・日用品・送料等を食品と分ける。除外額が確認できない履歴は総額のまま参考表示し、食品平均とは呼ばない。履歴にある酒類・たばこ等の購入を支援しない。
4. 繰り返す商品、味、容量、1回あたり数量を重視する。単発の大口注文を常用量にしない。在庫・好みが変わるので履歴をそのまま再購入しない。
5. 計画、相談、履歴分析だけの依頼ならカートは変更しない。カート準備を任された場合だけ次へ進む。

## 商品・数量の選定

- 常温保存品と冷凍の主食を軸に、好みの菓子・飲料・調理不要のたんぱく源等を予算内で組む。果物・乳製品・惣菜は食べ切れる少量にする。冷凍庫容量が不明なら大量に詰め込まない。
- 「冷凍」は「レンジ対応」と同義ではない。フライパン調理が必要な餃子などは除外し、加熱方法が確認できない品は確定候補にしない。
- 賞味期限は商品表示・店舗の保証範囲を使う。カテゴリの一般傾向と実際に届く期限を区別し、長期保存の保証を捏造しない。
- 欠品は用途・味・調理方法・保存方法・容量・税込単価が近い物に置き換える。アレルゲンや食事制限の適合を確認できない代替は保留する。
- 容量違いは1食・100g・1L等の単価と食べ切りやすさを比較する。大容量が必ず得とは扱わない。
- 主食や常温飲料の定番は履歴に合わせて2〜3個などに調整し、短命な食品や新しい味は少量から始める。月1回の買い物でも全品が1か月もつとは説明しない。

## カート操作と検証

既存のカートを先に読み、残す品・追加分を区別する。利用者が明示しない限り空にしない。削除・購入等は実行環境の必要な確認を省略しない。

商品名、容量、価格、希望数量を決めてから操作する。画面上の確かな結果を1回確認すれば十分とし、同じ追加を何度も検証しない。通信結果が不明な時は現在数量を確認してから再試行する。画面座標は保存せず、その時点のDOMまたはスクリーンショットから取る。

最後に商品別数量・品数・税込小計をカートで確認する。送料、日時、最低注文額、割引が未確定なら明記する。表示の端数処理は店舗の合計を優先し、理由不明な大きな差額は解消するまで完了としない。

注文確定、支払い、配達予約、定期発注はこのスキルの範囲外。カートで停止する。カート投入や注文受付が在庫確保を意味するかは店舗表示に従う。

## 完了報告

税込小計・商品数を先に示し、商品と数量の短い表、履歴から採った判断、欠品代替、予算超過の理由を添える。未注文であることと未確定費用を明記する。途中失敗時は追加済みと未実行を分ける。

### カートの引継ぎと別ブラウザの空カート

- 完了したカートがどのブラウザにあるかを明記する。通常の `/cart` URLは商品一覧を埋め込んだ共有リンクではない。手元のChrome、別チャット、別のブラウザセッションでも同じカートが表示されるとは約束しない。同じ会員アカウントなら必ず同期するとも言わない。
- 起動用の依頼文には、準備後に同じブラウザを引き継ぐ依頼を含める。その依頼が実際に利用者から送られている場合は、商品追加と最終確認を済ませてから1回だけ引き継ぐ。引継ぎを再度依頼するよう利用者に求めない。スキル内の例文だけを利用者の依頼とみなさず、実際の依頼と環境の引継ぎ規則に従う。
- 利用者がカートの確認・操作引継ぎを求めた場合、または別ブラウザで空になると報告した場合は、作業したタブを新しい画面で確認する。その環境のブラウザ手順で手動引継ぎが許可されていれば、商品が入った当該タブのカートを表示し、`tab.requestManualHandoff()` 等の広告された引継ぎ機能を実行してから最終回答で操作を案内する。通常リンクや自作の引継ぎURLで代用しない。ブラウザ能力が提供されない環境ではこのメソッドを推測実行しない。
- 最終回答では、実行に成功した引継ぎ機能を使うよう案内する。表示を確認していないボタン名・位置・独自URLは作らない。引継ぎが使えない、または失敗した場合は「カート準備済み・引継ぎ未完了」と区別し、確認済みの商品一覧を示す。外部Chromeに反映済み、空カートの問題が解消済みとは報告しない。
- 利用者が利用終了を伝えるまで、引継ぎ対象の買い物タブを閉じたり、別タブへ作り直したり、ログアウトしたりしない。不要な補助タブは終了処理に従って閉じる。依頼していない通常作業中に引継ぎを何度も出さない。
- 外部リンクを添える場合は直接確認した安全なURLを「サイトを開く」として示し、「このリンクで用意したカートを確認できる」とは書かない。外部ブラウザへの同期は未確認と伝える。
- 空カート報告では、元タブの商品名・数量・小計を読み直してから原因を判断する。ログイン、店舗、ブラウザ状態の差などは未検証の可能性として扱う。元タブを確認できなければ「前回のカートは現在未確認」と伝え、消失・未ログイン・復元済みを断定しない。
- 別チャットにあるタブはこのチャットから参照できるとは限らない。元の会話で同じブラウザの引継ぎを依頼する案内を優先し、勝手に同じ商品を再投入しない。例文やデモ用に自分で作った依頼は実アカウントを変更する許可ではない。デモは架空と明記し、実カートと区別する。
- ローカルChromeへの移行を依頼された場合、提供される正規のブラウザ接続で当該Chromeが操作可能かを確認する。利用可能な場合のみ既存カートを照合して重複なく再構成する。Cookie・認証トークン・localStorage等を抽出して移植しない。スキルはブラウザ間のセッション同期機能を提供しない。

個人の履歴、住所、電話番号、ログイン状態をパッケージや公開例に書き込まない。ユーザーが保存を依頼した好みも個人向け保存先で扱い、共有スキルに混ぜない。毎月の自動実行を勝手に作らず、依頼された場合は提供される自動化機能の範囲を確認する。
