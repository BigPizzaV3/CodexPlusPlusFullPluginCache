# 디자인 검토 체크리스트

## 감성 및 정체성

- [ ] 과한 핑크·하트 대신 두 사람의 기억 매체에서 출발한 시각 언어인가?
- [ ] 이름과 날짜가 없어도 교체 가능한 자리표시자가 분명한가?
- [ ] 사진이 없는 카드도 날짜·문장·장소·태그로 충분히 읽히는가?
- [ ] 샘플 추억은 실제 데이터처럼 저장하거나 사실처럼 제시하지 않는가?

## 모바일과 접근성

- [ ] 첫 화면에서 기록지의 핵심 가치와 `기록 추가` 행동이 보이는가?
- [ ] 필수 터치 영역이 44×44px 이상인가?
- [ ] 한 손으로 쓰기 쉬운 작성 흐름과 하단 내비게이션을 고려했는가?
- [ ] 본문·보조 텍스트·상태 색상이 충분한 대비를 갖는가?
- [ ] 포커스 링, 키보드 순서, 필드 오류 텍스트, 아이콘 이름이 있는가?
- [ ] 모션을 줄이는 환경에서도 정보와 조작이 유지되는가?

## 기록과 개인정보

- [ ] 초대 철회·링크 만료, 전체 내보내기·복원 시험, 삭제 예약·영구 삭제, 백업 최종 파기 시점이 서로 모순 없이 정의되어 있는가?

- [ ] 날짜 값은 `YYYY-MM-DD`로 처리해 시간대 이동을 피하는가?
- [ ] 기록 본문·사진·장소가 URL, 분석 이벤트, 공개 저장소에 들어가지 않는가?
- [ ] 로컬 저장은 기기·브라우저마다 분리됨을 명시하는가?
- [ ] 백업·복원·삭제가 데이터를 덮어쓸 수 있음을 알리는가?
- [ ] 공유형 서비스의 인증·권한·비공개 저장소를 별도 전제로 두는가?

## 구현성

- [ ] 컴포넌트와 상태가 한 화면에서 지나치게 얽히지 않았는가?
- [ ] 비어 있는 상태, 검색 결과 없음, 저장 실패, 손상된 백업을 다루는가?
- [ ] P0 완료 뒤에도 P1/P2로 자연스럽게 확장할 수 있는가?
- [ ] 정적 배포에서 SPA 경로 새로고침과 환경 변수 노출을 점검했는가?
