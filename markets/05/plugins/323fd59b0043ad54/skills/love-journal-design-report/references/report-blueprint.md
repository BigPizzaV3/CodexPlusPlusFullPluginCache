# 리포트 청사진

아래 순서로 Markdown 리포트를 작성한다. 프로젝트 규모가 작아도 `개요`, `MVP`, `화면`, `결정 로그`, `수용 기준`은 생략하지 않는다.

## 1. 한눈에 보기

- 제품 한 줄: 누구를 위한 어떤 기록 공간인지
- 목표: 사용자가 반복해서 하게 될 핵심 행동 1–2개
- 사실 / 가정: 제공 정보와 디자인 가정을 분리
- 방향 키워드: 3개 이내

## 2. 사용자 경험과 정보 구조

- 대표 흐름: 첫 설정 → 첫 기록 → 다시 보기 → 백업/공유
- 화면 맵: 오늘, 기록, 작성, 상세, 우리/설정
- MVP / 다음 단계 / 제외 기능 표

## 3. 화면 설계

화면마다 다음을 적는다.

| 화면 | 목적 | 핵심 콘텐츠 | 1차 행동 | 빈/오류 상태 |
| --- | --- | --- | --- | --- |

홈 화면에는 작은 텍스트 와이어프레임을 포함한다. 모바일 순서를 먼저 보이고, 데스크톱에서 변하는 레이아웃만 추가한다.

## 4. 시각 시스템

- 색상 토큰 표와 사용 규칙
- 제목·본문·날짜의 타이포그래피 역할
- 카드·타임라인·태그·버튼·모달/시트 명세
- 이미지가 없을 때의 기억 표지 규칙
- 모션, `prefers-reduced-motion`, 포커스와 대비 규칙

## 5. 콘텐츠와 데이터

- 문체와 UI 카피 원칙
- 기록 스키마와 필수/선택 값
- 사진, 백업, 삭제, 초대의 개인정보 경계
- 로컬 우선과 공유형 서비스의 차이

## 6. 구현 순서와 검증

- P0 / P1 / P2 구현 목록 및 완료 조건
- 결정 로그 표: `결정 | 이유 | 대안 | 변경 비용`
- 수용 기준 체크리스트
- 배포 전 체크리스트

## 7. 확인이 필요한 사항

결과 품질에 큰 영향을 주는 미결정만 1–3개 적는다. 예: 기념일 기준일, 단일 기기/공유 여부, 사진 보관 방식.
