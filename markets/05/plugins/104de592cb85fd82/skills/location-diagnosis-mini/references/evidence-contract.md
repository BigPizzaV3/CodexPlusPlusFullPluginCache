# 根拠・診断契約

## 根拠状態

| 値 | 表示 | 条件 |
|---|---|---|
| `confirmed` | 確認済み | 開いた本文で地点、内容、時点を確認した |
| `estimated` | 推定 | 1件以上の確認済み事実から限定的に推定した |
| `reference` | 参考情報 | portal、review、まとめ等の補助情報 |
| `not_found` | 公開情報では確認できず | 調べたが信頼できる公開情報へ到達しない。不存在ではない |
| `field_check` | 現地・資料確認が必要 | 公開Webだけで確定しない動線、物件、設備、地番照合等 |

`estimated`は断定文にせず、source IDを最低1つ付ける。`not_found`を「ない」、`field_check`を「不適合」へ変えない。

## 行政データ取得状態

| 値 | 条件 |
|---|---|
| `取得済み` | 対象範囲、年次、本文を確認済み |
| `上位地域で代替` | 小地域値でなく市区町村等の公表値を範囲明記で使用 |
| `地点照合が必要` | データはあるが住所と町丁、mesh、駅、道路区間等の追加照合が必要 |
| `初期診断では未取得` | 正規routeとfallbackを試したが公開Web調査では未取得 |
| `対象外` | 業態lensや移動手段に対応しない候補指標 |

上の5状態は個別metricへ使う。`一部未取得`はD1〜D4の集約表示専用で、個別metricには使わない。

取得状態はAIの性能点ではない。未取得を一律に`APIが必要`へ変換せず、統計表の直接処理、GIS照合、契約データ、物件資料、現地実測等の実際の次工程を示す。

複数指標をまとめるD1〜D4の取得状態は、個別指標を楽観側へ丸めず、次の優先順で集約する。

1. 必要な指標に住所・駅・道路区間等の未照合が残る: `地点照合が必要`
2. 未照合はなく、`取得済み`または`上位地域で代替`と`初期診断では未取得`が混在する: `一部未取得`
3. 必要な指標を全て公開Web調査で取得できない: `初期診断では未取得`
4. 必要な指標を上位地域の値だけで代替した: `上位地域で代替`
5. 必要な指標をすべて対象範囲で確認した: `取得済み`
6. 業態lens上、その指標群を使わない: `対象外`

取得できた指標と未取得・未照合の指標が同じD番号に混在する場合、取得できた指標の数値やgraphは残してよい。ただし、D番号全体の取得状態は上の優先順で表示する。

## source優先順位

1. 国、自治体、統計、鉄道、道路等の公式情報
2. 対象施設、店舗、運営会社等の公式情報
3. 発信主体が明確なpress release
4. 報道機関
5. portal、review、まとめ

上位sourceでも地点や時点が違えば採用しない。検索結果ページとsnippetはsourceにしない。開けなかったURLをsource registerへ入れない。

## source record

各sourceへ次を持たせる。

- `S1`からの一意なID
- page title
- 完全URL
- 発信主体
- 確認日
- 情報時点。確認できない時は空にせず`情報時点の明示なし`
- supportするR番号

## conflict

日付、発信主体、対象範囲、住所表記を比較する。解消できない時は勝手に片方へ寄せず、何が一致せず、何を確認すれば判断が変わるかを書く。

## 一次判定gate

一次判定は、公開情報で確認できた根拠にもとづき、この地点・業態で出店の検討をどう進めるかを1〜5で示す。成功確率、売上見込み、出店可否の最終判断ではない。未確認を0や不利な事実へ置き換えず、判定とは別に根拠確度と必須確認へ送る。

### 5 / 5 積極検討

- R2、R3、R4が`confirmed`または`estimated`
- 8軸中7軸以上が`confirmed`または`estimated`
- critical unknown、不一致、confirmed blockerが0件
- 複数の支持材料が懸念を明確に上回る

### 4 / 5 前向きに検討

- R2、R3、R4が`confirmed`または`estimated`
- 8軸中5軸以上が`confirmed`または`estimated`
- confirmed blockerが0件
- critical unknownは1件以内
- 支持材料が懸念を明確に上回る

### 3 / 5 条件次第

支持材料と懸念が拮抗している。情報不足を自動的に3へ置かず、確認済みの方向性を読み、根拠確度を別に下げる。

### 2 / 5 見送り寄り

確認済みまたは限定的に推定できる懸念が支持材料を明確に上回る。confirmed blockerがない不利な地点に使う。

### 1 / 5 見送り推奨

対象地点と一致した重大阻害要因を強いsourceで確認済み。需要材料の多さでblockerを相殺しない。confirmed blockerがない場合は1を許可しない。

## 根拠確度

- `high`: 7軸以上が`confirmed`または`estimated`でcritical unknown・不一致0件、または1 / 5を決めるconfirmed blockerがある
- `medium`: 5軸以上が`confirmed`または`estimated`、critical unknown 2件以内、不一致1件以内
- `low`: 上記以外

根拠確度は判定の方向ではなく、その判定を支える公開情報の到達度を示す。住所未確定またはWeb検索・本文確認不能は`low`にせず、判定自体を作らない。

## claim test

重要文ごとに確認する。

1. source本文で確認した事実か。
2. 事実でなければ、どの根拠状態か。
3. その違いを表示から読めるか。
4. その文が結論に必要なら、source IDと地点一致を再確認したか。
5. 不利な証拠または反証検索を無視していないか。
6. sourceの集計区分を別の期間・日種・対象者区分へ読み替えていないか。
7. 同じsource内に、現在値として使えるより新しい同一定義の時点がないか。
