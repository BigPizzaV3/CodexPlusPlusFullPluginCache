# 調査契約

## 目次

1. 地点同定

## 1. 地点同定

住所を都道府県、市区町村、町名、番地、建物へ分け、自治体、郵便番号、施設公式情報等で一意性を確認する。候補が複数ある時は混ぜず、利用者確認まで止める。移転や住所表記の揺れがある場合は、その履歴を別の事実として扱う。

## 2. 業態lens

次を内部で定義する。

- 主な来店目的
- 徒歩、鉄道、車、または複合の移動手段
- 需要が現れやすい時間帯
- 直接競合: 同じ用事を同じ方法で解決するもの
- 代替競合: 同じ用事を別の方法で解決するもの
- 相乗施設
- 重大になり得る立地risk

未知の業態では汎用lensを使い、その前提を表示する。内部weightや採点表を作らない。

## 3. 行政・活動データ

検索で偶然見つかった数値だけで完了にしない。次を固定順で取得試行する。

### D1 居住需要

- 町丁・大字等の人口、世帯数、年齢構成、比較可能な人口増減
- 全国共通の最初のrouteは国勢調査の小地域集計
- 自治体の推計人口や住民基本台帳は、年次と範囲を分けた鮮度補完
- 異なる境界や定義の値から増減率を作らない

### D2 事業集積

- 町丁・大字等の事業所数、従業者数
- 全国共通の最初のrouteは経済センサスの小地域集計
- 事業所数を同業競合数と読み替えない

### D3 活動需要

- 徒歩・鉄道型: 駅乗降客数、昼間人口、就業者、通学者から適切な指標
- 車型: 国または自治体の公表道路交通量
- 複合型: 徒歩・鉄道と車の双方を試行
- 朝、深夜、試合前後等の特定時間帯が業態成立の中心なら、その時間帯の活動量を必要指標として追加する。公開Webで取得できなくてもmetricから省略しない
- 駅、道路区間、meshと住所の一致を説明できない値は地点値にしない

### D4 変化・制約

- 将来人口、再開発、都市計画、用途地域、災害risk
- 計画、着工、開業済みを分ける
- polygon、mesh、道路segment等は地点一致を説明できる時だけ地点の事実にする

各D番号では、取得できた指標だけでなく、業態lens上必要なのに未照合・未取得となった指標もmetricとして残す。未照合・未取得のmetricは値を0にせず、`display_value`、年次、範囲、取得状態で何が不足したかを示す。D番号全体の取得状態は[evidence-contract.md](evidence-contract.md)の保守的な集約順に従う。同じ公表資料に同一定義の複数時点が収録されている場合、現在値には調査日時点で利用可能な最新時点を使う。古い時点を使う場合は、比較可能性、訂正、速報・確報等の理由を記録する。

sourceの集計区分を維持する。`主催公式戦以外`、`その他イベント`、`定期外`等を、sourceが明示していない`非試合日`、`観戦日以外`、`観光客`等へ置き換えない。別区分の需要を述べる場合は、その区分を直接確認した別sourceまたは限定的な推定根拠を付ける。

## 4. R1〜R8

| ID | 論点 | 最低確認事項 |
|---|---|---|
| R1 | 地点同定と周辺性格 | 正式住所、建物・街区、最寄り駅・主要道路、駅前・住宅地・商業地等の性格 |
| R2 | アクセス | 鉄道、bus、道路、駐車、横断、出入口。公開情報で確定しない動線は現地確認へ送る |
| R3 | 需要背景 | D1居住、D2事業集積、D3活動を分け、年次・範囲・取得状態を示す |
| R4 | 直接・代替競合 | 公式店舗情報を優先し、件数だけで飽和や需要を断定しない |
| R5 | 相乗施設・集客施設 | 施設の利用者、時間帯、目的と対象業態の適合を分ける |
| R6 | 街の変化 | 再開発、道路・駅整備、開業・閉館・建替え。段階と時点を示す |
| R7 | 用途・災害risk | 公式確認導線を示し、地点一致できない時は該当断定をしない |
| R8 | 最近の変化信号 | 公式の新店・閉店・移転、press release、報道。SNSだけなら参考に留める |

## 5. 多段調査

### Pass A: breadth

R1〜R8とD1〜D4を固定順で一巡し、空欄を可視化する。最初から一つの論点へ寄りすぎない。

### Pass B: industry depth

業態lensから判断に効く1〜3論点を選ぶ。例: カフェの時間帯需要、roadside小売の入出庫、医療serviceの昼間人口と競合診療科。一般論を増やさず、対象地点で確かめられる証拠へつなぐ。

### Pass C: negative sweep

`閉店`、`移転`、`休止`、`工事`、`規制`、`浸水`、`通行止め`等、業態と地点に合う反証語で調べる。有利なsourceの確認だけで終了しない。

### Pass D: audit

各主張について、地点、時点、範囲、発信主体、supportするR番号を確認する。結論を反転し得る未確認、不一致、重大阻害要因を別に残す。

### Pass E: semantic and copy audit

- sourceの集計区分を狭めたり広げたりしていないか確認する
- 同一資料の最初の表やpageだけで止まらず、最新時点まで確認する
- 業態lens上必要な未取得指標がmetricから落ちていないか確認する
- 業態適合所見と競合・相乗所見の題名・説明が重複していないか確認する
- 結論、lead、所見の助詞、主述、重複を日本語として読み直す

## 6. 終了条件

- 住所が一意でない: 質問して停止
- Web本文を開けない: 確認済みにせず格下げ
- sourceが衝突し解消不能: conflictとして残す
- 正規routeとfallbackを試しても未取得: 理由と次の取得方法を記録
- R1〜R8が一巡し、追加sourceが既存主張の重複だけ: 調査終了
- 重要なaccess、需要、競合または結論反転級の情報が欠ける: 調査を水増しせず、確認できた方向性で一次判定を付け、根拠確度を下げて必須確認へ送る
