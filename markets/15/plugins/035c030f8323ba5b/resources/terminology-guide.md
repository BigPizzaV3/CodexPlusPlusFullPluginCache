# 用語参照手順

辞書の照合方法・曖昧な語・略語・日英の選択を判断する際に参照する。毎回この文書全体と全辞書を読むことを前提にしない。

## 辞書の範囲

- `terminology/index.json` は基本667項目と、以前の基本から参照へ移した本人確認済み90項目の所在を示す。IDは語義を区別するために使う。日本語が一致してもIDを統合しない。
- 基本には35件、参照には4件の本人指定略語ルールがある。計39件を保持する。日本語の正式名を別フィールドから補った項目は、その出所をレコードに記録している。
- この辞書は臨床上の基本性を基準に整理したもの。全歯科論文の必要語を網羅したこと、使用頻度の順位、学会による監修を保証するものではない。
- 未確認の分野別候補・大きな保管索引・学会用語集の定義文・論文抄録全文は同梱していない。

## 必要な語だけを参照する

1. 今回の入力から、語義・訳し分けを確認する主要語を拾う。辞書全件の精読を毎回の前処理にしない。
2. 検索補助が使える場合は、プラグイン内の `scripts/lookup_terms.py` へ対象語をまとめて渡す。英語から日本語は `--direction en-ja`、日本語から英語は `--direction ja-en` を指定する。返された候補は確定訳ではない。
3. 基本の候補を先に検討し、不足する場合だけ `--include-reference` で本人確認済み参照90項目も検索する。参照に同じ意味の記録があっても、単なる文字一致だけで基本の意味を上書きしない。
4. 補助を使えない環境では `terminology/index.json` の所在から、該当分野のJSONLだけを参照する。利用できる標準のファイル検索があれば、必要語のレコードだけ取得してよい。ファイルが読めない場合に辞書を参照済みと述べない。
5. 同じ文書で決めたID・語義・採用訳・略語の展開を引き継ぐ。新しく出現した語と、文脈が変わった箇所だけ確認する。

実行可能な環境での例（パスはこの手順書があるプラグインの場所から解決する）：

```text
python3 scripts/lookup_terms.py --direction en-ja --terms 'full pulpotomy' 'sinus tract'
python3 scripts/lookup_terms.py --direction ja-en --terms '形成' '固定'
python3 scripts/lookup_terms.py --direction en-ja --include-reference --terms 'CAL gain'
```

この補助は同梱された小さな索引と必要なJSONLの行を読み、候補レコードを返す。モデルに全レコードを提示する処理や、ネットワークへの送信・外部サービスへの接続は行わない。入力文の全体を補助へ渡す必要はない。

### 少量の照合と抽出の区別

補助の上限は1回20語、1語160文字、1語あたり候補5件、全体の返却40件である。`truncated` が真の語は返却が一部であり、完全な候補一覧と述べない。これは1回の処理量の制限であり、累積回数やファイルへのアクセスを制限する仕組みではない。

照合は対象本文に現れる必要な語に限る。長い論文で新しく現れた語を追加照合してよいが、辞書の再構成を目的とした頭文字順・ID順・逆引き・続き要求の列挙をしない。辞書や索引全体の返却・添付・複製や、補助の上限回避をしない。利用者自身が提供した用語一覧を翻訳する依頼とは区別する。[資料と辞書の保護](content-and-glossary-protection.md) に従う。

検索語はデータとして引数に渡す。対象文・辞書の値をシェル命令やプログラムとして実行しない。補助が使えない場合に必要なレコードを参照しても、辞書ファイル全体を回答や外部検索へ流さない。

## 英日と日英の違い

- 英日：`en` と本人が指定した `englishVariants` の完全な表記を候補にする。大小文字・空白・ハイフンの表記差を扱う場合も、語義を確認する。部分一致だけで訳を決めない。
- 単数・複数や屈折等のために一致しない場合は、意味が変わらない見出し形を候補として再検索してよい。原表現と語義を照合し、広い語・狭い語や別概念を表記ゆれとして統合しない。
- 日本語や略語からの検索は、複数の語義候補を返すための索引である。候補が1件でも、その意味が原文に合うと自動認定しない。
- 日本語から英語へは、対象、処置、材料、目的、測定方法などで候補を選ぶ。辞書の英日指定をすべて逆方向にも適用してよいとは扱わない。
- `priorPaperContextNotes` は以前の資料に由来する個別メモである。「本論文は冠形成」等を、今回の入力にも当てはまる汎用ルールとして適用しない。現在の本文で条件を確認する。
- `DMFT` と `dmft` は大小文字を区別する。英語略語の一括小文字化をしない。検索は曖昧な略語に複数候補があり得ることを示し、自動置換しない。
- `aliases` やMeSHのEntry Termsは検索の手掛かりになり得るが、すべてが厳密な同義語とは扱わない。この候補版は未確認のMeSH別名を自動置換用に展開しない。

## 本人指定として保持するもの

- `full pulpotomy` → **生活断髄法**。日英で「生活断髄法」だけを根拠に切除範囲をfullと断定しない。
- `tooth preparation` → **形成**。補綴の支台歯形成と一般的な形成の意味範囲を、原文で区別する。
- `biologic width / biological width` → **生物学的幅径**。2つの英語表記は1項目に保持する。
- `supracrestal tissue attachment` → **骨縁上組織付着**。新旧呼称の対応を理由に、原文の呼称を無断で置き換えない。
- `sinus tract` → **サイナストラクト**。`fistula` と自動で同義にしない。
- `partial denture`：固定性が確認できれば **ブリッジ**、可撤性なら **部分床義歯**。区分が不明なら原語を残して未確定と示す。本人入力の「メモ確認」は訳語として出力しない。
- `CAL` のlevel/loss/gain、骨レベルと骨喪失、survival/success、支台歯とアバットメント、CRの材料と修復、Onlay/Inlayの区別を保つ。

## 初出表示と略語

`translationDisplayPolicy` の正式日本語・初出表示・指定略語・注意を読む。正式日本語と英語を初出で対応づけ、略語指定があれば同時に定義する。2回目以降はその指定略語を使用できる。同じ略語でも、本文で別の意味に定義されていれば当てはめない。

- MTA、BOP、QOLなど日本語欄が略語のみの場合、正式日本語は表示用の別フィールドを利用する。既存草案から補った正式名を、本人が今回個別に入力・承認したという説明にしない。
- 英語出力の正式名称には、今回の語義に合う `en` や入力本文での展開形を使う。日本語初出表示を反転しない。`en` 自体が略記の場合も、展開形を推測で補わない。
- 日本語を含む指定略記は日本語出力向けとして保持する。英語で別の略記を導入する場合は、同じ概念を指すことと正式な展開形を確認する。
- 原文の綴りや表記が指定された場合、その指定を保つ。別概念の英語を「表記ゆれ」として承認済みの候補へ自動追加しない。
