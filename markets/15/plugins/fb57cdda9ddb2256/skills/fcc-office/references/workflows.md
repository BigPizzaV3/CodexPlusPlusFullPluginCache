# FCC workflows

Version: 3.1.0. The current server descriptors and module instructions remain authoritative. A missing tool is not permission to imitate it with browser actions, SQL or a different write method.

1. Morning brief and daily plan. Read personal context, current work and the real programme step when authorized. Select at most three feasible next actions for the user's available time. Separate plans from recorded evidence. Save an ordinary private draft only when requested. A generated plan is not an active schedule. Keep the owner's existing morning schedule unchanged.
2. Current programme. Use fcc_office_program_current for the actual current task, criteria, example and practical alternative. Keep its source version. Opening a step, practising and an externally performed action have different meanings. Do not start, migrate or complete a programme as a side effect of reading it.
3. Contact continuity. Use fcc_office_contact for one minimal owned contact. Use fcc_office_contact_history only with the separate history permission. fcc_office_due_agreements returns a bounded authorized selection, not the entire CRM. Never request phone, email or historical private notes through these methods. fcc_office_prepare_activity prepares a proposed user report and next date linked to existing sources. Only the user can confirm the actual action and date in the portal. A business response may require its existing contact review flow.
4. Own content and voice. Read fcc_office_content_sources or fcc_office_content_source for selected own material. Save a new own idea with fcc_office_save_content_source when requested. fcc_office_propose_content_pack links proposed formats to the exact source revision. Do not add biography or product facts from a style sample. Use fcc_office_propose_voice for a proposed profile change and fcc_office_voice_history for permitted revisions. Persistent voice changes require personal review and never change global AI personalization.
5. Metrics and weekly review. Use fcc_office_propose_snapshot for the owner's actual native view or export and retain account, period, source and missing values. The user reviews transcribed values. Use fcc_office_weekly_evidence to separate preparation, practice, user reports and independently recorded source events. Recruitment, Retention, Productivity and Development remain the four Core areas. A linked activity and programme criterion are not two actions. Do not infer sales or income from social growth or CC.
6. Comments. Read the current comment_replies instruction first. With a connected authorized source use fcc_office_comments and fcc_office_save_comment_reply, retaining the exact source_id and source_hash. Without that source, use only the public text explicitly supplied by the user and label the result manual and unverified. Never use the portal to approve or send. Public sending requires the user's exact personal click in the existing review path.
7. Contacts from a photo. The personal AI reads the user supplied photograph. Stage only the needed structured text with the dedicated import tools. Mark uncertainty and possible duplication. A photograph does not establish accuracy or permission to contact. Only the user reviews selected rows and confirms import in FCC.
8. Own team and support. Use the existing team tools with a fresh server member_ref. Honour current relationship boundaries and member sharing choices on every read. If the member has restricted programme or activity information, explain the permitted boundary neutrally and do not infer inactivity. Prepare a support suggestion or question, never a ranking, message send or hidden copy of the member's private information.
9. Product recommendation. Use the current product workflow, exact market, approved facts and source_hash. FCC resolves the owner's correct recommendation link. Keep language separate from market. Personal AI prose remains a private draft, not a medically approved claim or proof of personal experience. A stale source requires renewed review.
10. Mobile continuation. Return the actual server review or result link. Do not invent an ID, a success receipt or an executable approval URL. A link opening is not confirmation. For a selected contact or draft use fcc_office_selected_context only for the authorized selected object.
11. Optional personal calendar and email. The user may separately connect a provider in their own AI. Select one business agreement or message, read the least needed content and obtain the provider's required review before a write. FCC does not need the full mailbox, provider keys or a new automation service. Never claim a schedule is running without its actual successful creation receipt.
