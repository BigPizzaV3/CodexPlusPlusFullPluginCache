# HDR Merge

Require2–4 actual opaque JPEG/PNG/WebP brackets of a static scene, explicitly already pixel-aligned with same white balance/aperture/focus and consistent actual sRGB processing. alignment_confirmed=true requires confirmation; tripod capture/equal dimensions do not prove alignment. Provide matching distinct exposure_ev values[-4,4], including exactly0 as reference. Positive captureEV means greater original exposure, not a request to brighten output. No EV inference,alignment,deghosting or camera-response calibration. Bounds20MB each/32MB combined,32–1024px per side after orientation,identical dimensions. Assume inverse-sRGB EOTF, divide each linear channel by2^captureEV and merge using triangular encoded-value weights. All-clipped components use0EV reference and are counted; never claim lost detail is restored.8-bit/JPEG processing,camera tone curves,noise and per-channel weighting can bias color/radiance. Units are arbitrary relative to0EV, not cd/m2 or physical radiance. Export actual Radiance RGBE with scanline RLE and sRGB/Rec709 D65 primaries header; shared-exponent quantization reduces precision. Output is not RAW,DNG,EXR,HDR10,Dolby Vision or a panoramic environment map. Preview uses per-channel Reinhard x/(1+x) then sRGB8bit PNG. preview_stops[-2,2] changes PNG only, never HDR values. The PNG is SDR and does not certify an HDR display. Audit computes actual range,clipping fallback and source hashes without storing exports. Create saves actual HDR/PNG/report/readme ZIP; preserve ZIP/document if optional standalone saves fail. Inputs are not rehosted or included; derived outputs are public. Reopen exact saved file URLs without merging again. Do not invent URLs, camera calibration or online/host success from local fixture evidence.
