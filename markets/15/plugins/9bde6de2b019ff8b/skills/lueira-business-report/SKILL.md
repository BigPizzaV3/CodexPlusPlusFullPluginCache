---
name: lueira-business-report
description: Answer a Lueira tenant's questions about orders, bookings, rental stock and instructors using its connected MCP data.
---

Use the connected Lueira account's available tools to build a report grounded in returned records. Discover the current tool definitions; available tools depend on the tenant's permissions and enabled features.

- For customer-specific questions, find the customer first and use the returned ID to filter orders. Orders carry no customer details, so the `customer_id` filter is the way to attribute them. Resolve ambiguous matches before attributing bookings or balances to someone.
- Distinguish orders created during a period from bookings starting during that period. `created_from` and `created_to` filter when the order was placed; `starts_from` and `starts_to` filter when a booked activity starts. `list_orders` takes RFC 3339 timestamps, so convert the business's local day boundaries including the UTC offset. Orders that contain only shop or custom items never match `starts_*`. Per-booking tools (`list_rental_orders`, `list_group_lesson_orders`, `list_private_lesson_orders`) have their own date filters, and aggregate tools such as `get_order_status_funnel` take `YYYY-MM-DD` in the tenant's timezone. Clarify an unknown timezone when it changes which records belong in the report; no public tool returns it.
- `list_orders` supports customer, status, payment-status and date filters. Inspect its current schema for the exact argument names and enum values. Use `get_order` and `list_order_items` for the details of an identified order. Use `center_id` to narrow orders to one center (plus orders with no center); without it every center is included.
- Follow pagination until the requested range is covered. A first page is not a complete dataset. `list_orders` returns only `items`: it has no `total`, `has_more` or `next_offset`, whatever its description says. Request the largest `limit` it allows, then repeat with `offset` increased by the number of rows returned until a page has fewer rows than `limit`. Rows are newest first, so a range that includes the present can shift while you page. Other list tools return `total`, `has_more` and `next_offset`; use those. If limits prevent completion, state the covered range and do not present partial sums as business-wide totals.
- Order prices are gross (tax included) and in minor units. Keep currencies separate and preserve the amounts and units returned by the tools. `list_orders` and `get_order` return the order total only, with no customer, items or payments. Use the `payment_summary_status` filter to select orders: `PENDING` means nothing has been paid, `PARTIAL`, `COMPLETED` means paid in full, `OVERPAID`, and `NONE` means the order total is zero. Amounts paid and outstanding are not returned per order by the public tools; `get_payment_summary` gives period totals and needs the sensitive `finance:read` scope. Do not infer paid or outstanding amounts from the order total.
- Count `CONFIRMED` and `COMPLETED` orders as sales. `IN_PROGRESS` orders are often unconfirmed carts, and `QUOTE` and `CANCELED` are not sales.
- Use rental-product stock tools for equipment questions and instructor tools for staff lookups. `list_rental_product_stock_items` (needs `product_id`) lists individual units with a status; it is not a stock count and says nothing about a date, so stock alone does not establish that equipment is available for a future booking. An instructor record alone does not establish scheduling availability: use `get_available_instructors` or `list_instructor_availability`.
- Give the scope and period of the answer, supported totals or records, and any missing information. Include returned Lueira links when useful. An empty result is different from missing access or a failed request.

This workflow reads data. On the public MCP, order and booking creation, modification and cancellation, payment registration, and refunds are outside the supported operations. Explain those limits when requested; do not claim a booking or payment was completed. On Lueira's admin MCP these operations exist as pending actions that the signed-in member confirms in the app: never say one is done before that confirmation.
