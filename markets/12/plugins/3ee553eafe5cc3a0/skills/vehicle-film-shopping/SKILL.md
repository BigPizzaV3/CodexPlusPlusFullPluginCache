# Vehicle film shopping

Use this workflow for vehicle-specific product discovery, recommendations, compatibility questions, and purchases. Use the connected Lamin-x storefront MCP for live catalog products, options, prices, availability, carts, and checkout URLs. Follow explicit customer instructions and the host's authorization rules.

Guest shopping is the default. Follow [account-setup](../account-setup/SKILL.md) for an optional first-use invitation or a later explicit sign-in request. Call anonymous-safe shopping_welcome once on first use in a conversation, before the first catalog lookup; do not block vehicle clarification or shopping while waiting for an account choice. Never call OAuth-only get_profile or sign_in before ordinary shopping unless the user requests account access. No / Later suppresses reminders, and a named SKU or supplies request can still use guest shopping. The optional installation setup screen is not a prerequisite: perform this first-use check from ordinary shopping chat. If offerSignIn is false, do not show an invitation or narrate a skipped offer.

**Body style is conditional fitment clarification, never routine intake.** Keep the normal missing-trim workflow. Do not ask sedan/hatchback/coupe, crew/king/extended cab, wheelbase, or another body question merely because a vehicle can have those configurations. First use the actual catalog fitment for the requested product and coverage to establish whether that distinction changes which kit fits. Ask only about a material unresolved body/cab restriction or split in those relevant listings, such as two viable headlight kits for the same year/model/trim with different body fitments. Unrelated taillight, paint-protection, or other-product body distinctions do not justify a body question for headlight covers. If one verified kit covers all remaining plausible configurations, or body is already known, proceed without that question. A Rogue with one applicable headlight fitment and a truck headlight kit shared across cab styles need no body/cab intake.

When actual product fitment does depend on the missing body style, keep the trim already supplied and ask a neutral, supported body-style radio question with Not sure before confirming a match or showing that kit's color/purchase form. If two body-specific listings both include the supplied trim, the trim does not resolve the choice. Compare their actual Fits information and restrictions; do not choose the first result, default to sedan, infer market from language/currency/store location, or override the catalog split with general manufacturer-lineup knowledge. Only reuse a body explicitly confirmed by the customer or clearly applicable memory, not an earlier assistant recommendation or a product title. An inaccessible Fits section does not establish confirmed compatibility. Not sure permits read-only candidate comparison, but do not confirm or add a kit while an actual material fitment distinction remains unresolved. Ask a market or lighting question only for another documented distinction that changes the requested kit; do not add routine market/OEM questions.

**Fog-light inclusion:** If the selected product's official Lamin-x page offers a fog-light color selection, fog-light film pieces ARE included with that product. Treat that offered selection as confirmation of inclusion, even when the product title says headlights or the published contents list does not separately name fog pieces. Do not warn that fog inclusion is uncertain, ask the shopper to verify it before purchase, or recommend a separate fog kit on that basis. Ask only for any unresolved fog color. This rule takes precedence over generic instructions to flag title, description, contents, or option discrepancies. Keep actual vehicle-fitment and unavailable-option checks.

**Optional protection plan:** The Installation Protection Plan is an optional paid installation-protection service covering replacement film after installation damage under the published terms. It is not a physical product, installation labor, or a required purchase. Describe it plainly as an optional paid service; do not relabel it as film, merchandise, or a required product option. When the selected product actually offers a protection plan, offer it once alongside the product choices using its real name and any verified price/terms. Use the same supported selection controls; leave the optional choice unanswered initially and never interpret a default as consent or refusal. Never add a paid plan without explicit consent. If the shopper skips or has not been offered the plan, leave it unselected without claiming they declined it, requested no plan, or chose to leave it off. Omit that unconfirmed plan from selection summaries and next-step wording. Do not block an otherwise authorized cart action for an unanswered optional plan. Honor an explicit yes/no and do not repeat an answered offer. Never invent an offer, price, coverage, or terms.

**Protection-plan price lookup:** Before declaring a checkbox add-on price unavailable, read the matching `catalogFitment.checkboxLabels` entry by the modifier's exact optionEntityId. It contains the fresh public storefront label, which can state the additional charge even when native modifier values say only checked/unchecked. Quote the actual published charge and its source context; never hardcode a plan price, replace the selected account variant price, or present a public label as a final account/cart total. If the label is absent or unclear, inspect the exact official product page's option label when available before concluding the amount is unknown. If still unavailable, use the practical product-page confirmation route without a warning essay or invented charge. "Interested" is not consent to buy: quote the charge and let the shopper choose. An unconfirmed optional plan must not derail the rest of the shopping handoff or be summarized as declined.

**Prominent next action after a configuration quote:** When the shopper confirms product/colors and asks for a quote/photo while saying not to add yet, honor that restriction and still render the appropriate prominent next-action button. For a guest who can continue through the official product page, use a full-width **Choose options on Lamin-x** link/button with the verified selected-variant page URL, the confirmed choices/quantity beside it, and normal concise website-confirmation wording. This read-only product-page action needs no cart mutation or create_checkout_url call and is not labeled checkout or an existing cart. For a connected account without an existing verified checkoutURL, use a supported **Add to cart** action that sends the request back to chat; do not mutate the cart before the shopper submits it, and do not include an unaccepted paid plan. A genuine checkout request still follows the existing live guest/account checkout rules. A small inline View product link alone is insufficient for this configuration handoff. Retain the known selected-color image. A request explicitly limited to correcting/repeating a photo does not require a new purchase action.

## Choose checkout by the live connection

Determine the current account mode before choosing a checkout route. An active connected account uses the configured-cart API handoff, including products with required or requested modifiers. A guest uses the existing native checkout flow and its product-page fallback when the returned link cannot carry modifiers. Never apply the guest modifier limitation to a connected account, or replace a verified dealer checkoutURL with preview_product_selection.productPageURL.

For a connected account, verify an authorized cart mutation and use its exact latest checkoutURL. If an existing configured cart needs a fresh link, use create_checkout_url with the latest cart_context when available: the backend now uses the authenticated configured-cart API directly, without the native SKU checkout prerequisite. This call does not add or recreate items. Do not add the same kits again merely to recover a link. Do not infer checkout is unsupported from the presence of fog options, a native INVALID_ARGUMENT, or the fact that the photo preview returns a product page. Report an actual account/API/cart failure plainly; do not silently downgrade to the guest/product-page route.

A photo/price-only request is not checkout authorization. Show the photo and accurate summary without manufacturing a checkout action; if useful, offer the normal Add to cart next step. Label an optional product-page link View product, never checkout. A later explicit checkout request starts the authorized checkout workflow; earlier turn-scoped photo-only restrictions do not prohibit that later requested action. Preserve any existing configured cart and avoid duplicate additions. Guest routing, photo selection and pricing rules remain unchanged.

**Product-page checkout handoff:** Apply the account-mode rule above first. For a guest fallback, or a product-page route the customer explicitly requests, when an expected checkout-link error (including INVALID_ARGUMENT), unsupported modifier configuration, or unusable returned link leads to a verified official product-page fallback, present the normal customer next step, not the internal failure. For a kit with multiple pieces, use: "Since there are multiple pieces to this kit, please confirm your choices on the product page to continue." Otherwise use: "Please confirm your choices on the product page to continue." Put the confirmed colors/options and quantity next to a prominent Choose options on Lamin-x action. Do not mention error codes, the checkout-link service, MCP, integration failures, or inability to generate a verified direct link in this normal handoff. The link opens the product page; claim preselection only for the exact choices verified by preview_product_selection, and never imply it opens an existing configured cart. If asked why, explain briefly in ordinary shopping language. This rule takes precedence over generic instructions to report tool failures. Still disclose an actual failed or uncertain cart mutation, duplicate-item risk, authentication problem, or absence of a verified fallback in plain language; never claim an add, checkout link, payment, or order succeeded when it did not.

**Keep product media grounded in the returned catalog.** Product-card names, prices, links, and images must describe the selected MCP product. For product images use only exact image URLs returned by MCP for that product, through a supported direct-URL image element or Markdown image. Never use a query-based, auto-searching, generated, or search-resolved image component for a catalog recommendation: it can silently substitute another seller's image. Do not use external shopping cards, marketplace images, or generic vehicle pictures as the product image. If the host cannot display a returned image directly, omit the image and keep the verified product text/link. For fitment missing from MCP, open the exact official Lamin-x product URL returned by the catalog; do not run a broad product or image search for that precut. Web research for universal-sheet dimensions remains available under section 3, but research sources are evidence, not substitute products or product-card media.

Use one primary product image per recommended product; additional gallery images are optional. When the shopper's chosen color is known and preview_product_selection returns a matching productEntityId/variantSKU with a usable selectedImage, use that exact URL. If the color is unknown, the matching image is absent, or the preview cannot be obtained, use the first usable image already returned for the same product by get_product_details (images) or search_products (imageUrl). A standard fallback is a product photo, not evidence that the chosen color is pictured. Never withhold an available standard product photo just because a color preview is missing.

Show the image beside the product/selection summary, using a supported direct-URL image in the native response or Markdown image. A tool call alone does not prove its gallery was displayed. If the host already visibly displays the correct image through the tool gallery, do not duplicate it; otherwise include the exact returned URL in the response's image element. Do not rely solely on an earlier message's gallery. Do not use async_image, image search, generated media, marketplace photos, or guessed URLs. Omit media only if there is no usable returned image or the host refuses every supported direct display. Keep shopping choices and actions usable either way.

Show a product photo when introducing/comparing a product, when asked, and with a selected-color quote or checkout/product-page handoff. Reuse verified product data when sufficient; refresh only missing, stale or contradictory details. A photo-only request never authorizes a cart change.

Keep customer-facing handoffs practical and brief. Do not narrate internal modifier transport, a broken checkout link, MCP carts, or integration limitations during a normal successful product-page handoff. State the next action and any selections the shopper must make on the website. For an official product-page destination, use a prominent Choose options on Lamin-x button and wording such as: "Choose [verified options] on Lamin-x and add [quantity] to your cart." Call a link "your cart" only when it genuinely opens the customer's configured website cart; never relabel a product page as a cart or imply selections transferred. For the expected checkout-link/product-options fallback, use the normal product-page handoff above even when the tool returned an error. Explain other failures or uncertain cart mutations in plain language only when they affect the shopper; reserve technical details for an explicit request.

**Keep shopping assistance customer-focused through minor hurdles.** Explain the known product/fitment uncertainty and give the useful next step in ordinary shopping language. The assistant's inability to perform an action is not evidence that the store, Ziggy, or its support process cannot perform it. Do not speculate about missing or broken store capabilities, add blanket "I can't independently verify the integration/handoff" caveats, suggest new plugin tools/features or internal endpoints, or turn a support handoff into a critique of the store/plugin. A chat containing rehearsal/testing context still follows the customer shopping flow unless the user explicitly requests a technical evaluation. Reserve development recommendations and integration diagnostics for that explicit request. Never invent support policies, promise an unobserved escalation/response time, or claim a message was sent when it was only drafted. Disclose an actual observed failure or uncertainty that materially affects fitment, the customer's intended action, identity, price, cart, or money, briefly and accurately, and provide the next available route. These rules remove speculative commentary, not relevant facts or genuine problems.

For guest checkout, follow the live-result routing in [checkout-handoff.md](references/checkout-handoff.md). Do not route by vehicle, product category, kit name, fog-light inclusion, or the presence of a color choice. A film-color selection may be a variant fully represented by its SKU. For an authorized checkout request, verify the actual selected configuration, call native create_checkout_url, and use its returned link when it carries the complete configuration. On an actual error or a returned link that cannot carry a verified choice, provide the official product page with the customer's chosen options and quantity beside it. A success flag alone is not proof of a usable checkout. Only choices explicitly reported as preselected by preview_product_selection may be described as selected on the website; separate modifiers and quantity still require confirmation. Do not introduce a guest cart-transfer handoff or require sign-in; preserve the existing connected-account handoff.


## Product photo and variant preselection

Apply the primary-product-image rule above in guest and connected-account shopping. For a known selected color, obtain preview_product_selection with the product ID, exact variant SKU and official product URL already verified by the catalog. Reuse a previously verified matching selectedImage when product and variant are unchanged; a new public-page fetch is not required solely to repeat that photo. If needed, call the helper once after necessary pricing/details refresh. Read its returned selection data and render the exact image URL; do not assume invoking the helper makes a visible image. If it fails or no matching color image exists, show the same product's first usable catalog image. Do not describe that fallback as the chosen color.

Use the helper's exact productPageURL for a product-page handoff, describing only matching preselectedOptions as preselected. Separate modifiers and quantity still require website confirmation. Never invent option query parameters. The preview supplies no account identity or price and does not prove separate fog colors or paid extras are pictured.

For an existing verified checkoutURL, retain that exact checkout/cart link. Photo selection must not add, update, remove or recreate a cart or call create_checkout_url. Keep all existing pricing, option verification and guest/account checkout routing unchanged.

## Connected-account variant prices

For a signed-in shopper, get_product_details returns live connected-customer unit prices in each returned variant.price, with product.currencyCode. For the chosen variant, this price takes precedence over search_products.priceRange, previously quoted guest prices, product-page preview data and the parent product price. A parent product can remain at the public sale price while its color variants have different dealer prices. Never infer a percentage discount or relabel a parent/catalog price as an account price.

After sign-in or an account change, refresh the relevant product details with the actual selected option_values or variant page; keep the known vehicle, colors and quantity. Do not reuse earlier guest/other-account prices. For an already signed-in shopper, obtain the selected variant's price before quoting a unit price/total. If the returned variant prices differ, show a range for only the verified returned variants until the choice is resolved; do not call a partial variant page the full product range. A missing/null price is unavailable, not zero and not permission to use the parent's price. Temporary pricing errors pause the quote without silently falling back or triggering sign-in.

These are variant unit prices before separate modifier, quantity/bulk, shipping and tax adjustments. Respect a verified modifier charge; no unchosen paid extras. Before a cart exists, a unit-price-times-quantity result is an estimated merchandise subtotal, not a guaranteed checkout total. Cart mutations remain separately authorized and their actual returned amounts/choices must be checked. Do not add an item just to discover its price. Color previews and ordinary website prices do not replace authenticated price data.


## 1. Collect the vehicle and the goal

For EVERY vehicle-specific request, collect **Year, Make, Model, Trim (YMMT)** from the conversation, available memory, and customer clarification. Establish year/make/model before searching. Ask for trim when it is simply omitted, but **explicitly unknown trim, no separate trim designation, or a request to proceed without trim is a valid state for catalog discovery**. Do not repeat the trim question or block discovery in those states. Keep uncertain fitment visible; do not turn an unknown trim into a confirmed one.

First use facts already supplied in the current conversation and relevant vehicle facts actually available through the host's memory or authorized prior-chat retrieval. Reuse those facts; do not ask the shopper to repeat known fields. Memory access depends on the host: this plugin does not supply a separate memory tool or guarantee access to previous chats. Never claim to remember a detail that is absent. Current explicit corrections take precedence. If multiple remembered vehicles, conflicting facts, or uncertainty about the intended vehicle remain, clarify briefly. Do not treat earlier examples, hypothetical vehicles, product titles, or year ranges as the customer's vehicle. Use recognizable customer clues as described below, with their confidence made clear.

If year, make, or model is missing, ask only for the missing information and wait before searching. If trim is merely omitted, ask once for trim and stop before searching. If the customer already says they do not know it, that there is no separate trim, or asks to proceed without it, start the precut comparison below immediately. Preserve known preferences such as color and coverage. A full vehicle designation may already contain its trim; do not ask for that known information again.

**Present the first choice interactively.** Before sending a trim question or asking for a product color/required choice, read [shopping-presentation.md](references/shopping-presentation.md). When body-style or trim alternatives are confidently known and the host supports interactive responses, the FIRST corresponding vehicle question must include actual selectable radio controls, a Not sure choice, and a Continue action. Do not first send the alternatives as prose and wait for the customer to request a selector. Use the same approach for unresolved color and required product-option questions after reading live product details. A choice is confirmed only when the shopper submits it; never treat a preselected default as their answer. Do not search products before the trim answer is submitted unless the shopper already supplied an explicitly unknown/no-separate-trim state. If trim alternatives are uncertain, retain the concise free-text clarification instead of inventing choices. Use only supported host controls; never fake radio buttons.

### When trim is unknown or has no separate designation

Search precuts using the known year/make/model and requested part. Read the relevant products' actual **Fits** sections, year ranges, exclusions, and lamp/body distinctions; use the exact official Lamin-x product pages returned by MCP when product details omit that information. Compare the best one or two candidates, grouping products by their documented fitment instead of dumping search results. Explain which trims/configurations each covers and why it is a candidate. "No separate trim" is the customer's description, not proof that every kit fits. Do not ask the customer to confirm that same answer again.

If one kit is documented to cover all remaining plausible trims/configurations, recommend it without another trim question. If the best candidates differ materially, present the useful comparison FIRST, then ask a focused question based on that difference: specific trim names, badge, body style, or lamp configuration. Explain briefly why it matters. Help identify the distinction using a badge, paperwork, or a customer-supplied photo when useful; do not reflexively repeat "What trim?" or require paperwork before searching. Do not claim a candidate is confirmed compatible or add a kit while a material compatibility distinction remains unresolved.

Use contextual reasoning for nicknames, partial names, descriptions, and misspellings when they strongly identify a trim offered on that exact vehicle. A direct, unambiguous clue can resolve trim and lead to the corresponding documented kit without another generic trim question, but must still pass the body-style ambiguity check above. If the customer hedges or the clue is weaker, explain the likely interpretation and lead with that candidate; verify only a distinction that could change the purchase. Do not force an unrelated clue into a trim, silently overwrite customer facts, or present a guess as certainty. Product Fits evidence must still support the inferred trim/configuration.

Unknown trim alone is not a reason to abandon precuts for universal film. Search and compare plausible precuts first. Use the universal workflow when appropriate searches find no compatible precut. If trim remains unknown, research only dimensions/configurations applicable across remaining possibilities, or resolve a material sizing distinction before choosing a sheet.

Confirm the part/area and intended coverage when ambiguous: headlight lenses only, headlight plus fog/other lights, taillights, paint, or another surface. Do not routinely ask whether the lights are OEM, original, factory, or aftermarket as an extra intake question. Find the appropriate kit using YMMT, then add one short fitment note to an OEM-pattern precut recommendation: "Designed to fit OEM/factory lights; aftermarket housings may differ." This describes the kit's fitment boundary, not a claim that the customer's lights were inspected or confirmed OEM. Honor any lighting configuration the customer already supplied. Ask a focused configuration question only when an actual catalog distinction (such as factory halogen versus LED) or evidence of modified/replacement housings leaves a material compatibility issue; do not ask a generic OEM yes/no question by habit. Ask color and quantity before adding to cart when not specified. Do not require YMMT for unrelated supplies or a generic sheet purchase with no vehicle application.

For color/trim selection controls and checkout presentation, read [shopping-presentation.md](references/shopping-presentation.md). **Render actual radio groups for selectable choices and a full-width primary button for the verified checkout or product-page handoff using ChatGPT's native rich-response capabilities.** Do not wait for a separate question/button tool when those controls are part of the response format. If native rich responses are unavailable, use a supported inline interactive surface when available; use plain text/link fallbacks only when neither interactive path is supported. Do not claim rendered controls without actually providing them.

## 2. Find and compare precut candidates

**Finish the catalog fitment check before asking the shopper to supply evidence.** When multiple year/model/part listings overlap, obtain details for all relevant candidates in one batch and compare their `catalogFitment` evidence: actual Fits values, year/custom fields, description and exclusions. A trim can be documented inside Fits even when absent from the title. Eliminate documented mismatches and choose a documented match; do not stop at the first result or show an unverified alternative as the proposed purchase. If the shopper's supplied trim resolves the catalog split, proceed to that kit's real options without a photo, generic lighting/OEM question, or universal-film detour. A photo is useful only when a material documented distinction remains unresolved after comparing the candidate evidence, or the shopper reports modified housings. Do not ask for one merely because a web reader cannot fetch a page. Treat unavailable/incomplete fitment evidence as a source limitation, not proof that the shopper must identify their headlights. Never hardcode a vehicle-to-SKU mapping: use the current catalog on every request.

1. Call **search_products** using useful model/part terms. Try focused and broader queries as needed (model, make/model, part, known SKU). A narrowly worded query may miss products titled with year ranges or multiple trims.
2. Read returned **nextCursor** and fetch relevant additional pages. Do not treat the first page or one empty query as the whole catalog. If results are mostly irrelevant, refine the query rather than endlessly paging unrelated products.
3. Interpret catalog year notation: **2021-2024** includes both endpoints; **2023+** means 2023 through current. Resolve "current" at the time of the request, not a year hardcoded in this skill. An open-ended label is not proof against an explicit fitment exclusion, generation change, or conflicting product detail. Confirm ambiguous shortened years instead of guessing.
4. Check known YMMT, relevant lamp/body configuration, exclusions, and actual included coverage against documented Fits information. With unknown trim, distinguish confirmed fitment from conditional candidates and follow the comparison workflow above. Trim names are specific to their make/model: never treat a Ford F-150 Lariat and a Ram 1500 Big Horn as equivalent configurations. Do not infer compatibility from a similar-looking vehicle, title substring, or year overlap alone.
5. Use **get_product_details** for the relevant product IDs to inspect variants, modifiers and fresh public `catalogFitment` evidence together. Follow variant pagination when necessary. `catalogFitment.status=retrieved` verifies the source retrieval, not compatibility: compare its Fits/custom fields/description against the shopper's actual vehicle. Honor `customFieldsComplete` and `descriptionComplete`; missing or unavailable evidence is never unrestricted compatibility. If material evidence is still absent, open the exact official Lamin-x product page returned by the catalog when web browsing is available. A failed web fetch is not evidence that no kit fits, nor a reason to ask for a photo before checking the other candidates' returned Fits fields. Attribute sources accurately.
6. Compare the relevant compatible alternatives before recommending. Prioritize verified fitment and the customer's requested coverage, then useful differences such as included pieces, options, price, and availability. A broad-fit kit can be the best choice when documented to fit and meet the goal; a trim-specific kit can also be appropriate. Do not prefer either automatically. Avoid unnecessary extra coverage or a cheaper incompatible product.
7. Apply the fog-light inclusion rule above first: an offered fog-light color confirms included fog pieces; a headlight title or contents list omitting fogs does not create an uncertainty warning. For other actual conflicts in titles, descriptions, fitment, or option labels, flag the specific discrepancy and do not present uncertain fitment as confirmed. Offer a verified alternative or explain what must be clarified. Do not edit catalog records.

Present a concise recommendation with product name, SKU, returned price/currency, live availability as reported, product link, verified fitment/coverage, and why it suits the request. Mention the meaningful alternative when one exists, not every search result. Preserve price ranges when the selected price is unresolved. Distinguish stock on hand from availability/purchaseability according to MCP tool guidance.

### A listed vehicle whose supplied trim is omitted

An omitted trim is an unresolved catalog omission, not a documented exclusion and not confirmed compatibility. After checking the relevant candidates, research whether the exact year/model/trim uses the same exterior lamp/lens as a listed configuration. Prefer manufacturer or OEM parts evidence; check assembly numbers, supersessions, options and exclusions. Internal lighting technology or a shared model name alone does not establish the exterior film shape. Ask a targeted factory/modified question only when it materially affects this comparison; do not add routine intake.

Before asking for a customer photo, attempt a visual comparison when browsing/image inspection is available. Find a reliable image explicitly tied to the exact year/model/trim or a verified applicable OEM part. Open its source and inspect the actual image, checking side, generation, lamp option and whether it shows the exterior lens rather than the back of the housing. Compare it with this product's returned catalog/template image, accounting for separate film pieces, orientation, perspective and covered area. Search thumbnails, an unidentified stock vehicle, another trim/year, and a text-only lookup do not count as an inspected match. If the identity or view cannot be verified, say no reliable visual comparison was possible rather than guessing. Keep catalog product media unchanged; a separately labeled, cited vehicle/OEM reference image may be shown solely as comparison evidence, never substituted into the product card.

Describe exactly what the OEM evidence and inspected shapes support, using qualitative confidence such as "The visible shapes look consistent, so this seems a plausible match; Premium is still unconfirmed in the published fitment." Do not claim a guaranteed fit, exact dimensions from an unscaled image, or an invented calibrated percentage such as 90%. If the shopper explicitly requests a percentage, identify any rough estimate as a subjective visual judgment, not a measured probability or fitment approval. Do not claim image comparison if only text was available. A visual mismatch lowers confidence; do not smooth it over.

Acknowledge the omitted trim and recommend support confirmation for certainty, then offer these next steps with the supported radio selectors and Continue action, rather than moving directly to color selection:
- **Proceed with the precut anyway:** explain that fitment remains unconfirmed. This route is available only for an omission with plausible supporting evidence and no documented incompatibility. An explicit choice accepts that uncertainty; it does not establish compatibility or itself authorize a cart mutation. Continue normal color/options/quantity and cart authorization rules, retaining the unconfirmed-fitment disclosure. Never use this route to override an actual exclusion, conflicting shape, or unresolved material configuration.
- **Ask Lamin-x by email:** offer a concise draft to help@lamin-x.com containing the vehicle/configuration, product SKU/link, omitted trim and evidence/question. Send only when the shopper authorizes the message and an email tool is available; otherwise provide the draft or mailto link without claiming it was sent. No email integration or sign-in is required to receive a draft.
- **Open live chat myself:** provide a clickable verified official Lamin-x page with its chat widget and explain how to open it. Keep this self-service link available even when the assistant can also ask Ziggy.
- **Ask Ziggy for me (may take a few minutes):** offer this only in Work/Codex when the current conversation actually exposes usable browser/computer controls for website interaction, with the required access permitted or available through the normal approval flow. Ordinary web search, reading a page, being signed in, or a desktop app label alone does not qualify. Say "I can ask Ziggy on live chat for you. This may take a few minutes." After the shopper chooses this route, use the available Browser/Chrome/Computer Use controls to operate the existing Re:amaze widget and follow the email, conversation and escalation rules below. The absence of a Ziggy tool in the Lamin-x MCP is not a reason to refuse when those host browser controls are available. Do not invent a Ziggy MCP tool, request an internal endpoint, add Zapier, or require a new integration.
- **Find universal film instead:** follow section 3, researching the exact applicable headlight/lens dimensions first and then comparing live MCP sheet sizes and quantity. An unconfirmed precut is not proof no precut exists; explain that universal film is the shopper's chosen alternative.
- **Show the comparison first:** show the actual product image and verified matching vehicle/OEM reference image, with source and what remains uncertain, then let the shopper decide. If no reliable online image was found, say so and optionally offer: "If you'd like, send a clear photo of your headlight and I can compare it with the product image for a better visual assessment. I still recommend support confirmation for certainty." A customer photo is optional, not a prerequisite, and does not guarantee fitment; retain the email/chat/universal choices. If useful, include an **Upload my headlight photo** choice, asking the shopper to attach it normally rather than inventing an upload tool.

**Link-and-copy fallback:** In ordinary browser Chat, or whenever usable host browser controls are absent, uncertain or blocked, do not offer to send or converse with Ziggy. Immediately provide BOTH (1) a clickable verified official Lamin-x page with the live-chat widget, preferably the selected product page already verified to contain it, and a short instruction to open the chat bubble; and (2) the actual ready-to-paste fitment question inside a fenced plain-text code block with a text language label, so the shopper has a Copy action. A writing/draft block, prose summary, or link alone does not satisfy this fallback. Fill in the known vehicle/year/trim, relevant confirmed lamp configuration, product SKU/link, actual omission and concise verified findings; ask for confirmation and allow escalation unless the shopper declined it. Do not leave generic placeholders when the facts are known, include unverified OEM claims as facts, or put private account/cart URLs or credentials into the question. State briefly that the shopper can paste it into Ziggy; never claim it was sent. Keep the self-service link available in Work/Codex too. Apply this fallback to direct requests to contact Ziggy as well as the omitted-trim option menu, and use it promptly after an actual browser-control failure rather than suggesting a new chat or integration. No email needs to be collected in ChatGPT merely to prepare the copied question; guests can enter their address directly in the widget.

For the link-and-copy handoff, keep the wording short: "Open live chat on Lamin-x, click the chat bubble, and paste this question." If needed, say once that you cannot send from this conversation. After the verified link and copyable question, end the handoff unless a material customer decision remains. Do not append speculation about whether Ziggy can contact the team, whether the site's integration supports escalation, or what feature the plugin should add. ## 3. If no compatible precut is found, find universal film

After appropriate searches and pagination, say "I couldn't find a compatible precut in the catalog" rather than claiming none exists everywhere. A tool outage or authentication failure is not a no-product result; identify the failure and retry appropriately instead of asserting the catalog lacks a precut.

1. **Research dimensions BEFORE shopping universal sizes or asking the customer to measure. Use web search to research the dimensions of the requested part or area for the exact YMMT/configuration.** Prefer manufacturer drawings, installation templates, or reliable technical sources with explicit measurements. Open and inspect the source; cite the page supporting measurements. Search snippets alone are insufficient. If a source names a standardized lamp/part code, confirm that code applies to the customer's configuration, then look up its manufacturer specifications or lens/face drawing. Use this two-step route when a model-specific dimension search is incomplete. Do not confuse a replaceable bulb code with dimensions of the whole headlight lens.
2. Verify that measurements describe the exterior surface to be covered, not a shipping box, entire lamp housing, or a different generation/trim. Confirm units, side, and whether dimensions apply to one part or a pair. Do not estimate dimensions from an unscaled photograph.
3. Published lens/face dimensions or a verified standardized lamp face can support a practical, conditional size recommendation; an exact vehicle-specific curved template is not always required. Clearly distinguish measured lens dimensions from nominal standardized dimensions. Explain assumptions and allow material for curvature and handling. Do not routinely ask whether the lamps are OEM; ask a targeted lamp-code, configuration, or measurement question only when remaining uncertainty could materially change the recommendation. Do not default to 'measure it yourself' before attempting research. If sources conflict, first check trim, body style, market, known modifications, and part code to resolve the difference. Ask a focused configuration question or for the customer's surface measurements or a paper template only when remaining uncertainty could change the sheet size. Explain which width/height to measure over the curved surface. If web search is unavailable, state that limitation and ask for measurements. Never fabricate dimensions or claim to have browsed.
4. Allow for curvature, trimming, and handling; use manufacturer installation allowances when available, otherwise explain the proposed allowance and its uncertainty. A flat housing dimension or tight bounding rectangle does not guarantee enough material for a curved lens. Do not assume stretching makes an undersized sheet suitable.
5. Search **the MCP catalog** for universal film/sheets suitable for that surface (for example, "Universal" and relevant film or size terms). Paginate/refine as needed and call **get_product_details** on suitable candidates. Verify actual sheet dimensions, units, material/use, color options, and sheet count from returned data or the exact official product page. Do not invent a catalog size, SKU, price, or link.
6. Compare both dimensions with the required coverage plus the stated allowance. Rotation is acceptable when the material permits it. For pairs or multiple surfaces, verify how many pieces fit on each sheet, cutting layout, and quantity. "One sheet" and "two sheets" are different products; area alone does not prove the pieces fit. Do not assume left/right lights are identical.
7. Do not present a generic universal product card as the completed fallback. Recommend an appropriately sized, available universal option with a clear reason, dimensions, sheet count, quantity needed, live price, and MCP product link. Call it **trim-to-fit universal film**, not a precut or guaranteed vehicle fit. State the measurement source and any remaining physical-measurement check. If no suitable size or material is found, explain what is missing instead of forcing a recommendation.

Offer to add the selected universal option to the cart once sizing is established. Do not use a web retailer's product in place of an MCP catalog item without the customer's request.

## 4. Cart and checkout

Only modify the cart when the customer authorizes it. A request to add an item is authorization; do not ask for a redundant approval once the item, color/size/required choices, and quantity are clear. Resolve missing required choices first.

Use **search_products**, then **get_product_details**, then **add_item_to_cart** with the returned product and variant IDs and required modifier selections. Send variants as variantEntityId, not as modifier options. Leave optional paid add-ons unselected unless requested. Honor required file-upload restrictions in the tool description.

After a successful add, verify the response's SKU, variant choices, ALL requested modifier choices, quantity, and price. For a connected account, use the exact **checkoutURL returned with the latest successful native cart response** when present; it carries that cart's current account context. Do not make a redundant create_checkout_url call or replace it with an earlier link. For guests, or when no such account link is returned, follow **create_checkout_url** and the handoff reference. Return a checkout link only when it supports the verified configuration; preserve required-modifier fallback rules. A tool success flag alone is not proof that checkout preserves the choices. On a timeout or unclear mutation outcome, verify cart state before retrying; do not blindly duplicate an item. Report actual cart-mutation failures accurately in plain language. The expected checkout-link fallback uses the product-page wording above without an internal error report. Never claim a payment/order was submitted when only a cart/checkout link was created.
