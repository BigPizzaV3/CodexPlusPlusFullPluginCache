# JCT Format — Extension of Time / Loss and Expense Application

Loaded at Step 6 when the contract profile (Pattern 13) names JCT, or the user confirms JCT
when no profile exists.

```
EXTENSION OF TIME APPLICATION AND LOSS & EXPENSE CLAIM
Project: [Name]
Contract: JCT [SBC/DB] 2016
Date: [today]

1. EVENT DESCRIPTION
   [One paragraph describing what happened, when, and where, citing diary evidence]

2. RELEVANT EVENT (Time — Clause 2.29)
   This event constitutes a Relevant Event under clause 2.29.[X] because [reason].

   Notice was given on [date / "Notice has not yet been given — this application serves as notice under clause 2.27.1"].

3. RELEVANT MATTER (Cost — Clause 4.22 SBC / 4.21 DB)
   [If applicable] This event constitutes a Relevant Matter under clause [4.22 (SBC) / 4.21 (DB)].[X] because [reason]. Loss and expense entitlement and notification are governed by clauses 4.20–4.21 (SBC 2016) / 4.19–4.21 (DB 2016).
   [If not applicable] "This event is a Relevant Event for time only. [Reason — e.g., weather is not a Relevant Matter]."

4. PROGRAMME IMPACT
   [Description of effect on progress]
   Activities affected: [list]
   Estimated delay to completion: [X working days / "not quantifiable from available records"]
   Extension of time requested: [X working days / "not quantifiable from available records"]

5. LOSS AND EXPENSE (if Relevant Matter applies)
   Heads of claim:
   - Prolongation: [X days additional site establishment / "not quantifiable from available records"]
   - Standing time: [X gang-shifts / "not quantifiable from available records"]
   - Disruption: [if measured — reference measured-mile analysis]

   Supporting resource data from Gather shift records attached.

6. EVIDENCE SCHEDULE
   See `evidence-schedule.md` for the shared
   table format.

NOTES
- This application is based on data recorded in Gather. It should be reviewed by the commercial team before submission.
- Financial quantification requires contract rates and cost data not available through Gather.
- The time-side clause references above (2.27.1 delay notice, 2.29 Relevant Events) follow SBC 2016 numbering — DB 2016 numbers its delay-notice and Relevant Events clauses differently, so adapt them when using DB. ICD and MW also use different clause numbering (MW has no equivalent loss and expense machinery) — the template must be adapted for those forms.
```
