# Local Codex authoring without a connected MCP server

Use this fallback only when the Polytweaks MCP tools are unavailable in the current chat. It supports local creation/editing and a reviewable file handoff; it does not simulate a connected account or save a Polytweaks version.

1. Inspect the available authoring tools or locate an installed Blender executable in the local environment. A successful executable/version check establishes availability. Do not assume Blender is installed, install software without a user request, switch the chat's model, or provision a paid API worker.
2. Use files the user supplied or an explicitly identified local workspace source. If the model exists only in Polytweaks, the user can download that version's original source and GLB through their signed-in viewer, or connect the plugin. Do not search private configuration for bearer tokens or use production/database credentials as a substitute for account linking.
3. Create or edit within the current task's working directory and keep input files intact. Prefer the actual Blender source, disable source-file script auto-execution and pack resources in the resulting `.blend`. If importing GLB, label the result an editable conversion. Export GLB and authored USDZ from the same finished scene; verify geometry, materials, scale and file contents with the tools available.
4. Render the result or inspect it in an available local 3D viewer. Return actual output file links and state which formats were verified. If a requested format cannot be authored or validated, say so; preserve the available output rather than claiming the set is complete.
5. When saving was requested but MCP is unavailable, provide the files for the Polytweaks upload/new-version flow and identify the intended existing asset/version. Saving to a local folder is not a Polytweaks save. Once the connector is available, use its file-transfer mechanism and `save_model` with the existing `assetId` to append a version. Never put a local path in `download_url`, invent a public file URL, or silently create a new asset to replace an inaccessible one.

Reading this skill from the repository is sufficient to follow the local workflow. It does not require installing the plugin, changing user settings or saving credentials. The user can ask a local chat to read `packages/chatgpt-plugin/skills/model-library/SKILL.md` in their checkout and work on a named local model file.
