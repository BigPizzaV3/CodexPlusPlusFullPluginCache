# External LP art direction

Shared references provide business knowledge. Runtime, UI, tool, or save examples
inside them describe the internal surface and must not be executed as written.
Follow this external workflow, the current live contract, and its confirmation
requirements.

Read the adaptive composition, image placement, and visual-standard references
before a new LP or full redesign. Fetch at most three relevant design lessons for
the page's actual problem. Transfer the reasoning; never clone an example's full
layout, facts, palette, image count, copy, or asset URLs.

Create an evidence ledger and give every useful image a distinct role, placement,
crop, and visitor decision it supports. Prefer publication-quality supplied photos
unchanged for factual roles. Generate or import only the missing roles. Repeated
crops, decorations, icons, and the same scene do not become additional evidence.

Do not impose image counts, chapter counts or generate filler. Restore compressed
PDF photographs by source-pixel editing while retaining their subject identity.
For a new LP prefer a short, verified text-bearing source-based hero. Keep
supporting photos free of added lettering and the real booking CTA outside image
pixels. Respect original-only, no-generation, image-free and existing-overlay
requests. Manual copy edits do not trigger a full visual rebuild.

Use the available Homin Cloud media generation, host-file import, or native HTTPS
import operation, then attach the returned asset identifier through the authorized
LP workflow. Keep every asset in its matching narrative block. Do not append an
overflow gallery merely to place unused images.

After save, read back the exact draft and inspect desktop and mobile preview. Check
facts, role-to-section alignment, legibility, crops, booking controls, and the full
page flow. Repair only the affected asset or block and retain optimistic version
and idempotency safeguards. Rendered evidence is required for a visual-quality
claim.

# Canonical domain guidance

# Shared LP art-direction quality rules

These rules apply to both the Homin Cloud internal assistant and external MCP
clients.

- Select useful source-backed visual roles. Do not impose image quotas or generate
  filler; respect no-image, no-generation and original-only instructions.
- Develop text, composition and images in the order that helps the page. Read
  complete example code whenever useful; generate additional images as the body
  develops. No complete asset plan is required before writing.
- For a normal full LP, aim for five or more image-bearing body chapters plus
  the hero, with or without source material. Give each chapter distinct content,
  meaningful imagery and visitor value. Calendar, map, booking, specification
  blocks and the hero do not count as body chapters; several photos in one gallery
  are not several chapters. This is an editorial goal, never a minimum or save
  condition. Respect explicit concise-page, single-image and image-free requests;
  a short prompt alone does not request a short LP. Do not pad a limited subject.
- Preserve source information architecture. Do not collapse a rich flyer or case
  study into a fixed block count. Choose visual roles from the event facts,
  audience questions, available proof, and reservation friction.
- Restore low-resolution PDF photos through faithful source-pixel editing.
  Prefer a short text-bearing source-based hero for a new LP, with dates, venue
  and real booking controls in native content. Respect explicit overlay or
  unchanged-asset requests. Never replace real subjects with invented scenes.
