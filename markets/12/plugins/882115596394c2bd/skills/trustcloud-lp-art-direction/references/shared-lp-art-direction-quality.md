# Shared LP art-direction quality rules

These rules apply to both the Homin Cloud internal assistant and external MCP
clients.

- Select useful source-backed visual roles. Do not impose image quotas or generate
  filler; respect no-image, no-generation and original-only instructions.
- Develop text, composition and images in the order that helps the page. Read
  complete example code whenever useful; generate additional images as the body
  develops. No complete asset plan is required before writing.
- For a normal full LP, aim for five or more image-bearing body chapters plus
  the hero, with or without source material. Give each chapter distinct content,
  meaningful imagery and visitor value. Calendar, map, booking, specification
  blocks and the hero do not count as body chapters; several photos in one gallery
  are not several chapters. This is an editorial goal, never a minimum or save
  condition. Respect explicit concise-page, single-image and image-free requests;
  a short prompt alone does not request a short LP. Do not pad a limited subject.
- Preserve source information architecture. Do not collapse a rich flyer or case
  study into a fixed block count. Choose visual roles from the event facts,
  audience questions, available proof, and reservation friction.
- Restore low-resolution PDF photos through faithful source-pixel editing.
  Prefer a short text-bearing source-based hero for a new LP, with dates, venue
  and real booking controls in native content. Respect explicit overlay or
  unchanged-asset requests. Never replace real subjects with invented scenes.
