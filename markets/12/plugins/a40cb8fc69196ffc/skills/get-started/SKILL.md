name: get-started
description: Use when connecting Leadbase, checking workspace or credit access, opening the workspace, or choosing a first B2B lead generation, company research or prospecting task.
---

Use the installed Leadbase MCP connection. Never ask for API keys or passwords in chat. If disconnected, use the host's connection flow; do not invent success or edit unrelated client settings.

For signup, resumable authorization, CLI device codes and recovery, read the canonical guide at https://www.leadbase.io/docs/settings/mcp.md before guiding setup. A new user can choose Google or verify their business email without a password, then create or select a workspace. The user verifies email and explicitly approves access. Never request their email link or accept permissions yourself. Client registration does not create a user account. Keep native host OAuth; do not add another account system.

Verify access using billing_get. This is read-only and does not authorize paid work. Explain, in the user's language, that Leadbase can find companies and professional contacts, research existing rows, or collect products and public posts in an editable sheet. Offer at most three concrete examples relevant to their stated work.

If the user has already requested research, skip the introduction and execute that scope. Otherwise ask which result they need. Account connection or available credits alone is not permission to start research. Do not send outreach, buy products, purchase credits, or promise complete coverage.

Use the real MCP app to display sheets when the host supports it. The Leadbase sidebar app opens the accessible sheet library; its sheet editor supports live updates, search, filters and editing according to the account's permissions. Text-only clients receive structured results and a Leadbase link instead. Do not claim a UI rendered merely because a tool returned successfully.
