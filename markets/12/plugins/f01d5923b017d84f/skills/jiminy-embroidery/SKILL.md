## Propose and complete production
Start with a useful design proposal, not a long questionnaire. Reuse prior choices. If the user delegates decisions, choose appropriate stitch methods and continue. Generate artwork only with an actual host image-generation tool; new creation is an option, not a requirement to upload an existing image. Preserve existing work and answered save choices. Use the selected live Studio and its current schemas, workspace/page IDs and actually available browser controls. If controls are unavailable, give precise manual steps and report the limit without claiming production.
For a dog-photo keepsake, ask for the real photo and offer host image simplification or original-photo editing. Read workflow's Dog photo keepsake section before fur production: required underlay, intentional gaps, wizard, direction arrows, color-mask eraser, combined final stitches and speed-based time advice. Do not substitute path points for final machine stitches.
For a bear, compare fur or long-short for hair, tatami for broad shapes, and satin/running for face details. Keep eyes, nose and mouth readable. Check whole design and enlarged face. For lettering use Satin Art Pro where suitable, split difficult branches/curves and inspect holes. For flowers/leaves read flower-veins. Recover useful shading around 8–12 colors when needed, then explicitly merge visually redundant colours; preserve face and clothing contrast rather than targeting a fixed 4–5 colors; remove unwanted background and tiny islands around 10px according to scale. Let the design and live preview determine settings, not rigid defaults. Read quality and relevant specialized references before exporting.

## Verify output and recovery
Read project-files, recovery and studio-operation. Separate generated bytes, host attachment, browser download request and confirmed device save. Never present blob URLs as durable chat downloads. JEF tests do not prove all machines work; PES/PEC/DST are experimental. Do not claim completed sewing from data previews.

## 増毛・三角毛（試験・2.15.0）
PROでfurStyle="zigzag"を選ぶ。根元中心を固定した等間隔の千鳥格子に配置する。zigzagSpacing=3〜40（PRO処理座標）、zigzagWidth=.05〜1（間隔に対する根元幅）、strokeLength=毛の長さを独立に調整。密度・旧zigzagRows／zigzagOverlapはこの方式では使わない。従来／ふわふわと通常の構成リストは変更しない。
1 毛束を配置で三角の配置ガイドを表示、2 くしで整えるで方向ブラシを使い、3 縫いを生成。根元中心はくしで移動せず、毛先の方向を変更する。細さ・長さが大きすぎれば均等配置でも重なるので確認する。画像の平坦部は同じ色・保護範囲内の方向を補間し、判定閾値だけで中心の根元を除外しない。全域に方向情報がなければ初期方向は仮なので手で整える。
輪郭／穴／選択マスクからの距離を4近傍で計算して外側から内側の帯へ縫う。同じ帯・同色の近い根元を候補にする。Aの出口根元とBの入口根元の中間点Mを作り、A毛先→M→B毛先。開始は最初の入口根元、終了は最後の出口根元。底辺は縫わない。候補の左右を比較し、近い側を入口にする。既存経路との交差、遠い相手、違う色、穴やマスクを横切る接続は除外する。繋がらない部分は別経路としてジャンプする。実際の3D形状を計算する方式ではなく、倒れた三角の毛を2D縫いで表現する。
PRO結果はファー構成リスト、任意の粗い畳／従来毛並みの下地は通常の構成リストに保持。短いジャンプの通常縫いへの接続は0固定。生成→最適化後の針数・JUMP・糸替え・時間幅を確認。送信／保存時は未生成の変更を再生成する。布での試し縫いが必要。
English: Uniform staggered fixed roots, independent spacing, width and length. Comb changes direction, not root positions. After placement, route outer distance bands first. Join tip A to midpoint(A exit root, B entry root) to tip B; leave triangle bases open. Validate colour/masks and crossings; disconnected chains remain jumps. Flat regions inherit nearby directions within the same protected colour region. This is a 2D stitch representation, not physical 3D simulation. Legacy/fluffy and optional normal-list underlay stay separate. Trial sewing is required.

## Shading and colour economy (2.17.0)

Inspect effective RGB groups and available thread codes with inspect_stitch_colors; explicitly merge with merge_stitch_colors when available. Keep black/dark-grey folds and readable face contrast. Verify actual export thread indices, not just quantization palette count. See the design-specific 12-to-7 example in the guides; do not use it as a universal target.

Disable only visually identified base regions replaced by the verified PRO result; do not remove required underlay or highlights.
Only call the two-PRO production complete after both results are actually imported and visually checked. Export JEF/PES and an editable JIMINY project; verify filenames, byte counts and hashes using supported host delivery. Separate generated data from actual sewing and disclose experimental PES output. If a required PRO or host interaction is unavailable, preserve completed work, report which step is blocked and ask before replacing that required PRO with another technique.
