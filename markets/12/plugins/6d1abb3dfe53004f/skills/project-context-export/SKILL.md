# Экспорт/импорт контекста

**Когда применять:** пользователь хочет сохранить утверждённые решения между чатами, перенести работу на другой аккаунт или продолжить прежний проект.

1. Сначала выясни, есть ли PROJECT_CONTEXT.md или подтверждённая стратегия в прикреплённом контексте. Не утверждай, что ChatGPT хранит информацию в плагине.
2. При экспорте создай один законченный Markdown-документ с шапкой: project_id (выбирает пользователь), context_version, date, provenance, privacy_note. Далее: цель, аудитория, позиционирование, ассоциации желательные/нежелательные, возможности и ограничения, утверждённая стратегия, продукт/оффер, каналы, контент, измерения, гипотезы, журнал решений, список источников, список неизвестного, следующий приоритет.
3. Для каждого значимого пункта отметь `approved`, `draft`, `user_report`, `verified_fact`, `hypothesis`, `unknown`. Не переносить персональные контакты, секреты, данные клиентов без явной потребности и согласия пользователя.
4. При импорте сначала покажи краткий реестр загруженной версии и коллизии с текущими данными. Не меняй утверждённые параметры молча.
5. Публикация, отправка, загрузка в Drive и долговременное хранение — только при существующих подключённых инструментах и явном разрешении. Без них отдавай готовый текст файла, а не фиктивное подтверждение сохранения.

**Выход:** переносимый PROJECT_CONTEXT.md и журнал изменённых решений либо диагностика отсутствующих данных.
