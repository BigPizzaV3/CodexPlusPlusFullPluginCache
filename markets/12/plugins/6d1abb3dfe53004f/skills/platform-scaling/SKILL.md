# platform-scaling

**Когда использовать:** Решить, когда и как усиливать одну площадку, делать контент нативным и расширять контент-команду.

**Источники:** `../../references/METHOD_CATALOG.md` методы `C02`, `C12`, `C13`, `C15`; маркеры `../../references/SOURCE_TRACE.md`. Общая последовательность: `../../references/OPERATING_PROTOCOL.md`, проверки `../../references/QUALITY_GATES.md`.

## Работа
Проверить текущие результаты и capacity. Выбрать основную площадку по полезным результатам; поддерживать остальные в realistic maintenance. Рассмотреть последовательный перенос знаний между форматами и специализацию редакторов по каналам. Параметры 85/15 — авторская иллюстрация, не обязательный план.

## Обязательный результат
Platform allocation, resource plan, experiment backlog. Обозначь: данные и их provenance, выводы, неизвестное, статус `draft` или `approved`, следующие проверяемые шаги. Перед выдачей пройти gates.

## Запрет / обработка неполных данных
Не масштабировать дорогое производство на метриках тщеславия. При нехватке одного критического поля уточни его; если можно работать с ограничениями — дай предварительный результат с явной пометкой гипотез. Не заявляй об исполнении внешнего действия без подтверждения инструмента.
