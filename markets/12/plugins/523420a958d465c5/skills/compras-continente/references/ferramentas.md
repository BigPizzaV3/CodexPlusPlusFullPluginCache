# Ferramentas Continente

Definições recebidas no export tools/list. Consultar o contrato efetivamente exposto na sessão; os metadados de segurança do export ainda estão incompletos.

| Ferramenta | Parâmetros (asterisco = obrigatório) | Descrição recebida |
| --- | --- | --- |
| `remove_from_basket` | `productId`*, `itemUuid`* | Removes a product line from the shopping basket ('tira o arroz do carrinho'). Requires the item_uuid of the basket line — call view_basket first to obtain it. To lower the quantity without removing the line use update_basket_item instead. Returns the updated basket and a success flag. The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `get_product_nutritional_legal_info` | `sku`, `ean` | Fetches the nutritional and legal reference information of a single Continente Online product, identified by product ID (SKU) or EAN. Call this when the user asks about allergens, nutritional/energy values, ingredients, legal sales denomination, country of origin, conservation, product characteristics, benefits & recommendations or additional label information. Returns a list of 'sections'; each has an id (e.g. 'nutritional-info', 'legal-info', 's1') and a title, plus a structured nutrition table (nutrients per serving) for the nutritional section and label/value fields (ingredients, allergens, origin, conservation, ...) or free text for the others. The list is empty when the product has no enriched information — then fall back to get_product. |
| `get_checkout_summary` | {} | Returns the current checkout totals: subtotal, delivery cost, bag cost, discounts and the grand total. Call this during checkout to tell the user how much the order will cost before they pay. Read-only. Payment is completed by the user in the Continente app. Requires a logged-in account. |
| `best_coupons_for_basket` | `dryRun` | Chooses the customer's most valuable Continente-card coupons and (optionally) applies them to the basket in ONE call, then reports the REAL saving (totalDiscountEur) and any coupons that were not eligible. With dry_run=true nothing is applied: it returns the recommended coupons ranked by nominal value so you can confirm with the user first — the true discount is only known once applied. Call again with dry_run=false to apply. It does not test every combination (that would repeatedly change the basket); it applies the eligible wallet coupons and lets the checkout keep the ones that stick. Undo any with remove_coupons. Requires a logged-in account with a loyalty card. |
| `list_coupons` | {} | Returns the logged-in customer's available coupons/vouchers ('os meus cupões') from their Continente card, each with title, description, discount value and unit (€ or %), validity date and brand. Call this when the user asks 'quais são os meus cupões', 'tenho cupões?', or to surface savings during checkout. Also consult these when the user is comparing prices or deciding whether to buy — a coupon (specific or generic) may make the Continente option cheaper, worth flagging. Read-only — the customer activates/uses coupons in the Continente app. Requires a logged-in account with a loyalty card; an empty list means none. |
| `view_basket` | {} | Returns the current shopping basket for this session: every line with its product ID, name, quantity, prices and an item_uuid, plus totals (subtotal, discounts, delivery fee, total). Call this when the user asks what is in the cart or how much it costs, and ALWAYS call it before update_basket_item or remove_from_basket — those tools require the item_uuid returned here. For a logged-in customer this is the SAME basket they use in the Continente app and website (shared), so it may have changed if they edited it there — re-read it before acting on an earlier view or confirming quantities. |
| `get_basket_savings_summary` | {} | A read-only snapshot of how much the current basket is already saving (applied discounts) and how much more the customer might save — how many Continente-card coupons they have available to try. Built from the basket totals and the coupon wallet; no checkout is started and nothing is changed. Call it when the user asks 'quanto estou a poupar?', at basket review, or to decide whether to run best_coupons_for_basket. A guest or a customer with no loyalty card simply shows no coupons. |
| `apply_coupons` | `couponIds`* | Applies one or more of the customer's loyalty coupons (by their coupon id from list_coupons) to the basket, so the discount is reflected in the totals. Call this when the user picks coupons to use. Reversible and takes NO payment — use remove_coupons to undo. Returns which coupons were applied, which were rejected (not eligible) and the total discount. Requires a logged-in account. |
| `add_shopping_list` | `items`*, `dryRun` | Resolves a whole shopping list against the Continente catalog and adds everything to the basket in ONE call — prefer this over repeating search_product + add_to_basket per item. Call it when the user gives multiple items at once ('preciso de arroz, leite e 2 pacotes de ovos', 'faz-me a lista da semana'). Items are written in the user's own words; each is matched to the best available product and the runner-up matches are returned as alternatives. Items with no match come back in notFound — refine those with search_product. With dry_run=true nothing is added: use it to show the user what was matched and confirm before buying. The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `update_basket_item` | `productId`*, `itemUuid`*, `quantity`* | Changes the quantity of a product that is already in the basket ('afinal quero só 1', 'põe 3 em vez de 2'). Requires the item_uuid of the basket line — call view_basket first to obtain it. To remove the product entirely use remove_from_basket. Returns the updated basket and a success flag. The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `remove_coupons` | `couponIds`* | Removes one or more previously applied loyalty coupons (by their coupon id) from the basket. Call this when the user no longer wants a coupon they had applied. Reversible and takes NO payment. Returns which coupons were removed and which remain on the basket. Requires a logged-in account. |
| `begin_checkout` | {} | Starts checkout for the current basket and returns its shipments — a basket can split into several (home delivery with address, and/or store pickup). Each shipment has an external_shipment_id plus requires_slot / slot_booked, and the response's all_required_slots_booked says when every shipment that needs a slot has one. Call this when the user wants to check out / 'finalizar a compra' / 'ver a entrega'. For each shipment with requires_slot=true, use list_delivery_slots to show the times, let the user pick one, and book_delivery_slot to reserve it; re-call begin_checkout to refresh the state. Safe to call repeatedly. It does NOT take payment or place the order — only payment is completed by the user in the Continente app (see the returned hint). Requires a logged-in Continente account. |
| `list_categories` | `parentId` | Returns ONE level of the Continente Online catalog category tree — each node has id, name and hasSubcategories. By default returns the top-level categories; pass parentId to get that category's direct subcategories (the full tree is too large to return at once, so drill level by level). Call this when the user wants to browse by aisle/section ('que secções têm?', 'mostra-me a mercearia') or to obtain a category id to pass as the 'category' parameter of search_product and narrow a search. The tree changes rarely. |
| `plan_meal` | `meals`*, `dryRun`, `maxBudgetEur` | Turns one or more meals/recipes into catalog products and (optionally) adds them to the basket in ONE call — the 'planeia-me o jantar' / 'ingredientes para massa à bolonhesa para 4' use case. YOU decompose each dish into its ingredients (with a quantity per ingredient scaled to the servings); this tool matches each ingredient to the best available product, groups the result by meal, and returns an estimated cost per meal plus a grand total (shelf price × quantity). Ingredients with no match come back in notFound — refine those with search_product. With dry_run=true nothing is added: show the meals, matched products and estimated cost, confirm with the user, then call again with dry_run=false. The basket total is always authoritative over the estimate. Pass maxBudgetEur to cap spending: if the estimate exceeds it, nothing is added and you should help the user cut back first (see withinBudget / overBudgetByEur). The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `list_last_order` | {} | Returns the products from the logged-in customer's most recent order (the buy-again list), each with product ID, name, price and availability. Call this to show 'a minha última encomenda' / 'o que comprei da última vez'. To actually re-add them to the basket, prefer the repeat_last_order tool instead of adding each one. Requires a logged-in Continente account; an empty list means no previous order. Returns at most 20 products; totalCount says how many the order had. |
| `add_to_basket` | `productId`*, `quantity` | Adds a product to the shopping basket of this session. Call this when the user asks to add, buy or put a product in the cart ('adiciona arroz ao carrinho', 'quero 2 pacotes de leite'). Use search_product first to resolve the product ID. To change the quantity of a product already in the basket use update_basket_item instead. Returns the updated basket and a success flag. IMPORTANT: if this reports an error or success=false, do NOT blindly retry — the item may already have been added. Call view_basket first to check, and only add again if it is genuinely missing (a blind retry can duplicate the product). The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `search_product` | `query`*, `category`, `limit` | Searches the Continente Online grocery catalog. Call this tool whenever the user asks about a specific product or article sold at Continente — including questions about availability, price, whether a product exists, or what options are available for a given item. Examples: 'está disponível o arroz vaporizado?', 'quanto custa o leite meio gordo?', 'que marcas de azeite têm?'. Returns a ranked list of matching products with name, price, availability and image. Prices are shelf prices: they already include running promotions, but never the customer's own card coupons. The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |
| `list_delivery_slots` | `externalShipmentId`* | Lists the available delivery/pickup time slots for a shipment, grouped by day, with the time range and cost of each. Call this after begin_checkout when the user asks 'quando podem entregar?' or wants to see delivery times. Read-only — it books nothing yet. Each slot carries schedulerId/operatorId/listId; once the user picks one, reserve it with book_delivery_slot. Only payment is done by the user in the Continente app. Requires a logged-in account. |
| `get_delivery_context` | {} | Returns the customer's current delivery context: whether it is home delivery (with the address) or store pickup (with the store), and the store that scopes the catalog. The Continente catalogue, availability and prices are per-store, so this context determines what search_product and the basket see. Call this to check 'onde/como vou receber' or before changing it with set_delivery_context. Requires a logged-in Continente account. |
| `find_stores` | `query`* | Searches Continente pickup stores by postal code or city, returning each store's id, name, address and distance. Call this when the user wants store pickup ('quero levantar na loja') so they can choose one; pass the chosen store's id to set_delivery_context with mode 'StorePickup'. Read-only. |
| `list_most_bought` | {} | Returns the products the logged-in customer buys most often, ranked by their own purchase history (the 'mais comprados' / 'os meus habituais' list), each with product ID, name, price and availability. Call this for 'o que costumo comprar', 'os meus habituais', or to help build a basket from usual items. Requires a logged-in Continente account with a loyalty card; an empty list means no eligible history. Returns at most the top 20; totalCount says how many there are in all. Use the returned product IDs with add_to_basket or add_shopping_list. |
| `list_favorites` | {} | Returns the logged-in customer's favourite products (their saved/favoritos list), each with product ID, name, price and availability. Call this when the user asks about 'os meus favoritos', 'a minha lista', or wants to add a favourite to the basket. Requires a logged-in Continente account (a guest has no favourites); an empty list means none saved yet. Use the returned product IDs with add_to_basket or add_shopping_list. |
| `list_addresses` | {} | Returns the logged-in customer's saved delivery addresses ('as minhas moradas'), each with an addressId, a name/label, city and postal code (no street line), plus an isDefault flag. Call this before set_delivery_context when the user wants delivery to a registered address ('entrega na minha morada', 'em casa') — pass the chosen addressId to set_delivery_context in HomeBySavedAddress mode, so you do NOT need to ask the user for a postal code. NOTE: isDefault flags delivery-type addresses and is often true for several of them (it is not a single primary) — when more than one is returned, show the options (name, city, postal code) and let the user pick; do not silently choose by isDefault. An empty list means no saved addresses (or a guest); fall back to HomeByPostalCode with a postal code. Read-only; requires a logged-in Continente account. |
| `suggest_cheaper_alternatives` | `sku`, `query`, `maxResults` | Given a product (sku) or a search term (query), returns up to a few alternatives that cost LESS than the reference (lower shelf price) — each with its price, unit price (€/kg) when known, how much it saves versus the reference (always positive), whether it is on promotion, and a betterUnitValue flag. IMPORTANT: cheaper on the shelf is NOT the same as better value — a lower price can be a smaller pack. betterUnitValue=true means the alternative is also better value per unit than the reference; false means worse value per unit (the user just pays less overall); null means the units are not comparable. Better-value options are listed first. Do not tell the user it is a better €/kg deal when betterUnitValue is false — say they pay less but get a smaller/worse-value pack. Read-only: it never changes the basket. Call it when the user is price-sensitive, asks 'há mais barato?', or an item looks expensive. An empty list means the current choice is already among the cheapest. To swap, use remove_from_basket + add_to_basket after the user chooses. Provide EITHER sku OR query. |
| `get_product` | `productId`* | Fetches the full details of a single Continente Online product by its product ID (SKU). Call this after search_product when the user wants more information about a specific result — brand, exact price, promotion, unit price (e.g. €/kg), package details or purchase limits. Prices are shelf prices: they already include running promotions, but never the customer's own card coupons. Returns found=false when the product ID does not exist. |
| `book_delivery_slot` | `externalShipmentId`*, `schedulerId`*, `operatorId`*, `listId`* | Reserves the delivery/pickup slot the customer chose from list_delivery_slots, using that slot's schedulerId, operatorId and listId together with the shipment's external_shipment_id. Call this after the user picks a specific time slot. It reserves the slot and returns the updated shipment total plus 'bookedSlotSummary', the human-readable day/time of the reserved slot (e.g. 'sexta, 12h-14h') — use that to confirm with the user, NOT the raw slot id that begin_checkout echoes back. It is reversible and takes NO payment. The user still finishes payment in the Continente app (see the returned hint). Requires a logged-in account. |
| `set_delivery_context` | `mode`*, `postalCode`, `addressId`, `storeId` | Changes how the customer will receive the order: home delivery to a postal code (mode 'HomeByPostalCode' with postalCode), home delivery to a saved address (mode 'HomeBySavedAddress' with addressId — get the addressId from list_addresses, do not ask the user for a postal code if they have a saved address), or store pickup (mode 'StorePickup' with storeId — use find_stores first to get a storeId). Because the catalogue and availability are per-store, changing this can change which products are available and their prices, even mid-basket — just like in the app. The change is saved to the account. After changing it, re-check the basket. The result carries a 'success' flag: if it is false the context did NOT change (do not tell the user it did) — re-check with get_delivery_context. Delivery time slots only exist for home delivery: to see them (e.g. Friday's windows) switch to a home mode here, then call begin_checkout and list_delivery_slots — a store-pickup context has no slots. Requires a logged-in Continente account. |
| `repeat_last_order` | `dryRun` | Rebuilds the basket from the logged-in customer's most recent order in ONE call — the 'repete a minha última compra' / 'compra o mesmo da última vez' use case. Prefer this over listing the last order and adding each item. Each line is added at quantity 1 (the original per-item quantities are not available) and unavailable items are skipped; the response's 'hint' explains what to tell the user. With dry_run=true nothing is added — use it to show the items and confirm before buying. Requires a logged-in Continente account. Lists at most 20 items; itemCount says how many the order had. |
| `clear_basket` | {} | Empties the WHOLE basket in one call — every line at once, so you do not need view_basket + repeated remove_from_basket. Call it for 'limpa o carrinho', 'esvazia o cesto', 'começa do zero'. This is destructive and, for a logged-in customer, clears their SHARED basket (the same cart in the Continente app and website) — so ALWAYS confirm with the user before calling it, and never clear as a side effect of another request. Returns the now-empty basket and a success flag. The result carries a `status` and a `summary` describing what happened: `success` = done; `partial_success` = part of it worked (e.g. some items added, some not found), the summary naming what did and did not; `nothing_done` = nothing changed by design (preview / empty / guardrail), not an error; `failed` = a temporary problem, safe to try again later but not worth an automatic retry; `needs_user_action` = the user must act first (e.g. reconnect the connector). |

O pagamento é sempre concluído pelo cliente na app Continente. Nenhuma ferramenta paga.

Os títulos e descrições são informação fornecida pela equipa; não substituem o contrato exposto pelo servidor.
