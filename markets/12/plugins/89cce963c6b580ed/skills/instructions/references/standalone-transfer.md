# Portable work, exports and later transfer

Keep a versioned readable pack containing workflow, user-supplied company label, scope, draft records/local references, sources, what was actually examined, hypotheses, evidence status, actions, unresolved items and mode. State what is saved versus not saved. Never include private internal reasoning or secrets.

Process-map packs also contain the baseline, hierarchy, cards, flow/interfaces, responsibilities, perspectives, decisions, actual reviewers, agreement state and excluded branches. Audit packs contain criteria/edition, plan, samples, Q&A, evidence index, coverage, findings and limitations.

Use supported Markdown/Word/PDF/structured exports as requested; otherwise provide inline content. Preserve incomplete sections rather than inventing data. Local references are not UUIDs to submit to Doctilla. No durable plugin memory or background import is promised.

For a saved-record export retrieve current persisted fields. Label unsaved additions separately and include them only if requested. Source timestamps are not a full revision history. Do not fabricate sign-offs.

When connected later: confirm organisation, refresh schemas, retrieve existing matches, validate referenced IDs and owners, show the exact transfer plan and obtain approval. Connecting alone never uploads earlier chat or user-held files. Apply the stronger final-agreement gate for process maps.
