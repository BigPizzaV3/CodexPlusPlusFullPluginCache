---
name: vectorize-image
description: Convert a user-supplied PNG, JPG, GIF, BMP or WebP logo, icon, or illustration into SVG, PDF, EPS or DXF with Vectali. Use for requested raster-to-vector conversion, not generating new artwork or general photo editing.
---

Use the Vectali MCP tools for images the user asks to vectorize. Check allowance when the user asks or when needed to explain an account problem; do not add a separate account call before every conversion. Ten API plans range from 500 credits ($19/month) to 100,000 credits ($1,199/month). See https://vectali.com/pricing/#api for every tier and https://vectali.com/contact/#volume for larger volumes. One successful conversion uses one credit; API and MCP share the allowance. Administrator-granted API credits also work without a subscription and are used after any monthly allowance. Browser export plans do not cover server conversions. Never initiate a purchase or switch plans as part of conversion. Do not invent other API tiers; refer users to the current billing page for available plans.

Choose the image handoff supported by the host. In ChatGPT, send its verified original attachment through `file` to `convert_image`. In Cursor, Grok Bot, Claude, or another host without that attachment handoff, call `prepare_image_upload`, give the user its first-party picker link, and wait for confirmation that the original image was uploaded. The picker requires the same Vectali account as the connection. Then pass the returned `upload_id` to `convert_image`; do not combine it with `file` or encoded input. A chat attachment alone does not mean that the first-party upload is complete. Uploading uses no credit; the picker link expires after 15 minutes.

Normally omit `request_id`. Vectali derives a stable ID from the image bytes; identical automatic retries or reattached copies reuse the saved result without another charge. Keep upload and conversion IDs internal. Never ask the user for an ID, URL, credentials or encoded bytes. Do not turn an internal workspace path, asset ID, or arbitrary public URL into a `file` input. Never generate, transcribe, copy or print base64 in a model response. Software clients may supply programmatically encoded original bytes for compatibility. Advanced clients can specify an explicit ID for a deliberate new conversion; preserve that ID on retries. The server accepts PNG/JPG/GIF/BMP/WebP up to 4 megapixels (4,000,000 pixels total), for example 2,000 × 2,000. Files must also be no larger than 10 MiB and 4,096 pixels per side. Send the original unchanged when it fits; do not resize to a smaller limit from an older plugin version. For an image above the current limit, explain the required size and ask before altering the artwork.

When explaining usage, use `allowance_used_this_call`: `1` for a new conversion, `0` for a retry or retrieval. `reused_result` confirms an existing SVG was returned. The legacy `allowance_cost_for_request_id` is a lifetime cost and does not mean this call used another allowance.

Return a short success message and the normal clickable Markdown download link for the selected format. Keep conversion IDs, path counts and processing statistics internal unless requested. When the user wants to inspect or compare the result, call `show_conversion` with the returned conversion ID and selected format. Its viewer shows the saved original and SVG, with zoom, pan, preview backgrounds and format selection. It never retraces or spends credits. Preview backgrounds do not change the artwork. Keep the ordinary Markdown download link even when the viewer is available; clients without UI still need it. If the viewer fails to display, keep the download link and do not repeat the conversion. Refresh or change format with `get_conversion`, not `convert_image`. Note visible limitations only if inspected. The link expires after 10 minutes; use `get_conversion` to refresh it without converting again. Links are bearer capabilities: do not publish them elsewhere without the user's request.

Inspect small lettering, holes, disconnected shapes, edges and gradients when visual access is available. Do not infer quality from byte size, path count or overlap alone. Do not claim an exact recovery of the original vector paths. Never claim to have inspected a result that you have not viewed.

Follow the error’s `next_action` and `retry_after_seconds`. Retry only when `retryable` is true, using the same image and explicit ID, or omitting the ID again. If the host cannot hand off its attachment, use the first-party picker instead of repeatedly asking for the same chat attachment. An expired picker needs a fresh upload link and a new confirmed upload; never claim an old upload succeeded. Invalid or missing image bytes need the original PNG/JPG/GIF/BMP/WebP again, not a different encoding invented by the model. A deleted or unavailable saved result needs a new explicit ID and one new allowance, only if the user wants a fresh conversion. Stop after two retries and explain the error. Authentication, quota and invalid-image errors require an account or input correction; do not loop. Never ask the user to paste credentials into the conversation.

When the user requests an output format, set `output_format` to `svg`, `pdf`, `eps` or `dxf`. Default to SVG. Change format using `get_conversion` with the same saved conversion ID; do not retrace. Share the returned `export_note` when relevant. Animated GIF/WebP inputs use their first frame. EPS flattens transparency onto white and simplifies mesh paints. DXF is closed CAD outlines in millimeters at 96 pixels per inch; check scale and duplicate edges before cutting.
