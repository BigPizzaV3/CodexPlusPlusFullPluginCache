---
name: mandate-light-review-design
description: Review a public Mandate Light project's design, delivery scope or visual against approved intent.
---

Use the public project's attached app context, including approved requirements, proposals, selected standards and frozen scopes. If context is absent or incomplete, ask the user to open the project and use Project details → Use in chat; do not invent read_workspace or borrow private Mandate tools.

Review the whole design unless a delivery scope is supplied. Distinguish approved intent, proposed changes, assumptions and evidence. Check the main journey, failures, dependencies, exclusions and measurable outcomes. Compare supplied sketches or images with agreed behaviour: a pictured feature is not an approved requirement. A mandate-image reference is not an inspected picture; review the recorded meaning and state when the original visual was not supplied. Name material findings, their consequence and the smallest useful resolution; reference the affected requirement titles. Do not manufacture defects or write filler to complete a checklist. An early design can still be reviewed.

End with one advisory conclusion: Proceed to engineering; Proceed with qualifications; or Clarification recommended before engineering. State what has not been verified. A design review does not approve requirements, issue a build brief or accept a build.

When a whole-project build is too broad, propose a named delivery scope with included approved requirements, explicit exclusions, dependencies and their reasons. The owner chooses these in Prepare for engineering, previews the verification brief and saves it. A dependency is context, not implementation authority. Saving a scope does not save this advisory assessment as a formal readiness review. Each issued brief keeps its own baseline; another scope at the same revision can be prepared separately. Use History for earlier build and verification briefs.

Keep the review in chat. Save changes only when requested, using propose_decision with the attached projectId and publicWorkspaceId; wait for a receipt or fresh context before claiming they were applied. Follow the selected standards as guidance; drafts do not approve product scope. Preserve Light's local storage and portable backup save route.
