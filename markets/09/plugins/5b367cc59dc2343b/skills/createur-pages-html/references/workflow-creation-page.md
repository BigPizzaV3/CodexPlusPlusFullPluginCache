### Si la cliente a des envies mais pas de charte complète

Lui permettre de fournir :

- quelques mots décrivant l’ambiance recherchée ;
- des couleurs qu’elle aime ou souhaite éviter ;
- des préférences typographiques ;
- des captures d’écran ;
- des liens vers des pages qu’elle aime ;
- des exemples de mises en page ;
- des références provenant de son univers ou d’autres secteurs.

Les références servent à comprendre une direction, pas à copier automatiquement une page.

Identifier ce que la cliente aime précisément dans chaque référence lorsque ce n’est pas évident : couleurs, typographie, sobriété, rythme, composition, formes, traitement des photos ou autre.

### Si la cliente n’a aucune direction artistique

Ne pas bloquer le projet.

À partir de son activité, son offre, son audience, son contenu et les éventuelles préférences exprimées, proposer une direction artistique cohérente.

Présenter simplement les grandes décisions proposées :

- ambiance générale ;
- palette ;
- approche typographique ;
- langage de formes ;
- style de composition ;
- traitement des boutons et médias.

Faire valider cette direction avant de produire la page complète.

Ne jamais appliquer automatiquement une identité visuelle particulière.

## 5. Analyser les références

Lorsqu’une page, une URL ou des captures servent de référence visuelle, les analyser avant le code.

Lorsque les outils disponibles permettent réellement de consulter une URL, distinguer :

### Invariants ou éléments identitaires

- logo ;
- palette ;
- typographies ;
- style photographique ;
- motifs ;
- formes ;
- signes graphiques distinctifs.

### Conventions visuelles

- rayons ;
- bordures ;
- ombres ;
- largeur des contenus ;
- traitement des CTA ;
- densité ;
- compositions ;
- rythme des fonds ;
- hiérarchie typographique.

### Points forts

Identifier ce qui fonctionne notamment pour :

- la lisibilité ;
- la hiérarchie ;
- la compréhension ;
- la cohérence ;
- la perception de qualité.

### Fragilités

Identifier notamment :

- contrastes insuffisants ;
- textes trop petits ;
- hiérarchie faible ;
- compositions répétitives ;
- effets datés ;
- problèmes mobiles ;
- densité excessive ;
- manque de respiration ;
- incohérences.

Distinguer clairement l’analyse des modifications proposées.

Ne jamais modifier silencieusement un invariant de marque.

## 6. Fixer la liberté créative

Déterminer le degré de liberté souhaité si cela n’est pas déjà clair.

### Fidélité stricte

Conserver la palette, les polices, la géométrie et le langage graphique.

Améliorer essentiellement :

- structure ;
- lisibilité ;
- responsive ;
- hiérarchie lorsque cela ne modifie pas l’identité.

### Modernisation contrôlée

Conserver une identité immédiatement reconnaissable tout en pouvant améliorer :

- espacements ;
- compositions ;
- hiérarchie ;
- formes ;
- traitements graphiques ;
- certains composants.

Une modification importante d’un invariant doit être approuvée.

### Réinterprétation créative

Utiliser l’univers existant comme point de départ tout en autorisant une évolution plus visible.

Identifier ce qui doit absolument rester et ce qui peut évoluer.

## 7. Déterminer le langage de formes

Lorsque la réponse n’est pas évidente à partir de la charte ou des références, demander le niveau d’arrondi souhaité pour les boutons, blocs et photos :

- complètement carré ;
- légèrement arrondi ;
- franchement arrondi, autour de 10 %.

Appliquer ensuite cette intention comme un système cohérent.

Ne pas imposer exactement la même valeur CSS à tous les composants.

## 8. Inventorier les ressources

Avant de coder, inventorier ce qui est disponible :

- logo ;
- photos ;
- portraits ;
- mockups ;
- captures ;
- vidéos ;
- témoignages ;
- avis ;
- preuves ;
- chiffres autorisés ;
- illustrations ;
- textures ;
- autres éléments de marque.

Lorsqu’une URL fournie contient déjà ces ressources et que les outils permettent réellement de les consulter, identifier ce qui peut être récupéré.

Ne pas demander à la cliente de renvoyer inutilement un élément déjà accessible.

Lorsque l’usage d’un élément récupéré n’est pas évident, demander confirmation avant de l’intégrer.

Ne jamais fabriquer un asset manquant.

## 9. Inventorier tous les liens

Avant une version finale, identifier les liens réellement nécessaires.

Selon la page, demander ou récupérer :

- destination de chaque CTA ;
- lien de réservation ;
- lien de paiement ;
- lien d’opt-in lorsque nécessaire ;
- lien vers les avis ;
- Mentions légales et CGV ;
- Politique de confidentialité ;
- autres liens du footer ;
- autres éléments cliquables.

Lorsqu’ils sont déjà présents sur une page fournie et que leur réutilisation est autorisée, les récupérer plutôt que de les redemander.

Ne jamais inventer une URL manquante.

Regrouper les liens manquants dans une seule demande lorsque possible.

## 10. Identifier les fonctionnalités Systeme.io

Déterminer uniquement les fonctionnalités réellement nécessaires :

- popup ;
- formulaire ;
- bouton natif ;
- compte à rebours ;
- FAQ ;
- vidéo ;
- CTA fixe mobile ;
- autre interaction utile.

Ne pas proposer automatiquement des fonctionnalités inutiles.

Pour un popup Systeme.io, obtenir avant finalisation :

- l’identifiant du popup ;
- un véritable bouton natif Systeme.io situé hors du popup ;
- la confirmation que son action est configurée sur « Afficher le popup » ;
- l’identifiant HTML de ce bouton.

Ne jamais considérer le seul identifiant du popup comme suffisant.

Pour un compte à rebours, récupérer en une fois :

- date ;
- heure ;
- fuseau horaire ;
- texte après expiration ;
- comportement à zéro si particulier.

## 11. Regrouper les informations manquantes

Après l’inventaire, classer mentalement les informations en quatre catégories :

1. déjà disponibles ;
2. récupérables depuis les sources fournies ;
3. indispensables mais manquantes ;
4. facultatives.

Ne poser des questions que pour les catégories 3 et, lorsque cela influence réellement le projet, 4.

Regrouper les questions interdépendantes.

Ne jamais faire subir à la cliente une longue succession de questions unitaires.

Ne pas bloquer toute la création pour un asset purement facultatif.

## 12. Inventorier le contenu avant de dessiner

À partir du dernier texte validé, lister les sections.

Pour chacune, identifier :

- fonction commerciale ;
- idée dominante ;
- contenu indispensable ;
- preuve ou média disponible ;
- densité ;
- CTA éventuel.

Ne choisir aucun composant à cette étape.

## 13. Dessiner le rythme global

Définir environ trois à cinq compositions dominantes et deux ou trois ruptures maximum.

Rechercher une alternance de silhouettes et de densités, pas une alternance mécanique de couleurs.

La page doit avoir un rythme éditorial intentionnel.

Éviter plusieurs sections textuelles denses identiques à la suite.

Utiliser lorsque pertinent :

- espace ;
- changement d’échelle ;
- média ;
- preuve ;
- citation ;
- chiffres ;
- comparaison ;
- processus ;
- rupture visuelle.

## 14. Établir la carte de composition

Pour chaque section, déterminer :

- fonction : problème, mécanisme, preuve, offre, objection, décision ou autre ;
- focale : phrase, chiffre, image, liste, processus, témoignage ou autre ;
- composition ;
- contraste ;
- continuité avec la section précédente ;
- transformation mobile.

Ne pas laisser le format du document source décider de la mise en page.

Interdire deux silhouettes identiques à la suite sauf continuité volontaire.

## 15. Choisir les compositions selon le contenu

Choisir une composition parce qu’elle sert l’information.

Exemples de logiques possibles :

- problème : opposition ;
- mécanisme : système, flux ou éléments reliés ;
- méthode : progression en étapes ;
- temporalité : parcours ou frise ;
- résultats : liste collective ou composition irrégulière ;
- autorité : photo, récit, chiffres et point de vue ;
- programme : grandes bandes, chapitres ou accordéons ;
- qualification : opposition oui/non ;
- témoignages : citation, photo et résultat ;
- prix : panneau dominant ;
- FAQ : ensemble accordéon ;
- conclusion : rupture forte ou manifeste.

Ces possibilités ne sont pas des templates obligatoires.

Toujours choisir selon le texte réel.

## 16. Repérer les contenus pouvant devenir visuels

Sans modifier leur sens, identifier les contenus qui gagneraient à devenir :

- étapes ;
- parcours ;
- frise ;
- comparaison ;
- avant/après ;
- séquence numérotée ;
- chiffres forts ;
- grille ;
- liste illustrée ;
- schéma simple.

Ne jamais inventer une relation, une étape ou une hiérarchie absente du contenu.

Créer les schémas simples en HTML, CSS ou SVG intégré.

Prévoir immédiatement leur transformation mobile.

## 17. Tester l’effet générateur

Avant les finitions, observer la page comme un ensemble.

Recomposer si :

- la majorité du texte est centrée ;
- la page ressemble à une suite de cartes ;
- les fonds alternent selon une formule prévisible ;
- les sections ont toutes une densité proche ;
- les médias semblent ajoutés après coup ;
- les CTA interrompent constamment la lecture ;
- plus d’un tiers des sections reprend exactement la même combinaison fond + cadre + titre + liste.

Le document source ne doit jamais être converti mécaniquement selon ses séparateurs, titres ou listes.

## 18. Concevoir le mobile comme une composition autonome

Pour chaque relation horizontale, déterminer :

- ordre ;
- empilement ;
- hiérarchie ;
- connecteur éventuel ;
- espacement ;
- comportement des médias.

Transformer les schémas horizontaux en parcours verticaux lorsque nécessaire.

Supprimer les décalages décoratifs responsables de débordements.

Ne jamais réduire une composition complexe jusqu’à la rendre illisible.

Conserver le corps de texte à 16 px minimum et les zones tactiles importantes à environ 44 px minimum.

## 19. Coder

Une fois le contenu, les ressources, la direction artistique et la carte de composition suffisamment définis, produire le fragment conformément à `01_REGLES_HTML_SYSTEMEIO.md`.

Ne pas coder une page complète avant d’avoir résolu les décisions indispensables.

## 20. Contrôler avant livraison

Appliquer intégralement `03_CHECKLIST_QUALITE.md`.

Corriger les problèmes détectés.

Lorsqu’un point exige une vérification visuelle ou technique impossible avec les outils disponibles, ne jamais prétendre qu’il a été validé.

Le signaler parmi les points restant à contrôler.
