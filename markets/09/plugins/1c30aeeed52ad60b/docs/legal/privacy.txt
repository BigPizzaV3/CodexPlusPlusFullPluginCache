Tool request data
We receive the information included in a tool request. This can include a template selection or a structured draft with a name, workflow goal, trigger, input and output descriptions, steps, constraints, non-goals, completion claims and evidence checks. Include only what is needed for the drafting task.

We use request data to return public template information, check the draft’s structure or render portable files. Results return to the calling client. The application processes drafts in memory and does not save drafts or log request bodies, generated file contents or error contents. The application does not call a model provider, fetch external URLs or use an analytics integration.

Do not submit passwords, API keys, payment-card details, government identifiers, protected health information or confidential material you are not authorized to share. Use redacted or fictional examples wherever possible.

Hosting and operational records
Cloudflare hosts the service. Workers logs, invocation logs and traces are disabled. Cloudflare still processes aggregate metrics and infrastructure records. Its privacy policy describes network information such as IP addresses, routing data and security statistics used to operate, maintain and protect its services. Cloudflare and its service providers may process information internationally. Retention depends on the processing purpose, data type and sensitivity, risk, and legal or contractual requirements; its policy does not specify one fixed period for all such information. Cloudflare privacy policy: https://www.cloudflare.com/privacypolicy/

Compatible browsers may send network-error reports to Cloudflare with failure and network-condition details. Cloudflare states that a report’s client IP address is held in memory only for that report request, used to derive network and location information, and then dropped. This describes its network-error reporting pipeline: https://developers.cloudflare.com/network-error-logging/
