# Carousel DSL — спецификация вёрстки для LLM

Самостоятельная инструкция для языковых моделей, плагинов и MCP-адаптеров. Версия формата: `carousel: 1`. Ревизия инструкции: **2026-10-04**, проверена по коду CarouselKit, commit `684692d`. Этот файл можно переносить в отдельный репозиторий: все необходимые справочники имён включены ниже. Изображения, шрифты и движок рендеринга остаются ресурсами приложения; Markdown не заменяет их байты.

Документ описывает **реализованный** формат, а не планы развития. «Обязательно» означает требование к генератору, даже если текущий читатель допускает отсутствие поля. Ограничения самого приложения и потери при открытии/сохранении перечислены в разделе 15. Полное покрытие всех функций приложения без потерь пока не достигнуто.

LLM: сначала выбери композицию и доступные ресурсы, затем выдай один `carousel.yaml` по разделам 1–14. Не придумывай поля и идентификаторы. Названия стикеров, рамок, гридов, шрифтов и режимов бери из встроенных справочников этого файла. Если вызывающая система передала более свежий проверенный каталог, используй его. Правила интеграции и готовые рецепты находятся после основного примера.

## 1. Формат документа

Выход LLM — один YAML-документ, без Markdown-обёртки и пояснений. Корень — отображение:

| Поле | Тип | Обязательность / значение |
|---|---|---|
| `carousel` | integer | Обязательно, `1` |
| `ratio` | enum | Обязательно, из таблицы ниже |
| `slides` | integer | Обязательно, `1…20` |
| `background` | color | Обязательно, общий фон всех слайдов |
| `requires` | string[] | Обязательно, список использованных расширений; без расширений `[]` |
| `assets` | map<string, asset> | Необязательно; без ресурсов опустить или `{}` |
| `layers` | layer[] | Обязательно; порядок от заднего слоя к переднему |

| `ratio` | Ширина : высота |
|---|---|
| `square-1-1` | 1:1 |
| `portrait-4-5` | 4:5 |
| `portrait-3-4` | 3:4 |
| `story-9-16` | 9:16 |
| `landscape-191-1` | 1.91:1 |

Каждый элемент `layers` содержит ровно один ключ типа слоя: `image`, `text`, `shape`, `sticker`, `frame`, `grid`, `blender` или `mask`. Вложенных слоёв нет. У слоя нет `id`, `name`, `children` и `zIndex`.

## 2. Синтаксис и базовые типы

- Строки свободного содержания, имена ресурсов, пути, цвета и ключи в `assets` писать в двойных кавычках.
- Значения enum, числа, `true`, `false`, `null` писать без кавычек. Исключение для однозначности YAML: значение `off` допустимо писать как `"off"`.
- Перенос внутри текста: `\n`. Кавычка внутри строки: `\"`. Обратная косая черта: `\\`.
- Не использовать одинарные кавычки, блочные строки `|` / `>`, YAML-якоря, алиасы, merge-ключ `<<`, повторяющиеся ключи.
- `color` — строка `"RRGGBB"` или `"RRGGBBAA"`, sRGB, без `#`; альфа в последних двух символах. Для `shadow.color`, `frame.ink.color` и `sticker.color` использовать только `"RRGGBB"`. Полностью прозрачный фон: `"00000000"`.
- `null` означает отсутствие содержимого. `"null"` означает строковый идентификатор ресурса.
- Все числа конечные. Текущий читатель ограничивает модуль числовых координат и параметров значением `1_000_000`.
- Не добавлять неизвестные поля: читатель может проигнорировать их, но это не создаёт соответствующей возможности вёрстки.

## 3. Координаты и размеры

Все слайды имеют одинаковые размеры `W × H`. Слайды образуют горизонтальную ленту. Нумерация начинается с `1`.

| Значение | Единицы и смысл |
|---|---|
| `slide` | Домашний слайд слоя, целое `1…slides` |
| `at: [x, y]` | Центр слоя: `x × W`, `y × H` относительно домашнего слайда |
| `size: [w, h]` | Размер слоя: `w × W`, `h × H` |
| `frame.width` | Ширина рамки: `width × W`; высота из пресета |
| `font.size` | Кегль: `size × W` |
| `tracking`, `leading` | Добавочные интервалы: значение `× W` |
| Радиусы, толщины, зазоры, внешние поля, длина и размытие тени | Значение `× W`, в том числе по вертикали |
| `rotate` | Градусы по часовой стрелке вокруг центра слоя; по умолчанию `0` |
| `flip: [h, v]` | Горизонтальное и вертикальное отражения; по умолчанию `[false, false]` |
| `opacity` | `0…1`, по умолчанию `1` |
| `locked` | Запрет перемещения в редакторе, по умолчанию `false`; на изображение не влияет |

Начало координат — левый верхний угол; X направлена вправо, Y вниз. Значения `at` могут быть отрицательными и больше `1`. Размеры должны быть положительными и могут быть больше `1`: слой может занимать несколько слайдов. Радиусы, толщины, размытие и отступы генерировать неотрицательными; их величина не должна уничтожать видимую область слоя или ячейки.

Для ленты без промежутков:

```text
centerX = (slide - 1 + at.x) × W
centerY = at.y × H
left    = centerX - size.w × W / 2
top     = centerY - size.h × H / 2
```

`left` и `top` вычислены до поворота. Расстояние между превью слайдов в интерфейсе не является частью DSL.

Физический квадрат со стороной `s × W` задаётся как `size: [s, s × W/H]`. На формате 4:5 квадрат шириной `0.4` имеет `size: [0.4, 0.32]`. Пара `[0.4, 0.4]` повторяет пропорцию слайда.

Для собственного фона слайда использовать нижний `shape` типа `rectangle` с `at: [0.5, 0.5]`, `size: [1, 1]`. Поля фона отдельного слайда нет.

## 4. Матрица возможностей

`—` означает: поле не генерировать для этого типа.

| Поле | image | text | shape | sticker | frame | grid | blender | mask |
|---|---|---|---|---|---|---|---|---|
| `slide`, `at` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `locked` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `size` | ✓ | — | ✓ | ✓ | — | ✓ | ✓ | ✓ |
| `width` | — | — | — | — | ✓ | — | — | — |
| `rotate` | ✓ | ✓ | ✓ | ✓ | ✓ | — | — | — |
| `flip` | — | ✓ | ✓ | ✓ | ✓ | — | — | — |
| `opacity` | ✓ | — | ✓ | ✓ | ✓ | — | ✓¹ | — |
| `shadow` | — | — | ✓ | ✓ | ✓ | — | — | — |

¹ У `blender` это сила операции смешивания. `opacity` слоя `image` и `image.blend.opacity` — разные параметры.

У каждого слоя обязательны `slide` и `at`; `size` обязателен везде, где он поддерживается. У `frame` обязателен `width`. У `text` размер выводится из содержимого и шрифта.

## 5. `text` — текст

| Поле | Значения | По умолчанию |
|---|---|---|
| `string` | Непустая строка | Обязательно |
| `font` | Объект шрифта | Обязательно |
| `color` | color | Обязательно |
| `background` | color или `null`; подложка текста | Нет |
| `align` | `left`, `center`, `right` | `center` |
| `case` | `original`, `upper`, `lower`, `title` | `original` |
| `tracking` | Добавочный межбуквенный интервал в долях W | `0` |
| `leading` | Добавочный междустрочный интервал в долях W | `0` |
| `decorations` | Список из `underline`, `strikethrough` | `[]` |
| `blendMode` | Режим смешивания блока — список Фигмы из раздела 8; требует `"text.blend-mode"` | Нет — обычный слой |

Объект `font`:

| Поле | Значения | По умолчанию |
|---|---|---|
| `design` | `system`, `rounded`, `serif`, `mono` | Ровно одно из `design` / `family` |
| `family` | Доступное имя семейства, например `"Onest@1"` | Ровно одно из `design` / `family` |
| `weight` | `light`, `regular`, `medium`, `semibold`, `bold`, `heavy` | `regular` |
| `italic` | boolean | `false` |
| `size` | Число `> 0`, доля W | Обязательно |

Правила вёрстки текста:

- Автопереноса нет. Строки разделяются только явным `\n`.
- Нет `width`, `height`, `size`, `maxWidth`, `wrap`, `autoFit`, ограничения числа строк и обрезки многоточием.
- `at` привязан к центру вычисленной коробки. Добавление строк увеличивает блок вокруг центра.
- `align` выравнивает строки внутри блока; не привязывает блок к левому или правому краю слайда.
- Для выравнивания блока по левому полю `m` после измерения ширины текста `T` использовать `at.x = m + T/(2W)`.
- `leading: 0` означает стандартный интервал шрифта без добавки; это не нулевая высота строки. Значение `1.2` не означает 120%.
- Один текстовый слой имеет один стиль. Разные кегли, шрифты или цвета внутри фразы требуют нескольких слоёв.
- `case` изменяет отображение; `string` хранит исходный текст.
- Не генерировать внешние пробелы и пустые строки вокруг текста. Читатель их обрезает, полностью пустой текст пропускает.
- Полей настройки отступов и радиуса текстовой подложки нет. Её геометрию определяет рендерер.
- Поля `opacity` у текста нет; прозрачность букв задаётся альфой `color`, подложки — альфой `background`.
- `blendMode` смешивает блок целиком — подложку вместе с буквами — с тем, что под ним; буквы со своей подложкой не смешиваются.

## 6. Фото-слоты

Свободная фотография `image` сама является слотом. В `frame.photos[]` и `grid.cells[].photo` используются оконные слоты.

| Поле | Значения | По умолчанию |
|---|---|---|
| `source` | Ключ `assets` или `null` | Генерировать явно |
| `order` | Целое, уникальное среди фото-слотов документа | Отсутствует |
| `required` | boolean; нужно ли заполнение | `true` |
| `crop` | `[x, y, w, h]` в долях ориентированного исходника | `[0, 0, 1, 1]` |

Только для оконных слотов:

| Поле | Значения | По умолчанию |
|---|---|---|
| `pan` | `[x, y]`, смещение фотографии в долях ширины и высоты окна | `[0, 0]` |
| `zoom` | Положительный множитель масштаба после aspect-fill | `1` |
| `rotate` | Поворот фотографии внутри неподвижного окна, градусы | `0` |

Порядок обработки: ориентация исходника → `crop` → aspect-fill по центру → `zoom` → `pan` → поворот фотографии → обрезка по окну. Режимы `contain` и произвольный `fit` отсутствуют.

Генератор должен задавать `crop` внутри исходника: `x,y ≥ 0`, `w,h > 0`, `x+w ≤ 1`, `y+h ≤ 1`. Для полного заполнения окна использовать `zoom ≥ 1` и сдвиг, не открывающий пустоту; универсального постоянного диапазона `pan` нет.

Для фотографии без поворота предел сдвига: `|pan.x| ≤ (filledWidth/windowWidth − 1)/2`, аналогично по Y. `filledWidth` и `filledHeight` — размеры фотографии после aspect-fill и `zoom`.

При `source: null` не писать `crop`, `pan`, `zoom` и поворот фотографии. Пустой слот не рисует фотографию и не имеет собственной заглушки. Исключение для бумаги марки описано в `grid.swap`.

`order` и `required` существуют в файловой модели, но текущий редактор не исполняет контракт автозаполнения по ним и не сохраняет эти метаданные при обычном открытии/сохранении. Не использовать их как рабочий механизм заполнения шаблона; см. раздел 15. Для новых документов по умолчанию опускать оба поля.

Для свободного `image` и обоих видов оконных слотов поддерживается `muted: true | false` (по умолчанию `false`). Он управляет звуком видео; у статической фотографии не нужен. В `image.blend` отдельного `muted` нет: звук выбирается на уровне всего `image`.

## 7. `image` — свободная фотография

Общие поля из матрицы + поля фото-слота + следующие поля:

| Поле | Значения | По умолчанию |
|---|---|---|
| `corner` | Радиус скругления, доля W | `0` |
| `border` | `{width, color}`; толщина в долях W | Нет |
| `blend` | Вторая экспозиция | Нет |
| `blendMode` | Режим смешивания слоя со слайдом — тот же список, что у `shape.blendMode` (раздел 8) | Нет — обычный слой |

`size` — рисуемый прямоугольник фотографии. Результат `crop` заполняет его по aspect-fill с сохранением пропорций и обрезкой лишнего по центру. Отдельных `pan` / `zoom` у `image` нет; положение и масштаб слоя задаются `at` / `size`. `rotate` вращает весь слой. `source` может быть фото или видео; отдельного типа `video` нет. `blendMode` накладывает готовый слой — картинку вместе с `border` и `opacity` — на слайд режимом Фигмы и требует `"image.blend-mode"`; это не `blend` (вторая экспозиция внутри фотографии), оба поля могут стоять вместе. Для обычного слоя `blendMode` опускать. У окон `frame.photos` и `grid.cells` режима нет.

У `image.border` генерировать только `color: "FFFFFF"` (белая) или `color: "1F1F1F"` (тёмная). Хотя читатель принимает произвольный цвет, редактор преобразует любой цвет, отличный от точного `"FFFFFF"`, в тёмный. Для цветной окантовки использовать отдельную фигуру под фото. Не путать это ограничение с обводками фигур и smart-grid: у них собственные цвета поддерживаются.

Объект `blend`:

| Поле | Значения | По умолчанию |
|---|---|---|
| `source` | Ключ ассета второй фотографии | Обязательно |
| `mode` | `normal`, `screen`, `multiply`, `lighten`, `darken`, `overlay`, `softLight`, `difference` | `screen`; генерировать явно |
| `opacity` | `0…1`, сила смешивания | `1` |
| `mask` | `off`, `darkAreas`, `brightAreas` | `off` |
| `threshold` | `0…1`, порог яркостной маски | `0.5` |
| `softness` | `0…1`, мягкость порога | `0.25` |

`blend` требует `blend.multi-exposure`. Основной `source` и `blend.source` могут быть фото или видео: фото+фото, фото+видео, видео+фото, видео+видео. Обязательно заполнять оба источника; для пустого шаблонного слота опускать `blend`. Отдельной геометрии, кадрирования, поворота или звука второй экспозиции нет: она центрируется и заполняет область смешивания по aspect-fill. Значения режимов и практический выбор описаны в разделе 18.

## 8. `shape` — векторная фигура

| Поле | Значения | По умолчанию |
|---|---|---|
| `kind` | Значение из списка ниже | Обязательно |
| `fill` | color или `null` | Генерировать явно |
| `stroke` | `{width, color}`; толщина `≥ 0`, доля W | Нет |
| `gradient` | Объект градиента | Нет |
| `blendMode` | Режим смешивания слоя, список ниже | Нет — обычный слой |

`kind`: `rectangle`, `ellipse`, `triangle`, `star`, `star5`, `pentagon`, `hexagon`, `diamond`, `semicircle`, `cross`, `heart`, `gem`, `arrow`, `crescent`, `burst`, `zigzag`, `arch`, `squircle`, `flower`.

Фигура растягивается до `size` по обеим осям. Обводка располагается **снаружи** коробки фигуры; учитывать её при отступах и пересечении шва слайдов. Стыки скругляются. `fill: null` означает отсутствие заливки. Параметров числа лучей, вершин, собственного SVG-path и радиуса скругления прямоугольника нет.

Объект `gradient`:

| Поле | Значения | По умолчанию |
|---|---|---|
| `style` | `linear`, `radial`, `triangle` | `linear` |
| `angle` | Градусы; генерировать в диапазоне `0…360` | `0`; для `radial` опустить |
| `stops` | От 2 до 32 элементов `{at, color}` | Обязательно |

`triangle` — угловой/конический градиент. У линейного `angle: 0` означает слева направо; увеличение угла — по часовой стрелке. `stops[].at` — позиция `0…1`; генератор сортирует стопы по возрастанию. Альфа стопа задаётся в `color`; отдельного `opacity` у стопа нет. При градиенте записывать в `fill` цвет первого стопа.

Порядок оформления: заливка → обводка → прозрачность слоя → тень → режим смешивания. Фигура требует `layer.shape`; градиент дополнительно требует `layer.shape.gradient`.

`blendMode` смешивает готовый растр фигуры с тем, что нарисовано под ней, как режим слоя в Фигме, в нелинейном sRGB. Значения и порядок — фигмовские: `normal`; `darken`, `multiply`, `plusDarker`, `colorBurn`; `lighten`, `screen`, `plusLighter`, `colorDodge`; `overlay`, `softLight`, `hardLight`; `difference`, `exclusion`; `hue`, `saturation`, `color`, `luminosity`. `plusDarker` — Linear Burn Фигмы, `plusLighter` — Linear Dodge. Прозрачность слоя ослабляет результат режима, прозрачные пиксели фигуры фон не меняют. Для обычного слоя поле опускать (`normal` допустим, но ничего не меняет). Требует `"shape.blend-mode"`. Это не блендер: смешивается один слой по своим пикселям, отдельного слоя-оператора и его рамки в редакторе нет.

## 9. `sticker` — графика

Общие поля из матрицы + обязательный `source`: ключ ассета, `"catalog:<группа>/<имя>"` или `null`.

`size` задаёт коробку вписывания. Графика сохраняет исходные пропорции и центрируется в коробке; это aspect-fit. `source: null` не рисует графику; при открытии редактор пропускает такой стикер, поэтому он не служит сохраняемым заполняемым плейсхолдером. Поля `crop` нет.

Необязательное `color: "RRGGBB"` заменяет цвета графики одним цветом по её альфа-силуэту, требует `"sticker.color"`. Прозрачность задаётся общим `opacity`; альфа в `color` рендерером tint не используется. В UI перекраска предлагается для паков `Shapes` и `Scribbles`. При импорте YAML рендерер применяет `color` и к другим стикерам, включая пользовательские, но превращает полноцветную графику в одноцветный силуэт. Поэтому по умолчанию генерировать tint для `Shapes`/`Scribbles`, для других — только при намеренном эффекте силуэта.

**При отсутствии `color` импортированный стикер сохраняет исходную краску PNG.** У `Shapes` и `Scribbles` она светлая, поэтому на светлом фоне явно задавать контрастный `color`, например `"202020"`. Автоматический выбор цвета при добавлении через UI не является умолчанием YAML.

Полный список **464 стикеров из 10 паков** с описаниями находится в каталоге ниже. Пак в идентификаторе не всегда совпадает с объединённой категорией интерфейса. Сопоставление строгое, с сохранением регистра, пробелов и знаков; `source` копировать целиком.

Для адаптера Figma соглашение об имени узла: `sticker:<ID приложения>`. Преобразование: `sticker:Bead Phrases__HOME` → `source: "catalog:Bead Phrases/HOME"`; заменить только первый разделитель `__` на `/`, добавить `catalog:`. Это соглашение адаптера, а не дополнительное поле YAML.

Прозрачные поля исходного PNG входят в коробку вписывания. Размер видимой графики не равен `size`; использовать полный файл, не обрезать прозрачные поля без пересчёта координат. Если внешняя система предоставляет `alphaBounds`, она должна пересчитать полную коробку при переносе обрезанного изображения. Категория стикеров `Shapes` не равнозначна векторному слою `shape`: такие записи экспортируются как `sticker`.

## 10. `frame` — готовая рамка с окнами

| Поле | Значения | По умолчанию |
|---|---|---|
| `width` | Положительное число, доля W | Обязательно |
| `preset` | Реальный идентификатор каталога рамок | Обязательно |
| `photos` | Оконные слоты, по одному на каждое окно пресета | Генерировать по каталогу |
| `ink` | `{color, opacity}`; перекраска графики рамки | Нет |

Высота равна физической ширине рамки, делённой на отношение ширины к высоте пресета. `size` у рамки — ошибка чтения. Положение и размеры окон принадлежат пресету; их нельзя задать в YAML.

Порядок `photos` соответствует порядку окон пресета. Пустые окна сохранять как `{source: null}`, чтобы не сдвинуть следующие фотографии.

`ink.color` — шестизначный цвет; `ink.opacity` — `0…1`, по умолчанию `1`. Перекраска доступна только поддерживающим её пресетам. `ink.opacity` изменяет только графику рамки; `frame.opacity` изменяет рамку вместе с фотографиями. `ink` требует `frame.ink`.

`flip` отражает графику рамки вместе с окнами; фотографии в окнах не отражаются, а переезжают в отражённые окна. `photos` по-прежнему идут в порядке окон пресета. `flip` у рамки требует `frame.flip`.

## 11. `grid` — сетка фото-ячеек

| Поле | Значения | По умолчанию |
|---|---|---|
| `cells` | Непустой список `{rect, photo}` | Обязательно |
| `spacing` | Зазор между ячейками, доля W | `0` |
| `outside` | Внешнее поле сетки, доля W | `0` |
| `corner` | Радиус ячеек, доля W | `0` |
| `color` | Цвет зазоров и внешнего поля | Обязательно |
| `swap` | Объект взаимных окон или `null` | Нет |

`cells[].rect: [x, y, w, h]` задаёт прямоугольник относительно внутренней области сетки после вычитания `outside`. Здесь `x,y` — левый верхний угол, не центр. `photo` — оконный слот. Для пустой ячейки генерировать `photo: {source: null}`.

Генератор должен размещать ячейки в пределах `[0,1] × [0,1]` и оставлять положительную видимую площадь после отступов. Половина `spacing` снимается только с внутренних краёв ячейки. На внешних границах сетки дополнительной половины зазора нет.

Обычный коллаж произвольной структуры задаётся списком `rect`; полей `rows`, `columns`, CSS Grid и вложенных сеток нет.

Сетка-лента распознаётся по геометрии: ширина равна N слайдам, N ячеек идут подряд, каждая занимает `1/N` ширины сетки и всю её высоту. В этом случае колонки привязаны к разрезам слайдов, `outside` применяется по внешним краям ленты, скругляются только внешние углы. Отдельного YAML-флага для этого нет.

Объект `swap`:

| Поле | Значения | По умолчанию |
|---|---|---|
| `mode` | `vertical`, `horizontal` | Обязательно |
| `area` | Доля площади ячейки, занимаемая окном | `0.2` |
| `aspect` | Физическое отношение ширины окна к высоте | `1` |
| `window` | `rectangle`, `stamp` | `rectangle` |
| `offset` | `[x, y]`, доли размера ячейки | `[0, 0]` |
| `border` | `{width, color}`, толщина в долях W | Нет |

`swap` требует ровно две ячейки. Каждая содержит окно с фотографией другой ячейки. `vertical` предназначен для расположения ячеек сверху вниз, `horizontal` — слева направо; сами `rect` всё равно задаются явно. У первой ячейки `offset` применяется напрямую, у второй зеркально по обеим осям. Окно ограничивается границами ячейки.

Рендерер ограничивает `area` диапазоном `0.20…0.50` для `rectangle`, `0.08…0.50` для `stamp`, а `aspect` — диапазоном `0.25…4`. Генератор должен оставаться в этих пределах. Если окно не помещается в ячейку, его размеры дополнительно уменьшаются пропорционально.

`stamp` вырезает окно в форме почтовой марки и требует `swap.stamp`. Обводка `swap.border` для него не рисуется. При одной заполненной ячейке рендерер может рисовать бумагу марки в пустой; дополнительный ассет бумаги не нужен.

## 12. `blender` и `mask` — операции над слоями

Эти слои не рисуют собственную графику. Их `at` и `size` определяют область действия. Место в `layers` определяет операнды.

**`blender`** смешивает композицию выше него с композицией ниже него внутри своей области. При нескольких блендерах список делится на группы: каждый следующий оператор смешивает следующую группу с накопленным результатом предыдущих. За пределами области верхняя группа рисуется обычным способом. Оператор без содержимого сверху не даёт эффекта. Требует `layer.blender`.

Поля: обязательный `mode` и необязательные `opacity`, `mask`, `threshold`, `softness`. Значения и умолчания совпадают с `image.blend`. Поля `source` нет.

**`mask`** работает с ближайшими соседними слоями содержимого: нижний — трафарет, верхний — текстура. Другие слои-операции при поиске соседей пропускаются. В области маски текстура видна там, где цвет трафарета совпадает с `color`; остальные слои не являются операндами этой маски. Нижний трафарет остаётся нарисованным. Верхняя текстура полностью исключается из обычной отрисовки, поэтому **за пределами области маски она тоже не видна**. Если фотография должна одновременно оставаться видимой целиком, добавить её отдельную копию. Маска без одного из соседей не действует. Требует `layer.mask`.

| Поле mask | Значения | По умолчанию |
|---|---|---|
| `color` | Цвет трафарета, пропускающий текстуру | Обязательно |
| `strength` | `0…1`, сила наложения | `1` |

Допуск совпадения цвета определяется рендерером и в DSL не настраивается. Операторы нельзя вращать. Вложенных групп и ссылок на слои по идентификатору нет.

## 13. `shadow` — тень

Доступна только `shape`, `sticker`, `frame`. Блок отсутствует — тени нет.

| Поле | Значения | По умолчанию |
|---|---|---|
| `enabled` | boolean | `true` при наличии блока |
| `color` | `"RRGGBB"`, без альфы | Обязательно |
| `opacity` | `0…1` | `0.5` |
| `angle` | Градусы по часовой стрелке; `0` вправо, `90` вниз | `45` |
| `distance` | Неотрицательная длина, доля W | `0` |
| `blur` | Неотрицательное размытие, доля W | `0` |

Тень вычисляется после применения прозрачности самого слоя. Одна тень на слой; внутренних и множественных теней нет.

## 14. Ресурсы и расширения

`assets` связывает произвольное строковое имя с объектом:

| Поле asset | Значение |
|---|---|
| `file` | Обязательный путь `"assets/<sha256>.<ext>"` к реальному файлу в архиве |
| `pixels` | Необязательные `[width, height]` в пикселях; справочные размеры |

Каждый файловый `source` должен ссылаться на ключ `assets`. Каждый объявленный ассет должен использоваться. Один физический файл объявляется одним ключом; ключ можно использовать многократно. Префикс `catalog:` зарезервирован и не используется для ключей `assets`.

Рамки задаются через `preset`; встроенные стикеры через `catalog:`; шрифты через `family` / `design`. Они не объявляются в `assets`. Шрифты в `.carousel` не вкладываются.

LLM должна получать список доступных файловых ассетов от вызывающей системы. Встроенные пресеты, стикеры и шрифты перечислены в этом документе; пользовательские ресурсы — только в явно переданном каталоге хоста. Не придумывать SHA-256, пути, каталожные имена, версии ресурсов и URL вместо `source`. При отсутствии фотографии использовать пустой слот. URL не скачивается читателем DSL: сначала хост импортирует разрешённый ресурс и выдаёт ключ ассета.

Упаковка `.carousel` — ZIP с `carousel.yaml` и используемыми файлами в `assets/`; необязательное превью — `assets/preview.png`. Подготовку байтов и хешей выполняет упаковщик, не LLM.

| Использованная возможность | Строка в `requires` |
|---|---|
| Любой `shape` | `"layer.shape"` |
| `shape.gradient` | Дополнительно `"layer.shape.gradient"` |
| `image.blend` | `"blend.multi-exposure"` |
| `blender` | `"layer.blender"` |
| `mask` | `"layer.mask"` |
| `grid.swap.window: stamp` | `"swap.stamp"` |
| `frame.ink` | `"frame.ink"` |
| `frame.flip` | `"frame.flip"` |
| Перекраска силуэта `sticker.color` | `"sticker.color"` |
| `shape.blendMode` | `"shape.blend-mode"` |
| `image.blendMode` | `"image.blend-mode"` |
| `text.blendMode` | `"text.blend-mode"` |

Записывать объединение необходимых тегов без повторений. Не выдумывать новые теги, в том числе `video` или `audio`: таких тегов в текущей реализации нет. **Хост обязан сам проверить `carousel == 1` и поддерживаемость всех `requires` до импорта.** Приложение пока не обеспечивает этот барьер полностью; наличие тега само по себе не защищает от открытия в несовместимом редакторе.

## 15. Покрытие и границы текущей реализации

DSL описывает все восемь типов содержимого приложения: `image`, `text`, `sticker`, `frame`, `grid`, `shape`, `blender`, `mask`. Это формат результата композиции; команды интерфейса и всё состояние редактора в него не входят. Нельзя считать его полностью взаимозаменяемым с любым состоянием приложения.

| Возможность приложения | Как выражается / ограничение |
|---|---|
| Free Layout, до 20 слайдов, пять пропорций | `slides`, `ratio`, `background`, `layers` |
| Фотографии и видео, crop, скругление, прозрачность, обводка | `image`; цвет обводки ограничен белым и тёмным |
| Видео в рамках и гридах, звук ролика | Оконный `source`, `muted`; см. раздел 19 |
| Текст, семейства/веса/курсив, регистр, интервалы, подчёркивание, зачёркивание, подложка | `text`; один стиль на слой, явные переносы |
| Векторные фигуры, градиенты, обводки, тени | `shape`; 19 форм, 3 вида градиента |
| Встроенные и пользовательские стикеры | `sticker`; пользовательские — файловые ассеты |
| Рамки, несколько окон, отражение, перекраска, тень | `frame`; встроенные ID перечислены ниже, пользовательский preset требует установки у получателя |
| Коллажи и smart-grid, включая почтовую марку | `grid.cells` и `swap`; имена гридов — рецепты геометрии, не поле YAML |
| Мультиэкспозиция и смешивание произвольных слоёв | `image.blend` и `blender` |
| Текст/фигуры с фототекстурой | Пара содержимых слоёв с `mask` между ними |
| Панорамная нарезка | Обычный грид с повторной ссылкой на один ассет и разными `crop`; нет типа `panorama` |
| Create Layout / Split One Photo | Их видимую композицию можно описать, но режим запуска и привязку грида DSL не сохраняет; эти режимы сами не предлагают сохранение проекта |
| Шаблоны | Тот же документ с пустыми фото-слотами; название шаблона не является командой создания слоёв |
| Дублирование, удаление, перестановка слоёв/слайдов | Генератор изменяет итоговый список и координаты, отдельных команд нет |
| Lock | `locked`: фиксирует геометрию при взаимодействии; это не запрет редактирования содержимого |
| Undo/redo, выделение, масштаб/сдвиг рабочего поля, временное скрытие текста | Состояние UI, не сериализуется; скрытый в редакторе текст остаётся в экспорте |
| Пользовательская библиотека шрифтов/рамок/стикеров, избранное, сохранённые цвета/градиенты | Ссылки и конкретные цвета/градиенты слоя возможны; сама библиотека не упаковывается в DSL |
| PNG/MP4-экспорт, сохранение в Фото, системный sharing, подписки | Действия и настройки приложения/хоста, не поля YAML |

Ограничения, которые генератор и интеграция должны учитывать:

1. **Метаданные слотов.** `order` и `required` существуют в читателе/писателе файла, но не переносятся в модели редактора. После открытия и обычного сохранения теряются у всех фото-слотов. Пустые оконные слоты теряют их ещё при чтении YAML. Не обещать автозаполнение по этим полям; новый генератор должен их опускать.
2. **Цвет рамки фотографии.** `image.border.color` принимает любой hex на уровне чтения, но редактор сохраняет лишь выбор белой/тёмной окантовки. Использовать только `"FFFFFF"` и `"1F1F1F"`.
3. **Версия и расширения.** Поля `carousel`/`requires` считываются, но полная проверка совместимости перед открытием не подключена. Хосту нужны собственный контроль версии и список поддерживаемых возможностей.
4. **Неизвестные поля и слои.** Неизвестные ключи знакомых слоёв могут молча игнорироваться и теряться. Неизвестные типы слоёв сохраняются как сырые узлы и включают ограничения редактирования, но текущая операция сохранения копии не гарантирует сохранность всех узлов и их порядка. Не прогонять более новый документ через старый редактор ради нормализации. Хранить исходный файл у интеграции.
5. **Межслайдовые слои.** `spans` не реализован; охват задаётся геометрией. Домашний `slide` при сохранении заново вычисляется по центру, поэтому исходные `slide`/`at` могут измениться без изменения видимых пикселей. Побайтовый round-trip не обещается.
6. **Слоты рамок.** Число `photos` должно точно совпадать с числом окон пресета. Редактор дополняет недостающие пустыми и отбрасывает лишние. Для импортированной пользовательской рамки получателю нужен тот же установленный preset; архив сам его не переносит.
7. **Шрифты и ресурсы.** Шрифты не вкладываются в `.carousel`. Недоступный шрифт меняет метрики и может сдвинуть текст. Встроенные ресурсы доступны только в совместимой поставке приложения. Неизвестный preset рамки лишает слой геометрии; его нельзя заменять выдуманным размером окна.
8. **Повторное сохранение нормализует файл.** Числа округляются до шести знаков после запятой, исходное форматирование и комментарии не сохраняются. Значения по умолчанию могут исчезнуть; цвета/числа/текст нормализуются; незначимые параметры пустых слотов и некоторые неактивные настройки не обязаны сохраняться.
9. **Пиксельное совпадение между движками.** Метрики текста, кривые фигур, окна и bitmap рамок, stencil и цветосмешивание зависят от рендерера. Одного Markdown недостаточно для независимого пиксельно идентичного рендерера. Для визуально точного плагина нужны те же ресурсы, измерение текста и проверки экспортом.

В DSL нет Auto Layout, constraints, flex-контейнеров, группировки, компонентов, переменных, rich text, автопереноса, произвольных векторных путей и анимации параметров слоёв. **Видео поддерживается**, но нет таймлайна, trim, скорости, переходов, отдельной музыкальной дорожки и управления громкостью. Градиент предусмотрен только у `shape`; для градиентного фона поставить прямоугольник размером со слайд. Размытие предусмотрено у тени, не как фильтр слоя. Не генерировать эти отсутствующие поля.

## 16. Полный пример без внешних ресурсов

Два слайда: текстовая обложка и сетка из двух незаполненных фото-слотов. Пустые слоты намеренно не показывают изображения.

```yaml
carousel: 1
ratio: portrait-4-5
slides: 2
```

## 17. Проверки генератора перед выдачей

1. Один YAML-документ, `carousel: 1`, допустимый `ratio`, `slides` в `1…20`.
2. Ровно один тип на элемент `layers`; все обязательные поля присутствуют.
3. `slide` каждого слоя существует. Размеры положительны; отступы не уничтожают площадь содержимого.
4. `at` — центр; `rect` и `crop` — левый верхний угол и размеры. Единицы осей не перепутаны.
5. Поля соответствуют матрице типа. У текста нет `size`; у рамки нет `size` и `height`. У `frame.photos` ровно столько элементов, сколько окон у пресета.
6. Текст содержит явные переносы. Его ширина проверена измерением выбранного шрифта, если измерение доступно; число символов не является точной мерой ширины.
7. Ссылки на ресурсы разрешимы; неиспользуемых ассетов и придуманных идентификаторов нет.
8. Порядок слоёв соответствует перекрытиям и операндам `mask` / `blender`.
9. `requires` содержит все используемые расширения; значения enum соблюдают регистр. Хост подтверждает поддержку версии и каждого тега до импорта.
10. Дополнительных полей для неподдерживаемых возможностей нет.

Проверка генератора должна быть строже текущего парсера: успешное чтение само по себе не подтверждает правильные диапазоны, поддержку неизвестных полей или визуальный результат.

## 18. Как выбирать смешивание

В приложении есть три разных механизма. Выбирать по задаче:

| Задача | Механизм | Порядок / область |
|---|---|---|
| Смешать две фотографии или два ролика как один редактируемый объект | `image.blend` | Основной `source` + `blend.source`; одна общая геометрия |
| Смешать текст, фото, фигуры, рамки или целые композиции | `blender` | Нижняя группа → оператор → верхняя группа; прямоугольная область |
| Заполнить буквы или силуэт фотографией/текстурой | `mask` | Один трафарет → оператор → одна текстура; совпадение заданного цвета |

Вторая экспозиция сначала заполняет исходную основу по aspect-fill, затем смешивается; общий `image.crop` применяется к готовой смеси. Чтобы независимо двигать, масштабировать или кадрировать два источника, использовать два `image` и `blender` между ними.

Режимы для `image.blend.mode` и `blender.mode` одинаковы:

| Точное значение | Подпись UI | Эффект и типичное применение |
|---|---|---|
| `normal` | Normal | Обычное наложение с альфой; плавная прозрачная текстура |
| `screen` | Screen | Осветляет; чёрное верхнего изображения почти не влияет. Световые блики, классическая двойная экспозиция |
| `multiply` | Multiply | Затемняет; белое верхнего изображения почти не влияет. Бумага, краска, тёмная текстура |
| `lighten` | Lighten | Выбирает более светлые компоненты; сохраняет светлые детали |
| `darken` | Darken | Выбирает более тёмные компоненты; сохраняет тёмные детали |
| `overlay` | Overlay | Контрастное смешивание с учётом нижнего изображения |
| `softLight` | Soft light | Более мягкое изменение контраста и света; точный camelCase обязателен |
| `difference` | Difference | Разница компонентов; контрастный, инверсионный эффект |

Других режимов у `image.blend` и `blender`, например `colorDodge`, `hue`, `luminosity`, нет. Режим не является общим полем любого слоя: `blendMode` у текста или стикера не работает. Исключение — `blendMode` у `shape` (раздел 8), `image` (раздел 7) и `text` (раздел 5): у фигуры, фотографии и текста собственный режим слоя со списком Фигмы, включая `plusDarker` (Linear Burn), `colorDodge`, `hue`, `luminosity`. Для «плашки в режиме смешивания» из макета это предпочтительный путь: одна фигура вместо пары блендеров.

Яркостное ограничение смешивания задаётся `mask` **внутри** blend/blender; это не цветовая операция слоя `mask`:

| Значение | Подпись UI | Где проявляется верхнее изображение |
|---|---|---|
| `"off"` | Everywhere | Во всей области |
| `darkAreas` | Dark only | В тёмных участках основы |
| `brightAreas` | Light only | В светлых участках основы |

Яркость основы: `L = 0.2126R + 0.7152G + 0.0722B`. Для `brightAreas` используется `L`, для `darkAreas` — `1−L`. `threshold` — центр перехода по выбранной величине: повышение порога оставляет только более светлые / более тёмные участки. `softness` — ширина перехода; `0` почти резкий край, `0.25` мягче. Практический старт: `threshold: 0.5`, `softness: 0.25`, `opacity: 0.7`. У `"off"` порог и мягкость визуально не действуют.

Верхняя группа блендера включает всё последующее содержимое до следующего блендера, даже заголовки и декор. Если поверх эффекта нужен обычный заголовок, можно завершить группу вторым `blender` с `mode: normal` и поместить заголовок после него. При цветовой маске трафарет и текстуру ставить соседями; избегать неоднозначных перекрывающихся пар из нескольких масок без проверки рендера.

## 19. Видео, шаблоны и готовый файл `.carousel`

### Видео и звук

Видео — файловый ассет `.mov`, `.mp4` или `.m4v`. Допустимые места: `image.source`, `image.blend.source`, `frame.photos[].source`, `grid.cells[].photo.source`. Встроенного видеостикера нет. Контейнер должен содержать файл, декодируемый целевой платформой; одно подходящее расширение не гарантирует поддержку кодека.

На каждом слайде звучит одно место с видео: самое верхнее незаглушённое в порядке `layers`; внутри грида — в порядке `cells`, внутри рамки — в порядке `photos`. Для детерминированного результата явно поставить `muted: true` всем нежелательным источникам и `muted: false` выбранному. Звук относится ко всему месту, в том числе ко всем слайдам, которые оно пересекает. Текущий отбор видео использует геометрическое пересечение по горизонтали, а не фактическую видимость пикселей: `opacity: 0`, маска или непрозрачный слой сверху не гарантируют выключения звука. Для выключения нужен `muted: true`.

У мультиэкспозиции звук берётся из основной экспозиции, если она видео; иначе из второй, если она видео. Выбрать звук второй экспозиции при двух видео или отдельно отрегулировать громкость через DSL нельзя.

Текущее поведение экспорта приложения: статический слайд → PNG; слайд с видимым видео → MP4/H.264, 30 кадров/с. Длина видео-слайда определяется самым длинным видимым роликом, для каждого источника используются первые максимум 60 секунд; короткие ролики повторяются. Это политика экспортера, **не поля** `duration`, `fps`, `loop` или `codec` в YAML. Прозрачный фон сохраняется в PNG; прозрачность видео этим контрактом не обещается.

### Документ и шаблон

Тип файла один и тот же. Шаблон — обычный документ, у которого `image.source` и оконные источники пустые. Чтобы превратить работу в шаблон:

1. Обнулить фото/видео в `image`, `frame.photos`, `grid.cells[].photo`; удалить `image.blend`.
2. Сбросить `crop` к `[0,0,1,1]`; у окон сбросить `pan`, `zoom`, `rotate`. Поворот самого свободного слоя/рамки остаётся частью композиции.
3. Пользовательские файловые стикеры обнулить; встроенные `catalog:` сохранить. Пустой пользовательский sticker при открытии может исчезнуть из редактируемых слоёв — он не надёжный заполняемый слот.
4. Собрать `assets` и файлы заново по оставшимся ссылкам, убрать ненужные теги из `requires`.
5. При необходимости приложить отдельный `assets/preview.png`. Он не объявляется в `assets` и не используется как `source`.

Превью шаблона может содержать исходные фотографии, даже если сами слоты очищены. Если нужен шаблон полностью без фотографий, превью также должно быть сделано из пустой раскладки или опущено. Шаблон с неизвестными слоями приложение не создаёт: невозможно определить, какие личные ресурсы в них спрятаны.

### Упаковка

Готовый импортируемый файл — обычный ZIP с расширением `.carousel`. Разрешены только:

```text
carousel.yaml
assets/<64 lowercase hex SHA-256>.jpg
assets/<64 lowercase hex SHA-256>.png
assets/<64 lowercase hex SHA-256>.heic
assets/<64 lowercase hex SHA-256>.mov
assets/<64 lowercase hex SHA-256>.mp4
assets/<64 lowercase hex SHA-256>.m4v
assets/preview.png                 (необязательно)
```

Каждая строка с `<...>` здесь — схема имени, не буквальное имя файла. Хеш вычисляется по точным байтам файла **после** преобразований и удаления метаданных. Если байты изменились, упаковщик меняет имя и соответствующее `assets.*.file`. JPG используется с расширением `.jpg`, не `.jpeg`; WebP/SVG/GIF, шрифты и отдельные каталоги внутри архива этим форматом не допускаются.

Упаковщик кладёт файлы напрямую с этими путями, без родительской папки, записи ZIP-каталога `assets/`, `__MACOSX`, `.DS_Store`, символических ссылок, абсолютных путей и `..`. Допустимы ZIP stored/deflate; ZIP64 не поддерживается. Дубликаты имён, неверные хеши, отсутствующие или посторонние ассеты отвергаются. Внешняя ссылка вместо приложенного файла не заменяет ассет.

Пределы текущего импорта: архив и суммарный распакованный размер до 3 GiB, один stored-файл до 1 GiB, один распакованный deflate-файл до 100 MiB, степень сжатия до 200, YAML до 4 MiB, изображение до 100 миллионов пикселей. Для крупных видео использовать stored. Это ограничения текущего читателя, не цель размера документа.

### Мультиэкспозиция с видео

Ниже **фрагмент списка `layers`**, не самостоятельный файл. Хост уже должен предоставить два ассета `portrait` и `lights-video` и записать их реальные `file` в корневой `assets`. Корень должен включать `"blend.multi-exposure"` в `requires`.

### Панорама через три квадратных слайда

Фрагмент `layers` для `ratio: square-1-1`, `slides: 3`. Ассет `panorama` должен реально иметь пропорцию **3:1**, быть объявлен в корневом `assets` и приложен к архиву. Ссылка повторяется; файл хранится один раз. Дополнительного `requires` не нужно.

```yaml
- grid:
    slide: 1
    at: [1.5, 0.5]
    size: [3, 1]
    color: "FFFFFF"
    spacing: 0
    outside: 0
    cells:
      - rect: [0, 0, 0.333333, 1]
        photo:
          source: "panorama"
          crop: [0, 0, 0.333333, 1]
      - rect: [0.333333, 0, 0.333333, 1]
        photo:
          source: "panorama"
          crop: [0.333333, 0, 0.333333, 1]
      - rect: [0.666667, 0, 0.333333, 1]
        photo:
          source: "panorama"
          crop: [0.666667, 0, 0.333333, 1]
```

Для другой пропорции исходника сначала найти центрированный прямоугольник с пропорцией ленты `N×W/H`, вписанный в исходник, затем разделить его. Если `A` — пропорция изображения, `B=N×W/H`, размеры видимой области в долях исходника: `cw=min(1,B/A)`, `ch=min(1,A/B)`, начало `cx=(1−cw)/2`, `cy=(1−ch)/2`. Crop ячейки `i` при нулевых полях: `[cx+i×cw/N, cy, cw/N, ch]`.

При ненулевых `outside`/`spacing` сначала вычислить реальные прямоугольники видимых ячеек после полей, нормализовать их относительно **всего** грида, а затем отобразить в `[cx,cy,cw,ch]`. Иначе кадрирование сдвинется, и соседние слайды перестанут стыковаться. При изменении zoom/кадрирования панорамы хост пересчитывает все crop; общего YAML-поля `panorama.zoom` нет.

## 21. Контракт использования в LLM, плагине или MCP

Следующий рабочий процесс — рекомендация для будущего адаптера, а не утверждение, что приложение уже предоставляет MCP-инструменты или эти имена API.

**Вход модели:** задача и язык текста; желаемые пропорция/число слайдов; материалы пользователя; перечень доступных файловых ассетов с ключами, реальными путями для архива, размерами и при необходимости длительностями; каталог возможностей целевого приложения. По умолчанию модель использует встроенные каталоги из этого файла. Пользовательские шрифты, стикеры и рамки добавляются только из подтверждённого хостом перечня.

Для модели с небольшим окном контекста хост может передавать основные правила и извлекать из этого MD только подходящие разделы каталогов. Поиск должен возвращать точные `source`/`preset`/рецепты, а не выдуманные сокращения; единственным нормативным источником остаётся полная версия инструкции.

**Выход модели:** один UTF-8 YAML-документ по этому контракту, без Markdown-ограждения, преамбулы, комментариев о выдуманных инструментах и дополнительных корневых полей. Если в интерфейсе нужен JSON-ответ, YAML можно передать строкой в оболочке инструмента, но оболочка не является содержимым `carousel.yaml`. План, комментарии и диагностику хранить отдельно от DSL.

**Последовательность:**

1. Определить размер, количество слайдов и роль каждого слайда: обложка, развитие, детали, завершение. Согласовать текст и ресурсы с реальными входными материалами.
2. Выбрать именованные ресурсы из каталога. Именованный грид раскрыть в `cells`/`swap`. Для `frame` проверить число окон и поддержку перекраски. Не заменять похожим по написанию идентификатором.
3. Сформировать плоский список от заднего слоя к переднему. Явно продумать соседей `mask` и группы `blender`.
4. Подобрать переносы и размер текста. Если у хоста есть измеритель шрифтов, проверить ширину по реальным метрикам. Без измерителя использовать короткие строки и запас по полям; не обещать точные габариты по количеству букв.
5. Проверить документ по разделу 17 и строгому разрешённому набору полей. Хост также проверяет типы, диапазоны, число окон, геометрию и ссылки, даже если встроенный reader их пропускает.
6. Выполнить настоящий разбор читателем целевой версии. Проверить, что не было неизвестных слоёв, подменённых шрифтов или пропущенных ресурсов. Ошибки возвращать модели с путём поля и причиной; исправлять документ, а не удалять неподдерживаемые эффекты молча.
7. Упаковать реальные байты; LLM не должна вычислять хеши «в уме». После упаковки повторно проверить ZIP, хеши и наличие файлов.
8. Если доступен рендерер, показать/проверить все слайды: текст не обрезан, важные лица в кадре, стыки панорамы непрерывны, декоративные ресурсы существуют, звук выбран намеренно. Для критичной переносимости проверить цикл «YAML → редактор → сохранение → повторное открытие».

У плагинов для других языков нет необходимости повторять Swift-модели: формат состоит из стандартных YAML map/list/string/number/bool/null. Но универсальный YAML-декодер должен сохранять возможность обнаружить повторяющиеся ключи и не превращать свободные строки в даты/булевы значения. Рекомендуемый профиль генерации строже текущего reader; он включает ровно известные поля из разделов 1–14.

Неизвестную возможность нельзя «включить» новым ключом. Если задача требует отсутствующего эффекта, адаптер может заранее подготовить растровый ассет и использовать `image`/`sticker`, явно сохранив сведения о потере редактируемости вне DSL. ### Шрифты и начертания

Для системных шрифтов задавайте `font.design`: `system`, `rounded`, `serif`, `mono`. Для встроенного семейства задавайте `font.family` с точным именем и `@1` из таблицы ниже. `design` и `family` взаимоисключающи. `font.weight`: `light`, `regular`, `medium`, `semibold`, `bold`, `heavy`; `font.italic`: boolean. `font.size` — доля ширины слайда. Шесть весов — запросы: когда нужного файла нет, приложение выбирает ближайшее предусмотренное начертание. У одновесовых семейств все шесть запросов дают один face.

`italic: true` хранится как запрос даже у семейств без отдельного курсивного face; результат зависит от доступной системной подстановки. Если важен воспроизводимый настоящий курсив, выбирайте семейство с курсивными faces. Для шрифта пользователя/устройства допустимо его точное системное имя семейства без `@1`, но файл шрифта не вкладывается в `.carousel`; у другого читателя его может не оказаться. Для переносимых каруселей предпочитайте встроенные или системные шрифты. `@1` — каноническое имя текущего набора; загрузчик сейчас снимает суффикс, а не выбирает историческую версию. Для конкретного языка хост должен проверить покрытие нужных символов: название семейства само по себе не гарантирует наличие всех глифов.

### Стикеры: полный список 464 встроенных ресурсов

Столбец `source` содержит готовую **кавычечную YAML-строку**. Вставляйте её в `sticker.source`. Например: `source: "catalog:Bead Phrases/HELLO"`. Имя ресурса приложения имеет вид `<пак>__<имя>`, а DSL — `catalog:<пак>/<имя>`; это одна и та же графика. Префикс Figma `sticker:` в DSL не используется.

Паки — постоянная часть ID. В интерфейсе `TornPaper` и `VintagePaper` объединены в раздел **Paper**, а `RetroDoodle` и `Doodle` — в **Doodle**, однако `catalog:Paper/...` не существует. У `VintagePaper/ 321x12` после слэша находится **значимый начальный пробел**. Имена с числами, пробелами и суффиксами копируйте целиком, не угадывайте непрерывные диапазоны.

В интерфейсе только паки **Scribbles** и **Shapes** предлагают перекраску силуэта через `sticker.color` (`RRGGBB`, с `sticker.color` в `requires`). У всех стикеров есть размеры, положение, поворот, прозрачность, отражения, тень и блокировка. Пользовательский стикер передаётся как обычный ассет с PNG/другим поддерживаемым изображением, без выдуманного `catalog:` имени.
