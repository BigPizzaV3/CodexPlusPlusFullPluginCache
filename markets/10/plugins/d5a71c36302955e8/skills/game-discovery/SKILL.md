---
name: game-discovery
description: Discover games with visual cards, browse release windows, read a connected wishlist or gaming brief, and apply explicit GamesLike wishlist, taste or group actions while preserving linked titles and current requirements.
---

Use this skill for GamesLike discovery and every follow-up about its returned games. Follow the user's explicit instructions over this skill's guidance.

- Use this plugin's GamesLike app tools. Public discovery uses `search_games`, `find_similar_games`, `browse_releases` and `find_party_games`. Connected reads use `recommend_from_library`, `list_wishlist` and `get_personal_brief` with `library:read`. Explicit wishlist and taste actions use `set_wishlist_entry` and `set_game_preference` with a separate `library:write` grant. Existing group picks use `get_group_games` with `groups:read` and verified membership. Never infer a broader grant from an existing connection.
- For games like one named title, call `search_games` with `include_similar`. When `similar` is returned, present those ranked games; when it is null, resolve the title or edition first and then call `find_similar_games`. Use `find_similar_games` for preferences or more results.
- Keep ordinary title lookup and similarity anonymous. For a request based on the user's own Steam library or backlog, offer optional Steam connection and use `recommend_from_library`. Do not require login for public discovery or repeatedly prompt a user who declines. GamesLike accounts require age 18; public discovery remains available from 13 under the existing terms.
- The library tool takes `mode` (`discover` or `backlog`), `limit`, and the same supported preferences as public similarity. Identity comes from OAuth, never a supplied Steam/user ID, password or API key. Follow the host's connection prompt. Steam sign-in verifies identity but does not unlock private game details.
- Explain personal results from returned taste evidence: playtime is a signal, not proof of enjoyment; explicit Loved/Not for me choices refine taste. Discover excludes known ownership. Backlog selects known owned games with less than five hours of recorded playtime; missing playtime is unknown. State ownership freshness from `owned_refreshed_at` and uncertainty from `ownership_note`. A complete snapshot does not prove current ownership. Respect sync, missing-taste, catalog-coverage and no-match states without inventing recommendations.
- Library reads do not trigger Steam imports. If a sync is needed, send the user to GamesLike's connection page for the explicit import action. Disconnecting ChatGPT there revokes access and leaves the GamesLike account/library intact. Account deletion remains a website action.
- Use `list_wishlist` for GamesLike wishlist entries, source labels and independent wishlist freshness. `saved_at` records when GamesLike learned an entry, not Steam's original date or priority. An unreadable Steam wishlist does not establish an empty or fresh wishlist.
- Use `browse_releases` for calendar-date ranges of at most 90 days; `to` is exclusive. Use the returned release label and precision. Month, quarter, year and unknown windows never confirm a specific release day. `get_personal_brief` supports a 1–30-day horizon and an IANA time zone, defaulting to UTC; keep the returned time zone and separate section states visible.
- The personal brief includes wishlist updates, upcoming radar, discoveries and one lightly played backlog pick. Keep missing taste, incomplete freshness, unknown ownership and unavailable sections visible. Request `deck_status` only for the user's stated exact status and `max_completion_minutes` only for total completion time. Missing or stale compatibility and missing completion estimates cannot satisfy a strict filter; estimates do not measure one play session.
- Show the supplied visual cards when the host supports them. Use returned artwork, GamesLike links and evidence; never invent art, release dates or compatibility. More like this uses the selected card's exact appid. All seeds, results, actions and group picks exclude sexual/explicit adult content and unknown classifications; never bypass that exclusion to fill a list.
- Apply a wishlist or taste write only after the user's explicit action on one exact game. `set_wishlist_entry` changes GamesLike's wishlist, not Steam's, and preserves ownership. Before removing an imported entry, explain that a later requested Steam sync can restore it. `set_game_preference` accepts Loved, Not for me or Clear; requery personal recommendations after a successful change. Report errors rather than claiming a saved choice.
- Manual party discovery needs 2–8 participants with three distinct exact safe favorites each. Manual ownership stays unknown. Use strict capacity by default; include unverified capacity only when the user accepts that uncertainty. `get_group_games` reads one supplied existing group/session for an authorized member. Do not enumerate groups, reveal member libraries or preferences, create rooms, invite or vote.
- Reading a brief does not subscribe, send, refresh Steam or mark games seen. For optional daily-when-changed or weekly email, direct the user to https://gameslike.co/brief for the actual available settings and confirmation flow. Do not claim enrollment or delivery from a tool read, or silently enable email or recurring Steam refresh. Automatic delivery into ChatGPT is not supported.
- Resolve the exact source title first. If the user names a series or the lookup leaves multiple possible editions, show linked choices and ask which edition before requesting matches. Never choose the first or latest edition automatically.
- Pass only stated, supported PC-platform, co-op and catalog-tag preferences. When requirements change, call the relevant similarity or library tool again before revising recommendations. When the user replaces preferences, drop earlier constraints that the replacement does not retain.
- Use each game's returned `title_markdown` unchanged every time you name it as a recommendation: lists, comparisons, repeated titles, final picks, and follow-ups that make no new tool call. For “which two?”, reuse the latest returned linked titles and evidence. If the exact linked title is unavailable, resolve it with `search_games`; never invent a URL or substitute a store link.
- Keep recommendation output compact with linked bullets. Do not add a duplicate recap or repeat the ranking's game titles. Any single final pick must keep its returned linked title.
- Explain distinctive shared gameplay and a relevant tradeoff from returned descriptions and evidence. Tags, theme, and franchise do not prove the same main loop. Do not invent matches, pad a shortlist, relax hard requirements, or turn scores into confidence percentages.
- A missing or excluded combat/violence tag does not prove absolutely no combat or violence. A 3D tag does not prove a fully 3D view. PC flags do not establish console support. Before offering a shortlist for a hard requirement that returned evidence cannot verify, state what cannot be verified and ask one concise question whether catalog-tag matches with those stated limits are acceptable. Wait for the user's answer; do not offer unverified candidates or replace the hard requirement while waiting. Proceed with catalog-tag matches only if the user accepts those limits.
- Preserve visible tool errors and honest no-match outcomes. These tools cannot buy games, read private Steam libraries, or manage accounts.
