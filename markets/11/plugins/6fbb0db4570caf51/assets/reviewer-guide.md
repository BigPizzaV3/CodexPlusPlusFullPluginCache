# Contexta Learning reviewer guide

Use the dedicated verified reviewer account supplied through the secure portal form and fictional material. This package targets the production product MCP. Supply credentials only through the secure reviewer form; do not include passwords, tokens, private source data or temporary file URLs in this package or demonstration.

OAuth consent, website sign-in, plan approval and recording submission are separate actions. Give the reviewer sufficient ordinary access for the cases without bypassing quotas. Verify any sign-in requirements ahead of time rather than expecting a reviewer to wait for account access.

The manifest has five positive and three negative cases. [Synthetic materials](reviewer-materials.json), [the wider evaluation suite](evals.json) and [tool annotation worksheet](tool-review.json) provide prepared fixtures and expected outcomes; none are executed evidence. The worksheet covers the base, capture and widget-enabled registry. The target must actually expose the required tools and current UI resource before audio/card cases can pass.

## Material and project cases

1. Add the exact capture text to an owned existing project through an append-only preview and explicit approval. Snapshot all old sources, pack metadata, sessions, answers and audio: unchanged. New packs are the default; an explicitly selected existing pack receives new sessions at its tail. Retry the identical operation: no extra sessions or jobs. Missing, foreign or mismatched destinations must not create an unrelated fallback or Inbox. Separately verify legacy raw-capture replay remains compatible.
2. Save long synthetic text with splitting. Reassemble the actual saved parts in order and compare with the accepted source. Unsplit oversize input must produce a useful error rather than silently truncating.
3. Import authorized synthetic PDF/PPTX/TXT/Markdown fixtures that the actual server parser accepts. Check private original retention and extracted-text metadata/warnings. Verify an unreadable or scanned file yields the actual useful fallback; do not treat a model summary or unchanged layout as evidence of extraction.
4. Preview a new ordinary project, using AI adaptation by default for Interview unless explicitly declined, and keeping source wording by default for Presentations & Meetings and Work & Study unless adaptation is explicitly requested. At plan_ready inspect actual sources, ordered packs/sessions, level, preservation and allowances. Verify no project exists yet; approve, wait for ready and open the exact owned link. Repeat creation on the same operation: one project. Test optional adaptation as a separate explicitly requested preview, with the original retained. Interview files need correct roles; do not guess them.

## Phrase and short audio cases

5. Save a useful core from the negated fixture, keeping essential negation/prepositions and exact source context. Save an exact expression from actual chat context and a separately labeled generated example. Repeat the same save and verify one entry/context with learned state unchanged.
6. Retrieve today twice before practice: the same account-local choice and truthful reason, with no earned review/mastery. Today, due and random choose actual multiword phrase entries, excluding individual words and historical single-token entries mislabeled as phrases without changing those records. Check due, explicit random and exclusion browsing separately. Read complete saved contexts using the same tenant-safe context resolver as the website, including readable legacy contexts anchored to this learner's material. Keep original, chat and generated labels; missing context must stay explicit, and foreign parents must remain inaccessible. Empty due review is not a newly measured weakness; a bank without eligible expressions must not receive silent samples. Explicit owned word selection remains compatible. Unknown/foreign phrase IDs reveal no other account data.
7. Choose the primary Practise phrase action: its reference is the exact saved expression. Submit real audio and check the assessed sound/letter coloring against the provider's phoneme groups. Separately choose secondary Read aloud: its reference is the complete saved context, not an excerpt or the phrase alone. The card disables this action when context is missing or exceeds the short 65-word limit and points to the website without truncating the source. Speak with this phrase asks for the expression in the learner's own short answer. Audio remains local until explicit Get feedback. Submit a valid short recording or file within 60 seconds/512 KiB and wait for genuine processing/ready state. Check available scores, word colors, phoneme details and wording corrections against the returned assessment, including gray unscored recognition uncertainty and absent metrics. A real measured zero must remain distinguishable.
8. Retrieve the card again while a matching owned unsubmitted phrase/context/speaking task is fresh: the relevant action resumes that task instead of consuming another reservation. Changed reference text or another learner's task must never resume. When starting a new audio task, unused ready tasks created more than 30 minutes ago expire; passive cards and every accepted recording or processing/completed attempt remain intact. An expired attempt offers a new attempt, not a dead-end retry. If fresh reservations still reach the actual allowance, preserve the honest limit. Retry a submitted assessment explicitly and verify one replay-safe retry task, with no inflated productive use/learning count. Exact phrase practice and Read aloud are receptive pronunciation evidence; productive phrase use requires the canonical service's actual eligible recognized Speaking use. Real phrase-member accuracy and phoneme details appear in the website pronunciation history as chat_widget evidence, without a synthetic portal session or duplicate audio key. Failed assessment must not produce a chat-invented score. Poll timeout/unmount must stop automatic calls and retain the existing task for safe refresh.

## Progress, boundaries and hosts

9. Compare actual saved measured patterns and project continuation with the website. Scope account/project evidence correctly. With insufficient data, say so. Completed projects must not be called generating; one score or retry is not a trend. Full four-exercise sessions stay on the website.
10. Run negative and connection cases: no automatic save for translation/attachments; no declined creation/upload; no arbitrary/internal URL fetch, foreign data or destructive access. Test supported scopes and unavailable tools. Host sign-in and website login remain distinct; do not re-create a project to repair browser access.
11. On each intended supported host, verify the installed local plugin routes the six skills, renders the real resource and uses actual MCP calls. Exercise light/dark, narrow/wide, keyboard, reference audio, microphone allowed/denied, file fallback and pending recovery. Browser fixture tests are useful evidence for layout/logic only; API presence does not prove microphone capture in ChatGPT desktop.

Record actual outcomes, target commit/resource, host and limitations. A validator/install does not prove live readiness, adoption, demand, retention or learning improvement.

## Suggested recording sequence

Use the dedicated reviewer account and the actual production installation. Keep
the recorder running only after sign-in is complete and private credentials are
off screen. Leave each result visible long enough to read it. This sequence is
reproducible guidance; use the verified recording above as the actual evidence.

1. Show the connected Contexta plugin and its six skills. For private rehearsal,
   the label is Contexta Learning — Production; the future public listing must
   show Contexta Learning, Contexta LLC and the C-loop icon.
2. Ask: "Create a B2 work and study project from this exact text. Keep the wording
   unchanged and show the plan first: An evaluation dataset helps a team compare
   model changes consistently. Ambiguous examples can make comparisons
   misleading. Strong offline results alone do not prove that a feature will
   help users; deployment monitoring remains necessary." Show the real plan,
   then explicitly approve it. Wait for ready and open the returned website link.
3. Ask: "Save the expression rule out from this sentence to my Phrase Bank:
   I cannot rule out a delay in the next phase. Keep this sentence as context."
   Show the saved receipt and the exact context.
4. Ask: "Show the phrase rule out that I just saved, with its original context."
   Show the phrase card. Choose phrase pronunciation practice, record a short
   real utterance, explicitly submit it and wait for measured feedback. If the
   host cannot record, show its honest website fallback and record that limit.
5. Ask: "Show my next full session for the project we just created." Show the
   actual continuation and website handoff, without inventing completed practice.
6. Ask: "Translate this Spanish sentence into English, but do not save anything:
   No descarto un retraso." Show the ordinary translation with no Contexta save
   or creation. All test requests are in English; the quoted source is Spanish.

Separately execute the five positive and three negative manifest cases; this
short video sequence does not replace their test record. Host and account setup,
measured audio, duplication checks and owner-isolation evidence remain required.
Host the finished recording at a reviewer-accessible HTTPS URL, verify playback
and access, then add that exact URL as `review.demo_recording_url`.
