# Connect DXIR

Use [connection and recovery](../research-strategy/SKILL.md#connect-and-recover-in-this-conversation) to read `action_room_account`, then the available `dxir_services_list` or earlier `dxir_services` tool. Let the host present its native login action when required. Preserve the user's original request and continue its read-only checks after connection. Neither check needs a folder, creates a project, uploads materials or starts paid work.

After successful reads, briefly identify the connected DXIR account and the next useful action in the user's language. Reuse an attached project folder. If no folder is attached, explain how to select the folder containing the materials in this host; offer the existing skill's folder setup only when the user wants help creating or connecting it.

An example request is: “이 프로젝트의 자료를 분석하고 결과를 설명해 주세요. 보고서에 따른 작업도 해주세요. 필요한 서비스는 추천해 주세요.” Translate it to the user's language. Do not send that example, open service selection or start analysis during setup. If the user has already requested substantive work, finish connection checks and perform that original request through the research-strategy or action-room skill within its existing authorization.

Keep helper commands, routing IDs and connection diagnostics out of normal guidance. A successful installation or browser login is not a verified DXIR connection. Stop prompting after a declined connection; provide one supported next step if connection remains unavailable.
