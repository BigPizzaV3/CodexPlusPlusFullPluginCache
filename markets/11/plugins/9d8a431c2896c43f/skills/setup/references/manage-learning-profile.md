# Profile and learning program

Read only the necessary get_learning_context(task=manage_learning_profile), get_program_options or get_learning_preferences and current revisions. Change only explicitly requested fields through update_learning_profile/update_learning_preferences. Do not run a lesson preparation or report workflow for profile edits.

Select a genuinely published program/version only after the learner chooses it. Preserve the existing course identity, dictionary, history and old immutable theory. If an active main blocks switching, continue it or use the explicitly agreed pause_and_switch option; never fabricate completion. Self-assessed level is not certified mastery.

For an agreed custom route use supported plan_lesson/select_next_lesson with real prerequisites and required content. Do not create automatic side lessons or debt from incidental errors. Conduct pedagogical route reviews in the chat; protocol-2 lessons do not require a saved route report. Retain only useful future focus in the bounded memory, without changing unrelated preferences.

Before a requested program switch, use get_program_options and explain the server-returned cooldown warning and next available change time. Do not promise unrestricted program changes. Respect current lesson and new-content access limits; they do not authorize discarding learner history or reducing the full applicable teaching method.
