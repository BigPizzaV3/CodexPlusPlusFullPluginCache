# 3D Skill (`filter: hana-3d(...)` / `hana-projection(...)`)

Hana has two *3D* layer effects. Both operate on the element's own layer (siblings of `filter: blur`), so html-to-hana exposes them as **functions on the CSS `filter` property** (never `data-*` attributes, never CSS `transform`). Both work on container `<div>`s, text elements, and `<img>`.

- **`hana-3d(...)`** builds a *new* lit PBR mesh: it **extrudes the shape's own silhouette**, or **replaces** it with a sphere/torus, then shades it with a material + light.
- **`hana-projection(...)`** keeps the element's *existing 2D picture* and **wraps it around a sphere or cylinder**, like a label shrink-wrapped onto a can or art mapped onto a globe.

## Which one?

- **Glossy orb, metal knob/coin, glass blob, extruded 3D headline/logo, donut/ring** — anything that should look physically lit and dimensional → **`hana-3d`**.
- **Curve / wrap *this image or label* onto a can / mug / bottle / globe / planet, or bow a poster** → **`hana-projection`** (the element's pixels become the texture on the surface).

Rotations and perspective are baked into both — author them via `rotation-x/-y/-z` / `perspective` *inside the function*, never via CSS `transform` (which is only honored inside `:hover`). Neither is valid in `backdrop-filter`. Unknown keys and unparseable values are warned and ignored (the field keeps its default).

Both take a space-separated `key=value` argument bag, and both share the same nested **light** sub-bag — described once at the end.

---

## 3D mesh — `hana-3d(...)`

The function call opts the shape in; every field has a default, so a bare `hana-3d()` already extrudes the element's silhouette.

```html
<!-- Minimal: extrudes this div's rounded-rect silhouette -->
<div style="width: 160px; height: 160px; background-color: #6366f1; border-radius: 32px; filter: hana-3d();"></div>
```

| Key | Maps to | Notes |
| --- | --- | --- |
| `geometry` | geometry | `extrude` (default — extrudes the silhouette, incl. corner radius / text glyphs), `sphere`, or `torus`. |
| `depth` | `extrudeDepth` (px) | extrude only |
| `bevel-size` / `bevel-type` | bevel | type ∈ `round`, `flat`, `flat-rounded`, `concave`, `inflate` |
| `radius` / `radius-b` | `radius` / `radius_b` | sphere uses `radius`; torus uses both (ring + tube) |
| `rotation-x` / `rotation-y` / `rotation-z` | rotation | **degrees**; omitted axes keep their default |
| `perspective` | `perspective` | camera perspective intensity |
| `subdivisions` / `crease` / `scale` / `centered` | advanced fields | rarely needed; `centered` is a bare flag |
| `material=(...)` | the material block | nested sub-bag (see below) |
| `light=(...)` | the light block | nested sub-bag (see "Light" below) |

**Material sub-bag** keys (`material=(key=value ...)`): `color` (any CSS color; alpha dropped), `metalness`, `roughness`, `reflectivity`, `transmission`, `ior`, `thickness`, `blur`, `chromatic-aberration`, `tonemapping` (bare flag ⇒ on). Fresnel and image-based environment reflections stay at their disabled defaults.

```html
<!-- Extruded 3D headline -->
<h1 data-singleline style="font-size: 96px; font-weight: 700; filter: hana-3d(geometry=extrude depth=24 bevel-size=3 bevel-type=round rotation-x=10 rotation-y=-20 material=(color=#ffd54a metalness=1 roughness=0.25));">HELLO</h1>

<!-- Glossy sphere -->
<div style="width: 240px; height: 240px; filter: hana-3d(geometry=sphere radius=120 material=(color=#3b82f6 roughness=0.1 reflectivity=0.8) light=(intensity=1.2 direction=45 shadows));"></div>

<!-- Glass blob — needs a colorful backdrop behind it to refract -->
<div style="width: 200px; height: 200px; filter: hana-3d(geometry=sphere radius=100 material=(transmission=1 ior=1.5 roughness=0.05 metalness=0 thickness=40));"></div>

<!-- Donut / ring decoration -->
<div style="width: 240px; height: 240px; filter: hana-3d(geometry=torus radius=110 radius-b=34 rotation-x=60 material=(color=#ec4899 roughness=0.3 metalness=0.4));"></div>
```

**Material cheatsheet** — *Glossy plastic/candy*: `roughness=0.1 metalness=0` + a saturated `color`. *Metal (chrome/gold/steel)*: `metalness=1 roughness=0.2–0.4`, light `color`, bump `reflectivity`. *Glass*: `transmission=1 ior=1.5 roughness=0.05 metalness=0`, add `thickness` (needs a colorful backdrop). *Matte/clay*: `roughness=0.8–1 metalness=0`.

**`hana-3d` pitfalls**: `depth` / `bevel-*` apply to `extrude` only; `radius` / `radius-b` apply to `sphere` / `torus`. Keep `color` in the **material** sub-bag, not the element's CSS `background-color` (for sphere/torus the CSS background is irrelevant). Don't over-tilt extruded text — past ~30° it gets hard to read.

## Projection wrap — `hana-projection(...)`

A bare `hana-projection()` already wraps the element's picture onto a sphere (default framing, light off).

```html
<!-- Wrap this image onto a sphere -->
<img src="..." style="width: 260px; height: 260px; filter: hana-projection(kind=sphere);" />
```

| Key | Meaning | Notes |
| --- | --- | --- |
| `kind` | surface | `sphere` (default) or `cylinder` |
| `radius` | curvature / size of the surface | 0.1–100, default 3; **larger = bigger surface, gentler curve** |
| `height` | cylinder length | **cylinder only**; 0.1–100, default 6 |
| `rotation-x` / `rotation-y` / `rotation-z` | orient the surface (degrees) | spin a globe with `rotation-y`, tilt with `rotation-x` |
| `perspective` | camera perspective intensity | 0–170, default 10; higher = stronger foreshortening |
| `input-size-x` / `input-size-y` | "wrap area": fraction of the element mapped onto the surface | default 1 / 1 (= 100%); 0.1–10. < 1 wraps a crop; > 1 zooms out |
| `input-quality` | render resolution multiplier | integer 2–12 (2 = 1×, 4 = 2× default, 12 = 6×); raise for crisp text/edges |
| `side` | which faces render | `both` (default), `front`, or `back` |
| `light=(...)` | the light block | nested sub-bag (see "Light" below) |

```html
<!-- Soda-can / mug label: wrap a label image around a cylinder -->
<img src="label.png" style="width: 220px; height: 300px; filter: hana-projection(kind=cylinder radius=3 height=8 rotation-y=20);" />

<!-- Globe: map a world map onto a lit sphere, tilted and spun -->
<img src="worldmap.png" style="width: 280px; height: 280px; filter: hana-projection(kind=sphere radius=4 rotation-x=-15 rotation-y=30 light=(intensity=1.4 direction=140));" />

<!-- Curved poster: gently bow a gradient panel of text -->
<div style="width: 360px; height: 220px; background: linear-gradient(135deg,#0ea5e9,#9333ea); color:#fff; font-size:40px; filter: hana-projection(kind=cylinder radius=12 height=20 perspective=40);">SALE</div>
```

**`hana-projection` pitfalls**: it wraps the element's *own picture* — the element needs visible content (a `background`, image, or text) to map. `height` is cylinder-only; on a sphere it's ignored (use `radius` for sphere size).

## Light (shared by both, off by default)

Both effects shade their surface with the same light, expressed as a nested `light=(...)` sub-bag. A bare `light` flag enables it with defaults; `light=(...)` enables it **and** overrides fields.

| Key (inside `light=(...)`) | Meaning | Notes |
| --- | --- | --- |
| `intensity` | key-light brightness | 0–1000, default 1 |
| `color` | key-light color | CSS color (alpha dropped); default white |
| `direction` | azimuth (degrees) | -360–360, default 200 |
| `height` | elevation (degrees) | -360–360, default 40 |
| `ambient` | ambient fill amount | 0–1, default 0.3 |
| `ambient-color` | ambient fill color | CSS color, default white |
| `specular` | specular highlight strength | 0–2, default 0.3 |
| `shadow-color` | shadow tint | CSS color, default black |
| `shadows` | enable cast shadows | bare flag ⇒ on |

For `hana-3d`, the light is enabled by default with sensible values; for `hana-projection` it is **off** until you add a `light` flag or `light=(...)`.

## Animating on `:hover` / `:hana-active`

Both functions' numeric fields (and nested `material` / `light`) tween if you redeclare `filter` in a pseudo-state rule — e.g. spin a globe on hover with a larger `rotation-y`, or brighten `light=(intensity=...)`. Two rules: declare the effect on the **base** too (a pseudo-state can modify but not add an effect), and **restate the whole function** in the pseudo rule — `filter` is one CSS property, so the hover value replaces the base wholesale and omitted args revert to defaults.
