# Build directive — public analyst V1

## Product and scope

**SigRank | SignalAF** / **Performative stats and benchmarks for AI users, not models.** / **AI Operator Leaderboard**. Tokenpull measures → SigRank evaluates → SignalAF publishes. The plugin explains the observable structure of AI use, not intelligence, productivity, work quality, model quality or personality. Archetypes are operating patterns.

V1 uses the dedicated public MCP endpoint for authoritative facts and skills for interpretation and communication. The launch board experience is one Active / Total / All-time snapshot; other windows remain backend compatibility for explicit requests. Methodology, the operating ratio (`R/I : 1 : O/I`), public aggregate token-pillars and the ten Build Archetypes are first-class explanations. SignalAF articles supply dated research context, never substitute live ranks. The live public operator tool returns no official archetype label, so a label calculated from complete observed I/O/W/R must be identified as **derived under current rules**; withhold it when an axis is missing. Four data tools are read-only. `report_beta_bug` is the sole side-effecting exception: a minimal redacted support email after the user approves the exact draft. No SignalAF account or OAuth is required. ChatGPT uses public codenames; Codex may read an existing local identity's codename and then call the same public operator tool. A guided preview from user-supplied counts is optional beta guidance, not a launch calculator claim; it neither scans logs nor publishes.

## Exact sequence and gates

1. **Lock canon:** use `SOURCE_MAP.md`, TTEOP and current app code; preserve I/O/W/R and null semantics, current ten Build Archetypes, cohort/window distinctions, and claim limits.
2. **Isolate transport:** expose only `get_leaderboard`, `get_operator`, `compare_operators`, `get_field_stats`, `report_beta_bug` at `/api/plugins/sigrank/mcp`; leave `/api/mcp` and its submission tools untouched. Reject unavailable live reads rather than using fixtures.
3. **Prove data contract:** check title, five-tool inventory, no OAuth scheme, four windows, Total versus By platform populations, I/O/W/R, operating ratios, provenance, errors, privacy, and annotation truthfulness against deployed data.
4. **Harden analyst:** use the 20 synthetic fixtures and unfamiliar live profiles. Assess the actual tool choice, metric relationships, interesting structure, compatible field context, supported movement, archetype rationale and claim boundary. Tool success alone is insufficient.
5. **Harden communication:** produce plain-English, technical, unusual-finding, LinkedIn, X and share-card copy from the same sourced finding. Reuse existing SignalAF URLs/cards; do not invent an asset or publish for the user.
6. **Run fresh hosts:** install the candidate in ChatGPT and Codex; capture unedited prompts, tool calls and answers; score against `ANALYST_EVALUATION.md`. Codex additionally tests local identity resolution without exposing keys. Record failures and revise before retest.
7. **Freeze one package:** manifests, endpoint, tool count, skill, examples, review cases, privacy text and current deployed route must agree. Archive superseded prototypes. Build and inspect one ZIP.
8. **Prepare review:** only after behavior and package gates pass, complete current OpenAI submission materials and portal checks. Upload, review submission and publication are separate states.

## Non-goals

No OAuth, remote `get_my_profile`, native Tokenpull scanning, measurement submission, new scoring backend, new database, silent estimation, SEO/redesign work, or automatic social posting. Do not relabel unclaimed rows as seeded: a seeded archive comparison requires separately proven origin and a dated dataset. Historical movement is described only when the returned data supports a compatible comparison. `TOKENPULL_V2.md` documents a possible later integration, not current behavior.

## Stop conditions

Do not call an unsupported value verified, convert missing W to zero, compare incompatible windows, use retired SIGNA-RATE as canonical Yield, or turn a rank into a claim about human worth. If a required field is absent, identify the smallest upstream data change and continue with supported analysis.
