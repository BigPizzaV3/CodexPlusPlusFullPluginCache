# V1 test plan

## Cold invocation

In a fresh ChatGPT conversation, send only `@SigRank | SignalAF`. Pass if the answer opens with a short explanation of the AI Operator Leaderboard, conveys competition plus learning, and offers a few natural paths into the live board, metrics, provenance, a profile, or the Four Degrees. Fail if it only asks what tool to call, lists APIs, invents live placements, claims scores prove talent/work quality, or spotlights a predetermined account. Repeat in Codex. Then ask for the live board and verify a single `get_leaderboard(window="all", view="total")` call; a specific board request should skip the welcome. Record the actual host response against the candidate version.

## Contract and isolation

After PR #175 is live, MCP `initialize` must say `SigRank | SignalAF`; `tools/list` must return exactly `get_leaderboard`, `get_operator`, `compare_operators`, `get_field_stats`, `report_beta_bug`, all with `noauth`. Four reads must be annotated read-only; the beta tool must be marked side-effecting. No `get_my_profile`, OAuth challenge, shared-MCP submission tool, or mock fallback may appear. Validate both success/error structured outputs against the exact schemas in `sigrank-app/lib/mcp/plugin/contracts.json`.

For the launch path, call `get_leaderboard(window=all, view=total)` and compare the Active / Total / All-time response with the corresponding rendered website board, not homepage examples. Verify I/O/W/R, Yield, Velocity, Leverage, operating ratio, board URL, category, population, nulls and provenance. Contract-test 7d, 30d and 90d only as supported explicit-request compatibility. Test empty/failed upstream, missing display name, limit, unsupported cohort and no cursor. Call `get_field_stats` with default and `view=total`; do not merge those populations. `compare_operators` must leave delta null when `comparable=false`.

For the narrative test, ask the plugin to read a live operator's raw token pillars and operating ratio. It must explain `R/I : 1 : O/I` as cache-read : fresh-input : output, map the first/last terms to Leverage/Velocity, distinguish W and Construction, and avoid treating rounded display terms as exact inputs. It should analyze complete four-pillar shares only when all pillars are observed. Ask it for the lesson from *Volume Isn't Yield* and ensure it cites the dated article without importing its superseded eight archetypes or seed-cohort ranks into the Active board. Ask for private session telemetry and ensure it states that this plugin only sees public aggregates.

For **insight discovery**, give the host unfamiliar boards with I/O/W/R, Yield, and total volume, then ask open questions such as “What stands out?” Vary population size, rank order, metric distribution, user interest, and whether any additional category is reliably supplied. A passing answer identifies at least one defensible relationship in the stated cohort, explains its metric drivers, and can choose a different lead when the evidence or question changes. A plain leaderboard recap is acceptable when no stronger finding is supported. Fail if it repeats a memorized operator-specific conclusion, treats #1 as the universal benchmark, invents account types or field percentiles, calls I literal human keystrokes, or claims output quality from Yield. Use held-out values to test transfer, not a single favored example.

For a top-two comparison, confirm the returned #1 remains the focal operator and the second tool codename is taken from the returned #2 row, even if its public display name differs. Require a varied read of the focal operator: its own I/O/W/R structure, the second snapshot's contrasting axis, and matching Active Total field median/quartiles. When comparable, describe returned deltas as differences between displayed board snapshots; if observation dates differ, do not imply equal-duration activity. When the homepage's four-degree ladder is requested, name the static modeled AA baseline, Operator Center of Mass median, top-100 median, and top eval with the page's as-of state; keep its broader cohort separate from the 22-person Active MCP response. Test that `total_eligible` counts ranked rows, operator-row `ranking_eligible=true` means published board inclusion, and per-row measurement class and verification state remain unknown when the website does not publish them; the field stats Unknown bucket accounts for those rows. The envelope is not an operator and can carry `ranking_eligible=false`.

Ask how the homepage headline median Yield relates to the Four Degrees Center of Mass Yield. Pass only if the answer verifies that both now use the same all-time real-operator median and distinguishes that broader population from the Active plugin board and the aggregate API's yieldable-snapshot cohort. It must not claim the historical 34.45 legacy score is current Yield or invent an Active median.

For an unspecified board request, verify the skill makes only one explicit all-time Total read. For a requested window, verify it uses that window. The launch prompts must use only the Active all-time board. Seeded board behavior is deferred; no broader By-platform row may be called seeded solely because it is unclaimed.

Beta privacy: missing/false consent cannot send; reject malformed reports, redact secrets, enforce rate limit and give a clear delivery error. Only send a harmless test email after the displayed draft is approved. Check no full chat, code or local log is included. Local identity resolver must return only status and codename for a bound fixture, return `no_identity` for missing/partial files, and never print a private key, device ID or operator ID.

## Analyst behavior — focused launch check and extended internal evaluation

For the launch check, capture fresh ChatGPT and Codex answers to a casual board question, a statistical explanation request, a technical operating-ratio request, and a focal top-two comparison. Check that each answer leads with the live result or finding, follows the user's demonstrated interest and requested depth, links the source, and keeps material scope notes proportionate. Do not require a rigid voice or infer user age or occupation. A 200 tool response alone does not pass. Confirm `archetype: null` is never presented as an official published label; derive under current rules only with complete positive I/O/W/R. In Codex, test “show my profile” with and without a local identity; ChatGPT must ask for a public codename. Use the 20 `ANALYST_FIXTURES.json` profiles and `ANALYST_EVALUATION.md` for extended internal regression coverage, not as an OpenAI publication requirement.

If a test finds missing board metadata, record a short maintainer issue with the affected tool, returned field, expected field, observed result, source URL, and whether any user-facing answer was affected. Keep that report separate from the leaderboard response. The public `report_beta_bug` tool sends to support only after the user has seen and approved the exact concise report; it must not silently forward conversation context or telemetry.

Probe movement with two compatible historical records and with the current public history gap. When canonical I/O/W/R history is absent, withhold numeric Yield movement and name the missing field. Do not reuse retired SIGNA-RATE as Yield.

Optional beta test, outside the public launch claim: for a manually supplied token-count preview, test complete four pillars, missing W, missing R, observed zero, I=0, cumulative-versus-turn ambiguity, cached-input double-count risk, and mismatched periods. Confirm the plugin MCP receives no counts and no score is published. A hypothetical Active board insertion must disclose complete row coverage, source state, tie rule and missing-bounds comparison limits; a capped or incomplete list permits only a side-by-side numeric illustration. Verify the site paste page is described as remote processing and the browser Yield calculator as client-side.

For one operator and one comparison, generate from the same sourced finding: plain-English explanation, technical explanation, “what is unusual?”, LinkedIn copy, X copy and share-card headline/supporting line. Check every number, scope, link and limitation remains consistent. Do not invent a card, badge or publication event.

## Completion and regressions

Run app typecheck, canonical tests, focused MCP tests, full app suite (record unrelated baseline failures separately), plugin local-identity test, manifest schema validation, archive inventory and live endpoint smoke as appropriate to changed components. Then run the five positive and three negative review cases in fresh hosts, recording actual tool calls, arguments and answers. Mark each Passed/Failed/Blocked; drafted cases are not passes. Rebuild the ZIP after any fix and inspect the ZIP itself. Complete the focused host checks and current submission-portal requirements before public review.
