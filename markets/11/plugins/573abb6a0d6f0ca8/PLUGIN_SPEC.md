# Plugin specification

**Name:** SigRank | SignalAF  
**Subtitle:** AI Operator Leaderboard  
**Description:** Performative stats and benchmarks for AI users, not models.  
**Hierarchy:** Tokenpull measures → SigRank evaluates → SignalAF publishes.

The plugin is a public AI-operator analyst and communication layer. Its V1 board experience is one **Active / Total / All-time** snapshot. The underlying MCP retains 7-day, 30-day and 90-day compatibility lookups for explicit requests, but the listing and launch tests use the single all-time board. It explains methodology and the operating ratio, analyzes public aggregate I/O/W/R counts, draws appropriately dated insight from SignalAF articles, reads public profiles, compares compatible structures, interprets field statistics and drafts share copy. It can guide an **unverified, manually supplied four-count preview** without scanning logs or publishing a score; this is beta guidance, not an advertised deterministic calculator. It uses the dedicated SignalAF MCP, never the older shared submission endpoint. [SigArena](https://sigeconomy.com/all-time) is a separate mixed seeded/live historical board with its own read-only MCP; it is not attached to this V1 plugin and does not expose a seed-only cohort.

**ChatGPT:** public discovery, profile interpretation, comparisons, methodology and share-copy drafting. Ask for a public codename when the user says “my profile.” **Codex:** the same public workflows, plus optional local resolution of an already enrolled SigRank codename through `scripts/resolve-local-profile.mjs`; then call `get_operator`. The script returns only `status` and `codename` and never sends identity keys. If no local identity exists, ask for a public codename. Tokenpull remains a separate local system.

The remote MCP has five no-auth tools: `get_leaderboard`, `get_operator`, `compare_operators`, `get_field_stats`, and `report_beta_bug`. The first four only read; the fifth sends a consent-gated support report to `hello@signalaf.com`. No custom MCP UI is in V1. Manual preview uses only user-supplied aggregate counts and transparent formulas; the plugin MCP receives no counts. The existing SignalAF paste page is an optional server-side calculator, not a plugin submission path. Results are explained in chat with links to current SignalAF profile, board and share surfaces. Starter prompts: “Show the Active Total / All-time board”; “Explain Yield and the ten Build Archetypes”; “What is structurally unusual about this operator?”; “Turn this supported finding into a plain-English explanation and X post.”

Manifests: portable `plugin.json`/`mcp.json`, Codex `.codex-plugin/plugin.json`/`.mcp.json`. Listing links: [plugin](https://signalaf.com/plugin), [support](https://signalaf.com/support), [privacy](https://signalaf.com/privacy), [terms](https://signalaf.com/terms). All available countries; no in-plugin purchases. Public `developerName` must match the verified publisher before submission.

Claims boundary: observable I/O/W/R token-flow structure only; no intelligence, productivity, work-quality, personality or causal claims. An archetype is a pattern, class is qualification/scale, rank is field position. Unclaimed does not prove seeded. Missing is not zero. The live board is the authority for published placements. Ranked operator rows have `ranking_eligible=true`; this means board inclusion. The website board does not expose each row's measurement class, so the plugin leaves that field unknown instead of running a second verification process. Normal answers lead with the board and use a short provenance note only when it matters.
