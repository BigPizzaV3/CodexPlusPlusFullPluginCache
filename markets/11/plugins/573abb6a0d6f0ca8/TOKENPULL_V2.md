# Tokenpull V2 — deferred measurement attachment

This document preserves the requested future integration boundary; **none of it is implemented by the analyst plugin**. Tokenpull/Upsilon owns collection and normalization, TTEOP owns the portable I/O/W/R and metric contract, SigRank owns evaluation, and SignalAF owns publication.

For Codex usage records, map `input_tokens → I`, `output_tokens → O`, `cache_write_input_tokens → W`, and `cached_input_tokens → R` only when the source schema and per-turn/cumulative semantics are confirmed. Preserve model, device, session, window, source file/version and adapter version in a local evidence envelope. Distinguish per-turn deltas from cumulative snapshots, compaction resets, duplicate records and multi-device merges before aggregation. Never silently estimate W or R; null means unavailable, zero means observed zero.

The proposed measurement classes are **Exact-4**, **Reconstructed-4**, **Partial**, and **Unverified**. These are design labels, **not current SignalAF production verification states or field cohorts**. Define evidence tests and approve them upstream before exposing them publicly: Exact-4 requires directly observed four pillars and known semantics; Reconstructed-4 requires a documented deterministic transformation and source lineage; Partial preserves missing pillars; Unverified is user-provided or lacks trusted lineage. Do not promote a local class to a public verified claim without SigRank's acceptance rules.

Adapter/refactor sequence, when authorized: inspect current Tokenpull/Upsilon parser and Codex log format; create fixtures for old logs and cumulative-vs-turn usage; normalize without reading prompt content; run TTEOP conformance vectors; compare with existing ingest bridge; produce a local report first; add an explicit user-controlled submission path only after privacy and proof review. No local logs, prompt text or code should be sent to the remote MCP for mere analysis. There is no automatic upload.
