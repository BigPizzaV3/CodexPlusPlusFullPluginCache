# Interpret LIUYAO

Selected method school: `liuyao.school.jingfang-zengshan.v1`.

1. **confirm** Confirm the explicit question, requested domains, time horizon, and whether the user supplied six lines or requested a virtual cast. For a virtual cast, call `confirm_casting_details`, relay its complete summary, and wait for confirmation; for supplied lines, require the question to be explicit and confirm that the lines must not be recast. This is the confirmed reading contract.
2. **calculate** For supplied lines, call `calculate_liuyao_chart` with the exact six lines in bottom-to-top order, the exact confirmed question, and `confirmedQuestion: true`; for a confirmed virtual cast, call `cast_liuyao` with the exact `confirmationToken`, exact resolved fields, and `confirmedQuestion: true`. Use only the exact nested `structuredContent.canonicalResult` from that calculator tool result in the current conversation. Never pass the whole enriched `structuredContent`, display data, or reconstructed data, and never use stale, other-conversation, or remembered facts. Require its `system` to be `liuyao` and its `schemaVersion` to be exactly `omds.liuyao-reading.v1`; on mismatch stop as unavailable rather than repairing or recalculating it.
3. **prepare_interpretation** Call `prepare_interpretation` with the confirmed `system`, that exact `canonicalResult`, the same optional exact `temporalResult`, and the same confirmed `readingContract`. Retain both returned digests—`calculationDigest` and `preparedContextDigest`—plus `reportScaffold`, complete ordered `methodPlan`, evidence index, temporal availability, and limitations without editing them. The `reportScaffold` field `calculationDigest` must equal the returned `calculationDigest` exactly; `preparedContextDigest` is a separate validator input and must never be copied into the report.
4. **read_complete_method_pack** Read the complete packaged method pack [from its first heading through every `**End method card:**` marker](references/method-pack.md). Follow the prepared `methodPlan` order and statuses exactly: execute only `active` cards and preserve every `unavailable` or `disputed` card, prerequisite, obligation, and temporal layer as a limitation. Never use a partial reference or source narrative. Never use remembered traditional meanings.
5. **draft_report_v2** Outside the Worker, draft `inner-lens.interpretation-report.v2` from the returned `reportScaffold` and [the active shared report contract](../../references/report-contract.md), using only active claim rules and evidence from the prepared context. Set `report.calculationDigest` to the exact prepared `calculationDigest`. Every exact entry in `reportScaffold.limitations` is required; additional schema-valid bounded limitations are allowed, and order is not semantic. Preserve unavailable or disputed methods and layers as limitations. The current manifest activates 7 of 7 `liuyao` method cards (`liuyao.method.question-contract.v1`, `liuyao.method.use-spirit-selection.v1`, `liuyao.method.month-day-strength.v1`, `liuyao.method.moving-line-effects.v1`, `liuyao.method.combinations.v1`, `liuyao.method.tomb-storage.v1`, `liuyao.method.timing.v1`): attempt a real interpretation with them. For every `active` card in the prepared `methodPlan`, emit a material block only where that card's own reviewed claim rule and the prepared evidence index genuinely support one, citing the exact `evidenceId`, `factPath`, `canonicalIds`, `methodCardId`, `claimRuleId`, `temporalLayer`, and `provenanceRef` the prepared context returned, with real supporting and counter evidence. Where an active card's claim rule is not satisfied by the prepared evidence, keep that obligation an explicit limitation instead of a block -- exactly as for every temporal layer the prepared context reports as unavailable. Never fabricate a material claim, timeline, scenario, or recommendation to fill the schema.
6. **validate_interpretation_report** Retain both returned digests. Call `validate_interpretation_report` with the exact current-conversation `canonicalResult`, the same optional exact `temporalResult`, the same `readingContract`, and the returned `preparedContextDigest` exactly as `preparedContextDigest`; never substitute `calculationDigest`. Pass the candidate `report` and `attempt: 1`. If it returns `repair-once`, apply only its static errors to the same report once and call the validator exactly once with `attempt: 2`; the maximum is one repair. Never resend `attempt: 1`, never create `attempt: 3`, never replace the report with remembered prose, and never bypass the validator.
7. **render_widget** Stop after the validator result. The attached report widget renders automatically, using only a returned `validatedReport` or the attempt-two facts-only `fallback`. Never render an invalid draft or summarize claims absent from `validatedReport`. Never substitute a chart or export tool for this report widget.

Method school boundary: Use `liuyao.school.jingfang-zengshan.v1` as the selected method school for this rendered package. The system default is `liuyao.school.jingfang-zengshan.v1`. No alternate executable school is available. A profile selection changes the method pack only, never the returned calculation facts.

Treat Liuyao as question- and casting-moment-specific. Never turn it into a natal personality profile.
