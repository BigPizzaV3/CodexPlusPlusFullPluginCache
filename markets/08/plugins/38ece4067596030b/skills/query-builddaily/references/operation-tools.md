# Explicit operation tools

Version 2.4.1 exposes 370 reviewed operations through 740 named preparation and execution tools in the 1020-tool public catalog. Permissions and assistant grants may narrow the tools available to a connection. Preparation stores only a temporary plan and sends no email, domain notice or review notification. Source staging is a separate private file-storage action.

Each preparation tool takes an idempotency_key and items for only its named operation. Project operations also require project_id. Include source_evidence when facts come from email, a spreadsheet, a file or chat. Present the full preview and obtain confirmation, then call only its matching execution tool with plan_id, plan_digest and confirmation_phrase CONFIRM. Never mix operations or supply an action selector. An execution tool rejects a saved plan for a different operation, including already completed plans. Legacy owner_in_builddaily assistant plans cannot execute through MCP.

The assistant/client must obtain the user's explicit confirmation in chat. The server rechecks the exact plan and current authority/state but cannot inspect the chat transcript; the confirmation phrase is not independent proof of human approval. `signature.prepare` is a domain operation: only `execute_signature_prepare` creates that signature draft; its preparation tool stores the review plan.
