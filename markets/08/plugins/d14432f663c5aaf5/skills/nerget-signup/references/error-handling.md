# 오류 및 예외 처리

## 오류·복구 안내의 내부 정보 비노출

아래 오류 코드·필드명·Tool명·snapshot·JSON은 내부 판단에만 사용한다. 사용자에게 오류 원문,
누락 필드 목록, 복구한 코드·배열을 출력하지 않으며, 필요한 경우 '선택 내용을 다시 확인하고 있습니다'
또는 '<사용자용 항목명>을 확인해 주세요'처럼 자연어로 안내한다. 사용자 확인은 실제 복구 불가
항목에만 요청한다. 코드가 노출된 이유를 질문받아도 해당 코드·값을 재인용하지 않고 사용자용
명칭으로 정정한다. 이 규칙으로 Tool 인자나 내부 선택 상태를 삭제·변환해서는 안 된다.

## 우선순위: 호출 전 누락 방지

Skill의 최우선 규칙에 따라 일반 조회·다음 화면·handoff 호출 전에 현재 유효한 전체 선택과 인자를
대조한다. 사용자 변경·초기화를 제외한 기존 필드의 누락·값 변형·타입 손실이 있으면 해당 호출을
멈추고 정확한 정상 응답에서 보충한 뒤 재검사한다. 아직 미선택인 후속 필드는 검사 대상이 아니다.
완전한 snapshot이 있으면 예방을 이유로 Data 조회나 재선택을 추가하지 않는다.

추가 코드 확인이 필요한 경우에만 아래 복구 절차로 전환한다. 복구용 `*Data`는 전체 코드가 아직
복원되지 않았어도 확인된 유효한 선택값을 모두 전달해 조회할 수 있다. 이는 불완전한 상태로 일반
진행하지 말라는 규칙의 예외이며, 조회 결과로 기존 선택을 축소하거나 미확인 값을 임의 보충하지 않는다.
호출 후 응답에서 누락·의도하지 않은 값 변경이 발견돼도 해당 응답을 정상 상태로 채택하지 않고
복구 후 다음 호출 전에 다시 검사한다. 재선택은 복구 불가 항목에만 적용한다.

## 선택 반영 실패

위젯 전용 `selectPlanAndBenefit`은 전달 형식을 해석하고 요금제·혜택을 즉시 검증한다. 다른
app-only `select*`는 이번 선택 patch를 요청의 `selectionSnapshot`에 병합한다. GPT는 이 Tool들을
직접 호출하지 않으며, 최종 가입 유효성은 `createSignupHandoff`에서 다시 검증한다.

Tool 실패 응답이나 연결 오류가 발생하면 이번 patch를 완료로 간주하지 않는다. 가장 최근 성공한
model context 또는 호환 fallback 메시지의 전체 snapshot을 유지한다. 실패한 이번 선택은 복구 완료로
간주하지 않으며 필요하면 해당 항목만 재시도·재선택한다. 성공 응답에
`event=SIGNUP_SELECTION_UPDATED`, `selectionPatch`, 전체 `selectionSnapshot`이 모두 없으면 patch만
기준으로 계속하지 않는다.

## Snapshot 누락 또는 손상

서버 저장본과 상태 토큰이 없으므로 서버가 이전 선택을 자동 복구하지 않는다. 최초 호출이 아닌데
다음 Tool 인자나 응답의 snapshot에 기존 값이 빠졌다면 빈 값으로 덮어쓰거나 완료됐다고 말하지 않는다.
복구 순서는 다음과 같다.

1. 호출 전후 snapshot을 현재 유효한 선택과 비교한다. 가장 최근 정상 model context·fallback·성공
   응답의 전체 snapshot에 이후 성공한 선택 patch를 순서대로 한 번씩 병합한다. 전체 snapshot에
   이미 반영된 patch는 중복 적용하지 않는다. 명시적 전체 초기화 이전 값이나 변경·취소된 값은 제외한다.
2. 정확한 코드가 없으면 사용자 발화·위젯 선택 통지·기존 자연어 요약에서 선택명과 조건을 확인한다.
   GPT 요약은 원래 사용자 선택과 이후 변경 요청에 부합해야 한다. 추천·단순 조회·모델이 임의로
   안내한 내용을 선택 확정 근거로 사용하지 않는다. 근거가 충돌하면 해당 항목만 확인한다.
3. `tool-selection.md`의 복구용 `*Data` Tool로 실제 코드를 조회한다. 요금제명·가격·혜택 종류·기간,
   스마트기기의 색상·할부 개월 등 기존 조건과 유일하게 일치하는 항목의 실제 코드만 사용한다.
   요금제 코드를 먼저 확인하고 그 코드로 혜택을 조회한다. 목록에 항목이 존재하거나 필수 혜택이라는
   이유만으로 사용자가 선택했다고 간주하지 않는다. 여러 후보 중 임의 선택·유사 상품 대체는 금지한다.
4. Data 조회에는 현재까지 근거로 확인한 선택값을 전달하고, 응답의 빈/부분 snapshot은 상태
   초기화로 해석하지 않는다. 복구한 필드만 기존 유효 상태에 병합해 다음 호출에 전체 snapshot을
   전달한다. 자동 복구 중에는 위젯과 `select*`를 호출하지 않는다. 이름만 확인됐다고 복구 완료나
   서버 검증 완료로 안내하지 않는다.
5. 복구에 필요한 조회·대조를 마쳐도 코드가 없거나 후보가 여러 개이거나 상세 선택 근거가 부족하면
   해당 항목만 짧게 확인한다. 실제 재선택이 필요한 항목만 위젯으로 받는다. 위젯이 사용자 선택에
   따라 `select*`를 호출하며 GPT는 직접 호출하지 않는다. 정상 항목 전체를 다시 고르게 하지 않는다.

모르는 혜택 배열을 `[]`로, 결합 여부를 `false`로 채우지 않는다. 선택 없음의 명시적 근거나 조회
결과상 해당 선택 대상이 없다는 근거가 있는 경우에만 빈 배열을 사용한다. 필요한 Data Tool이 실제
카탈로그에 없으면 존재하지 않는 Tool을 만들거나 선택 Tool을 복구용으로 대신 호출하지 않는다.
정확한 이전 응답으로 복구할 수 있는지 확인한 뒤 부족한 항목만 사용자에게 확인한다.
이 절차는 PLAN/BENEFIT 완료 후 재조회 금지 및 전체 JSON 부재 시 즉시 재선택하는 지침의 예외다.

혜택 배열의 `[]`는 선택 없음이 확인된 실제 값이다. `giftCodes: [0]`은 숫자 0을 포함한 유효한
사은품 선택이므로 미선택이나 오류로 처리하지 않고 다시 묻지 않는다. 필드 자체가 없거나 전체
snapshot을 확인할 수 없는 경우와 혼동하지 않는다. 현재 patch 하나를 전체 snapshot처럼 사용하지 않는다.

`isMobileHomePlan`은 요금제 정보이므로 `true` 또는 `false`가 없으면 요금제 선택을 완료로 처리하지
않는다. 반면 `deviceBenefitCodes`, `benefitCodes`, `giftCodes`는 해당 요금제에 선택 대상이 없으면
`[]`로 완료할 수 있다.

`INVALID_SELECTION_SNAPSHOT`은 PLAN/BENEFIT 선택 뒤 `deviceBenefitCodes` 항목의 `code`,
`colorCode`, `contractMonthCount` 중 하나가 유실됐다는 뜻이다. SIM·가입 유형·개통 방식으로 계속
진행하지 말고 위 절차로 세 값을 먼저 복구한다. 해당 오류가 불완전한 snapshot의 Data 조회도 막으면
같은 요청을 반복하지 않고 정상 응답에서 복구한다. 그래도 복구할 수 없는 상세 항목만 확인·재선택한다.

## 메시지 전달 실패

가입 선택 흐름은 선택 성공 후 표준 `ui/update-model-context`에 정확한 상태를 전달하고 짧은
`ui/message`로 다음 모델 턴을 시작한다. model context 갱신을 사용할 수 없으면 compact snapshot을
메시지에 포함한다. 메시지 전송에 실패하면 위젯을
성공 상태로 닫거나 다음 단계를 추정하지 않고 오류를 표시한다. 직전 성공 메시지에 없는 이번 선택은
반영됐다고 간주하지 않는다. 이번 선택의 실제 성공 응답이 대화에 있으면 복구 절차로 확인하고,
근거가 없으면 해당 선택의 재시도·재선택을 요청한다.

## Tool 스키마 캐시 불일치

모든 가입 조회 Tool과 `createSignupHandoff`의 입력 스키마에 `selectionSnapshot`이 보여야 한다.
선택 Tool은 `_meta.ui.visibility=["app"]`로 위젯에만 보여야 한다.
예전 상태 bootstrap Tool이나 상태 토큰 인자가 보이면 오래된 플러그인 또는 MCP Tool 카탈로그가
로드된 상태다. 알 수 없는 인자를 생략한 채 흐름을 계속하지 말고 플러그인/MCP 연결을 새로고침한 뒤
새 대화에서 Tool 스키마를 다시 로드한다.

## 최종 handoff 실패

- `USER_CONFIRMATION_REQUIRED`: 사용자의 별도 명시적 동의를 먼저 받는다.
- `SIGNUP_SELECTION_INCOMPLETE`: `missingFields`를 기존 선택 근거와 대조해 먼저 복구하고,
  실제 미선택·복구 불가 항목만 확인·재선택한다.
- 요금제·혜택 또는 enum 오류: 전달 코드 누락·불일치이면 Data 조회로 기존 선택을 복구한다.
  현재 제공되지 않거나 조건이 달라진 선택은 임의 대체하지 않고 해당 항목만 다시 확인·선택한다.
- Tool/연결 오류: 저장 완료나 URL 발급 완료라고 말하지 않는다. 최종 호출을 다시 하면 새
  `signupFlowId`와 row가 생길 수 있으므로 성공 응답을 확인한 뒤 가장 최근 성공 응답만 사용한다.

복구 후 전체 snapshot에 대응하는 사용자용 명칭과 조건만 다시 요약해 별도 명시적 동의를 받는다.
내부 코드·필드명·JSON은 표시하지 않는다. `*Data` 조회를 통한 복구는 최종
가입 검증을 대신하지 않는다. 이미 handoff가 성공했다면 자동 재호출하지 않는다.

성공 응답의 `canOpenActivationPage=true`와 완전한 `activationPageUrl`이 있을 때만 외부 페이지를 연다.
URL을 클라이언트에서 추정하거나 수정하지 않는다.
