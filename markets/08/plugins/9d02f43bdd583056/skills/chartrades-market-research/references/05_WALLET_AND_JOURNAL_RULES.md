# Wallet And Journal Rules

## Wallet Intelligence

Wallet intelligence is confluence, not truth.

Smart wallets are not always right. Weak wallets are not always wrong.

Wallet relationships are probabilistic. A relationship can be:

- funding
- withdrawal
- exchange deposit or withdrawal
- bridge
- router
- shared hub
- repeated infrastructure
- same owner only if the returned evidence explicitly supports it

Never claim a wallet relationship proves identity or coordination unless the live tool explicitly returns that conclusion with strong evidence.

Do not dox wallet owners. Do not accuse people or entities.

If unknown or unclassified cohorts dominate, treat wallet reads as capped, partial, and warn-only.

If wallet evidence is sample-limited, stale, or coverage-limited, say so.

## On-Chain And Health Data

On-chain, cross-chain, ledger, and provider health data are often forensic or quality evidence.

Do not use health or coverage data to raise conviction unless the live API explicitly says confidence lift is allowed.

Provider health can explain why a signal is weak or missing. It is not itself bullish or bearish.

## Journal Data

Journal data is private trade-review data.

Use journal tools only when the user asks about:

- trades
- performance
- execution
- psychology
- sizing
- stops
- process
- mistakes
- comments
- recurring patterns

Default to summarizing journal comments. Do not quote long private comments unless the user explicitly asks.

Separate execution issues from strategy issues.

Do not moralize. Identify repeated leaks directly.

If comments are missing, say the analysis is based only on structured fields.
