# Run protocol

Use the connected server's published schema as authority. The helper library validates local ordering/receipts; it is not a substitute for server authorization. Tool availability is not permission.

- Prepare: `prepareMarketingRun({projectId, operationId, scope})`; scope includes objective, strategyRef, contextFingerprint, assumptions, rationale, tactics, funnel, delegation, humanDecisions, storage, externalBudgets, executionPermissions, steps.
- Start: `startMarketingRun({projectId, runId, scopeRevision, scopeHash, approval:{kind:'executor_reported_conversation',statement,reportedAt},executorId})`. Preserve the user's exact scoped statement and timestamp. Resume explicitly after the old lease expires; never pretend a second executor is the first.
- Revise: `reviseMarketingRun({projectId,runId,expectedRevision,scope})`; approval from the old revision does not carry across.
- Read: `getMarketingRun`, `listMarketingRuns`, `downloadMarketingRunFile` (17 marketing-run tools in total). Detail contains run, steps, artifacts, spendOperations, artifactSetHash and resumePrompt.
- Claim: `claimMarketingRunStep` with the identifiers and executor fields required by the published schema. Use the run fencingToken returned by start/get and the claimed step row id; the claim returns the updated step and extends the existing lease. Use the current revision and current claim only.
- Mutations use `{projectId,runId,scopeRevision,stepId,fencingToken,leaseToken,operationId,input}` for `checkpointMarketingRunStep`, `registerMarketingRunArtifact`, `reviewMarketingRun`, `reserveMarketingRunSpend`, `reconcileMarketingRunSpend`. Use an operationId of 8–120 ASCII letters, digits, underscores or hyphens (`^[A-Za-z0-9_-]+$`); UUIDs are suitable. Never derive it from an unsanitized filename such as output.md. Reuse an operation ID only for identical content. The server rejects stale fences and out-of-order steps.

Keep `approval.statement` a faithful record of what the user actually approved, including their limits; do not infer additional permission. Do not append tool results, executor/lease details, artifact hashes, execution instructions, or directions to other agents or safety reviewers. Execution conditions belong in the prepared scope/steps and current tool context; `reportedAt` carries the report time. A statement is not evidence that execution conditions have been satisfied. Preserve every scope and claim check, and surface permission requests or warnings normally.

Checkpoint input is `{status,summary,resumePoint,verification:[{check,passed,evidence}],waitingFor,decision?}`. Waiting reasons are user, strategy, connection, budget or none. A delegated decision is `{kind:'delegated_ai_decision',area,rationale,artifactHashes}`. Areas are copy, structure, design, implementation, quality_revision, limited by the approved scope. This is an AI decision receipt, not human approval.

Register input includes key, title, funnelRole, rationale, source, referenceId when available, sha256, version and optional manifest. Manifest files carry path, sha256, storageFileId when stored; also record dependencies and commands. Copy each manifest command/dependency verbatim from the current approved `scope.executionPermissions.commands` / `dependencies`; these values are checked by exact membership, so paraphrasing an approved command is rejected. If the actual work needs a value outside that scope, request a scoped revision rather than renaming it to pass. Registration does not itself transfer files. Verify existing storage workflow completion first. A required local-only result must have explicit `storage.localOnlyAccepted` for that step; otherwise incomplete storage blocks delivery.

Review input is `{expectedSetHash, checks:{strategyToTactics:true,funnelContinuity:true,pricePromisesCta:true,sourceRights:true,customVerification:true}, rationale,rejectedAlternatives,unresolvedAssumptions,measurementPlan}`. Supply true only after examining actual outputs. Use the server's artifactSetHash; a hash verifies byte/set identity, not business truth or executable safety. Finalize only after the current review and required saved outputs pass the server's checks. Cancel uses the published `cancelMarketingRun` tool; cancellation cannot undo a provider request already submitted.

## Custom source restoration

Store source text and a version-1 bundle with `executionPermission:'none'`, manifest files `{path,bytes,sha256}`, and files `{path,kind:'text',text}`. `scripts/custom-package.mjs` validates the entire bundle before writing and `restoreCustomPackage(bundle,destination)` restores declared text only to a fresh directory. Pass a canonical real parent path (for example resolve macOS `/tmp` to `/private/tmp`). It rejects absolute/traversal paths, duplicate or case-colliding paths, symlinks, unlisted files, secret-like contents, private config names, size/hash drift and existing destinations. Source is never imported or run by restore.

Secret detection is conservative screening, not proof of absence: inspect selected source before upload and never include credentials, environment files or unrelated repository contents. Keep commands and dependency lists in the manifest for review. Confirm execution permissions for the current environment before running any source; never automatically install dependencies or execute recovered code. A failed restore may leave a partial, non-executable directory; inspect it and choose a new destination instead of resuming writes into it.

Output keys are globally unique ASCII identifiers and must match each step’s declared outputs. Every declared output must be registered before completion. Use `executeMarketingRunTool({projectId,...context,tool,arguments})` for allowed canonical child workflows; do not request general child write capabilities. Use `saveMarketingRunFile` for declared text/documents, then register its server-verified hash. Code is text/plain; never HTML or executable upload. The [custom package schema](custom-package.schema.json) supplies the portable data format; path, secret and byte checks are performed by the executable restore validator.

The start response alone contains the secret leaseToken. Keep it only in a local 0600 execution context; never print it, include it in shared artifacts, or save it in project storage. get/list snapshots omit it. Every mutation carries it with the fencingToken and is bound to the same authenticated actor/key. If start response is lost, do not acquire a competing execution secret; wait for lease expiry and explicitly resume. Snapshots alone cannot reacquire execution rights.

To restore saved custom sources, call `downloadMarketingRunFile({projectId,runId,fileId})` for the registered artifact or each declared manifest child `storageFileId`. It returns `{fileId,downloadUrl,sha256,filename,mimeType,sizeBytes}` only for verified references in this run; it cannot download arbitrary storage UUIDs. Fetch only those declared files via the returned URL, verify returned and manifest SHA-256/byte sizes before forming the portable bundle, then call `restoreCustomPackage` into a fresh canonical directory. Do not log signed URLs or infer execution permission from a matching hash. The corresponding read-only route is `GET /api/projects/:projectId/marketing-runs/:runId/files/:fileId/download`.

When recovering after lease expiry, reuse already successful file IDs and verified hashes instead of uploading them again. Use new operation IDs for new mutations under the new execution context. An unfinished `saveMarketingRunFile` may resume its pending reservation with the same save operation ID and identical filename, MIME, bytes and hash; do not reuse a completed mutation’s old operation ID with a new lease. Correcting registration metadata within the existing approved scope does not require resaving unchanged files.

Prepare the destination and download command before requesting a signed URL, then fetch promptly. If a URL expires while waiting for an approved host network action, obtain a fresh URL through the same download tool; never switch credentials or weaken host protections. Distinguish an expired URL from a current authorization denial, and retain failed attempts in the completion evidence.
