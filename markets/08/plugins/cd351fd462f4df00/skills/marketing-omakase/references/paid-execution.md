# Paid execution and resume

The initial run has no external budget (`externalBudgets:[]`); absence of a provider/model budget means cap 0, submissions 0 and regenerations 0. Approval must fix currency, provider/model, capMicros, maxSubmissions, maxRegenerations and maxQuantity. Micro amounts are integer millionths of currency units. Never change a model name merely to fit the budget.

The image pricing profile is `fal-ai/flux/schnell`, USD, rounded-up megapixels per image. The [official model page](https://fal.ai/models/fal-ai/flux/schnell) states $0.003 per rounded-up megapixel; its [API schema](https://fal.ai/models/fal-ai/flux/schnell/api) defines image size and output count. This support does not select or change the user's model. Only the image profile here and the narrow video profile below are supported; every other endpoint is blocked until its price-affecting parameters have a verified profile. The existing standalone video adapter remains unchanged outside marketing runs.

The profile requires explicit pixel width/height and num_images; enum/default sizes, dynamic sizes, sync mode, unknown options and unreviewed acceleration settings are rejected. Quantity is exactly `ceil(width*height/1_000_000)*num_images`, not image count alone. For 2048×2048 and one image it is 5 units, at least 15000 USD micros. Dimensions are bounded and multiples of 8, and output count is 1–4. The fixed-unit quote must use the exact model page, USD and a unit price at least the verified 3000 micros. Check current price within 24 hours before execution; if the current API/pricing changed, stop and update/test the profile before generating. Provider/model, currency, maximum cost, computed quantity and canonical payload hash must match the server's one-shot permit immediately before POST. No generic count/duration heuristic authorizes an unprofiled model.

The video profile is `fal-ai/kling-video/v3/pro/text-to-video`. The [official price](https://fal.ai/models/fal-ai/kling-video/v3/pro/text-to-video) is $0.112 per second with audio off; audio on and voice control have higher rates. The [endpoint schema](https://fal.ai/models/fal-ai/kling-video/v3/pro/text-to-video/api) returns one video, exposes no resolution control, and defaults audio to true. This profile therefore requires every field below explicitly, allows only these seven fields, and rejects audio, voice IDs, multi_prompt, resolution, multiple outputs and other options. Quantity must be 5, quote currency USD, source the exact model page, unit price at least 112000 micros and reservation at least 560000 micros ($0.56). Refresh the quote within 24 hours; stop if price/schema changed. This is supported capability, not a default model selection; the model must already be in the user-approved scope.

```json
{"prompt":"The approved single-shot prompt","duration":"5","generate_audio":false,"shot_type":"customize","aspect_ratio":"9:16","negative_prompt":"blur, distort, and low quality","cfg_scale":0.5}
```

The bounded five-second silent route can supply a clip to the existing production workflow; it does not claim to generate an entire 15–30-second ad or native audio. Sound, finishing and all existing final QC still apply. Longer sequences need separately scoped submissions; unprofiled routes remain blocked. No provider call was used to validate this candidate; local tests exercise reserve → begin → one POST → status → result → same-ID resume through mocks.

Use `scripts/fal-run-adapter.mjs::runFal` with an injected host `callQuality(name,args)` bridge and transport from `falTransport({credential})`. Credentials stay in the existing local fal resolver. `dryRun:true` is the default and makes zero network/tool calls. Do not persist credentials, authorization headers, or begin permits. All paid host/custom routes use this boundary; no SDK subscribe/implicit retry path is allowed for a marketing run.

`reserveMarketingRunSpend` receives input `{provider:'fal',model,currency,maxCostMicros,quantity,payloadHash,pricing:{basis:'fixed_unit',unitPriceMicros,sourceUrl,checkedAt},regenerationOf?}`. `beginMarketingRunSpend` receives `{projectId,...context,spendId,payloadHash}` and can issue its permit once only. Reserve and begin occur through the same connected actor. Both server and local adapter check cost before submission.

The adapter writes a durable pre-submit journal before begin, validates its permit, sends one bounded HTTP POST with redirects disabled, then immediately persists request_id. A timeout, invalid response, process interruption between begin and request-ID persistence, or ambiguous submission becomes `submission_unknown`; the reservation remains held and there is no automatic resubmission. Find the original provider request through authorized human reconciliation; never infer failure from a missing response. If no request ID can be recovered, leave the operation unresolved.

A known request ID resumes with GET status/result only. One invocation makes one status check; the host can call again later in the active task. fal's service may retry processing internally; this adapter prevents duplicate client submissions and does not claim to control the provider's internal retry policy. Provider errors may still cost money. Completion with unknown actual cost keeps `actualCostMicros:null`; never claim zero cost or release a reservation without evidence. Local results stay pending child-skill QC.

The journal uses an exclusive lock directory. After a process crash, verify there is no active executor and inspect the journal before manually removing a stale lock; do not clear it automatically. Resume requires the same run, scope revision, step, operation ID and request identity. A changed scope requires server reconciliation of existing spend before a new operation.

## Existing video CLI

`performance-video-ad/scripts/fal-generation-adapter.mjs --job-dir JOB --shot SHOT --run-context RUN.json --execute` uses the bounded run adapter after the original animatic, dependency, cost and single-attempt gates. Without `--execute` it remains a dry run. Without `--run-context` the existing standalone workflow is unchanged.

RUN.json contains projectId, context `{runId,scopeRevision,stepId,fencingToken,leaseToken,operationId}` and request with the reservation fields above. Its payloadHash must match the fully resolved route candidate input. Any media input must already use a scoped provider URL; the text-to-video profile has no media input. The run adapter does not perform an unapproved upload. Keep sensitive source URLs only in local provider inputs, not public artifacts. Host callers can inject their existing connector bridge; the CLI can alternatively use an explicitly user-configured `MARKETING_RUN_MCP_URL`, `MARKETING_RUN_APPROVED_ORIGIN` and `MARKETING_RUN_ACCESS_TOKEN` environment. It never discovers/extracts a host token. The URL must be HTTPS `/mcp/quality` and match the explicitly approved origin. The bearer helper only supports JSON MCP responses; use the host bridge when the transport requires session negotiation or SSE.

References checked for implementation: [fal queue REST lifecycle](https://fal.ai/docs/documentation/model-apis/inference/queue). Actual paid generation and real-client OAuth/MCP verification are release checks requiring separately authorized execution.
