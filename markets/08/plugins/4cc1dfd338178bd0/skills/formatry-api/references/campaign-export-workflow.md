# Campaign and Studio Export Workflow

## Own a campaign through delivery

When the user asks for a finished campaign, continue through the authorized steps instead of stopping after a proposal, job id or preview. Use their objective, audience, source assets, brand, requested channels/formats, copy and output count. Ask only for a missing decision that materially changes the work; otherwise state a reasonable assumption and proceed. A request to propose only, or to wait for a separate confirmation, still limits execution.

- Reuse account-owned assets and Brand Kit/presets when relevant; preserve exact source fingerprints. Never invent unavailable source images or licensing rights.
- Start or resume the correct saved creative. Keep the returned project/creative ids, exact revision, operation idempotency keys, quote id, job id and artifact/file ids. If the host permits saving run state, keep only these non-secret references and user-facing output paths in the selected workspace. Never save credentials, capabilities or signed URLs. After interruption, read current state and resume the existing job before creating anything new.
- Apply cohesive typed design operations within the tool schema. Read back the creative after mutation. On revision conflict, read the new state and reconcile the user's intent; never silently force an older document over it.
- Check the whole preview: copy, clipping, brand assets, CTA, contrast, spacing, hierarchy and the requested aspect ratios. Preview a representative output for each distinct layout and inspect actual pixels with host tools. Fix concrete defects within scope, without generating unrequested variants or burning allowance on endless retries.
- Quote exactly the requested output set. Free Images uses the same account allowance as Studio. An explicit authorization to produce a bounded free set can cover its confirmation; show the real allowance and obtain a decision if output count, cost or scope changes. Preserve proposal → separate confirmation when requested, including reviewer demos. For non-free terms, show the ordinary credit cost and use `formatry_confirm_credit_export` only after exact cost approval; insufficient account funds cannot trigger an upgrade or checkout.
- Follow each accepted job to a terminal state with returned polling guidance. Retry transient reads with bounded backoff. Never create a replacement job merely because a read timed out. Surface a terminal failure with its safe code and retain the original identifiers for recovery.
- Save every requested ready file, verify it, inspect the result, and present the actual deliverables in the host. Summarize filenames/formats, successful output count and any unresolved limitation. Do not claim a campaign is complete while a requested output is missing or unverified.

## Creating and configuring creatives

1. For a new campaign, call `formatry_start_creative` with the requested project name, an optional first-creative name and a stable idempotency key. Retain the returned ids. It creates saved design data only, not a render or export. Read the new creative, then continue with typed operations. Existing grants may need native reauthorization for `projects:write`; never bypass a scope refusal.
2. For several independent concepts in one campaign, call `formatry_add_creative` for each requested named concept using the same projectId and a distinct stable creation key. It creates a blank raster creative; configure it with typed operations and a current revision. Retrying the same name/key returns the existing creative and its current revision without resetting later edits. A renamed or archived target returns a conflict with its ids for inspection; do not silently create a duplicate or reactivate it. This tool does not clone an existing design. Multiple output sizes within one concept use supported per-size configuration and selected-output export.
3. For a saved Studio creative, read its exact revision and use the individually exposed editing tool, such as `formatry_set_studio_copy` for `set_copy` or `formatry_apply_studio_preset` for `apply_preset`. Each tool accepts the canonical `projectId`, `creativeId` and `command` envelope, with only its declared operation kind. Keep matching target ids, a UUID `commandId`, exact `expectedRevision` and stable `idempotencyKey`. Apply different operation kinds sequentially, retaining each returned revision and reading back the saved result before continuing. Apply only user-authorized edits. An explicit instruction to make an ordinary edit supplies authorization; a request to propose or inspect does not. Honor an explicit request to wait for separate confirmation.
4. For visual editing in supported hosts, call `formatry_open_studio` with the saved creative's `projectId` and `creativeId`. In MCP Apps hosts this opens the interactive surface for that same creative. After manual edits, read the current saved revision before the next agent command; reconcile conflicts instead of overwriting newer changes. A successful opener result alone does not prove the interface appeared. If the host lacks embedded UI support, state that limitation and continue with actual tool previews and delivered files.

## Match the asset slot to the scene

Use `product` for a contained product photo with `mediaSurface: product`, `person` for a person cutout with `mediaSurface: person`, and `media` for a phone-screen visual with `mediaSurface: phone`. `secondaryMedia` is a second phone-screen visual and requires the primary `media` binding. Keep logo, background and font bindings independent of that choice.

An uploaded asset retains its declared slot. Selecting Product does not convert an existing `media` asset into a product photo. Bind a matching existing asset or upload the authorized source to the correct slot through the native file workflow. Inactive visual-family bindings may remain saved for switching modes; they do not render in the selected scene. Read back the selected surface and bindings, inspect the actual returned image, and never claim the user's photo is present merely because a bind command succeeded.

## Export quoting, confirmation, and delivery

1. Read the saved creative revision, call `formatry_create_studio_export_quote` with `current` or `selected` output scope, and show the output set, `billingMode`, `freeUnits` and `freeRemaining`.
2. For free raster quotes: after the user confirms a free raster quote, call `formatry_confirm_studio_export_quote` with the server-issued quote id and a stable idempotency key.
3. For non-free quotes: show the fresh quote's ordinary account credit cost and funding source (`fundingSource: account_balance`), then call `formatry_confirm_credit_export` only after approval of that exact `approvedUnits` value and a stable idempotency key. Approved non-free exports use the same ordinary account credit and subscription balance as Studio; they never purchase new credits. Unlimited access has no debit; insufficient funds create no job or charge. Never substitute credit spending for an explicitly free-only request.
4. The older `formatry_confirm_included_export` remains subscription-only for compatibility. Do not reuse an old included-only quote or approval to spend ordinary credits: obtain a fresh account-balance quote and cost approval. A changed funding mode or stale quote must fail safely; unchanged accepted retries reuse the original job without another debit.
5. Follow `job.id` through `formatry_wait_for_generation_job`, require a ready `formatry_get_artifact_manifest`, and save each requested file with the native download workflow (or `formatry_download_artifact_file` in compatible resource-aware hosts).
