# NC58 — public listing and customer copy

Technical package: berrer-build-mcp. Display name: Build_.
Subtitle: Build and test Windows apps.
Starter: Press Enter to begin.

## Current public description

Describe an app and let our plugin build it for you. New to Build_? Select Build_ in ChatGPT and press Enter for the welcome, or choose the suggested “Press Enter to begin” prompt if it appears. You can also type your app idea immediately. Start with an idea, even if it is rough: we can discuss the key details before choosing the first prototype. When you approve a proposed build, Build_ creates a Windows desktop Python app, runs useful checks available in the chat environment, and provides one complete ZIP for Windows testing. A direct request to build an app already counts as approval to begin. You do not need to specify Python, ZIP format, logging or project continuity.

Extract the ZIP and double-click run.bat. Each customer ZIP contains only run.bat and PROGRAM/ at the top level; PROGRAM/readme.md explains the coded project records.

After testing upload LogReport.zip back to Build_ to review the results, and describe changes and improvements to your app. Logs are saved beside run.bat in root. They are never uploaded automatically. Reports can include functional success/failure observations without exposing saved values. Build_ can repair evidenced defects or advance already-approved work without inventing features.

To continue, select the same Build_ entry from the @ menu and add your reply. Relevant follow-ups can use the existing conversation context, but permanent tool routing is not guaranteed. When a chat gets too long, select Build_ in a new chat and attach the latest app ZIP, plus relevant LogReport.zip feedback, to continue from the retained source and project context.

Type /help for a quick guide. Downloaded apps require Python 3.10 or newer unless a runtime is included.

A small read-only MCP tool can refresh the Build_ workflow guide during relevant conversation turns. For third-party packages, an optional compatibility tool checks published Windows PyPI wheel metadata. The gateway receives only a workflow phase or the package and target details required by the selected tool. It does not execute customer code, store projects, receive project files or diagnostic ZIPs, or make AI API calls. Tool selection depends on the host; continuous automatic routing is not guaranteed. Unavailable GUI or native Windows checks are disclosed in the delivery reply. A complete Windows-testable ZIP does not imply that those checks ran.

## Boundary

The listing describes complete Windows-testable app delivery with actual available
checks and truthful omissions. It does not guarantee native Windows execution,
permanent chip selection, future automatic routing or public approval. The private
installation and its App binding are separate from this portable public upload.
