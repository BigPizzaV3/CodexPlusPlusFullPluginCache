# SX18 — components

plugin.json is the portable manifest; .codex-plugin/plugin.json retains the existing
compatibility configuration. Both describe the same berrer-build-mcp identity and portable public MCP connection.
skills/build is the main workflow and skills/build-start is read-only onboarding.
Public MCP configuration is mcp.json, with a synchronized .mcp.json compatibility
view. The private account binding is absent from this upload. CT90 defines the phase-only guide call;
check_windows_dependencies supplies live PyPI wheel evidence only when useful.
Both services are nonblocking support; neither executes or stores customer builds.

RA89 describes supported installed-resource loading. prepare_runtime.py verifies
and materializes the same 14 pinned Python engine files. bootstrap_runtime.mjs
transfers complete resource-reader results to an advertised Python executor when
no mount/bundle download is available. These operations load existing code, not a
replacement engine. EX89 detects transfer/version mistakes, not publisher identity.

iteration/engine.py owns project state, source revisions, static checks, immutable
ZIPs and delivery history. layout.py produces run.bat plus PROGRAM/. records.py
creates meaningful project context under stable coded names. runner_template.py
and lifecycle_template.py are copied as ZP90.py and RT42.py. Their LogReport protocol
and startup/error handling remain the original compatible runtime contract.

deliver.py --mode windows-testable exports the intact engine-produced archive after
static, inventory and trusted-template checks. It records delivery separately from
qualification, keeps unperformed checks explicit, and does not create an RC18 pass.
A complete Windows-testable delivery can be used as the next iteration's baseline.

deliver.py --mode qualified --allow-execute retains full observed qualification:
run the real tests, freeze the payload receipt, re-run the exact final archive and
export only its verified bytes. RC18 is evidence of its stated tests, not a promise
of universal correctness or native Windows execution. Failure is never relabelled.

guide.py previews narrow welcome/help aliases without executing application code.
check_package.py is an optional publisher check. Neither is a customer build gate,
an installer, a remote service, or proof of native host selection.
