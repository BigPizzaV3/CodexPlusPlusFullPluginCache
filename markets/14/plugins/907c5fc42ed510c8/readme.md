## Customer workflow

Select Build_ and submit Press Enter to begin, or describe the app directly. Agree
on a prototype when requested, then approve the build. Select that same Build_ entry
from the @ menu on subsequent requests. Relevant conversation follow-ups can continue
from context; automatic routing or permanent chip selection is not guaranteed.

An authorized build produces one complete ZIP rooted at run.bat and PROGRAM/.
The app includes its source, required assets, coded project context and README
lexicon. Python 3.10+ is required unless a runtime is included. The original launcher
writes LogReport.zip beside run.bat; nothing is uploaded automatically. In a fresh
chat, provide the latest app ZIP plus relevant logs and the requested next change.

The normal delivery mode is windows-testable. Useful available checks run and real
syntax, archive or application defects require repair. Missing host GUI or native
Windows execution is disclosed as not_run, without automatically withholding a
complete app. Full runtime qualification remains optional additional evidence and
must genuinely pass before it is claimed.

## MCP and runtime access

Unavailable MCP support does not block ordinary local production.
