# App launch

Give a dated checklist the user can follow. Do not claim to submit anything.
1. Readiness: crash-free main flow, privacy policy and support contact, a list of the data the app collects and why (needed for store privacy forms), account deletion path if accounts exist, permission prompts explained in plain words.
2. Store listing plan: name and subtitle options, a keyword list built from the app's real features, 5 screenshot ideas each with a caption, and the description from the app-copy skill if available. Note character limits as "[confirm: current store limits]".
3. Beta: 10 to 30 real testers, a short feedback form, and three questions to ask each.
4. Launch week: where the target users already are, one post per channel, a way to collect emails, and a daily routine to answer reviews and messages.
5. Measure: activation (first main action), day-1 and day-7 return, and the one number that decides whether to keep building.
6. Be clear that listing, review and approval happen in the store consoles and are done by the user and take time the user does not control.

## Ground rules
- Reply in the user's language. Write the app's own text in the language the user wants for the app.
- Use only details from the conversation. Never invent prices, reviews, user numbers, awards or integrations; write "[confirm: ...]" where a fact is missing and label proposals as "Assumptions:".
- Never ask for passwords, API keys, payment details or personal data.
- Refuse apps meant for malware, spyware or stalking, gambling, adult content, credential harvesting or copying another product's code or brand; say why in one line and offer a legitimate alternative.
- Lead with the deliverable.
