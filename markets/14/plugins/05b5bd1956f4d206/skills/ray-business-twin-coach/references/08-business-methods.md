# RAY 个人商业咨询方法论

公开插件使用边界：本资料用于方法与任务协作。课程工具只帮助用户定位其已拥有权限的资源；不得主动推销数字课程/会员、展示优惠与升级方案、发起支付或导向新订阅。不能获取受限资料。实际执行遵守本技能入口和用户当前请求。


版本日期：2026-10-26。用途：分身的跨模块商业判断底座。由 RAY 正式方法、课程与本项目现行专项方法整理；不是逐字引用库，也不是对每个使用者都适用的标准答案。

## 一、先还原事实，再判断第一限制

先确认对话要完成什么：理解一个概念、选择方向、做一项产物、解决反复卡点，还是复盘已执行任务。操作问题直接解答；复杂经营问题才展开诊断。
商业事实包括：个人能力与做成过的事、服务谁、客户当前场景、买什么、付过什么、如何获得客户、怎样交付、客户结果、时间与资源约束。把事实、本人解释、分身推断和关键缺口分开。
例如“平台限流”“用户不愿付费”“我不会卖”是解释。要问发生了什么、最近怎样变化、有没有例外、看过什么记录。没有数据可以从最近一次真实尝试开始，不能补造数字。

检查商业对齐：内容吸引来的人、愿意购买的人、本人能服务出结果的人是否一致。若是错配，单纯加大内容量或换工具很难解决。
第一限制不是永远最上游，而是当前最影响总体结果且有证据可干预的一环。新手常需先核对用户与价值；稳定销售但客户结果恶化时，应先修交付和容量，不能机械重做定位。
复杂问题保留竞争解释。例如有阅读无咨询，可能是受众错，也可能是入口断。找能够区分两者的证据，再决定改哪一环。

## 二、看趋势、反馈与行动代价

依实际业务周期查看最近几次或一段时期：做过哪些动作、何时变化、结果是否有延迟、哪个样本不同。短期无成交不一定失败，一次爆款也不证明稳定。
经营中的几条重要反馈：
1. 合适客户 → 有效交付 → 结果 → 案例与信任 → 更多合适客户。
2. 真实对话 → 更懂问题 → 更准确的定位与表达 → 更高质量对话。
3. 成交增长 → 容量紧张 → 质量下降 → 口碑和复购受损。
4. 同时做多平台、多产品、多工具 → 每条投入不足 → 反馈稀薄 → 更焦虑和分散。
这些是分析视角，不能当成已证明的个案因果。要核对实际记录和反例。
行动可分为直接执行、小步验证、先补材料、交人工确认。选择时比较效果、成本、时滞、副作用与可撤回性。优先找到能产生证据的一步，不把复杂系统建设当成果。

## 三、定位：把能力转成具体用户的购买理由

定位回答：这个 IP 为什么值得存在，先服务哪一类人，在什么时刻解决哪个付费问题，带来一个什么结果，凭什么可信。
能力、证书、兴趣和身份是资产，不能直接当用户结果。沿着“我有何资产 → 谁可能信任 → 哪个真实场景 → 什么可观察改变 → 为什么现在重要 → 什么付费与交付证据”往下拆。
强资产记录学历、行业、年限、职位、项目规模、做成的改变、转型与可公开证明。只用真实且与购买有关的背书，不为好看夸大。
人群不只写“有问题的人”。进一步看处境、已有经历、购买触发、旧尝试、现实损失与支付条件；每个细分条件都应解释为何改变需求或交付。

候选方向至少比较：问题痛不痛和急不急、解决后的改变大不大、是否有付费能力及行为、自己能否交付、是否能接触这群人、是否有可信理由、本人是否愿长期服务。没有证据的项目写“待验证”，不拿虚构分数包装精确结论。
对用户的定位表达可用：帮助【某种处境中的具体人】，解决【当前问题】，通过【可信路径】，取得【约定边界内的结果】。
“成长”“赋能”“疗愈”“优势”若仍抽象，追问其在生活或业务中具体改变什么；不把中间指标无止境升级成无法负责的人生保证。
0→1 选一个问题假设去接触客户；1→10 从购买、未买、成功和未达结果样本中收敛；10→100 深耕成熟客群，形成组织共同使用的定义。
不因市场大就进入，不因一单高价就永久定方向。也不能把 RAY 自己的高客单入口强套给没有相应能力的人。

## 四、核心方法：怎样从起点走到结果

核心方法回答因果路径，Offer 回答怎样购买和服务，课程/社群/咨询/软件只是承载方式。
从真实交付倒放：客户起点与目标 → 跨过哪些阶段 → 每阶段任务 → 具体障碍 → 有效动作与判断 → 无效动作 → 结果及反例。
压缩成一条结果主线和若干必要步骤，每一步有进入条件、任务、反馈与通过标准。步骤数量依据问题，不为凑模型硬造三步、五步。
命名保留本人反复使用且用户听得懂的比喻和动作词；先展示机制，再命名。只有设想时叫初版假设，不声称已验证、独创或行业唯一。
在内容里解释为什么旧方法失效，在销售中说明实现结果的路径，在交付中落实阶段任务，在案例里核对哪个动作带来何种变化。四处要讲同一套方法。

## 五、Offer 与定价：从障碍倒推服务

先写用户起点、一个核心结果及完成标志，列出旧尝试、阻碍、顾虑与执行限制。按因果顺序挑必须解决的障碍；为每个障碍选动作；再决定教、带着做或代做，以及咨询、异步、课程、工具、线下等形式。
最小完整服务包括：适配/排除条件、要解决的问题、具体结果、关键步骤、每步双方动作、检查点、周期、服务范围、责任、价格逻辑、结果证据、不能承诺的内容。
权益必须解释帮助客户跨过哪个障碍，不用课时、资料数量、无限答疑制造表面价值。能减少客户执行负担且不损害结果的形式优先。
0→1：设计一页 Offer 和首单交付预案，验证愿买与能交付；不是先录一套大课。
1→10：用首单实际承诺、动作、工时和结果修订主力 Offer，分标准项、必要个性化项和不应继续做的项。
10→100：拆共性任务与个别关键判断，用一对多与协作扩容量；关键反馈不能因变成录播就消失。

定价需要结果价值、买家场景、信任证据、替代办法、直接成本、本人容量与专业责任。先给逻辑、待核变量或明确标注的测试方案，不凭赛道名直接报统一价格。
客户说贵，可能是不急、结果不值、路径不可信、人与产品不匹配、缺决策条件，也可能确实价格与价值不符。核对原话和真实报价过程，不自动降价。
低价引流、免费诊断、社群、试点、直接销售和企业提案都是可选机制，只有它能更好检验当前缺口或促成合适购买时才采用；不是所有人必须走同一产品梯队。
退费、延期、效果承诺按现行合同与实际证据，不自行生成无条件保障。

## 六、内容与获客：围绕同一用户结果积累信任

先问目标客户在哪里、已有何种关系或渠道、哪种形式能持续；公域、私域、转介绍、合作和线下都可能有效。选择一个主入口，把触达、合格对话和后续结果记录起来。
内容四个根对象：问题、结果、方法、案例。本人真实经历、观点、用户对话和服务过程提供材料，AI 不能替代真实素材。
三层内容任务：
- 扩圈曝光：让可能需要这项价值的人停留；宽入口要能筛回定位。
- 问题诊断：具体场景、常见误判、机制、后果与第一步，让用户看懂自己的问题。
- 专业种草与转化：方法、案例、过程、产品适配与自然下一步，让用户有依据作决定。
内容层是决策功能，不要求每篇同一模板，不要求每天固定比例。只有曝光易来错人，只有抽象干货难建立购买理由，只有广告又缺理解与信任。

内容流程：明确本次服务哪种用户决策 → 找对应原话/案例/素材 → 选题 → 写判断与依据 → 适配平台表达 → 核对真实性与专业边界 → 发布 → 看合格咨询及来源 → 复盘写回素材和 SOP。
公众号可承载深度观点与信任，小红书适合发现和场景问题，朋友圈承接日常信任与产品可见度，直播集中讲问题、方法与决策。先选当前客户能触达的形式，不强制同步、短视频或平台矩阵。
账户包装须明确身份、对象、问题、真实背书与下一步；各平台资产分开，不能把朋友圈背景图写成公众号置顶，不虚构平台可置顶数量。
内容复盘分受众、触达、主页/入口、合格私信、预约、购买、交付适配。阅读与点赞是信号，不能替代商机和客户结果。
少量试发可检查入口与表达，不能凭三条内容断言市场没有需求；样本与观察期应随平台、渠道和成交周期确定。

## 七、私域与销售：补齐决定所需的信息

私域让用户逐渐理解你是谁、解决什么、方法怎样有效、证据是什么、谁适合、边界是什么、下一步怎么走。朋友圈、群、诊断或活动是条件性节点，不是必备三件套。
先做好能让新人快速理解的头像、名称、简介、背景/置顶或欢迎信息。信任资产按实际平台能力和用户状态选择，不强制三条置顶。
初次联系可问“你希望我在哪方面帮到你？”；核对来源、问题和合作意愿，不加好友就灌长问卷或硬推服务。
朋友圈可以组合真实生活、判断、问题、方法、交付过程、授权案例和产品说明；节奏由实际经营任务决定，不伪造紧迫性、付款截图和稀缺名额。
有持续真实对话时，用简单潜客记录看来源、处境、问题、意向、下一动作和约定时间。跟进应有用户允许或明确沟通基础，不自动群发。

诊断式销售顺序：先确认对话目的 → 当前状态 → 想要结果与重要性 → 阻碍与旧尝试 → 核对差距与第一障碍 → 解释解决路径 → 判断匹配 → 说明服务、责任、价格和下一步。
一句问句只核一个变量；问卷是准备材料，不替代真人对话。未理解客户结果前不要用专业术语替客户下定义。
合作条件包括时间、精力、决策权、预算、能力与风险，不能把“听话”当筛选标准。可合作表现是共同确认任务、完成一次测试周期、提交真实数据、遇阻及时沟通。
异议处理先确认疑虑属于问题、结果、方法、服务者信任、执行、时间、预算还是决策；回答实际疑虑，不无限说服。明显不适配就说明原因并结束销售。
“问题、欲望、信任、行动”等可作诊断维度，不是可计算的成交概率公式。不要给伪精确乘法得分。

## 八、交付、案例与经营复盘

交付开始前记录客户基线、约定结果、责任、节奏和检查点。每阶段说明输入、双方动作、检查、反馈、纠偏与升级。上完课、客户说满意、任务全勾选，均不自动等于取得结果。
异常先判断是准入不匹配、承诺/目标不清、关键方法无效、客户执行困难、反馈缺失还是容量不足；专业风险交给有责任的人员，按服务约定处理。
选择一个客户完整重放，区分确实发生的变化、客户自报、分身解释及其他影响因素。保留未达结果、部分成功和反例。
案例至少有起点、目标、动作、时间范围、实际变化、证据、归因限制、适用与不适用条件、公开授权。不能把方案设想写成发生过的成绩；不能串入另一位客户资料。
结果回流：用户原话进用户洞察；有效动作进方法和 SOP；失败改筛选、承诺和路径；授权材料进入内容和销售；跨单数据进入经营复盘。

经营看板先用同一观察窗、同一客群与 Offer 口径记录：合格线索、实际咨询、报价、付款、交付中/结束、达标/部分达标/未达标，及收入、退款、直接成本、本人工时。
转化率必须说明分子分母及是否同批客户，分母为零记不适用；不把本月付款除以无关月份咨询。不完整样本先给事实，不补全漂亮漏斗。
结果率说明约定结果、已到验收时点的客户与待追踪客户，不能让未结束服务拉低或抬高结果。
可算每单收入减直接成本，并单列本人工时及未计入费用，不把它直接叫净利润。降低工时同时看返工、投诉、结果与客户体验。
每轮只选一个当前主断点，给一个改动、预期信号、反证、观察窗与停止条件；新反馈可能使限制迁移，不能永久重复最初方案。

## 九、发售与规模化

发售把产品、用户问题、核心方法、信任、异议与购买行动集中呈现。准备前核实主力服务是否有依据，受众能否触达，案例能否引用，销售数是否在交付容量内。
流程可由真实情况选择：准备用户/异议证据 → 确认 Offer 与容量 → 预热与邀约 → 问题/目标/旧方法/新路径/证据/产品/适配/行动 → 申请或咨询 → 筛选成交 → 入组交付 → 复盘。
不要求人人先开群或大直播。产品未验证时先小范围诊断与付费交付，不借规模发售验证所有未知。
六位数课程案例是历史案例/学习目标，不是成员结果保证。实际时间、价格、名额和活动政策要重新核对。

## 十、AI+SOP 与组织

四要素见 01：方法论、SOP、知识库、AI 员工。先围绕真实任务构建，不按机器人数量建设。
SOP 写清触发、目标、输入、动作、判断、输出、边界、验收、异常、反馈和版本；同一份业务原记录可以服务不同视图，不为每个 AI 复制一套矛盾知识。
知识库至少区分稳定规则、当前 Offer、增长中的客户事实、假设、过时版本和权限。使用者自己的事实与 RAY 通用方法分开；分身不共享不同用户记忆。
AI 岗位要有任务目标、所读资料、SOP、输入输出、允许动作、交接、验收人与错误升级。一个工具可承担多类教练能力，但外部动作必须有真实连接与授权。
先拿真实任务与失败样本测试，记录正确性、需修改处、返工和节省时间。没有读回执不说已保存，没有人验收不说已上线。
规模化时先拆创始人必做、可交协作者、可交 AI 和可集中交付，再设计交接与质检。新建岗位先试一段流程，比较结果、工时与成本后再扩。

## 十一、把建议变成使用者能执行的下一步

不是把每个模块讲完，而是选与当前问题相关的一段：已有事实 → 关键判断 → 为什么优先 → 共创完成物 → 真实动作 → 验收和反馈。
信息不足时只追问会改变动作的问题；已有资料就继续处理。需要 RAY 或本人最终决定的部分，给具体可审阅方案和唯一确认点。
收入目标、完成时间和样本量都要依据本人基线与周期；不用统一 3/7/30/90 天替代业务证明。短期任务是启动验证，长期结果继续追踪。
