# Host execution

Use the chosen host's actual exposed capabilities; do not require two hosts.

| Request | Required evidence before claiming success |
| --- | --- |
| Remember a preference | Successful persistent RH write, or explicit host memory confirmation |
| Save a production goal | Saved goal revision; explain that it is planning if no executor exists |
| Deliver a daily digest | A real scheduled task with timezone, destination, next run and pause/cancel path |
| Respond to an RH event | Active subscription in a host supporting that event protocol; confirmed server delivery path |
| Publish on several platforms | Exposed publishing tool, authorized owned destinations, preview and required platform choices/consents, then per-platform receipts |
| Report today's growth | Authorized metrics with observation time, reporting period, availability and a comparable baseline |

ChatGPT Work MCP Events and a plain tools-only MCP connection are different.
Do not claim events are installed because documentation describes them. The RH
producer foundation has no events/list, subscribe, callback dispatcher or scheduler.
Native scheduled tasks may be used when actually exposed and requested; their
availability, permissions and notifications depend on the user's host configuration.

Claude cloud routines, Cowork tasks and running Claude Code channels have distinct
execution lifetimes. Choose only the mechanism supported by that user's host.
Do not claim an ordinary Claude chat is a continuously running channel or that
all Claude runtimes use the same private conversation memory.

When publishing becomes exposed, keep separate per-platform states and retry
only failed/reconcilable destinations using original operation IDs. An uncertain
remote upload must be reconciled before resending. Honor mandatory platform UI,
privacy, music/commercial declarations and current scopes. A standing RH policy
cannot override the platform or host. Recheck temporary-file expiry before
scheduling; never extend the existing media-retention window implicitly.

If the user asks for an end-to-end workflow whose last action is unavailable,
complete the independent research, script and edit preparation; state exactly
which last action remains unavailable. Do not ask the user to assemble JSON,
re-enter known preferences, or approve every free planning step.
