# vidIQ Packaging Studio

Read [Live surface notes](references/live-surface-notes.md) first, even when using only supplied evidence.

Create an honest title-thumbnail package from a concept, script, reference, or published video.
Use the creator's supplied audience, format, language, tone, and assets.

## Match the request

- For a focused title or thumbnail edit, go directly to that edit. Resolve a channel or fetch
  evidence only when the action needs it.
- For an idea or script, establish what the content can truthfully deliver.
- For a published video's performance diagnosis, investigate before attributing weakness to
  packaging. Read [Research and diagnosis](references/research.md).
- For a full package, research only gaps that can change the creative decision. Reuse sufficient
  supplied evidence.
- Before evaluating external references, including examples already supplied by the creator,
  read [Discovery evidence](references/discovery-evidence.md).
- For an explicit comparison of distinct concepts, use `vidiq-packaging-comparison`.

A critique does not imply generation; a title request does not imply a thumbnail or script.
Ask only for missing information that changes the requested result.

## Develop the package

Preserve what each number measures: video length does not prove how quickly an action was
completed. Use a speed claim only when demonstrated or explicitly supported by the brief.

1. State the viewer payoff, tension or proof, and factual limits. Preserve the supplied story and
   numbers. When covering someone else's story, distinguish its subject from the host analyzing it.
2. If references need to be retrieved, read [Research and diagnosis](references/research.md).
   Transfer
   abstract mechanisms and composition principles while using original expression. Respect the
   creator's own or appropriately licensed assets.
3. Develop the requested title candidates. Keep them truthful and within the platform limit.
   Describe originality as a creative judgment; claims about other videos need supporting evidence.
   Pair the title with thumbnail imagery or text that adds tension, proof, or stakes.
   Judge the pair against the brief; a model score is not a performance verdict.
4. Before using vidIQ tools to generate, score, or refine titles, thumbnails, or scripts,
   read [Production and scoring](references/production.md).
   Before an asynchronous call, read [Job lifecycle](references/job-lifecycle.md).
5. Inspect completed images for factual accuracy, legibility, rights, and attribution.
   If visual inspection is unavailable, return the draft with that limitation; do not claim it
   passed. Keep the version that best meets the brief, explaining any score tradeoff.

## Deliver

Return the requested titles, thumbnail directions, edited assets, or critique, with the rationale
and material limitations. Include source-to-adaptation reasoning when references informed the
work. For executed tools, report generated URLs or pending job IDs, relevant scores and their
context.

Omit unused stages and empty report sections. Include a script, comparison table, or iteration log
only when requested or useful to understand work actually performed.
